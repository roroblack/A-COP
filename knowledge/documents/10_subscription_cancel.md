## 해지 신청과 확정
해지 버튼을 누르면 요청을 만들고 결제·권한 서비스의 확정 이벤트를 기다린다. 요청 생성만으로 회차를 즉시 닫지 않는다. 요청 생성과 효력 발생을 따로 관리한다. 즉시 해지는 확정 이벤트가 도착한 시각에 적용하고, 기간 종료 해지는 다음 갱신일을 예약값으로 둔다. 결제 큐가 먼저 승인되면 해지 요청만으로 그 회차를 소급 취소하지 않는다. 확정 이벤트가 늦으면 예약 상태를 유지하고, 버튼을 다시 누른 행위만으로 즉시 해지나 즉시 변경을 만들지 않는다. 보존 대상 원장은 화면 표시와 무관하게 접근 정책을 따른다. 원장을 보호한다. 이력 접근을 제한한다.

## 즉시 해지와 기간 종료 해지
즉시 해지는 승인된 시각에 권한을 끝내고, 기간 종료 해지는 현재 회차의 종료시각까지 사용권을 유지한다. 고객이 선택한 유형을 화면에 다시 보여준다. 플랜 변경은 상향, 하향, 좌석 조정으로 나눠 계산한다. 상향은 승인 뒤 권한을 열고 하향은 다음 갱신에 예약하는 것이 기본이며, 즉시 하향은 사용 구간과 환불 가능성을 별도 판정한다. 가격표 유효일도 결과에 포함한다. 차액이 발생한 변경은 승인번호와 적용 구간을 남기며, 다음 회차로 넘긴 금액을 현재 회차의 환불로 표시하지 않는다. 효력일과 요청일을 따로 표시해 예약 변경을 즉시 변경으로 읽지 않게 한다. 효력일을 표시한다. 요청 시각을 보존한다.

## 효력시각의 기준
효력시각은 UTC로 저장하며 계정 시간대는 표시만 바꾼다. 23:59 UTC 경계에서 날짜가 달라 보여도 원장 시각을 우선한다. 자동갱신 설정을 끄는 일은 현재 구독을 해지하는 일과 다르다. 설정 변경 시각 이후에 생성되는 결제만 막고 이미 승인된 회차는 별도 절차로 처리한다. 화면에는 현재 기간의 종료일과 다음 결제 예정 여부를 함께 보여준다. 자동갱신 해제 뒤에도 현재 권한은 기간 종료까지 유지하고, 해지 확정 이벤트가 오기 전에는 권한을 닫지 않는다. 차액 계산의 원 회차를 남겨 다음 갱신에 중복 반영하지 않는다. 원 회차를 남긴다. 적용 구간을 표시한다.

## 청구 큐와의 경쟁
청구 기준시각 10분 전부터 큐 작업이 시작될 수 있다. 늦은 해지로 결제가 발생하면 해지 시각과 승인 시각을 비교해 환불 문서의 14일 창구를 적용한다. 체험판의 종료와 유료 전환 사이에는 결제 승인 이벤트가 필요하다. 7일 체험을 사용했다는 사실만으로 유료 상태를 만들지 않으며, 승인 실패 시 권한을 즉시 유료 범위로 열지 않는다. 전환 시각과 선택 플랜은 같은 기록에 남긴다. 체험 종료 시각과 유료 승인 시각이 다르면 유료 전환을 승인 이벤트가 생긴 시점부터 계산한다. 현재 기간의 권한 종료일은 설정 변경 시각으로 앞당기지 않는다. 현재 기간은 유지한다. 현재 상태를 유지한다.

## 해지 철회
기간 종료 전 철회가 들어오면 아직 종료 이벤트가 실행되지 않았는지 확인한다. 이미 끝난 권한을 화면 설정만으로 되살리지 않는다. 팀 구독의 변경 권한은 대표자 또는 지정 관리자에게만 준다. 좌석 수를 줄일 때 사용 중인 좌석이 남으면 먼저 정리 대상을 확인하고, 결제 결과가 확정되기 전에는 기능 범위를 바꾸지 않는다. 개인 계정 요청을 팀 전체 변경으로 확대하지 않는다. 팀 관리자 변경은 좌석 권한의 변경과 분리해 처리하며 새 대표자가 승인하기 전에는 기존 대표자의 요청을 자동 승계하지 않는다. 전환 실패는 체험 종료와 별도 상태로 저장해 재결제를 판단한다. 승인 시각을 따른다. 전환 시점을 적는다.

## 팀 구독의 대표자
팀 대표가 해지하면 팀 전체의 다음 갱신을 멈출 수 있다. 구성원 개인의 요청은 대표 권한이 없으면 계정 전체 해지로 승격하지 않는다. 미납 상태에서 변경 요청이 들어오면 구독 상태와 변경 내용을 별도 사건으로 저장한다. payment_failed 회차가 승인되면 승인 직전 가격을 쓰고 뒤의 변경은 다음 회차에 적용한다. unpaid 동안 상위 기능을 선제적으로 열지 않는다. 미납 회차의 재결제가 성공해도 예약된 플랜 변경의 적용 시각을 임의로 앞당기지 않고 원래 예약을 다시 검토한다. 대표자 변경과 좌석 변경의 승인자를 각각 확인한다. 관리자 범위를 확인한다. 관리자 승인을 확인한다.

## 미납 계정
payment_failed와 unpaid는 해지와 다른 상태다. 미납 계정의 해지는 미래 청구를 막지만 이미 발생한 채무를 없애지 않는다. 예약된 변경은 화면에 예약 시각과 적용 플랜을 표시한다. 사용자가 철회하면 원래 예약만 취소하고 이미 반영된 권한은 별도 복구 절차를 따른다. 동일 요청을 다시 보내도 24시간 중복 키가 있으면 새 변경을 만들지 않는다. 예약 취소 결과가 지연되면 화면에 이전 예약을 숨기지 않고 철회 처리 중이라는 상태와 확인 시각을 표시한다. 미납 해소와 플랜 적용의 순서를 기록해 권한을 앞서 열지 않는다. 권한을 앞서 열지 않는다. 미납 상태를 우선한다.

## 예약된 해지의 표시
예약 해지는 종료 예정일과 현재 플랜을 함께 표시한다. 고객이 이미 기능을 잃었다고 오해할 수 있는 ‘비활성’ 문구를 사용하지 않는다. 청구서와 플랜 변경을 연결할 때는 변경 승인번호와 적용 구간을 함께 저장한다. 문서 발행이 늦어져도 구독 상태를 임의로 되돌리지 않으며, 5분 뒤에도 번호가 없으면 발행 대기로 분류한다. 고객에게는 금액과 효력일을 분리해 안내한다. 문서 발행 지연을 구독 효력 지연으로 안내하지 않으며, 두 시스템의 상태를 각각 조회한 뒤 답변을 작성한다. 철회된 예약도 취소 시각을 보존해 이력에서 사라지지 않게 한다. 예약 취소 시각을 남긴다. 예약 값을 남긴다.

## 데이터 보존
계정 종료 뒤 청구 원장과 감사 hash는 90일 보존한다. 지원 담당자는 삭제된 개인정보를 복원하지 않는다. 권한 반영이 늦어지면 결제 성공 화면만 근거로 기능을 열지 않는다. entitlement 이벤트의 도착 시각을 확인하고 20초가 지나도 반영되지 않으면 동기화 진단으로 넘긴다. 재시도는 동일 이벤트의 식별자를 유지한다. 권한 이벤트가 중복 도착하면 마지막 이벤트만 남기는 대신 원본과 중복 수신 사실을 모두 추적한다. 문서 번호와 구독 이벤트를 연결해 고객 답변의 근거를 만든다. 상태를 각각 조회한다. 문서 상태를 구분한다.

## 해지 후 추가 결제
회차 중 해지했는데 다음 청구가 발생하면 큐 등록, 승인, 해지 효력을 시간순으로 조사한다. 승인 없는 환불 실행은 금지한다. API로 같은 해지나 변경을 재전송할 때는 idempotency 키를 사용한다. 첫 요청이 처리 중이면 두 번째 호출은 새 작업 대신 현재 상태를 반환하고, 키가 만료된 뒤에는 원래 요청과의 관련성을 다시 검증한다. 카드 정보는 로그에 남기지 않는다. 동일 키의 API 재호출 결과가 처리 중이면 새 요청번호를 만들지 않고 최초 요청의 상태 조회 주소를 돌려준다. 중복 이벤트는 하나의 효력만 만들고 수신 횟수는 별도로 집계한다. 한 번만 적용한다. 수신 횟수를 센다.

## API 해지 요청
API는 동일 구독에 대한 재전송을 idempotency 키로 묶는다. 성공 응답을 받았는데 화면이 그대로면 새 해지를 보내지 말고 이벤트 전파를 확인한다. 완료 판정은 결제, 구독, 권한 상태가 서로 맞을 때 내린다. 하나라도 처리 중이면 고객 화면에 진행 중으로 표시하며, 10분 후에도 불일치하면 담당 큐에 올린다. 확정되지 않은 효력일을 완료 시각으로 대체하지 않는다. 불일치가 지속되면 고객에게 반복 재로그인을 요구하지 않고 결제·구독·권한 담당 큐를 함께 묶어 조사한다. 재전송 결과는 최초 키와 묶어 호출자가 상태를 추적하게 한다. 최초 키를 유지한다. 키 만료를 확인한다.

## 완료 판정
해지는 subscription 상태와 entitlement 종료 이벤트가 모두 확인될 때 완료다. 한쪽만 바뀐 경우 동기화 지연으로 분류한다. 과거 구독 자료를 조회할 때는 최신 플랜만 덮어 보여주지 않는다. 각 회차의 시작일, 종료일, 변경 이유를 확인할 수 있어야 하며, 감사 자료는 90일 동안 보존한다. 삭제 요청이 들어와도 법정 보존 대상 기록은 별도 분리한다. 구독 이력의 삭제와 화면 숨김을 같은 동작으로 보지 않으며 보존 대상인 원장 자료는 별도 권한으로 보호한다. 불일치 조사에는 마지막 정상 상태와 현재 상태를 함께 포함한다. 마지막 상태를 보존한다. 불일치 시각을 적는다.
