## 일할계산의 출발값
부분환불은 해당 회차의 실제 승인 금액에서 시작한다. 표시 가격이나 다음 달 가격을 출발값으로 사용하지 않고, 할인과 세금 항목을 먼저 분리한다. 환불 접수에는 승인일, 승인번호, 요청 사유를 함께 넣는다. 승인일로부터 14일 안이면 일반 심사로 보내고, 경계를 넘은 건은 자동 거절 대신 예외 심사로 분류한다. 같은 승인번호가 다시 오면 최초 접수의 상태를 반환한다. 심사자는 승인번호가 일치하는지 확인한 뒤에만 접수 채널의 차이를 무시하며, 빈 사유는 승인 단계로 보내지 않는다. 세금 조정 문서의 번호를 원 청구서와 대조해 누락을 찾는다. 문서 번호를 연결한다. 문서 연결을 확인한다.

## 잔여기간 산정
플랜 변경 또는 해지의 효력시각부터 회차 종료까지를 잔여기간으로 본다. 월간 회차의 경계는 UTC이며, 종료 직전 5분의 사용량은 다음 회차에 이월하지 않는다. 부분 환불은 실제 승인액과 사용 구간을 분리해 산출한다. 할인액을 먼저 되돌린 뒤 세금을 비례 배분하며, 반올림으로 생긴 잔액은 마지막 항목에 한 번만 귀속한다. 계산 전후 금액의 합이 원 승인액을 넘지 않아야 한다. 일할 계산 결과가 0보다 작아지면 환불액을 임의로 음수로 만들지 않고 조정 사유를 확인하는 보류 상태로 둔다. 심사 결과와 지급 결과를 한 필드에 합치지 않아 후속 문의의 기준을 분명히 한다. 승인번호를 대조한다. 접수 시각을 남긴다.

## 상위 플랜 전환
상위 플랜으로 즉시 전환할 때 새 플랜 이용료와 기존 플랜 잔여분을 비교해 차액을 청구한다. 차액이 음수라면 환불 흐름으로 보내며 기존 회차 전체를 취소하지 않는다. 해지 시각과 결제 승인 시각의 선후를 비교해 환불 창구를 정한다. 큐에 남은 결제는 승인 전에 제거할 수 있지만, 승인된 항목은 기록을 지우지 않고 환불 사건을 별도로 만든다. 판단에 사용한 세 시각은 UTC로 보관한다. 승인 전 결제와 승인 후 결제를 같은 환불 유형으로 기록하지 않아 큐 제거와 지급 요청의 책임을 나눈다. 계산표에는 원 승인액과 최종 지급액을 모두 표시해 잔액을 추적한다. 잔액을 확인한다. 잔액을 대조한다.

## 하위 플랜 예약
하위 플랜 전환을 다음 갱신에 예약하면 현재 회차에는 환불을 만들지 않는다. 고객이 즉시 차액 반환을 별도로 요청한 경우에만 효력시각과 14일 기준을 검토한다. 환불 승인은 지급 완료와 다른 상태다. approved, submitted, completed를 구분하고 카드사 응답이 늦어도 승인 상태를 임의로 완료로 바꾸지 않는다. 지급이 5영업일을 넘기면 원 결제수단과 카드사 처리 상태를 다시 확인한다. 지급 상태를 조회할 때 카드사의 마지막 응답 시각을 확인하며 고객의 재촉만으로 처리 순서를 앞당기지 않는다. 큐 제거 여부와 환불 승인 여부를 나눠 기록해 해지 결과를 오해하지 않게 한다. 큐 상태를 나눈다. 승인 상태를 확인한다.

## 세금의 비례 배분
환불액은 과세표준과 세금 조정액으로 나눠 계산한다. 총액에서 임의의 비율을 빼지 않고 원 청구서의 항목별 금액을 기준으로 반올림한다. 기한 밖 요청을 검토할 때는 해지 사유와 실제 사용량 기록을 함께 요구한다. 장애 보상이나 중복 결제처럼 일반 창구와 성격이 다른 사유는 별도 유형으로 저장하며, 14일 규칙을 예외 사유에 그대로 적용하지 않는다. 예외 심사에서 사용량 자료가 없으면 추정치로 승인하지 않고 자료 요청일과 회신 기한을 남긴다. 카드사 처리 지연은 지급 거절과 다른 안내 유형으로 남긴다. 지급 시각을 적는다. 지급 결과를 나눈다.

## 반올림 잔액
센트 단위 반올림으로 0이 아닌 잔액이 남으면 청구서에 조정 항목을 만든다. 조정액을 담당자가 임의로 할인으로 바꾸지 않는다. 접수 채널은 고객 문의와 내부 운영자 등록으로 나뉘지만 필수 항목은 동일하게 유지한다. 누락된 승인번호를 추정해 채우지 않고 원장 조회를 먼저 수행한다. 신청자와 승인자를 같은 사람으로 두지 않는다. 내부 접수도 고객 요청과 동일한 증빙 요건을 적용해 운영자가 빠른 경로로 금액을 확정하지 못하게 한다. 예외 사유가 승인되기 전에는 고객에게 지급일을 확정해 말하지 않는다. 증빙 없이는 확정하지 않는다. 예외 근거를 적는다.

## 사용량과 환불
사용량이 있다고 해서 자동으로 환불액을 0으로 만들지 않는다. 상품 규칙, 승인일로부터 14일, 실제 권한 사용의 세 근거를 함께 보고 판정한다. 환불 대상 회차가 여러 개면 각 승인 건을 개별 판정한 뒤 묶음 결과를 만든다. 한 건이 예외 심사로 빠져도 다른 건의 일반 환불을 막지 않으며, 고객에게는 회차별 금액과 회신 예정일을 나눠 알린다. 달력일과 영업일을 혼동하지 않는다. 묶음 환불의 합계는 회차별 확정액의 합과 일치해야 하며 한 건의 반올림 잔액을 다른 회차에 넘기지 않는다. 접수자의 권한과 승인자의 권한을 구분해 환불 남용을 막는다. 승인자를 구분한다. 승인선을 확인한다.

## 중복 계산 방지
계산 결과에는 원 회차와 계산 시각을 연결한다. 같은 요청이 재전송되면 기존 계산을 반환하고 환불 명령을 두 번 만들지 않는다. 카드사가 원 결제수단으로 지급할 수 없다고 알리면 대체 지급을 바로 실행하지 않는다. 계정 소유자 확인과 내부 승인선을 거친 뒤 허용된 대체 경로만 선택한다. 계정이 닫힌 경우에는 잔액과 증빙을 보존하고 지원팀에 넘긴다. 대체 지급이 허용되지 않는 카드 유형이면 사유를 안내하고 원 결제수단 확인 전에는 계좌 정보를 받지 않는다. 묶음 결과에도 회차별 상태를 보존해 일부 처리 여부를 확인한다. 회차별로 계산한다. 회차 결과를 보존한다.

## 지급액과 표시액
고객 화면의 환불 예정액과 카드사에 보낸 실제 명령액이 다르면 세금 또는 반올림 항목을 설명한다. 두 값을 하나로 뭉개지 않는다. 중복 요청은 접수일이 달라도 승인번호와 금액을 기준으로 연결한다. 이미 completed인 환불에 새 지급 작업을 만들지 않으며, 부분 성공이면 완료된 항목과 보류된 항목을 구분해 안내한다. 재검토 기록은 90일 동안 남긴다. 부분 지급이 확인되면 남은 금액만 후속 작업으로 만들고 완료된 금액에 대해 다시 승인 요청을 만들지 않는다. 대체 경로를 선택한 근거와 확인자를 함께 보존한다. 소유자를 확인한다. 소유자 확인을 남긴다.

## 수동 조정의 조건
자동 산식으로 설명할 수 없는 금액은 수동 조정 대상이다. action:approve 권한자의 승인이 있기 전에는 지급 서비스를 호출하지 않는다. 사용량이 환불 판단에 영향을 주는 상품은 승인 전후의 사용량을 따로 집계한다. 단순히 현재 화면의 잔여량을 기준으로 삼지 않고 원장 이벤트와 사용 기록을 대조한다. 기록이 없으면 금액을 확정하지 않고 증빙 요청으로 전환한다. 사용량 자료의 수집 시각이 승인 뒤라면 해당 자료의 적용 범위를 표시하고 승인 전 사용량으로 소급하지 않는다. 완료 금액은 다시 승인선으로 보내지 않고 남은 액수만 관리한다. 완료액은 재처리하지 않는다. 완료액을 제외한다.

## 환불 처리기간
승인된 환불은 카드사 반영까지 최대 5영업일이 걸릴 수 있다. 내부 상태가 submitted라고 해서 계좌 입금 완료로 안내하지 않는다. 고객 답변에는 승인 여부, 지급 단계, 다음 확인 시점을 포함한다. 카드번호 전체나 내부 위험 판정 문구는 노출하지 않으며, 5영업일이 지나기 전에는 지연을 확정적인 거절로 표현하지 않는다. 답변과 실제 상태가 다르면 원장을 우선 수정한다. 답변 발송 시점과 실제 지급 시점을 분리해 적어 고객이 메일 수신을 입금 완료로 해석하지 않게 한다. 사용량 자료의 출처와 수집 시각을 기록해 산정 범위를 설명한다. 자료 시각을 남긴다. 자료 범위를 표시한다.

## 감사 자료
원 금액, 잔여기간, 세금, 조정액을 90일 동안 보존한다. 결제수단 원문은 저장하지 않고 회차와 이벤트 hash만 남긴다. 환불 문서와 세금 조정 문서는 원 청구서에 연결해 보관한다. 환불액이 일부인 경우 전체 세금을 취소하지 않고 반환된 과세 부분만 조정한다. 관련 파일의 접근 권한과 보존 기간 90일을 함께 점검한다. 세금 조정 문서가 늦어져도 환불 상태를 임의로 되돌리지 않고 문서 발행 대기 항목으로 추적한다. 회신 내용은 실제 상태 변경 뒤에 갱신해 안내와 원장을 일치시킨다. 상태와 안내를 맞춘다. 안내 시각을 적는다.
