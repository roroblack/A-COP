## 설정의 의미
자동갱신을 켜면 다음 회차 결제를 시도하고, 끄면 현재 기간 뒤의 결제만 멈춘다. 설정값은 해지와 동일한 상태가 아니다. 요청 생성과 효력 발생을 따로 관리한다. 즉시 해지는 확정 이벤트가 도착한 시각에 적용하고, 기간 종료 해지는 다음 갱신일을 예약값으로 둔다. 결제 큐가 먼저 승인되면 해지 요청만으로 그 회차를 소급 취소하지 않는다. 확정 이벤트가 늦으면 예약 상태를 유지하고, 버튼을 다시 누른 행위만으로 즉시 해지나 즉시 변경을 만들지 않는다. 보존 대상 원장은 화면 표시와 무관하게 접근 정책을 따른다. 원장을 보호한다. 이력 접근을 제한한다.

## 설정 변경 시각
변경 시각은 UTC 이벤트로 저장한다. 기준시각 10분 전 이후의 변경은 이미 시작된 큐 작업에 반영되지 않을 수 있다. 플랜 변경은 상향, 하향, 좌석 조정으로 나눠 계산한다. 상향은 승인 뒤 권한을 열고 하향은 다음 갱신에 예약하는 것이 기본이며, 즉시 하향은 사용 구간과 환불 가능성을 별도 판정한다. 가격표 유효일도 결과에 포함한다. 차액이 발생한 변경은 승인번호와 적용 구간을 남기며, 다음 회차로 넘긴 금액을 현재 회차의 환불로 표시하지 않는다. 효력일과 요청일을 따로 표시해 예약 변경을 즉시 변경으로 읽지 않게 한다. 효력일을 표시한다. 요청 시각을 보존한다.

## 알림 발송
갱신 예고와 결제 결과 알림은 서로 다른 이벤트다. 메일 반송이 있어도 자동갱신 설정을 임의로 끄지 않는다. 자동갱신 설정을 끄는 일은 현재 구독을 해지하는 일과 다르다. 설정 변경 시각 이후에 생성되는 결제만 막고 이미 승인된 회차는 별도 절차로 처리한다. 화면에는 현재 기간의 종료일과 다음 결제 예정 여부를 함께 보여준다. 자동갱신 해제 뒤에도 현재 권한은 기간 종료까지 유지하고, 해지 확정 이벤트가 오기 전에는 권한을 닫지 않는다. 차액 계산의 원 회차를 남겨 다음 갱신에 중복 반영하지 않는다. 원 회차를 남긴다. 적용 구간을 표시한다.

## 카드 만료
카드 만료가 감지되면 갱신 실패 가능성을 알리되 결제수단 전체를 지원 티켓에 노출하지 않는다. 결제 실패 뒤에는 72시간 유예가 적용된다. 체험판의 종료와 유료 전환 사이에는 결제 승인 이벤트가 필요하다. 7일 체험을 사용했다는 사실만으로 유료 상태를 만들지 않으며, 승인 실패 시 권한을 즉시 유료 범위로 열지 않는다. 전환 시각과 선택 플랜은 같은 기록에 남긴다. 체험 종료 시각과 유료 승인 시각이 다르면 유료 전환을 승인 이벤트가 생긴 시점부터 계산한다. 현재 기간의 권한 종료일은 설정 변경 시각으로 앞당기지 않는다. 현재 기간은 유지한다. 현재 상태를 유지한다.

## 갱신 성공
승인 이벤트가 확인된 뒤 5분 안에 청구서 생성이 시작된다. paid 상태와 invoice_ready 상태를 따로 표시한다. 팀 구독의 변경 권한은 대표자 또는 지정 관리자에게만 준다. 좌석 수를 줄일 때 사용 중인 좌석이 남으면 먼저 정리 대상을 확인하고, 결제 결과가 확정되기 전에는 기능 범위를 바꾸지 않는다. 개인 계정 요청을 팀 전체 변경으로 확대하지 않는다. 팀 관리자 변경은 좌석 권한의 변경과 분리해 처리하며 새 대표자가 승인하기 전에는 기존 대표자의 요청을 자동 승계하지 않는다. 전환 실패는 체험 종료와 별도 상태로 저장해 재결제를 판단한다. 승인 시각을 따른다. 전환 시점을 적는다.

## 갱신 실패
실패는 payment_failed로 기록하며 즉시 해지하지 않는다. 72시간 뒤 unpaid가 되면 제한 검토를 시작한다. 미납 상태에서 변경 요청이 들어오면 구독 상태와 변경 내용을 별도 사건으로 저장한다. payment_failed 회차가 승인되면 승인 직전 가격을 쓰고 뒤의 변경은 다음 회차에 적용한다. unpaid 동안 상위 기능을 선제적으로 열지 않는다. 미납 회차의 재결제가 성공해도 예약된 플랜 변경의 적용 시각을 임의로 앞당기지 않고 원래 예약을 다시 검토한다. 대표자 변경과 좌석 변경의 승인자를 각각 확인한다. 관리자 범위를 확인한다. 관리자 승인을 확인한다.

## 수동 갱신
수동 결제 요청은 자동갱신 큐와 회차가 겹치는지 확인한다. 같은 회차의 중복 결제를 허용하지 않는다. 예약된 변경은 화면에 예약 시각과 적용 플랜을 표시한다. 사용자가 철회하면 원래 예약만 취소하고 이미 반영된 권한은 별도 복구 절차를 따른다. 동일 요청을 다시 보내도 24시간 중복 키가 있으면 새 변경을 만들지 않는다. 예약 취소 결과가 지연되면 화면에 이전 예약을 숨기지 않고 철회 처리 중이라는 상태와 확인 시각을 표시한다. 미납 해소와 플랜 적용의 순서를 기록해 권한을 앞서 열지 않는다. 권한을 앞서 열지 않는다. 미납 상태를 우선한다.

## 연간 계약
연간 선불 계약도 갱신 기준은 승인 시각이다. 1년 만료일을 현지 자정으로 임의 변환하지 않는다. 청구서와 플랜 변경을 연결할 때는 변경 승인번호와 적용 구간을 함께 저장한다. 문서 발행이 늦어져도 구독 상태를 임의로 되돌리지 않으며, 5분 뒤에도 번호가 없으면 발행 대기로 분류한다. 고객에게는 금액과 효력일을 분리해 안내한다. 문서 발행 지연을 구독 효력 지연으로 안내하지 않으며, 두 시스템의 상태를 각각 조회한 뒤 답변을 작성한다. 철회된 예약도 취소 시각을 보존해 이력에서 사라지지 않게 한다. 예약 취소 시각을 남긴다. 예약 값을 남긴다.

## 설정과 환불
자동갱신을 끈 뒤 발생한 청구는 설정 변경과 승인 시각을 비교한다. 적격 환불은 승인 후 14일 창구로 판단한다. 권한 반영이 늦어지면 결제 성공 화면만 근거로 기능을 열지 않는다. entitlement 이벤트의 도착 시각을 확인하고 20초가 지나도 반영되지 않으면 동기화 진단으로 넘긴다. 재시도는 동일 이벤트의 식별자를 유지한다. 권한 이벤트가 중복 도착하면 마지막 이벤트만 남기는 대신 원본과 중복 수신 사실을 모두 추적한다. 문서 번호와 구독 이벤트를 연결해 고객 답변의 근거를 만든다. 상태를 각각 조회한다. 문서 상태를 구분한다.

## 팀 관리자
팀 자동갱신은 대표 관리자만 바꿀 수 있다. 구성원의 개인 설정을 팀 계약의 갱신 중단으로 해석하지 않는다. API로 같은 해지나 변경을 재전송할 때는 idempotency 키를 사용한다. 첫 요청이 처리 중이면 두 번째 호출은 새 작업 대신 현재 상태를 반환하고, 키가 만료된 뒤에는 원래 요청과의 관련성을 다시 검증한다. 카드 정보는 로그에 남기지 않는다. 동일 키의 API 재호출 결과가 처리 중이면 새 요청번호를 만들지 않고 최초 요청의 상태 조회 주소를 돌려준다. 중복 이벤트는 하나의 효력만 만들고 수신 횟수는 별도로 집계한다. 한 번만 적용한다. 수신 횟수를 센다.

## 지연된 권한
결제 성공 뒤 권한 반영에는 최대 20초가 걸릴 수 있다. 짧은 지연 중 다시 결제하지 않는다. 완료 판정은 결제, 구독, 권한 상태가 서로 맞을 때 내린다. 하나라도 처리 중이면 고객 화면에 진행 중으로 표시하며, 10분 후에도 불일치하면 담당 큐에 올린다. 확정되지 않은 효력일을 완료 시각으로 대체하지 않는다. 불일치가 지속되면 고객에게 반복 재로그인을 요구하지 않고 결제·구독·권한 담당 큐를 함께 묶어 조사한다. 재전송 결과는 최초 키와 묶어 호출자가 상태를 추적하게 한다. 최초 키를 유지한다. 키 만료를 확인한다.

## 감사
설정 변경과 갱신 결과를 90일 보존한다. 원문 결제 식별자는 감사 이벤트에 포함하지 않는다. 과거 구독 자료를 조회할 때는 최신 플랜만 덮어 보여주지 않는다. 각 회차의 시작일, 종료일, 변경 이유를 확인할 수 있어야 하며, 감사 자료는 90일 동안 보존한다. 삭제 요청이 들어와도 법정 보존 대상 기록은 별도 분리한다. 구독 이력의 삭제와 화면 숨김을 같은 동작으로 보지 않으며 보존 대상인 원장 자료는 별도 권한으로 보호한다. 불일치 조사에는 마지막 정상 상태와 현재 상태를 함께 포함한다. 마지막 상태를 보존한다. 불일치 시각을 적는다.
