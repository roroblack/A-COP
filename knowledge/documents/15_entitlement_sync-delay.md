## 이벤트의 출발점
결제나 플랜 변경이 승인되면 subscription 이벤트가 권한 서비스로 전달된다. 승인 화면만으로 권한이 즉시 바뀐다고 보장하지 않는다. 권한 판정은 플랜 원장과 현재 구독 상태를 함께 읽는다. 화면 캐시만으로 기능을 열거나 닫지 않으며, 두 값이 다르면 최신 이벤트의 순서를 확인한다. 반영 지연이 20초를 넘으면 정상 응답 대신 진단 경로를 선택한다. 판정 결과가 캐시와 다르면 캐시를 원장에 맞추고 원장을 화면 값에 맞춰 수정하지 않는다. 감사 접근은 읽기 전용으로 수행하고 결과를 고객 데이터와 분리한다. 읽기 전용으로 접근한다. 열람자를 기록한다.

## 정상 반영 시간
대부분의 변경은 20초 안에 반영된다. 20초가 지나기 전에는 같은 변경을 반복 제출하지 않는다. Free, Pro, Business의 차이는 기능 이름이 아니라 허용 범위와 한도로 계산한다. 플랜표에 없는 기능을 추정해 열지 않고, 변경 전후 권한을 비교한 결과만 사용자에게 보여준다. 요청 시각과 판정 플랜을 같이 보존한다. 플랜표에 없는 조합은 가장 가까운 플랜으로 추정하지 않고 관리자 검토가 필요한 미정 상태로 둔다. 판정 시각과 캐시 갱신 시각을 나눠 남겨 지연을 설명한다. 판정 시각을 적는다. 캐시 시각을 남긴다.

## 지연 상태
이벤트가 전달됐지만 권한 원장이 갱신되지 않으면 sync_pending으로 표시한다. 고객에게 결제 재시도를 권하지 않는다. 사용량은 성공한 작업만 세고 실패 요청을 중복 산입하지 않는다. 한도 경계에 도달한 요청은 처리 시작 시점의 잔여량으로 판정하며, 이미 진행 중인 작업은 결과를 임의로 삭제하지 않는다. 집계 기간은 갱신 시각을 기준으로 나눈다. 한도 갱신 시각에 걸친 요청은 시작 시각과 완료 시각을 모두 비교해 한 기간에 중복 산입하지 않는다. 미정 조합은 관리자에게 넘기고 임의의 상위 권한으로 대체하지 않는다. 미정 상태로 보낸다. 판정 근거를 적는다.

## 캐시 만료
읽기 캐시는 원장보다 늦게 갱신될 수 있다. 캐시를 지운 뒤에도 원장 값이 맞는지 확인한다. 이벤트 큐의 재처리는 원래 이벤트 ID를 유지해야 한다. 순서가 뒤집힌 메시지가 오면 먼저 버리지 말고 선행 상태의 존재를 확인한 뒤 재정렬한다. 같은 이벤트가 2번 도착해도 권한 변경은 한 번만 적용한다. 재처리 실패가 이어지면 메시지를 새로 복제하지 않고 원 이벤트의 오류와 마지막 시도 시각만 갱신한다. 경계 요청은 한 기간에 한 번만 집계되도록 원장 이벤트를 대조한다. 한 번만 집계한다. 기간 값을 대조한다.

## 순서가 뒤집힌 이벤트
하향 이벤트가 상향 이벤트보다 먼저 도착하면 버전과 발생시각을 대조한다. 단순 도착 순서로 최종 권한을 덮지 않는다. 캐시를 새로고침하는 것은 원장 수정이 아니다. 수동 갱신 뒤에도 권한이 달라지면 토큰 scope와 플랜 상태를 각각 조회하고, 화면 숫자만 고쳐서 복구 완료로 표시하지 않는다. 고객 콘텐츠는 진단 로그에 복사하지 않는다. 수동 새로고침 결과가 이전과 같아도 새 권한을 만들지 않으며 원장 이벤트가 없는지 먼저 확인한다. 재처리 횟수보다 원 이벤트의 최종 결과를 기준으로 완료를 판단한다. 원 이벤트를 보존한다. 원본 메시지를 보존한다.

## 재처리
실패한 전달은 동일 이벤트의 재처리 큐로 보낸다. 새 결제를 만들어 동기화를 고치지 않는다. 팀 계정에서는 대표자와 구성원의 권한을 분리한다. 좌석이 줄어든 경우 해제된 구성원의 세션과 API 토큰을 확인하되 다른 좌석의 권한까지 함께 끄지 않는다. 새 구성원 반영이 20초 지연되면 초대 상태를 유지한다. 좌석 해제와 토큰 폐기는 서로 다른 작업이므로 구성원 삭제 뒤에도 남은 토큰의 만료 상태를 별도로 점검한다. 새로고침은 조회 동작으로만 남기고 권한 부여 사건을 만들지 않는다. 조회로만 처리한다. 조회 결과를 기록한다.

## 팀 구성원
대표 플랜의 변경은 구성원별 권한 계산을 다시 만든다. 한 구성원만 늦게 바뀌면 전체 장애로 확대하지 않는다. 권한 초과 요청은 API 응답의 상태와 다음 갱신 시각을 함께 안내한다. 결제가 성공했어도 한도가 즉시 늘어난다고 약속하지 않으며, 예외 증액은 승인 주체와 만료 시각을 기록한 경우에만 적용한다. 승인 없는 우회 호출은 금지한다. 예외 증액의 만료 시각이 지나면 다음 요청부터 기본 한도를 적용하고 진행 중 작업의 결과를 소급해 취소하지 않는다. 좌석과 토큰의 종료 시각이 다른 경우 각각의 상태를 안내한다. 토큰 상태를 따로 본다. 구성원 범위를 나눈다.

## 알림 기준
20초를 넘긴 지연은 지원 알림 후보가 된다. 90일이 지난 로그는 복원하려 하지 않는다. 장애가 의심되면 한 계정의 문제와 여러 계정의 공통 문제를 분리한다. 동일 기능에서 2개 이상의 계정이 20초 넘게 실패하면 incident 후보로 올리고, 특정 토큰에서만 재현되면 개별 진단을 계속한다. 최초 관측 시각은 UTC로 저장한다. 여러 계정의 공통 오류는 샘플 계정의 재현 결과와 영향 계정 수를 함께 기록해야 장애 후보가 된다. 예외 권한에는 부여 이유와 만료 시각이 없으면 적용하지 않는다. 만료 시각을 필수로 한다. 예외 만료를 확인한다.

## 권한 회복
결제가 성공해도 entitlement 회복 이벤트가 확인될 때까지 완료 답변을 보류한다. 기능이 실제로 열렸는지 확인한다. 권한이 회복된 뒤에는 실제 기능 호출로 결과를 확인한다. 토큰 재발급만 성공했다고 완료로 보지 않고, 이전에 실패한 요청을 자동 반복하지 않는다. 고객에게는 회복 시각과 다시 시도할 수 있는 범위를 명확히 알린다. 회복 확인은 화면 표시가 아니라 권한이 필요한 실제 호출의 성공으로 판단하며 실패 요청을 자동 재생하지 않는다. 공통 오류 판정에는 표본 계정과 전체 영향 범위를 함께 적는다. 영향 범위를 센다. 표본 수를 적는다.

## 수동 새로고침
고객에게 반복 로그인을 먼저 요구하지 않는다. 원장, 이벤트 큐, 캐시 순서로 진단한다. 예외 권한은 플랜 원장에 영구 값을 쓰지 않고 만료가 있는 별도 부여로 관리한다. 업무 목적과 승인자를 남기며, 만료 뒤에도 기능이 열려 있으면 캐시와 이벤트를 순서대로 점검한다. 예외 부여는 90일 감사 범위에 포함한다. 임시 권한 부여가 끝나면 승인 기록은 남기되 영구 플랜 변경으로 복사하지 않는다. 복구된 호출의 응답과 권한 원장을 대조해 일시 성공을 걸러낸다. 실제 호출로 확인한다. 호출 결과를 저장한다.

## 중복 이벤트
같은 이벤트 식별자가 두 번 오면 한 번만 적용한다. 중복으로 한도를 두 배로 만들지 않는다. 진단 결과에는 계정, 구독, 권한 원장, 이벤트 큐, 토큰 scope를 구분해 적는다. 어느 단계에서 값이 갈렸는지 모호한 표현으로 묶지 않으며, 고객 식별 정보는 필요한 최소 범위만 사용한다. 종료 전에는 재현 결과를 한 번 확인한다. 진단 중 발견한 값의 차이는 단계별로 표시해 담당자가 계정 문제와 이벤트 문제를 섞어 처리하지 않게 한다. 임시 부여의 만료 뒤 기본 플랜으로 돌아갔는지 확인한다. 기본 플랜을 대조한다. 기본값을 확인한다.

## 장애 전환
여러 계정에서 20초 초과 지연이 관찰되면 incident 절차로 올린다. 단일 계정의 잘못된 플랜은 별도 티켓으로 둔다. 티켓은 1개 계정의 원장만 다룬다. 보존 자료에는 판정 플랜과 한도, 이벤트 시각, 실제 응답을 남긴다. 90일이 지난 자료를 임의로 복원하지 않고 정해진 보존 정책에 따라 접근한다. 동일 장애의 후속 보고서는 원본 사건과 연결하되 새 권한 변경으로 기록하지 않는다. 감사 자료를 다시 열람할 때에는 조회자와 목적을 남기며 고객 콘텐츠를 별도 파일로 추출하지 않는다. 진단 단계마다 조회한 자료의 시각과 범위를 기록한다. 단계를 나눠 기록한다. 진단 단계를 표시한다.
