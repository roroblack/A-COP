## Free의 기본 범위
Free는 핵심 기능과 제한된 저장공간을 제공한다. 팀 기능과 확장 권한은 기본적으로 열지 않는다. 권한 판정은 플랜 원장과 현재 구독 상태를 함께 읽는다. 화면 캐시만으로 기능을 열거나 닫지 않으며, 두 값이 다르면 최신 이벤트의 순서를 확인한다. 반영 지연이 20초를 넘으면 정상 응답 대신 진단 경로를 선택한다. 판정 결과가 캐시와 다르면 캐시를 원장에 맞추고 원장을 화면 값에 맞춰 수정하지 않는다. 감사 접근은 읽기 전용으로 수행하고 결과를 고객 데이터와 분리한다. 읽기 전용으로 접근한다. 열람자를 기록한다.

## Pro의 기능 묶음
Pro는 개인 작업 자동화와 더 큰 사용량 한도를 제공한다. 결제 승인과 권한 반영은 별도 이벤트다. Free, Pro, Business의 차이는 기능 이름이 아니라 허용 범위와 한도로 계산한다. 플랜표에 없는 기능을 추정해 열지 않고, 변경 전후 권한을 비교한 결과만 사용자에게 보여준다. 요청 시각과 판정 플랜을 같이 보존한다. 플랜표에 없는 조합은 가장 가까운 플랜으로 추정하지 않고 관리자 검토가 필요한 미정 상태로 둔다. 판정 시각과 캐시 갱신 시각을 나눠 남겨 지연을 설명한다. 판정 시각을 적는다. 캐시 시각을 남긴다.

## Business의 관리자 권한
Business는 팀 관리자, 감사 조회, 좌석 관리 기능을 포함한다. 구성원에게 관리자 권한을 자동 상속하지 않는다. 사용량은 성공한 작업만 세고 실패 요청을 중복 산입하지 않는다. 한도 경계에 도달한 요청은 처리 시작 시점의 잔여량으로 판정하며, 이미 진행 중인 작업은 결과를 임의로 삭제하지 않는다. 집계 기간은 갱신 시각을 기준으로 나눈다. 한도 갱신 시각에 걸친 요청은 시작 시각과 완료 시각을 모두 비교해 한 기간에 중복 산입하지 않는다. 미정 조합은 관리자에게 넘기고 임의의 상위 권한으로 대체하지 않는다. 미정 상태로 보낸다. 판정 근거를 적는다.

## 요청 한도
플랜 한도는 UTC 날짜가 바뀌면 갱신한다. 화면의 현지 날짜가 먼저 바뀌어도 원장 기준을 따른다. 이벤트 큐의 재처리는 원래 이벤트 ID를 유지해야 한다. 순서가 뒤집힌 메시지가 오면 먼저 버리지 말고 선행 상태의 존재를 확인한 뒤 재정렬한다. 같은 이벤트가 2번 도착해도 권한 변경은 한 번만 적용한다. 재처리 실패가 이어지면 메시지를 새로 복제하지 않고 원 이벤트의 오류와 마지막 시도 시각만 갱신한다. 경계 요청은 한 기간에 한 번만 집계되도록 원장 이벤트를 대조한다. 한 번만 집계한다. 기간 값을 대조한다.

## 저장 용량
용량 초과는 즉시 기존 자료를 삭제하는 사유가 아니다. 새 업로드를 제한하고 관리자에게 정리 경로를 보여준다. 캐시를 새로고침하는 것은 원장 수정이 아니다. 수동 갱신 뒤에도 권한이 달라지면 토큰 scope와 플랜 상태를 각각 조회하고, 화면 숫자만 고쳐서 복구 완료로 표시하지 않는다. 고객 콘텐츠는 진단 로그에 복사하지 않는다. 수동 새로고침 결과가 이전과 같아도 새 권한을 만들지 않으며 원장 이벤트가 없는지 먼저 확인한다. 재처리 횟수보다 원 이벤트의 최종 결과를 기준으로 완료를 판단한다. 원 이벤트를 보존한다. 원본 메시지를 보존한다.

## 좌석 수
Business 좌석은 계약에 명시된 수를 넘겨 활성화하지 않는다. 초과 요청은 결제와 권한 양쪽의 상태를 확인한다. 팀 계정에서는 대표자와 구성원의 권한을 분리한다. 좌석이 줄어든 경우 해제된 구성원의 세션과 API 토큰을 확인하되 다른 좌석의 권한까지 함께 끄지 않는다. 새 구성원 반영이 20초 지연되면 초대 상태를 유지한다. 좌석 해제와 토큰 폐기는 서로 다른 작업이므로 구성원 삭제 뒤에도 남은 토큰의 만료 상태를 별도로 점검한다. 새로고침은 조회 동작으로만 남기고 권한 부여 사건을 만들지 않는다. 조회로만 처리한다. 조회 결과를 기록한다.

## API 접근
API 권한은 플랜과 별도의 토큰 scope로 제한한다. 비밀키 원문은 지원 기록에 남기지 않는다. 권한 초과 요청은 API 응답의 상태와 다음 갱신 시각을 함께 안내한다. 결제가 성공했어도 한도가 즉시 늘어난다고 약속하지 않으며, 예외 증액은 승인 주체와 만료 시각을 기록한 경우에만 적용한다. 승인 없는 우회 호출은 금지한다. 예외 증액의 만료 시각이 지나면 다음 요청부터 기본 한도를 적용하고 진행 중 작업의 결과를 소급해 취소하지 않는다. 좌석과 토큰의 종료 시각이 다른 경우 각각의 상태를 안내한다. 토큰 상태를 따로 본다. 구성원 범위를 나눈다.

## 내보내기 권한
데이터 내보내기는 Business 관리자에게만 열며 완료 파일의 접근 기간을 제한한다. 일반 구성원에게 링크를 전달하지 않는다. 장애가 의심되면 한 계정의 문제와 여러 계정의 공통 문제를 분리한다. 동일 기능에서 2개 이상의 계정이 20초 넘게 실패하면 incident 후보로 올리고, 특정 토큰에서만 재현되면 개별 진단을 계속한다. 최초 관측 시각은 UTC로 저장한다. 여러 계정의 공통 오류는 샘플 계정의 재현 결과와 영향 계정 수를 함께 기록해야 장애 후보가 된다. 예외 권한에는 부여 이유와 만료 시각이 없으면 적용하지 않는다. 만료 시각을 필수로 한다. 예외 만료를 확인한다.

## 기능 플래그
실험 기능은 플랜 표에 쓰인 권한과 혼동하지 않는다. 플래그가 꺼져 있으면 유료 플랜이어도 노출하지 않을 수 있다. 권한이 회복된 뒤에는 실제 기능 호출로 결과를 확인한다. 토큰 재발급만 성공했다고 완료로 보지 않고, 이전에 실패한 요청을 자동 반복하지 않는다. 고객에게는 회복 시각과 다시 시도할 수 있는 범위를 명확히 알린다. 회복 확인은 화면 표시가 아니라 권한이 필요한 실제 호출의 성공으로 판단하며 실패 요청을 자동 재생하지 않는다. 공통 오류 판정에는 표본 계정과 전체 영향 범위를 함께 적는다. 영향 범위를 센다. 표본 수를 적는다.

## 한도 초과 안내
한도에 도달하면 현재 사용량과 다음 갱신시각을 함께 보여준다. 갱신 전 임의로 한도를 늘리지 않는다. 예외 권한은 플랜 원장에 영구 값을 쓰지 않고 만료가 있는 별도 부여로 관리한다. 업무 목적과 승인자를 남기며, 만료 뒤에도 기능이 열려 있으면 캐시와 이벤트를 순서대로 점검한다. 예외 부여는 90일 감사 범위에 포함한다. 임시 권한 부여가 끝나면 승인 기록은 남기되 영구 플랜 변경으로 복사하지 않는다. 복구된 호출의 응답과 권한 원장을 대조해 일시 성공을 걸러낸다. 실제 호출로 확인한다. 호출 결과를 저장한다.

## 변경 직후 상태
플랜 변경 승인 뒤 entitlement 반영에는 최대 20초가 걸릴 수 있다. 짧은 지연은 결제 실패로 분류하지 않는다. 재확인은 1회만 수행한다. 진단 결과에는 계정, 구독, 권한 원장, 이벤트 큐, 토큰 scope를 구분해 적는다. 어느 단계에서 값이 갈렸는지 모호한 표현으로 묶지 않으며, 고객 식별 정보는 필요한 최소 범위만 사용한다. 종료 전에는 재현 결과를 한 번 확인한다. 진단 중 발견한 값의 차이는 단계별로 표시해 담당자가 계정 문제와 이벤트 문제를 섞어 처리하지 않게 한다. 임시 부여의 만료 뒤 기본 플랜으로 돌아갔는지 확인한다. 기본 플랜을 대조한다. 기본값을 확인한다.

## 판정 자료
권한 판정에는 현재 플랜, 유효시각, 사용량 원장을 사용한다. 오래된 캐시만으로 권한을 확정하지 않는다. 보존 자료에는 판정 플랜과 한도, 이벤트 시각, 실제 응답을 남긴다. 90일이 지난 자료를 임의로 복원하지 않고 정해진 보존 정책에 따라 접근한다. 동일 장애의 후속 보고서는 원본 사건과 연결하되 새 권한 변경으로 기록하지 않는다. 감사 자료를 다시 열람할 때에는 조회자와 목적을 남기며 고객 콘텐츠를 별도 파일로 추출하지 않는다. 진단 단계마다 조회한 자료의 시각과 범위를 기록한다. 단계를 나눠 기록한다. 진단 단계를 표시한다.
