## 3. 주장 C — 기각을 수용하되 결론은 살아남는다

Codex 지적 중 내가 못 본 것 두 가지가 결정적이다.
하나, uh 원문의 "문의 처리가 실패하면 다음 상태로 분쟁 격상"이라는 표현 자체가 L을 상태처럼 쓴다.
즉 직교성이 깨지는 건 구현 단계가 아니라 원문 서술 단계에서다.
둘, 이의제기·외부 절차는 선형 층이 아니라 재진입 경로여서 4×6 격자로는 정상 경로와 재진입이 구별되지 않는다.

다만 Codex가 산정한 비용(1~3인주)은 **전체 격자를 유지할 때**의 값이다.
격자를 폐기하고 L을 메타데이터로 내리면 필요한 것은 enum 필드 둘과 허용 조합 화이트리스트뿐이며,
"두 안의 통합 비용이 작다"는 원래 결론은 근거만 바뀐 채 유지된다.
바뀐 근거: 직교하기 때문이 아니라, 한 축을 축으로 쓰지 않기 때문에 싸다.

## 4. Codex 판정 중 되돌리는 것 두 가지

### 4.1 자동 해결률은 주 지표로 유지한다
Codex는 L0~L1의 정의가 uh와 sw 사이에서 흔들릴 수 있다는 이유로 이를 보조 지표로 강등했다.
그러나 자동 해결률은 층 정의에 의존하지 않고 정의할 수 있다 —
**운영자 개입 없이 종결된 Case 비율**이면 layer 없이 성립한다.
정의가 흔들린다는 것은 정의를 고정하면 해결되는 문제이지 지표를 버릴 이유가 아니다.
게다가 이 지표는 실무 CS의 표준 지표이고, 층별 모델 등급 전략(아래층 소형·캐시 → 위층 고성능)의
비용 서사와 직결된다. 심사에서 "성능과 비용을 함께 봤다"를 증명하는 유일한 숫자다.

주 지표 최종: route accuracy, 상태 전이 정확도, 리스크 경로 정확도, 승인 위반율 0%, 자동 해결률.

### 4.2 L0의 위상 — Codex 문서 내부가 엇갈린다
Codex는 6장에서 "L0를 완전히 배제하면 분쟁만 처리하는 시스템으로 회귀한다"며 존치를 권고했지만,
5장 (c)안과 최종 권고에는 L0가 없다. 격자를 폐기하는 것과 L0 자체를 없애는 것은 다른 문제다.

판정: L0는 유지한다. 단 "층"이 아니라 **자동 종결 경로**로 부른다.
조회형·안내형·경량 처리형 문의가 Agent Team을 거치지 않고 `resolved`로 직행하는 경로이며,
여기에 자동 해결률 지표가 붙는다. 이 경로가 없으면 uh-2가 스스로 교정했던
"CS의 대부분은 분쟁이 아니다"라는 인식이 다시 사라진다.

## 5. Codex가 추가한 것 중 채택 — 확장성 증명 실험

sw의 Port/Adapter와 COMMON/TENANT 분리는 현재 문서상의 선언이며 10주 안에 Phase 4까지 못 가면
"확장 가능"이 아니라 "확장 설계"라고 말해야 한다. Codex가 제시한 최소 실험을 그대로 채택한다.

1. `OrderPort` · `LogisticsPort` · `ActionPort`를 공통 계약으로 고정
2. `tenant_a` / `tenant_b`가 환불 한도 · SLA · 정책 문서만 다르게 보유
3. 동일 Case fixture를 두 tenant에 실행해 결과 JSON · 상태 전이 · 승인 여부를 비교
4. Adapter를 Mock A → Mock B로 교체해도 Controller와 Team 코드는 무수정
5. contract test 한 벌 + tenant 누출 테스트를 남긴다

이것이 uh 판매자 온보딩을 자르고도 확장성 데모가 살아남는 방법이다.
config는 수동 등록하되, 등록만으로 그래프·SLA·승인 한도가 바뀌는 1분 데모를 만든다.

## 6. 데이터 전략 확정 + 보완

Codex안 채택: Olist 거래 골격 + 통제된 합성 한국어 VOC.
AI Hub 스토어별 배정을 개발 데이터로 쓰지 않는 이유가 설득력 있다 — 리뷰를 임의 배정하면
tenant·책임 주체·SLA 라벨이 인공적으로 생겨 라우팅 평가가 오염된다.

평가셋 3분할: 개발/튜닝 · 내부 golden · 외부 holdout. 해시와 생성 시점을 기록한다.
- 텍스트 외부 holdout — AI Hub 리뷰 별도 subset (의도·감성·이슈 평가 전용, 라우팅·환불 평가에는 미사용)
- 결정·근거 holdout — 공공데이터포털 소비자 분쟁 상담·피해구제 자료 중 정책 RAG에 넣지 않은 문항
- 접근 승인이 안 나면 그것을 외부 holdout이라 부르지 않고, 일반화 주장을 보류한다

### Codex가 짚지 않은 보완
Olist는 브라질 데이터다. 거래 골격(주문-상품-결제-배송-판매자 연결 구조)만 빌리고
반품 기간·배송비 부담·환불 규정 같은 정책 변수는 전부 tenant config로 덮어써야 한다.
이 전제를 명시하지 않으면 "브라질 거래 관행 위에 한국 소비자분쟁해결기준을 적용했다"는 지적이 나온다.
