# 추적 화면 교차검증과 그 뒤

`[실측]` 2026-09-01 codex 교차검증. 원본은 `program/research/_codex_추적화면_교차검증_2026-09-01.md`.

## 총평은 "반대"였다

> 현재 구조는 "원본 하나"가 아니라, **전역 상태와 배열 인덱스가 우연히 일치해야 하는 구조**다. 이미 4단계 제목이 서로 다르다.

## ★ 이관하며 알게 된 것 — 대부분 이미 고쳐졌다

`[실측]` 2026-09-02 에 코드를 직접 확인했다.

| # | 지적 | 지금 |
|---|---|---|
| 1 | monkey patch 로 데이터 추출 | **없다** |
| 2 | 12단계 대조가 개수만 본다 | **번호·제목·색·담당을 다 본다** |
| 3 | 줄 번호로 코드를 자른다 | **글자로 찾는다** |
| 4 | 2.0MB 단일 HTML | 지금 판은 **15~20KB 낱장** |
| 5 | 접근성·사용성 | **일부만.** 키보드 범위(좌우만 어디서나, 나머지는 입력칸 밖에서만)·`prefers-reduced-motion`·그림 `alt`까지. 모달 초점 가두기·`aria-live`·`role="dialog"`는 **안 받아들였다** — 팀 안에서 도는 학습 자료라서 |
| 6 | 그 밖에 깨질 지점 | **고쳤다.** 데이터에 `</script>`가 오면 파일이 깨지던 것(`dump()`가 `<` `>` U+2028/2029 이스케이프), `esc()`가 따옴표를 안 막던 것, 최종 경로에 바로 쓰던 것(`.part` → `os.replace`), 영상이 윈도우 글꼴을 못 박고 쓰던 것 |

`[실측]` 5·6번은 `program/onboarding/versions/README.md` "교차 검증 (2026-09-01)"이 **사실로 확인되어 고친 것 11건 / 받아들이지 않은 것 4건**을 표로 남겨 둔 것으로 채웠다. 09-02에 코드로 확인한 4개와 어긋나는 게 없다.

### 받아들이지 않은 것과 그 이유

| 지적 | 왜 안 했나 |
|---|---|
| `steps.py`를 순수 데이터로 다시 쓰기 | 지적한 실패는 전부 전역 상태·import 순서에서 났고, 전용 이름으로 따로 읽으면 사라진다 — 순서를 바꿔 돌려 확인. 350줄 재작성은 얻을 것보다 크다. **단 인자 순서가 계약이라는 건 맞다** — `step()` 서명을 바꾸면 `sheet_data._collect`도 같이 |
| 접근성 전부 | 위 5번 |
| `cut()`을 AST 기준으로 | **지적이 맞다.** 끝 줄이 밀리면 조용히 잘린다. 다음 판에서 함수 이름으로 찾는다. 지금은 첫 줄 앵커가 잡아 준다 |
| 산출물 신선도 검사(PNG·HTML·MP4 한 명령) | 맞는 말인데 **아직 안 했다** `[미확보]` |

**"맞다, 그런데 안 한다"를 이유와 함께 남긴 게 이 기록의 값이다.** 다음 사람이 같은 지적을 다시 받았을 때 재검토가 아니라 결정을 읽는다.

## 무엇이 어떻게 고쳐졌나

### 2번 — 12단계 대조

`[실측]` `build_trace_html.py:70-114` 의 `check()` 가 이렇게 적고 있다.

> ★개수만 세면 안 된다. 실제로 4번 단계 제목이 한쪽은 **"의도·이슈·감성"**, 다른 쪽은 **"의도와 이슈와 감성"** 으로 갈라져 있었는데 개수 검사는 그것을 그대로 통과시켰다.

지금 보는 것.

```
번호가 1..12 인가      제목이 같은가
색이 같은가            담당이 같은가
```

**담당 대조는 리뷰에 없던 것이다.** 나중에 사고가 나서 붙었다.

> 실제로 2026-09-01 VOC 재판정 때 **낱장은 최연우, 지도는 송채영**이었다.

### 3번 — 코드 절단

`[실측]` `trace_data.py:23` 의 `cut()`.

> ★줄 번호로 자르지 않는다. 처음엔 그렇게 했는데 `final_project_cs` 가 한 줄만 늘어도 인용이 통째로 밀렸다. **실제로 하루에 세 번 밀렸다.**

그리고 유일성을 강제한다.

> `head` 와 `tail` 은 파일 안에서 **유일해야 한다.** 여러 군데 걸리면 그 자리에서 멈춘다.
>
> **조용히 엉뚱한 코드를 넣느니 실패하는 것이 낫다.**

## 여전히 유효한 지적

`[실측]` 리뷰가 짚은 **가장 위험한 것 3개** 중 첫째는 구조 문제다.

> 두 개의 12단계 배열을 **인덱스로 결합**하면서 정체성을 검증하지 않는 것

`check()` 가 대조를 하지만 **결합 자체는 여전히 배열 인덱스다.** 리뷰의 권고는 이랬다.

```
id · n · title · short_title · color · 낱장 내용 · 누적 추가분 · 상태 · 코드 참조
  → 한 단계 객체에 둔다
배열 위치를 식별자로 쓰지 않는다
```

`[미확보]` **이건 안 고쳐졌다.** 검사로 막고 있을 뿐 구조는 그대로다.
