# 설계 원칙 10개

`[실측]` `program/research/학습게임_방법론_조사.md`(2026-08-30 조사)에서 이관. **원본은 그대로 있다.**

## 핵심 루프

```
관찰 → 예측 → 실행/추적 → 설명 → 수정 → 회고
```

## 원칙 10개

| # | 원칙 | 도장의 어디 |
|---|---|---|
| 1 | **첫 30분 안에 축소된 전체 시스템을 실행시킨다** | `learn 0` 해설된 완주 |
| 2 | **모든 퀘스트를 실행 증거로 끝낸다** — 테스트·트레이스·재현 명령·코드 링크 | pytest 판정 |
| 3 | 관찰·예측·실행·설명·수정·회고를 **핵심 루프로 고정** | `learn 1`·`learn 2` |
| 4 | **디렉터리보다 호출·데이터·상태·도구·권한·평가 관계로 지도를 만든다** | 트랙 경계 |
| 5 | 전문가 사고를 보여 준 뒤 **발판과 힌트를 점진적으로 제거** | `learn 0→1→2` |
| 6 | **실제 장애·코드 리뷰·오개념에서 mutant 와 보스전을 만든다** | 결함 카탈로그 |
| 7 | **시간·XP 가 아니라 다른 맥락으로 전이되는 수행으로 숙달을 판정** | **`boss`** |
| 8 | 같은 개념을 **1·3·7일 뒤 다른 문제 형식으로 인출** | **`review`** |
| 9 | 게임성은 **패턴 발견과 의미 있는 선택**에서. PBL 은 보조 | — |
| 10 | **LLM 은 생성자·코치로 쓰고 정답은 분석·실행 oracle·전문가 검수로 승인** | pytest 가 판정 |

## 셋이 특히 도장의 형태를 정했다

### 원칙 6 — 실제 장애에서 결함을 만든다

**지어낸 버그가 아니다.** 이 저장소에서 실제로 터진 것을 mutant 로 만든다.

`[실측]` 카탈로그의 결함들이 실제 사례에서 왔다 — 승인 엔드포인트가 읽기 권한으로 열림, Bearer 형식 검사 제거, 배송 상태를 모르는데 아는 척.

→ [../../final_project_cs/wiki/quality/blind-spots.md](../../final_project_cs/wiki/quality/blind-spots.md)

### 원칙 7 — 전이로 숙달을 판정한다

**`boss` 가 이것이다.** 안 배운 모듈에서 같은 규칙을 찾아 고치게 한다.

**같은 규칙을 다른 자리에서 못 찾으면 외운 것이지 안 게 아니다.**

### 원칙 10 — LLM 은 채점하지 않는다

**정답은 pytest 와 실측 트레이스가 판정한다.**

**이게 [평가 프로토콜](../../wiki/evaluation/judge.md)의 "자기채점 방지"와 같은 원칙이다.**
