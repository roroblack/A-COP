# A-COP 도장

`final_project_cs` 의 구조와 동작을 **실행 증거로** 배우는 학습 프로그램이다.
정답은 사람이 아니라 pytest 와 실측 실행 트레이스가 판정한다.

파이썬 3.12 이상이 필요하다(`sys.monitoring`). 대상 저장소가 쓰는 PostgreSQL 이
붙어 있어야 한다 — 전체 424개 테스트 중 상당수가 DB 를 쓴다.

```bash
python dojo.py doctor
```

워크스페이스 루트의 `dojo.py` 는 설치 없이 어디서든 돈다.
정식 설치는 `pip install -e acop_dojo` 로 하고, 그러면 `acop-dojo` 명령이 생긴다.

## 왜 이 형태인가

설계 근거는 [`program/research/학습게임_방법론_조사.md`](../program/research/학습게임_방법론_조사.md)
와 [`학습게임_설계검수_2026-08-30.md`](../program/research/학습게임_설계검수_2026-08-30.md) 에 있다.
요약하면 세 가지다.

**예측 퀴즈를 중심에 두지 않는다.** prequestion 메타분석에서 물어본 내용에는
효과가 있었지만(g=0.54) 묻지 않은 내용으로는 사실상 전이가 없었다(g=0.04).
"다음 호출은?" 을 반복해 맞히면 그 호출 순서만 남는다. 그래서 예측은 자기설명을
끌어내는 재료로만 쓴다.

**먼저 해설된 완주를 보여준다.** 처음 보는 사람에게 곧바로 예측을 시키면 탐색
부담이 학습으로 오인된다. 0단계는 채점하지 않는다.

**마지막은 안 배운 모듈에서 본다.** 같은 코드에서 한 번 더 물으면 그 코드를 외웠는지만
알 수 있다. 보스전은 0~2단계 트레이스가 한 번도 지나가지 않은 Team 모듈에서 열리고,
기록도 acquisition(처음 성공) · retention(재시도) · transfer(안 배운 모듈)로 나눠 남긴다.

**자동 뮤테이션을 쓰지 않는다.** 구글의 대규모 사례에서 개발자가 뮤턴트의 85% 를
무의미하다고 분류했다. 대신 이 저장소가 문서로 못 박은 불변식에서 사람이 손으로
만들고, 등록 전에 기계가 "지정 테스트를 실제로 죽이는가" 를 확인한 것만 쓴다.

## 명령

| 명령 | 하는 일 |
|---|---|
| `doctor` | 대상 저장소·파이썬·테스트 수집 점검 |
| `trace [--verify]` | 시나리오 트레이스를 뜬다. `--verify` 는 두 번 돌려 같은지 본다 |
| `learn 0` | 해설된 완주. 채점 없음 |
| `learn 1` | 복원 — 빈칸에 들어갈 함수를 고른다 |
| `learn 2` | 대조 — 예상 순서를 세우고 실측과 겹친다 |
| `defect [ID] [--fix 패치]` | 결함 문제. `--fix` 를 주면 pytest 가 판정한다 |
| `boss [--fix 패치] [--defect ID] [--force]` | 보스전 — 안 배운 모듈에서 같은 규칙을 찾고 고친다 |
| `defects [--rebuild] [--only ID,ID]` | 결함 카탈로그 등록 게이트를 돌린다 |
| `stability [--repeats N]` | 결함이 매번 같은 신호를 내는지 본다 |
| `report` | 검증 결과로 사각지대 보고서를 다시 쓴다 |
| `map` | 웹 지도를 그린다 |
| `status` | 진행 상황 |

## 안전

원본 저장소는 절대 바꾸지 않는다. 결함은 임시 사본에 적용하고 블록을 벗어나면
지운다. 사본은 `eval/reports`(18MB) 만 빼고 통째로 뜬다 — `legacy/` 는 unit
테스트 두 개가 import 하므로 반드시 포함해야 한다.
