# RAG 코퍼스를 쓸 때 지키는 것

`[실측]` `docs/plans/2026-08-17_코퍼스_25문서_배분안.md` 에서 이관.

## 왜 게이트가 있나

**같은 말을 여러 문서에 흩어 두면 검색이 아무거나 집어 온다.** 그래서 중복을 막는다.

## 어휘층을 scope 마다 분리한다

`[실측]` **같은 말을 다른 자리에서 쓰지 않는다.**

| scope | 주어·목적어 | 시간 단위 | 행위 동사 |
|---|---|---|---|
| `order` | 주문번호 · 품목 · 결제수단 | 마감시각 · 분 | 접수 · 변경 · 취소 |
| `shipping` | 운송장 · 물류센터 · 기사 | 영업일 · 경유지 | 스캔 · 출고 · 회수 |
| `return` | 반품접수번호 · 수량 · 사유코드 | 수령일 기준 일 | 회수 · 검수 · 판정 |
| `exchange` | 교환건 · 대체상품 · 재고 | 재출고 일정 | 대체 · 소진 · 전환 |
| `refund` | 승인번호 · 지급요청 · 잔액 | 카드사 영업일 | 산정 · 지급 · 대조 |
| `support` | 티켓 · 채널 · 담당자 | 응답 목표시간 | 배정 · 승급 |
| `incident` | 장애구간 · 공지 · 영향범위 | 복구 시각 | 탐지 · 공지 · 집계 |

## ★ 게이트를 우회하는 네 가지 — 이미 거부됐다

`[실측]` **sample 에서 실제로 거부된 수법들이다.**

| 수법 | 결과 |
|---|---|
| 무작위 토큰을 섞어 유사도를 낮춘다 | **v3 거부 사유** |
| 청크를 짧게 써서 겹치는 6-gram 을 줄인다 | **v4 거부 사유.** 평균 56자 |
| 섹션 끝에 의미 없는 문장을 붙여 글자 수만 채운다 | 거부 |
| **게이트를 느슨하게 고쳐 통과시킨다** | 거부 |

**네 번째가 가장 위험하다.** 통과는 하는데 아무것도 안 막게 된다.

### ★ 게이트 항목이 늘어난 순서가 곧 우회의 순서다

`[실측]` [DoD-06](../../docs/evidence/DoD-06_정책FAQ_25건_300청크.md). 위 표는 결과만 적었고, **회차마다 게이트에 무엇이 추가됐는지**가 교훈이다.

| 회차 | 잡힌 것 | 그때 게이트에 추가한 검사 |
|---|---|---|
| v1 | 25문서가 같은 12개 섹션 제목, 꼬리문장 12/12 반복 | 문장 반복 · 제목 공유율 |
| v2 | 청크 중앙 유사도 **0.460**, 공유 6-gram 127종 — 제목을 유일하게 지어서 v1 검사가 **통째로 안 돌았다** | 전역 청크쌍 유사도 |
| v3 | `(s1-625)`·`[제목/ref-6024]` 같은 토큰 주입으로 유사도만 낮춤 | 우회 토큰 패턴 · 14자 공통 문구 |
| v4 | 문체는 통과했는데 **청크 평균 56자** | 청크 길이 |
| v5 | — | 인수 |

**계약에는 적었지만 게이트에 없던 항목(구체 수치·청크 길이)은 매번 지켜지지 않았다.**

> **검증되지 않는 요구는 지켜지지 않는다.**

`[미확보]` v5를 인수하면서 남긴 잔여 결함이 있었다 — 200자 하한을 채우려는 **필러 문장 2개/섹션(청크의 약 15%)**. 옛 sample 코퍼스 기준이고, 지금 쇼핑몰 코퍼스에서 같은 잔여를 다시 센 기록은 없다. groundedness 가 기대보다 낮게 나오면 이걸 첫 용의자로 보라고 원문이 적어 뒀다.

## ★ 어휘 분리만으로는 부족하다

`[실측]` 교차검증에서 나온 반박이 옳았다.

> 게이트는 **공백을 제거한 뒤 문자 6-gram** 을 만든다. `주문/배송/반품` 같은 **명사만 바꿔도 종결어미와 공통 업무 문구의 6-gram 은 그대로 남는다.**

```
~할 수 있다 · ~확인한다 · 숫자+단위 표현
```

**이것들이 구조적으로 겹친다.** 그래서 **길이·공통 6-gram·14자 공통 문구·시나리오 probe 를 함께** 확인한다.

## ★ 한 개를 먼저 써 보고 25개를 쓴다

`[실측]` `doc_01` 초안이 **13섹션 전부 200자 미달**이었다. 평균 150자.

| 검사 | 초안 | 수정 후 |
|---|---|---|
| 섹션 수 | 13 | 13 |
| **길이 위반** | **13/13** | 3/13 |
| 평균 길이 | 150자 | **216자** |
| 문장 반복 | 0 | 0 |

> **한 개를 먼저 검증한 덕에 25개를 잘못 쓰지 않았다.**

**이게 이 문서에서 가장 값진 한 줄이다.** 25개를 다 쓰고 나서 알았으면 전부 다시 써야 했다.

### ★ [2026-09-03 추가] 5문서마다 돌린다 — sample 에서 4번 버렸다

`[실측]` `docs/plans/2026-08-17_코퍼스_25문서_배분안.md` 에서 이관.

```powershell
python -m scripts.check_corpus     # 5개 쓸 때마다
```

> **25개를 다 쓰고 나서 걸리면 전부 다시 써야 한다. sample 에서 그렇게 4번 버렸다.**

**한 개 검증 → 5개마다 검증**이 규칙이다. 앞 절이 "한 개"이고 이게 "그 다음"이다.

### 유사도는 표본이다 — 같은 seed 로 안심하지 마라

`[실측]` 게이트가 재는 것은 **전체 청크쌍이 아니다.**

| 계획서 초안이 적은 것 | 실제 구현 |
|---|---|
| "전체 청크쌍" 중앙 유사도 | **seed 7 의 무작위 표본 최대 3,000쌍** 중앙값 |
| 검사가 유사도 하나 | 공유 6-gram 종류 · **30% 초과 청크의 14자 공통 문구** · 문서 내 반복 문장 |

> **여러 seed 또는 전체 쌍으로 따로 진단해 우연한 통과를 배제한다.**

**표본으로 통과한 것을 통과로 믿으면 안 된다.**
