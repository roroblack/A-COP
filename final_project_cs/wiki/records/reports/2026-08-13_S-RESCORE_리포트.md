# S-RESCORE 리포트

## 결과

`golden.jsonl` 60건과 `holdout.jsonl` 20건의 `expected_next_action`을 v5 §7의 계약 어휘로 정렬했다. 데이터셋의 원본 응답(`eval/reports/raw_*.jsonl`)은 변경하지 않았고, 재채점 결과는 `rescored_*.jsonl`에 별도로 기록한다.

판단 우선순위는 다음과 같다: 승인 게이트는 `wait_for_approval`, 사용자에게 정보가 더 필요한 경우는 `wait_for_input`, 조회·검증은 `call_tool`, 지원팀으로 넘기는 경우는 `handoff`, 종결성 있는 장애·보안·정책 실패는 `escalate`, 설명·피드백 기록은 `respond`이다. `wait_or_escalate`는 정책/장애 판단을 안전하게 확정할 수 없는 상태이므로 `escalate`로 정렬했다.

## 재채점 사용법

세 군 모두 동일한 현재 데이터셋·judge prompt를 사용한다. 각 명령은 arm을 재실행하지 않고 raw prediction만 읽는다.

```powershell
python -m eval.rescore --input eval/reports/raw_baseline_a.jsonl --output eval/reports/rescored_a.jsonl
python -m eval.rescore --input eval/reports/raw_baseline_b.jsonl --output eval/reports/rescored_b.jsonl
python -m eval.rescore --input eval/reports/raw_proposed.jsonl --output eval/reports/rescored_proposed.jsonl
python -m eval.stats.make_pairs --input eval/reports/rescored_a.jsonl eval/reports/rescored_b.jsonl eval/reports/rescored_proposed.jsonl --output eval/reports/rescored_pairs.jsonl --x Proposed --y A
python -m eval.stats.bootstrap --input eval/reports/rescored_pairs.jsonl --arm-x Proposed --arm-y A
python -m eval.stats.mcnemar --input eval/reports/rescored_pairs.jsonl
```

judge 호출은 LLM 네트워크가 필요하다. 이 환경에서는 외부 네트워크가 차단되어 있으므로 재채점 명령 자체는 실행하지 않았다. mock judge나 540런 재실행으로 대체하지 않았다.
