## 2. 신 계획서가 v5 에서 **바꾼 것**

### 2-1. A2A 추가 (§9-C)

v5 에는 없던 축이다. 핵심 구분:

> MCP 는 도구를 빌려주는 것이고, A2A 는 일을 통째로 맡기는 것이다.

**MVP 에서 요구하는 것은 전면 구현이 아니라 경로 분리다:**
- 개인 AI(ChatGPT·Claude) → **MCP** (현재 구현됨 ✅)
- 고객사 Agent 플랫폼 → **A2A** (미구현)
- Team 을 원격 분리 배포하는 통로 → `TeamExecutorPort` 를 두고
  실행 경로만 `LOCAL` ↔ `A2A` 로 교체 (미구현)

★**이건 큰 작업이 아니다.** 지금 Controller 가 `TeamModule.execute()` 를 직접 부르는 자리에
`TeamExecutorPort` 를 끼우고 `LocalTeamExecutor` 를 기본으로 두면 된다.
`TeamResult` 계약은 그대로 쓴다.

### 2-2. Graph 는 **도입하지 않는 것이 결론** (§9-D)

신 계획서는 Graph DB 도입을 **명시적으로 거부**한다:

> 현재 시나리오 A 와 B 의 관계 질의는 깊이 1~2 이며 JOIN 과 집계로 정확히 계산된다.
> "그거 그냥 JOIN 아니냐"는 질문에는 **"현재 규모에서는 맞다"**고 답한다.

요구되는 것은 **`GraphStorePort` + `SqlGraphAdapter`(PostgreSQL JOIN·재귀 CTE)** 까지다.
Neo4j/AGE 는 Phase 2 비교 대상이다.

★판단이 뒤집히는 조건도 명시돼 있다 — Remote A2A Agent 2개 이상(깊이 3+),
정책 계층 상속, multi-hop 근거 포함률 미달.

## 3. 반영 계획

| 항목 | 범위 | 우선순위 |
|---|---|---|
| `TeamExecutorPort` + `LocalTeamExecutor` | Controller 가 Port 를 통해 Team 호출 | **높음** — 구조 변경이라 늦을수록 비쌈 |
| `A2ATeamExecutor` 골격 + Agent Card | 실제 원격 호출은 PoC 수준 | 중 |
| A2A Task ↔ Case 상태 매핑 Adapter | Controller 는 Case 상태만 본다 | 중 |
| `GraphStorePort` + `SqlGraphAdapter` | `neighbors` / `path` / `subgraph` 를 JOIN·재귀 CTE 로 | 중 |
| 설명가능성 경로 질의 | `Case → Evidence → Document → Policy → Decision → Action` | 낮음 (Port 위에서) |

★**v5 의 In/Out 경계를 넘지 않는다.** Graph 저장소 본체와 완전한 A2A 서버는
신 계획서 자신이 Phase 2 로 미룬 것이다. **Port 와 로컬 어댑터까지만** 만든다.
