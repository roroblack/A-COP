# 결함 리포트 — 분류 결과의 빈 라벨이 API 경로에서 통과한다

## 해결됨 (2026-09-03)

`app/application/classification.py` 가 **키 존재가 아니라 값**을 보도록 고쳤다.

```python
# 전: 키만 본다 — ""·"  "·None 이 전부 통과
if not result or not all(label in result for label in REQUIRED_LABELS):
# 후: 값이 실제로 있는지 본다
if not result or not all(str(result.get(label) or "").strip() for label in REQUIRED_LABELS):
```

★이 리포트를 쓴 작업이 회귀 테스트를 `xfail(strict=True)` 로 남겨 둔 것이
그대로 알람이 됐다 — 코드를 고치자 `XPASS(strict)` 로 **실패**해서 "이제
통과하니 표식을 떼라"고 알려줬다. 표식을 뗐고, 저장소 전체에서 `xfailed` 가
0 이 됐다(618 passed).

★한 가지 옮겨 적는다: 이 검사는 리포트를 쓸 당시 `app/presentation/api/cases.py`
에 있었으나, 그 뒤 인라인 분류의 실행 절차가 코어 1 로 올라가며
`app/application/classification.py` 로 옮겨졌다(v8 §3-A). 아래 "1. 위치" 의
경로는 당시 기록 그대로 둔다.

## 4. 위험도

**낮음 — 지금 배선에서는 도달하기 어렵다.** 운영 경로의 분류기는
`app/modules/customer_ops/feedback.py::classify` 이고 거기서는
`not raw[key].strip()` 으로 공백을 거른다. 그래서 실제로는 예외가 나고 escalated 로 간다.

문제는 **두 곳의 기준이 다르다**는 것이다. `create_app(classifier=...)` 로 다른 분류기를
주입하면 API 쪽 가드가 유일한 방어인데, 그 가드가 값을 보지 않는다. 분류기를 교체하거나
provider 를 바꾸는 순간 빈 라벨이 Case 에 저장되고 그 라벨로 라우팅까지 간다.
`CLAUDE.md` §1 은 "값을 모르면 비워 둔다. 추정으로 채우면 그 오류가 조용히 고객 답변까지
간다" 고 적고 있다.

## 5. 제안

`app/presentation/api/cases.py` 의 조건을 값까지 보게 한다. 소유는 S-API 다.

```python
if not result or not all(
    isinstance(result.get(k), str) and result[k].strip()
    for k in ("intent", "issue_code", "sentiment")
):
```

고치면 `test_create_escalates_when_a_label_is_blank` 의 `xfail(strict=True)` 이
"예상과 달리 통과했다" 로 알려준다. 그때 xfail 표시를 떼면 된다.
