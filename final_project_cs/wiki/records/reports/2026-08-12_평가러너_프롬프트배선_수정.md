# 평가 러너 프롬프트 배선 수정

## 변경 내용

- `eval/runners/common.py`
  - arm별 프롬프트와 버전을 분리했다.
  - arm 호출은 예측 JSON만 만들고, judge 호출은 별도 단계에서 수행한다.
  - `success`는 judge의 `pass`, `score`는 judge의 `total`을 사용한다.
  - judge rubric 필드가 없거나 범위를 벗어나거나 합계가 맞지 않으면 `success=False`로 조용히 처리하지 않고 오류 레코드로 남긴다.
  - Proposed arm은 기존 `ContextBroker`와 실제 Team 실행을 계속 사용한다.
  - Baseline B는 Team 없이 `search_policy()` 결과를 arm 프롬프트에 전달한다.
- `prompts/judge/judge_v1.txt`
  - 후보 답변을 생성하지 않는 별도 채점 단계임을 명시하고 pass 규칙을 명시했다.
- arm 프롬프트
  - `prompts/judge/arms/baseline_a_v1.txt` (`baseline-a-v1`)
  - `prompts/judge/arms/baseline_b_v1.txt` (`baseline-b-v1`)
  - `prompts/judge/arms/proposed_v1.txt` (`proposed-v1`)

## 검증

기존 평가 테스트: `3 passed`.

지정 probe 실행 명령:

```powershell
python -m eval.runners.baseline_a --dataset eval/datasets/golden.jsonl --repeats 1 --seed 7 --provider openai --limit 3 --concurrency 3 --output eval/reports/probe.jsonl
```

실제 출력 요약:

```text
output: eval\\reports\\probe.jsonl
rows_written: 3
config.prompt_version: baseline-a-v1
config.judge_prompt_version: judge-v1
estimated_llm_calls: 6
```

이 환경에서는 OpenAI 네트워크 호출이 불가능해 세 건 모두 다음 오류로 종료됐다.

```text
APIConnectionError: Connection error.
```

각 결과 레코드는 `cost_usd: 0.0`, `input_tokens: 0`, `prediction` 미생성으로 기록됐다.

따라서 지정된 `cost > 0`, `input_tokens > 0`, 실제 OpenAI `prediction` 키 검증은 이 환경에서 통과시킬 수 없다. probe 결과를 성공 실행으로 보고하지 않는다. `--provider mock` smoke에서는 `prediction` 키가 `answer`, `intent`, `issue_code`, `next_action`, `policy_evidence`, `sentiment`로 기록되고 rubric은 별도 `judge` 필드에 기록되는 것을 확인했다.
