## 0. 한 줄

여행 Team 여섯은 **계약·가드·흐름이 완성**돼 있었고 **데이터 원본이 하나도 없었다.**
이번 작업으로 6종 중 **4종(67%)** 이 붙었고, 실 DB + 실 외부 API 로 **8건 중 6건(75%)**
이 고객 답변까지 완주한다.

---

## 1. 왜 이 작업인가 — 막고 있던 것은 외부 API 가 아니었다

`config/project.yaml` 등록까지 끝난 뒤에도 **모든 여행 Case 가 첫 도구에서 escalate**
했다. 원인을 좁혀 보니:

| 도구 | 원본 | 막힌 이유 |
|---|---|---|
| `read.booking` | **우리 DB** | 테이블이 없었다 (19테이블 중 여행 0개) |
| `read.place` | **우리 DB** | 동 |
| `read.supplier` | **우리 DB** | 동 |
| `read.weather` | 외부 | 어댑터가 없었다 |
| `read.route` | 외부 | 동 |
| `read.transit` | 외부 | 동 |

즉 **셋은 외부 API 문제가 아니라 우리 스키마 문제**였다. 외부 키를 기다릴 이유가
없는 자리였고, 그래서 먼저 했다.

## 2. API 조사 — 실호출로 확인한 것 (2026-09-09)

★문서를 읽고 적은 것이 아니라 **실제로 찔러 본 결과**다.

| 소스 | 용도 | 키 | 실호출 결과 | 상태 |
|---|---|---|---|---|
| [Open-Meteo](https://open-meteo.com/) | `read.weather` | **불필요** | `HTTP 200`, hourly 48행 | ★**붙음** |
| [기상청 단기예보](https://www.data.go.kr/data/15084084/openapi.do) | `read.weather` 대안 | 필요 | `HTTP 401 SERVICE_KEY_IS_NULL` | 골격만 |
| [한국관광공사 TourAPI](https://www.data.go.kr/data/15101578/openapi.do) | `read.place` 보강 | 필요 | `HTTP 401 SERVICE_KEY_IS_NULL` | 골격만 |
| [ODsay](https://lab.odsay.com/) | `read.route`·`read.transit` | 필요 | **`HTTP 200`** + `[ApiKeyAuthFailed]` | 골격만 |

### ★ODsay 의 응답이 설계를 하나 바꿨다

인증 실패인데 **HTTP 200 을 준다.** `raise_for_status()` 만 믿는 어댑터였다면
**인증 실패가 성공으로 지나가** `read.transit` 이 빈 값을 돌려주고, Team 은 그걸
「확인했다」로 읽는다. 조용한 성공 위장이다.

같은 날 data.go.kr 계열은 401 로 정직하게 답했다 — **공급자마다 다르다.** 그래서
「본문까지 검사한다」를 공통 규칙으로 못 박았다(`app/infrastructure/travel/base.py`).

### 요금·갱신 (조사 시점 기준, 배포 전 재확인 필요)

- Open-Meteo: 비상업 하루 10,000 호출 무료라고 공급자가 밝히고 있다. **상업 배포 전 재확인.**
- 기상청·TourAPI: 공공데이터포털 활용신청 → **승인 최소 1일**. 기상청은 **2년마다 갱신**.
- ODsay: 무료/유료 구간이 나뉜다. 구체 한도는 신청 화면에서 확인해야 한다.

## 3. 지은 것

### 3.1 어댑터 계층 `app/infrastructure/travel/`

```
base.py        규율 4가지 — ①못 가져오면 None ②confirmed_at·source 필수
               ③HTTP 상태만으로 성공 판정 금지 ④미스를 센다
open_meteo.py  실제로 도는 유일한 외부 소스
```

Team 은 HTTP 를 모른다. 아는 것은 `read.weather` 라는 **이름 하나**다.
공급자를 갈아끼워도 Team 은 안 바뀐다.

★**주입은 조립이 한다.** `ReadToolbox(travel=...)` 의 기본값이 `None` 이라
**안 넣으면 바깥으로 안 나간다** — 테스트가 조용히 네트워크를 타는 사고를 구조로 막았다.

### 3.2 여행 도메인 테이블 `010_domain_travel.sql`

| 테이블 | 대응 | 요점 |
|---|---|---|
| `places` | ← `products` | 좌표·`weather_sensitive`·`hours_confirmed_at`·`dietary`/`dietary_absent` |
| `bookings` | ← `orders` | 시각·인원·정원·`locked` |
| `supplier_bookings` | ← `shipments` | ★**우리 것과 일부러 따로 둔다** — 어긋남을 찾는 것이 `booking.verify` 의 일이다 |

19테이블 → **22테이블**. 재실행 안전(`IF NOT EXISTS`), 커머스 테이블은 안 건드린다.

### 3.3 시드 `scripts/seed_travel.py`

places 5 · bookings 8 · supplier_bookings 4 · **status_mismatch 1**.
분기마다 데이터를 하나씩 뒀다 — 옥외/실내, 기한 안/지남, 인원 초과, 좌표 모름,
잠긴 예약, 공급자 불일치. **데이터로 한 번도 안 밟히는 코드 경로는 도는지 알 수 없다.**

### ★종단 실행이 잡은 결함 2건 (단위 테스트가 못 잡았다)

| 결함 | 왜 못 잡았나 | 조치 |
|---|---|---|
| **근거가 덮어써졌다** — `_evidence()` 가 매번 컨텍스트에서 다시 시작해 두 번째 호출이 첫 번째를 지웠다. 근거 4건이 **1건**으로 | 있던 검사가 전부 도구를 **한 개만** 쓰는 경로였다. 하나짜리에서는 덮어써도 결과가 같다 | `base=` 누적으로 수정. `tests/unit/travel/test_evidence_accumulates.py` 4건 |

## 5. 남은 것 — 큰 것부터

### ① RAG 코퍼스가 아직 쇼핑몰 25문서 ★가장 큰 것

`BK-GOLF-LATE` 가 `unknown_취소 기한` 으로 escalate 하는 이유다. `read.policy` 는
붙어 있고 **돈다** — 다만 코퍼스에 여행 취소·환급 규정이 없다. Activity 의
`check_cancelable` 은 규정 없이는 **정의상** 판정할 수 없다.

★**이것은 API 문제가 아니라 우리가 써야 하는 문서다.** 커머스 때도 코덱스 재작성이
조사 오손 3,401건을 내서 직접 썼다(`CLAUDE.md` §5 RAG corpus 행).

### ② 사람이 해야 하는 일 — 키 발급 3종

★**내가 대신 할 수 없다**(계정 생성·인증 정보 입력). 발급 후 `.env` 에 채우면
어댑터는 그대로 동작한다 — `.env.example` 에 자리와 절차를 적어 뒀다.

| 키 | 어디서 | 걸리는 시간 |
|---|---|---|
| `ACOP_TOUR_API_KEY` | 공공데이터포털 「한국관광공사_국문 관광정보 서비스」 | 승인 최소 1일 |
| `ACOP_ODSAY_API_KEY` | lab.odsay.com | 즉시~ |
| `ACOP_KMA_API_KEY` | 공공데이터포털 「기상청_단기예보」 (Open-Meteo 대안) | 승인 최소 1일, 2년마다 갱신 |

### ③ Mobility 가 아직 못 돈다

`read.route`·`read.transit` 둘 다 ODsay 키에 걸려 있다. 여섯 팀 중 **유일하게
종단 실행을 못 한 팀**이다.

### ④ `[미확보]`

- Flight 는 시드에 없어 실행으로 확인하지 못했다. Lodging 과 **같은 클래스**
  (`_LockedBookingTeam`)를 쓰므로 같게 돌 것으로 **예상**하지만, 잰 것이 아니다.
- `read.place` 는 우리 DB 만 본다. TourAPI 를 붙이면 운영시간 원본이 둘이 된다 —
  어느 쪽이 정본인지 정해야 한다.
