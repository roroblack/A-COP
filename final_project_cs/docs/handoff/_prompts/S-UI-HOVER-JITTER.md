# S-UI-HOVER-JITTER — 마우스 오버 하이라이트가 튀는 버그 원인 특정·수정

## 0. 배경

- `docs/release_checklist.md` §5-3 — "마우스 오버 하이라이트가 튀는 UI
  버그 — 원인 미특정." 지금까지 원인을 못 찾았다는 뜻이다. 지어내지 말고
  실제로 재현·확인한 뒤 고쳐라.
- 하이라이트 관련 CSS/스타일은 `app/presentation/ui/theme.py` 에 있다
  (`CLAUDE.md` "운영 UI 품질" 항목 — 상태별 의미색·다크모드·375px 가로밀림
  0 을 이미 검증해 둔 디자인 시스템 파일이다. 이 파일의 다른 부분을
  망가뜨리지 마라).
- 이 프로젝트엔 로컬 개발 서버가 있다: `.claude/launch.json` 의 `acop-ui`
  (포트 8041, `--reload`). 서버를 띄워서 실제로 재현해라 — 코드만 읽고
  추측하지 마라.

## 1. 할 일

1. 개발 서버를 띄우고(`acop-ui`, 8041) 운영 UI 화면들(`/ui/cases`,
   `/ui/approvals`, `/ui/voc`, `/ui/trace`)에서 표/목록 행에 마우스를
   올렸을 때 하이라이트가 "튀는"(jitter — 깜빡이거나 위치가 어긋나거나
   반복 재계산되는) 현상을 재현해라. 재현이 안 되면 재현이 안 됐다고
   정직하게 리포트에 적어라 — 억지로 원인을 지어내지 마라.
2. 재현되면 원인을 특정해라. 흔한 원인 후보(전부 가능성일 뿐, 실제
   DOM/CSS 를 보고 확정해라):
   - hover pseudo-class 가 걸린 요소와 실제로 시각적으로 하이라이트되는
     요소가 다른 계층에 있어서 마우스가 경계를 넘나들 때 재트리거됨
   - `:hover` 에 반응하는 요소 안에 다시 `:hover` 반응 자식이 있어 이벤트가
     겹침
   - transition/animation 지속시간과 반복 hover 이벤트가 충돌
   - 표 행 높이가 hover 시 padding/border 변화로 미세하게 바뀌어 레이아웃이
     흔들림(그래서 마우스 밑에서 요소가 움직여 hover 가 껐다 켜졌다 함)
3. 최소 침습적으로 고쳐라 — 디자인 시스템의 색상·다크모드·반응형 규칙은
   그대로 유지한다.
4. **브라우저로 실제 확인해라.** 수정 후 같은 화면에서 다시 hover 해보고
   튀는 현상이 없어졌는지 확인한다. 스크린샷이나 캡처 도구가 없다면
   확인한 조작 절차와 관찰 결과를 리포트에 구체적으로 서술해라(어느
   화면, 어느 요소, 어떻게 움직였는지/안 움직였는지).

## 2. 쓰기 대상

- `app/presentation/ui/theme.py` (원인이 여기 있다면)
- 다른 CSS/템플릿 파일(원인이 다른 곳에 있다고 확인되면 그 파일 — 정확한
  경로를 리포트에 남겨라)
- `docs/reports/2026-08-20_S-UI-HOVER-JITTER_리포트.md` (신규)

## 3. 하지 말 것

- 재현도 못 했으면서 "수정했다"고 보고하지 않는다 — 재현 실패는 재현
  실패라고 적는다
- 디자인 시스템의 다른 검증된 부분(상태별 의미색, 다크모드, 375px 반응형)
  을 건드리지 않는다
- `docs/release_checklist.md` 직접 수정(Claude 가 검증 후 갱신한다)

## 4. 검증

- `python -m pytest -q -m "not live"` 로 기존 UI 관련 테스트가 깨지지
  않았는지 확인하고 실제 출력을 리포트에 붙여라.
