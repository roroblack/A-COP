# S-TEAM-DIAGRAM-REDO — 팀모듈 데이터 흐름 다이어그램 재작성 (교차 화살표 제거)

## 0. 배경

- 이전 버전(`scratch_team_diagram_reference.html`, 저장소 루트, 읽기
  참고용 — 이 파일을 고치지 마라)의 SVG 다이어그램이 지저분하다는
  피드백을 받았다. 원인: 데이터 소스 박스(정책 RAG/케이스 유사도/DB

  특히 DB 조회 박스에서 나오는 화살표 하나가 캔버스 거의 전체를

- 이 작업은 **같은 정보를 교차선 없이 다시 그리는 것**이다. 정보 자체

  표현 방식만 바꾼다.

## 1. 새 레이아웃 — 곡선 연결선 대신 색상 태그 방식

**핵심 원칙: 박스와 박스를 잇는 긴 곡선을 쓰지 마라.** 대신:

1. 상단부(Case → Controller → Registry)는 이전과 동일하게 수직 일자
   흐름으로 유지한다 — 이 부분은 지저분하지 않았다.
2. Registry 아래에 6개 팀 박스를 **3열 × 2행 격자**로, 균등한 간격으로
   배치한다. 격자 밖으로 튀어나오는 요소가 없어야 한다.
3. 각 팀 박스는 **왼쪽 테두리(4px 두께 컬러 바)** 로 데이터 소스 종류를
   표시한다 — 화살표를 그리지 않는다:
   - 정책 RAG 사용 (Return&Refund, Procurement, Fulfillment, Response
     Review) → 초록 계열 바
   - 케이스 유사도 인덱스 사용 (VOC&Store Manager) → 파랑 계열 바
   - 데이터 없음 (Catalog&Verification) → 회색 점선 테두리 전체
4. 6개 팀 박스 아래에 **범례(legend) 3줄**을 두고, 각 줄에 "컬러 바 —
   무슨 뜻인지 — 어느 팀들이 해당하는지"를 텍스트로 명시한다. 화살표
   없이 텍스트 범례만으로 데이터소스↔팀 관계를 전달해라.
5. 임베딩 모델이 플랫폼 전체에 하나뿐이라는 사실은 범례 아래 한 줄
   텍스트("모든 정책 RAG·케이스 유사도 조회는 text-embedding-3-small,
   1536차원 하나를 공유한다")로 명시하고, **별도 박스나 화살표로 다시
   그리지 마라** — 이미 범례에 색으로 표현됐다.
6. Catalog&Verification 박스는 6개 격자 안에 포함하되(회색 점선), 화살표로
   다른 데이터 박스와 연결하지 마라 — "데이터 없음" 상태 자체가 이
   팀의 특징이다.

## 2. 구체적 치수 (반드시 지켜라 — 애매하게 두면 또 교차선이 생긴다)

- 전체 `viewBox`: `0 0 1100 620` 정도로 좁혀라(이전 860 높이보다 낮아짐
  — 데이터 박스 3개 + 곡선들이 없어지므로).
- 6개 팀 박스: 각 220×110, 열 간격 30, 행 간격 24. 3열이면
  `220*3 + 30*2 = 720` 폭 — 캔버스 중앙 정렬.
- 왼쪽 컬러 바는 박스 왼쪽 변에 붙은 `rect` (폭 4~5px, 박스와 같은 높이)
  로 그려라 — 이게 유일하게 "화살표 대신 쓰는 시각 장치"다.
- 범례는 박스 그리드 아래 최소 24px 여백을 두고 시작해라.
- 텍스트가 박스 경계를 넘어가지 않는지 각 박스의 텍스트 폭을 확인해라
  (박스 안 텍스트는 최대 2줄, 각 줄 폭이 박스 폭-20px 을 넘지 않게
  줄바꿈해라).

## 3. 유지해야 할 것 (바꾸지 마라)

- 6개 팀의 이름·team_id·데이터 소스 분류는 이전 버전과 동일해야 한다
  (읽기 참고 파일에서 그대로 가져와라):
  - VOC & Store Manager (voc_store_manager) — 케이스 유사도
  - Response Generation & Review (response_generation_review) — 정책 RAG
  - Return & Refund (return_refund, Mock) — 정책 RAG
  - Procurement + Order & Payment (procurement_order_payment) — 정책 RAG
  - Fulfillment & Logistics (fulfillment_logistics) — 정책 RAG
  - Catalog & Verification (catalog_verification, A2A, 미착수) — 데이터 없음
- 페이지의 나머지 섹션(팀별 카드, 임베딩 콜아웃, 데이터 공백 섹션)은
  이전 버전 그대로 재사용해라 — **다이어그램 섹션(`<section id="diagram">`)
  안의 SVG만 다시 그린다.** CSS 토큰(`--ink`, `--rag`, `--sim`, `--accent`
  등)도 그대로 재사용해라, 새로 만들지 마라.
- 라이트/다크 테마 모두에서 색이 정의돼 있어야 한다(기존 CSS 구조를
  그대로 따르면 자동으로 된다).

   각 라벨 길이를 세어서 확인해라(한글 기준 대략 문자당 13~14px 로
