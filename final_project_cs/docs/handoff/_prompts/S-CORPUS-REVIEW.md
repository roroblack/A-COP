## 1. 반드시 확인할 것

### 1-1. ★법정 기준이 맞나 (가장 중요)

계획서 §1 의 표를 **직접 확인**하라. 내가 웹에서 본 값이며 틀렸을 수 있다.

| 내가 적은 값 | 확인해야 할 것 |
|---|---|
| 청약철회 단순변심 **7일** | 기산점이 "공급받은 날" 이 맞나 |
| 표시·광고 상이 시 **3개월 / 안 날부터 30일** | 두 기간의 관계가 맞나 |
| 대금 환급 **3영업일** | 기산점이 무엇인가 |
| 환급 지연이자 **연 40% 이내** | 요율과 근거 조문 |
| 반품 배송비 단순변심 **소비자 부담** | 예외가 있나 |
| 청약철회 제한 — 복제 가능 재화 **포장 훼손** | 다른 제한 사유가 더 있나 |

★**조문 번호까지 확인해서 알려 달라.** 내 표에 없는 제한 사유가 있으면 그것도 적어라.
숫자가 하나라도 틀리면 코퍼스 전체가 **틀린 답을 가르치는 자료**가 된다.

### 1-2. 25문서 배분이 실제 쇼핑몰 CS 를 덮는가

- 실무에서 문의량이 많은데 **빠진 주제**가 있나
- 반대로 **문의가 거의 없는데 넣은 것**이 있나
- scope 별 개수(order 5 / shipping 5 / return 4 / exchange 3 / refund 4 / support 2 / incident 2)
  가 실제 문의 분포와 어긋나지 않나

### 1-3. ★중복 게이트 전략이 통할 것 같나

계획서 §4 의 "scope 별 어휘층 분리" 로
**전체 청크쌍 6-gram 중앙 유사도 0.25** 를 넘길 수 있을 것 같나.
안 될 것 같으면 **왜** 안 될지, 대안은 무엇인지 적어라.

★한국어 정책 문서는 종결어미("~한다", "~하지 않는다")가 고정돼 6-gram 이 겹치기 쉽다.
이 구조적 문제를 어휘 분리만으로 해결할 수 있나?

### 1-4. 시나리오 두 개가 적절한가

1. 배송완료로 찍혔는데 고객이 못 받았다 → 조사 → 분실 판정 → 환불 제안
2. 주문 수량(3개)보다 많은 반품(5개) 요청 → 대조에서 차단 → escalated

이 둘이 **쇼핑몰 CS 의 대표 시나리오**로 적절한가. 더 나은 후보가 있나.
