- 계획: 없음. 앞선 두 승인 큐 유령 항목 결함 수정의 자발적 후속 —
  "이 결함이 재발할 수 있는 다른 계약 문서 부정확도 있는가"를 살피다가 발견

## 1. 무엇을 했나

`create_action_request` 호출부 전수 조사를 마친 뒤, `docs/handoff/` 계약 문서가
실제 코드(옛 구독·청구 도메인 → 커머스 도메인 마이그레이션)와 얼마나 어긋나
있는지 훑었다.

### 1-1. 기계적 어휘 동기화 (완료)

- `03_REST_MCP_인터페이스.md` — 예시 요청/응답의 `intent`가 옛 `billing` 값
- `05_분업_규칙.md` — `S-TEAM` 소유 경로가 삭제된 `billing.py`/`technical.py`,
  존재하지 않는 `prompts/billing/`·`prompts/technical/` 를 가리킴
- `06_가드레일_수치.md` — scope 목록이 이름 정리 전 `subscription:read`/
  `technical:read`(이미 `order:read`/`return:read` 로 개명됨), golden 구성 표
- `07_모듈화_구조.md` — 목표 구조 매핑 표가 삭제된 파일 경로를 가리킴
- `08_모듈_컴포넌트_목록.md` — Agent Team 표가 존재하지 않는 클래스명
  (`BillingSubscriptionTeam`/`TechnicalEntitlementTeam`) 사용
- `config/guardrails.yaml` — golden 구성 주석도 같은 문제라 함께 고쳤다

### 1-2. ★더 큰 발견 — §5/§6(08 문서), §3(04 문서)이 "미구현"이라고 적어 둔 것이 실은 이미 구현됐거나(§5/§6), 반대로 "구현됐다"고 전제한 것이 실은 미구현이었다(04 §3)

- `08_모듈_컴포넌트_목록.md` §5 는 "구성기가 Team 을 하드코딩 import 해서
  선언이 조립을 못 바꾼다"는 **이미 해결된 문제**를 현재형으로 적고 있었다.
  실제 `app/composition.py` 는 `load_project_config()` + `importlib` 로
  `config/project.yaml` 을 동적으로 읽는다(하드코딩 import 없음). §6 의
  "권고안, 아직 미구현" 표도 실은 지금 `config/project.yaml` 그대로다.
  → 두 절 모두 "해결됨"/"실제 설정값"으로 갱신.
- 반대 방향 결함을 하나 발견했다 — **04 문서 §3 "prompt 등록 규칙"**은
  `prompts` 테이블·`llm_calls.prompt_id` FK 로 프롬프트 버전을 추적한다고
  적혀 있지만, 실제로는 `create_llm_call`/`record_llm_call`/
  `register_prompt_files` 호출부가 **0건**이다. `OpenAITeamLLM.complete()`
  는 프롬프트를 그 자리에서 조립할 뿐 `prompts` 테이블을 전혀 참조하지
  않는다. 상세 리포트: `docs/reports/debugs/2026-08-17_2340_프롬프트_감사추적_미연결.md`.
  ★**이건 고치지 않았다** — 설계 결정(프롬프트를 어떻게 저장/조회할지, 12개
  옛 도메인 프롬프트 파일을 어떻게 할지)이 필요해 사람 검토 없이 오늘 밤
  밀어붙이면 절반짜리 배선이 될 위험이 컸다(CLAUDE.md §3 "오진 위에 수정을
  쌓지 않는다"). 04 문서 §3 에는 "설계됐으나 미배선"이라고 정직하게 표시하고
  실제 배선이 안 됐다는 사실만 남겼다.

## 2. 검증 방법과 결과

문서 전용 변경이라 런타임 영향은 없다. 그래도 회귀 여부를 확인했다:

```powershell
python -m pytest -q
# 298 passed, 2 deselected (변화 없음 — 문서 편집이 테스트에 영향 없어야 정상)
```

`grep -rn "billing\|technical\|subscription" docs/handoff/*.md` 로 남은 옛 도메인
잔재를 재확인 — `10_도메인_교체_가이드.md` 만 남았고, 이 문서는 **의도적으로**
옛→새 도메인 대응표를 다루는 문서라 정상이다.
