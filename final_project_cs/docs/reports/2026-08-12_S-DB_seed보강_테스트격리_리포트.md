# S-DB seed 보강·테스트 격리 리포트

## 1. 작업 목표

1차 판정에서 확인된 결함 1(seed 데이터가 계약 건수에 미달)과 결함 2(통합 테스트가 실 DB를 오염)를 수정했다. `demo` seed는 고객 10명, 구독 10건, 결제 30건, entitlement 10건, incident 3건을 만들며, 두 시나리오를 포함하고 재실행해도 같은 건수로 수렴한다.

## 2. 변경 파일 목록

- `scripts/seed.py` — 계약 건수의 결정적 demo fixture, 최근 14일 결제 분포, 두 시나리오 및 primary-key upsert
- `tests/integration/db/test_db_integration.py` — 테스트별 `test_<uuid>` tenant와 FK 순서 teardown
- `docs/reports/2026-08-12_S-DB_seed보강_테스트격리_리포트.md`
- `docs/history/2026-08-12_S-DB_fix.md`

`001_schema.sql`은 수정하지 않았고 `002_*.sql`도 만들지 않았다. 기존 mock 테이블 컬럼만으로 요구사항을 충족했다.

## 4. 정리한 오염 행 건수

`demo`를 제외한 기존 오염 tenant 18건, customer 18건, customer case 18건, case event 30건을 삭제했다. subscription, payment, entitlement, incident 잔여는 각각 0건이었다. 테스트 teardown은 이후 각 테스트가 만든 `test_<uuid>` tenant와 모든 하위 행을 삭제하며 `demo` tenant에는 접근하지 않는다.

## 5. 마이그레이션

추가 마이그레이션 없음. 현재 mock 테이블 컬럼만 사용했으며 컬럼 추가가 필요하지 않았다.
