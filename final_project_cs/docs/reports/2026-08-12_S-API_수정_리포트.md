# S-API 수정 리포트

## 1. 대응 내용

- 결함 1: `app/presentation/security.py`에서 `os.getenv`를 제거했다. `get_settings()`의 `tenant_id`와 `secret_key`만 사용하고, 개발 키는 `secret_key`와 scope의 HMAC으로 결정적으로 파생한다. 따라서 현재 `Settings`에 API-key 전용 필드는 추가하지 않았다.
- 결함 2: `app/presentation/api/app.py`에 `HTTPException` 및 `RequestValidationError` 핸들러를 추가했다. 응답은 `{"error": {"code": "...", "message": "..."}}`이고 `JSONResponse(status_code=...)`를 키워드로 호출한다. 403/404/409/422가 실제 HTTP status로 렌더링된다.
- 결함 3: 테스트 전용 tenant fixture와 실제 `TestClient`·PostgreSQL 검증을 추가했다. 동일 생성 요청 10회 idempotency, ownership 404, MCP side-effect 경계, 정상 생성/상세 조회, 409 및 unauthorized matrix를 검증한다.

## 2. unauthorized matrix

REST 5개 endpoint는 각 scope key로 실제 HTTP 호출했다. 생성 직후 기본 분류기가 없으므로 message의 올바른 `case:write` 호출은 상태 전이 계약에 따라 422이다.

| key scope | POST cases | GET cases | GET detail | POST messages | POST approve |
|---|---:|---:|---:|---:|---:|
| case:read | 403 | 200 | 200 | 403 | 403 |
| case:write | 201 | 403 | 403 | 422 | 403 |
| subscription:read | 403 | 403 | 403 | 403 | 403 |
| technical:read | 403 | 403 | 403 | 403 | 403 |
| action:approve | 403 | 403 | 403 | 403 | 404 |
| mcp:read | 403 | 403 | 403 | 403 | 403 |

FastMCP는 현재 REST 앱에 transport route로 mount되어 있지 않아 MCP 도구는 실제 callable 3종(`get_my_cases`, `get_case_detail`, `open_support_case`)을 `mcp:read` principal로 실행 검증했다. 세 도구 모두 metadata의 `required_scope=mcp:read`를 유지하며 write action 도구는 없다.

## 4. `Settings`에 API key 필드가 필요한 경우의 요청 목록

현재 구현은 기존 `tenant_id`, `secret_key`만으로 동작하므로 추가 필드는 0개다. 운영 key store를 연결할 때 `app/core/settings.py`에 추가가 필요한 후보는 다음과 같다. 해당 파일은 소유 범위 밖이므로 이번 수정에서는 추가하지 않았다.

- `api_key_hashes` (`ACOP_API_KEY_HASHES`): 저장된 key digest 목록
- `api_key_scopes` (`ACOP_API_KEY_SCOPES`): digest별 scope 매핑
- 운영 전환 시 `api_key_hash`/`api_key_scope` 단일값 호환 필드가 필요하면 별도 명시
