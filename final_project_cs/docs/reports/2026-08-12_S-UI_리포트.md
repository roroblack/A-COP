# S-UI 운영 화면 구현 리포트

## 1. 목표

v5 §3 In 범위의 Case 목록/상세, append-only Trace, 근거 기반 Approval, VOC 일일 리포트를 서버 렌더링 UI로 제공한다.

## 2. 구현 내용

- `app/presentation/ui/routes.py`: `/ui/cases`, `/ui/cases/{case_id}`, `/ui/cases/{case_id}/trace`, `/ui/approvals`, `/ui/voc`
- DB는 `get_settings()`의 tenant와 `get_connection()`을 이용해 읽기만 수행한다.
- Trace에는 aggregate version 순서와 append-only 안내를 표시하고 수정/삭제 UI를 제공하지 않는다.
- Approval은 `arguments_json.evidence`가 없으면 승인/거절 버튼을 모두 disabled로 표시한다.
- Approval 쓰기는 DB를 직접 변경하지 않고 기존 REST `/v1/cases/{case_id}/actions/{action_id}/approve`를 ASGI HTTP 호출로 통과한다.
- 고객 식별자, actor, action id, idempotency key는 masked 값만 표시한다.
- VOC report가 없으면 `리포트 없음`을 표시한다.

## 3. 변경 파일

## 4. 검증

타깃 테스트:

```text
python -m pytest tests/e2e/test_operations_ui.py -q
....                                                                     [100%]
4 passed in 2.26s
```

전체 테스트:

```text
93 passed, 3 failed
```

실패 3건은 기존 RAG 통합 테스트가 `api.openai.com` embeddings에 연결하려다 현재 실행 환경의 네트워크 제한으로 실패한 것이다. S-UI 테스트는 모두 통과했고 `pytest.skip`은 사용하지 않았다.

## 5. 실제 출력 원문

명령:

```powershell
python -m uvicorn app.presentation.api.app:app --port 8010
curl.exe -s -o NUL -w "cases=%{http_code}`n" http://127.0.0.1:8010/ui/cases
curl.exe -s -o NUL -w "approvals=%{http_code}`n" http://127.0.0.1:8010/ui/approvals
curl.exe -s -o NUL -w "voc=%{http_code}`n" http://127.0.0.1:8010/ui/voc
curl.exe -s -o NUL -w "health=%{http_code}`n" http://127.0.0.1:8010/health
```

실제 출력:

```text
cases=404
approvals=404
voc=404
health=200
```

`create_app()` 결과에 `mount_ui(app)`를 호출한 테스트 composition에서는 위 네 화면이 실제 HTML을 반환한다. 현재 기본 API 앱에는 UI router 등록이 없으므로 운영 경로는 API 세션의 등록 작업 후 재검증해야 한다.

## 6. API 세션 요청

소유 범위 제한으로 `app/presentation/api/app.py`는 수정하지 않았다. API 세션에서 다음 한 줄을 composition root에 등록해 달라.

```python
from app.presentation.ui import mount_ui
mount_ui(app)
```

등록 후 동일한 uvicorn/curl 명령과 `python -m pytest tests -q`를 다시 실행하고, `/ui/cases`, `/ui/approvals`, `/ui/voc`가 200인지 확인해야 한다.
