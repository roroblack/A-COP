# 결함 — 평가가 환각 인용에 점수를 주고, 진짜 검색하는 군에 0을 준다

- 발견: 2026-08-13 12:00, Claude 검수 (평가 360/540행 시점)
- 상태: **DoD 15·16 판정 보류**. 이 상태의 수치를 리포트에 싣지 않는다
- 위험도: **매우 높음** — 이 프로젝트의 **중심 주장이 뒤집힌다**

## 1. 실측

```
=== raw_baseline_a.jsonl (RAG 없음이 설계) ===
  policy_evidence: ['doc_06 §1']
  judge: policy_grounding=3  total=17  pass=true
  성공 35/180  score 분포 최소10 중앙13 최대19

=== raw_baseline_b.jsonl (RAG 있음이 설계) ===
  policy_evidence: []
  judge: policy_grounding=0  total=13  pass=false
  성공 0/180   score 분포 최소6 중앙13 최대15
```

두 군의 `answer` 는 **문자 그대로 동일**하다:
> "I understand your concern regarding the charge after cancellation.
>  We will investigate this issue and propose a refund if applicable."

## 2. 무엇이 잘못됐나 — 두 가지가 겹쳤다

### 결함 A — arm A 가 인용을 **지어낸다**

v5 §15-1 은 A 를 **"단일 LLM + 원문 prompt + 최소 DB 조회"** 로 정의한다. **RAG 가 없다.**
그런데 A 의 출력에 `policy_evidence: ['doc_06 §1']` 이 있다.

★**인용 형식이 다르다.** 이 시스템의 실제 인용 id 는 `doc_06#c3` 형식이다
(`app/core/context.py:PolicyChunk.source_id` = `f"{document_id}#c{chunk_no}"`).
`doc_06 §1` 은 **어디에서도 생성되지 않는 형식**이다 — LLM 이 만들어낸 것이다.

judge 는 그 인용이 **실재하는지 확인하지 않고** `policy_grounding=3` 을 줬다.

### 결함 B — arm B 의 검색 결과가 출력까지 오지 않는다

B 는 정책 retrieval 을 하는 군인데 `policy_evidence` 가 **빈 배열**이다.
검색을 안 했거나, 했는데 프롬프트/출력에 실리지 않는다.

## 3. 왜 치명적인가

이 프로젝트의 중심 주장은 **"정책 근거에 기반한 답변이 더 낫다"** 이다.
지금 상태의 평가는 그 반대를 측정한다:

- **환각 인용에 점수를 준다** (A: grounding 3)
- **실제 검색하는 군에 0 을 준다** (B: grounding 0)

이대로 Proposed 를 돌려 A 를 이기더라도, 그 차이가 **근거의 질 때문인지
인용 문자열을 뱉었는지 때문인지 구분할 수 없다.**
v5 §15-3 의 policy groundedness 지표가 **측정하려는 것을 측정하지 못한다.**

★코퍼스 5회차에서 겪은 것과 같은 종류다 — 지표가 실력이 아니라 형식을 잰다.

## 4. 고쳐야 할 것

1. ★**judge 가 인용의 실재를 검증한다.** `policy_evidence` 의 각 id 가
   실제 `knowledge_chunks` 에 존재하는지 대조하고, 없으면 `policy_grounding=0`.
   **환각 인용은 근거가 아니라 감점 사유다.**
2. **arm A 는 policy_evidence 를 내지 않는다** (설계상 RAG 가 없으므로).
   내더라도 §1 의 검증에서 전부 탈락해야 정상이다.
3. **arm B 의 검색 결과를 프롬프트와 출력에 싣는다.** `search_policy()` 결과의
   `source_id`(`doc_NN#cM`)를 그대로 `policy_evidence` 에 넣는다.
4. 인용 형식을 **`doc_NN#cM` 하나로 통일**하고 judge 가 그 형식만 인정한다.

## 5. 현재 수치를 쓰면 안 되는 이유

`raw_baseline_a.jsonl` / `raw_baseline_b.jsonl` 의 360행은 **버리지 않고 보존**하되,
DoD 15·16 의 근거로 쓰지 않는다. 비용 $0.0842 는 이 결함을 발견한 값으로 친다.

★**"A 19.4% vs B 0%" 를 결과로 보고했다면 정반대 결론을 냈을 것이다.**
