# 결함 — Case 를 만들 때마다 승인 대기 큐에 유령 항목이 하나씩 쌓인다

`docs/reports/debugs/2026-08-17_2250_UI승인큐_유령항목.md` 와 **같은 뿌리의 결함**을
`create_action_request` 의 다른 호출부에서 하나 더 찾았다. 영향 범위가 더 크다 —
승인 결정이 아니라 **Case 생성 자체**가 트리거라 시스템이 살아 있는 한 계속 쌓인다.

## 1. 위치

`app/presentation/api/cases.py:91`(수정 전) — `POST /v1/cases` 핸들러.

## 2. 재현

```powershell
python -m pytest tests/integration/api/test_case_create_audit_row_excluded_from_queue.py -q
```

(수정 전에는 "Case 생성이 대기 큐에 유령 항목을 남겼다"로 실패한다.)

실 서버로도 재현: 실행 중인 서버에 `POST /v1/cases` 를 한 번 보내고
`SELECT action_type, status FROM action_requests WHERE case_id=...` 를 조회하면
`action_type='case.create', status='proposed'`(수정 전)가 나온다.

## 3. 원인

`POST /v1/cases` 는 idempotency 대조용으로 `action_requests` 에
`action_type="case.create"` 행을 하나 더 쓴다(줄 74 의
`WHERE tenant_id=%s AND idempotency_key=%s` 조회가 이 행을 근거로 삼는다).
`repository.create_action_request(...)` 를 `status` 인자 없이 호출해 기본값
`"proposed"` 로 저장됐다. `/ui/approvals` 의 `_actions()` 는
`status IN ('proposed','pending_approval')` 인 모든 행을 `action_type` 구분 없이
대기 항목으로 보여준다 — **Case 생성**이라는, 애초에 사람이 승인/거절할 대상이
아닌 사실 기록이 승인 대기 목록에 영구히 남는다.

`action.approve` 결함과 정확히 같은 패턴이라 같은 `create_action_request` 호출부를
전수 조사(`grep -rn create_action_request app`)했고, 이 한 곳이 더 있었다.
다른 두 호출부(`repository.py` 정의부, `controller.py:251` — 실제 Team 이 낸
`ActionProposal` 저장)는 진짜 승인 대상이라 손대지 않았다.

## 4. 실측

- 실 서버(포트 8099)에 `POST /v1/cases` 1회 → `action_requests` 에
  `action_type='case.create', status='proposed'`(수정 전) 확인.
- 이 저장소의 데모 시나리오는 `scripts/seed_demo_cases.py` 가 DB 에 직접
  쓰므로 이 REST 경로를 안 타 영향받지 않았다 — 그러나 **실 REST API 로 만든
  모든 Case, 즉 실제 고객 메시지 전부**는 영향을 받는다.

## 5. 위험도

- 결함 A(`action.approve`)와 같은 종류지만 **트리거 빈도가 다르다** — 승인
  결정마다가 아니라 **Case 생성마다** 발생한다. 운영이 시작되면 승인 대기
  큐가 실제 처리 대상 수와 무관하게 계속 불어나, "몇 건이 대기 중인가"라는
  가장 기본적인 운영 신호가 무의미해진다.
- 고객 답변·과금에 직접 영향은 없다(이 행 자체는 승인 API 로 재호출되지 않는다).
- CLAUDE.md §0 이 요구하는 "승인 없이 실행하지 않는다"의 신뢰 기반 —
  승인 큐를 못 믿게 만드는 결함이라는 점에서 결함 A 와 동일 선상에 있다.

## 6. 수정

`cases.py` 의 `create_action_request` 호출에 `status="succeeded"` 를 명시했다
(Case 생성은 승인 대상이 아니라 이미 끝난 사실이므로 종결 상태로 기록).
`action_status` enum 에 이미 `succeeded` 가 있어 스키마 변경 불필요.

회귀 테스트: `tests/integration/api/test_case_create_audit_row_excluded_from_queue.py`.
