# 결함 — `prompts`/`llm_calls` 버전 추적이 실 런타임에 배선돼 있지 않다

★**고치지 않고 보고부터 한다**(`RULE.md` §4.1). 범위가 플랫폼 전체의 감사추적
설계에 걸쳐 있어, 오늘 밤 자동으로 밀어붙이지 않고 사람 검토를 먼저 받는다.

## 1. 위치

- `app/infrastructure/db/repository.py:58` `create_llm_call()` — 호출부 0건
- `app/tools/read_tools.py:139` `record_llm_call()` — 호출부 0건 (정의 자체 제외)
- `app/tools/read_tools.py:118` `register_prompt_files()` — 호출부 0건
- `app/infrastructure/llm/openai.py:17` `OpenAITeamLLM.complete()` — 실제 LLM 호출부.
  `prompts` 테이블을 전혀 참조하지 않고 프롬프트를 그 자리에서 JSON 문자열로 조립한다.
- `prompts/billing/`, `prompts/technical/` — 옛 구독·청구 도메인 프롬프트 12개.
  커머스 버전(`prompts/order_shipping/`, `prompts/return_exchange/` 등)도 없다.

## 2. 재현 (부재의 증거)

```powershell
grep -rn "create_llm_call\|record_llm_call\|register_prompt_files" app --include=*.py
# → 정의부만 나오고 호출부가 없다

grep -rn "llm_calls" tests --include=*.py
# → 스키마 존재 검사·teardown DELETE 뿐, "실행 후 llm_calls 에 행이 생겼다"는
#   양성 단언(assert)이 어디에도 없다
```

## 3. 실측

- `create_llm_call`/`record_llm_call` 호출부: **0건** (정의 제외)
- `register_prompt_files` 호출부: **0건**
- `llm_calls` 를 양성 검증하는 테스트: **0건** (스키마·teardown 용도만 3개 파일에서 참조)
- 실제 Team 코드(`order_shipping.py:47`, `return_exchange.py:38`)가 쓰는
  prompt_key: `"order_shipping.answer"`, `"return_exchange.answer"` — 이 값은
  어디에도 저장되지 않고 `OpenAITeamLLM.complete()` 안에서 메타데이터 라벨로만
  쓰인다. `prompts` 테이블의 `(prompt_key, version)` 과 무관하다.

## 4. 원인

`app/infrastructure/llm/openai.py::OpenAITeamLLM.complete()` 가 프롬프트를
DB 조회 없이 그 자리에서 조립한다. `prompt_key` 인자는 받지만 어디에도
쓰지 않는다(단순히 LLM 에 보내는 JSON 안에 문자열로 끼워 넣을 뿐). 이 어댑터가
호출된 뒤에도 그 결과를 `llm_calls` 에 기록하는 코드가 어디에도 없다.

`register_prompt_files()`(마크다운 파일을 읽어 `prompts` 테이블에 등록하는
유일한 경로)를 부르는 마이그레이션·seed·startup 훅이 존재하지 않는다.

## 5. 위험도

- **CLAUDE.md §1 "산출물에 버전을 박는다"**가 명시적으로 요구하는 것과 정반대다:
  > `llm_calls` — `prompt_id` FK 로 어떤 프롬프트가 만든 답인지 추적
  지금은 이게 **전혀 추적되지 않는다.** 프롬프트를 바꿔도 어떤 버전이 어떤
  답을 냈는지 사후에 알 방법이 없다.
- 직접적인 고객 손해 경로는 아니다(승인 게이트·재검증은 별도로 동작한다) —
  하지만 **사고가 난 뒤 원인 추적(root cause)이 막힌다.** "이 환불 제안은
  어떤 프롬프트 버전이 만들었나"를 물으면 지금은 답할 수 없다.
- `docs/plans/`·상태표에서 "Agent Team — 완료"로 보고돼 있었지만, 이 감사추적
  하위 요구사항은 검증된 적이 없다 — **완료 판정에 포함된 검증 공백**이다.

## 6. 왜 오늘 밤 고치지 않는가

이건 1~2줄 수정이 아니라 설계 결정이 여러 개 필요하다:

1. 프롬프트 템플릿을 실제로 `prompts` 테이블에서 읽어 오도록
   `OpenAITeamLLM.complete()` 를 바꿀 것인가, 아니면 지금처럼 인라인 조립을
   유지하되 **조립한 텍스트 자체**를 매 호출마다 `prompts` 에 등록(사실상
   매번 새 버전)할 것인가 — 정책 선택에 따라 스키마 사용 방식이 달라진다.
2. `prompts/billing/`·`prompts/technical/` 12개 파일 — 지우고 커머스로
   새로 쓸지, `docs/handoff/10_도메인_교체_가이드.md` 처럼 보존본으로 남길지.
   내용을 새로 쓴다면 RAG corpus 때처럼 Codex 산출물 품질을 믿을 수 없어
   **Claude 가 직접 써야 할 가능성**이 크다(도메인 문서 12건, 상당한 작업량).
3. `run_id`/`agent_runs`/`team_tasks` 를 누가 만드는지(Controller 인지 Team
   인지)부터 확인해야 `record_llm_call(run_id=...)` 를 어디서 부를지 정해진다.

CLAUDE.md §3 "오진 위에 수정을 쌓지 않는다"·"꼭 필요한 부분만 구현" 원칙상,
설계 결정 없이 밀어붙이면 절반짜리 배선(반쪽 구현)이 나올 위험이 크다.
사람이 1번 정책부터 정하고 나서 계약(`docs/handoff/_prompts/`)을 쓰는 편이 맞다.
