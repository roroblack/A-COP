# judge 의 `policy_grounding` 은 상수다 — 근거의 질이 아니라 "인용이 있었나"를 잰다

## 미해결

- 발견: 2026-09-06
- 판정: **실재, 미수정.** judge 프롬프트를 고치면 지금까지의 모든 수치와
  비교가 끊긴다. 그 결정을 이 리포트 하나로 내리지 않는다.
- 위험도: **높음** — DoD-15(judge–사람 일치도)가 **지금 이 축을 못 잰다**.
  그리고 계획서·`CLAUDE.md` 가 대표 수치로 인용하는 "grounding 0.00 / 2.22 /
  3.98" 의 뜻이 알려진 것과 다르다.

## 어떻게 발견했나

DoD-15 사람 채점을 대신할 수 없어서(모델이 모델을 채점하면 사람과의 일치가
아니다), 대신 **어긋나는 행을 골라 사람이 볼 순서를 정하려고** 2차 채점기를
만들었다(`eval/judge_second_opinion.py`). 첫 세 건을 돌려 judge 와 대조하다
한 건이 눈에 걸렸다.

```
문의   주문번호 일부만 기억나는데 주문을 찾으려면 어떤 정보를 준비해야 하나요?
답변   주문 기록에서 해당 주문을 확인했습니다.
기대   wait_for_input        실제  respond

judge  correctness 2 · next_action 1 · personalization 1   ← 낮게 줬다. 맞다
       policy_grounding 4                                  ← 만점
```

**묻지도 않은 말을 한 답변에 근거 점수 만점이 붙었다.** 다른 축은 제대로
낮았으므로 judge 가 통째로 후한 것이 아니다. 이 축만 이상했다.

## 실측 — 이 축은 분산이 0 이다

DoD-15 가 쓰는 holdout 채점 결과(`eval/reports/2026-09-02_rescored_holdout_ko.jsonl`,
72행):

| 축 | 평균 | 분포 |
|---|---|---|
| correctness | 2.53 | 1:9 · 2:29 · 3:21 · 4:13 |
| next_action | 1.90 | 0:9 · 1:30 · 2:1 · 3:23 · 4:9 |
| safety | 3.01 | 2:11 · 3:49 · 4:12 |
| personalization | 1.06 | 0:19 · 1:30 · 2:23 |
| **policy_grounding** | **4.00** | **4:72** ← 전부 같은 값 |

**다른 넷은 전부 변하는데 이 축만 상수다.**

holdout 만의 일이 아니다. `eval/reports/*.jsonl` 전체(약 2,700행)를 세면
이 축은 사실상 **0 아니면 4** 이고, 그 외 값은 **9행**뿐이다.

★**초판에서 golden 근거를 잘못 인용했다.** "golden 60×3 Proposed 도 176/180
이 4" 라고 적으며 `rescored_proposed.jsonl` 을 들었는데, 그 파일은
**2026-08-17 에 무효화된 옛 구독 도메인**(`g-billing-01` 등) 산출물이다.
현행 쇼핑몰 도메인의 golden Proposed 는
`eval/reports/2026-08-28_reeval_Proposed_v3.jsonl` 이고 **214/216 이 4**(99%)다.
**결론은 그대로다** — holdout 특유가 아니라는 것이 현행 도메인에서도 확인된다.
틀린 것은 인용한 파일이다.

## 이 축이 실제로 재는 것

```
A         grounding 평균 0.00   |  유효 인용이 있었던 비율    0%
Proposed  grounding 평균 3.98   |  유효 인용이 있었던 비율  100%
```

★**`CLAUDE.md` 와 계획서가 인용하는 "grounding 0.00 / 2.22 / 3.98" 은
근거의 질이 아니라 「인용이 붙었나」의 비율에 4 를 곱한 값에 가깝다.**
ablation 의 "RAG 제거 시 3.98 → 0.00" 도 같은 뜻이다 — RAG 를 빼면 인용이
사라지므로 당연히 0 이 된다. **방향은 맞지만 재고 있다고 믿은 것을
재고 있지 않다.**

## 원인 — 프롬프트가 한쪽만 강제한다

`prompts/judge/judge_v1.txt`:

```
if citations.valid is empty, policy_grounding MUST be 0 regardless of any other assessment
...
If citations.valid is non-empty, score policy_grounding from the supplied policy-grounded record.
```

- **인용이 없을 때** → `MUST be 0`. 강한 규칙이고 실제로 지켜진다
- **인용이 있을 때** → "score ... from the supplied policy-grounded record".
  **답변이 그 근거를 실제로 쓰는지 묻지 않는다.** 레코드가 근거를 달고 있으니
  근거 점수를 주라는 말로 읽히고, 그래서 늘 4 가 나온다

즉 이 축은 **0~4 눈금을 쓴 이진 플래그**다.

★**이 프로젝트에서 같은 모양의 결함을 이미 한 번 고쳤다.** `return_refund`
가 반품 제한을 안 보고 "정책 **근거상** 검토할 수 있습니다" 라고 답하던 건
(2026-09-03)과 구조가 같다 — **근거를 댔다고 말하면서 근거를 안 본다.**
이번엔 채점자 쪽에서 같은 일이 일어났다.

## 왜 안 잡혔나 — 검사기가 한 방향만 본다

`eval/check_judge.py` 는 이렇게 센다.

```python
if not valid and grounding > 0:   # 근거 없는데 점수를 줬다  → 결함으로 센다
if valid and grounding == 0:      # 근거 있는데 0 을 줬다    → 경고로만 낸다
```

**"근거가 있을 때 점수가 늘 만점인가" 는 아무도 안 본다.** 그래서
`근거 없이 grounding 점수를 받은 행 0건` 이라는 통과 문구가 계속 나왔고,
그 문구는 지금도 사실이다 — **다만 그 검사가 이 결함을 볼 수 없을 뿐이다.**

## DoD-15 에 미치는 영향 — 지금 당장 걸린다

`eval/stats/agreement.py::_cohen_kappa` 에 상수 축을 넣으면:

```
judge 전부 4, 사람이 4/3 을 섞어 줌   → kappa 0.0
judge 전부 4, 사람도 전부 4          → kappa 1.0   (0/0 을 완전일치로 특례 처리)
```

**두 값 말고는 안 나온다.** 사람이 24건 중 한 건이라도 4 가 아닌 점수를
주는 순간 이 축의 일치도는 0.0 으로 떨어지고, 전부 4 를 주면 1.0 이 된다.
어느 쪽도 "judge 가 사람과 얼마나 맞는가" 가 아니다.

★**사람이 앉기 전에 알아야 한다.** 채점 폼의 결함 둘(인용 미표시·"정할 수
없다" 부재)을 사람이 작업하기 전에 고친 것과 같은 이유다.

## 고치려면 — 판단이 필요해서 이 리포트로 남긴다

고치는 방향 자체는 분명하다. "인용이 있을 때" 쪽에도 판단을 요구하면 된다 —
**답변의 주장이 인용된 본문으로 실제로 뒷받침되는가**, 인용이 걸려만 있고
답변이 쓰지 않으면 점수를 주지 않는다.

문제는 **비용**이다.

1. judge 를 바꾸면 **지금까지의 모든 수치와 비교가 끊긴다.** 평가 이력
   전체가 judge-v1 으로 매겨져 있다
2. `prompts` 는 `(prompt_key, version)` UNIQUE + sha256 immutable 이라
   고치는 것이 아니라 **v2 를 새로 등록**하는 일이다
3. `RULE.md`·`CLAUDE.md` §4 — **holdout 으로 프롬프트를 고치지 않는다.**
   다행히 이 결함은 현행 도메인 golden(214/216)에서도 같으므로 holdout 을 만지지 않고
   golden 에서 v1↔v2 차이를 잴 수 있다

★**그래서 지금 판정을 바꾸지 않았다.** DoD-15 를 "이 축은 못 잰다" 고 적고
넘어갈지, judge-v2 를 만들어 golden 에서 재측정할지는 **평가 설계 결정**이라
한 세션이 조용히 정할 일이 아니다.

## 후속 측정 — 고칠 수 있으나 한 축만 따로는 못 고친다 (2026-09-06)

`docs/reports/2026-09-06_S-JUDGE-GROUNDING-축_측정_리포트.md` 에서 golden
현행 도메인 72건으로 쟀다(holdout 은 안 만졌다).

```
grounding 변별       v1 2종(최빈 99%) → v2 5종(51%) · v3 4종(58%)
안 바꾼 네 축 이동    v2 1.12 · v3 0.63
```

**고치면 변별한다.** 다만 grounding 문장 하나만 바꿨는데 **나머지 네 축이
같이 움직인다.** 어조를 중립으로 낮추면(v3) 오염이 절반으로 줄지만 0 은
아니다. 즉 이것은 프롬프트 한 줄 교체가 아니라 **재기준선 결정**이다.

## 최소한 지금 해 둔 것

  DoD-15 를 닫지 못한다.** 사람이 볼 순서를 정하는 용도이고, 이 결함을

  어긋나는가" 를 가리키는 용도로만 쓴다.** 이것도 적어 둔다
