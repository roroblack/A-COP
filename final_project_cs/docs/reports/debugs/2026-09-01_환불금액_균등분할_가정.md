# 환불 금액을 주문 총액의 균등 분할로 추정하고 있었다 (2026-09-01)

D-001 조치 **1-A** 구현. 쇼핑몰 일정과 무관하게 지금 데이터로 고칠 수 있는 부분이다.

## 무엇이 잘못돼 있었나

`app/modules/customer_ops/return_refund.py` 의 `refund.calculate` 는 한 줄이었다.

```python
amount = total * int(quantity) // item_count
```

이 한 줄에 **말하지 않은 가정이 둘** 들어 있었다.

| 가정 | 틀리면 |
|---|---|
| 주문의 모든 품목 값이 같다 | 비싼 품목을 반품했는데 싼 값으로 환불된다(또는 그 반대) |
| 주문에 할인이 없다 | 정가로 계산해 **실제 결제액보다 많이** 환불된다 |

"환불됩니다" 를 잘못 말하면 고객이 손해를 본다(`CLAUDE.md` §0). 근거 없는 금액을
제안까지 밀어 올리고 있었다.

## ★왜 지금까지 안 보였나 — seed 가 이 결함을 가린다

`scripts/seed.py` 는 주문 하나에 `order_items` 를 **정확히 한 행**만 넣고,
`total_cents = unit × quantity` · `item_count = quantity` 로 맞춘다. 그러면

```
옛 계산 = (unit × quantity) × r // quantity = unit × r
새 계산 = unit × r
```

**두 값이 같다.** 데모·통합테스트가 전부 통과하는 이유가 이것이다. 이 결함은
품목이 여럿이거나 할인이 붙은 주문에서만 드러나는데, seed 에는 그런 주문이 없다.

## 고친 방향 — 가정을 **검사 가능한 조건**으로 바꿨다

지우거나 그대로 두는 대신, 두 가정이 성립하는지 런타임에서 확인한다.

| 조건 | 어떻게 아는가 | 성립 안 하면 |
|---|---|---|
| 할인이 없다 | 품목 단가 합 == 주문 총액 | `refund_amount_not_derivable` 로 escalate |
| 어느 품목인지 안다 | 주문 품목이 한 줄 | `refund_item_unattributable` 로 escalate |
| 수량이 주문 범위 안 | `quantity <= 품목 수량` | `refund_quantity_exceeds_order` 로 escalate |

성립하면 **단가 × 수량**으로 정확히 구한다. 추정이 아니다.

★품목 단가 합과 총액의 차액이 곧 할인·쿠폰·배송비다. 그게 있으면 "이 품목의
실결제액" 을 이 데이터만으로는 알 수 없다 — **D-001 1-B(쇼핑몰이 실결제액을
줘야 함)가 바로 이 지점**이다. 이제 그 경계가 문서 속 가정이 아니라 코드에서
걸린다.

## ★새로 드러난 사실 — `returns` 에 품목 참조가 없다

`002_domain_commerce.sql:46` 의 `returns` 는 `order_id`·`reason_code`·`quantity`
뿐이다. "주문 X에서 3개 반품" 은 알지만 **어느 품목인지를 모른다.**

그래서 품목이 여럿인 주문은 지금 데이터로는 금액을 정할 수 없다. 균등 분할은
그 모름을 숫자로 덮고 있었을 뿐이다.

이건 쇼핑몰 대기 항목이 **아니다** — 우리 스키마다. `returns` 에
`order_item_id`(또는 sku)를 더하면 다품목 주문도 정확히 계산된다. D-001 에
1-A 의 후속으로 넣을 만하다.

## 툴은 이미 있었다

`read.order_items`(`app/tools/read_tools.py:95`)가 `sku`·`quantity`·`unit_cents` 를
tenant/customer 격리로 돌려주고 있었다. 다만 이 Team 의 `allowed_tools` 에 없어
Registry 가 막고 있었다.

```diff
- allowed_tools=["read.order", "read.return", "read.policy"]
+ allowed_tools=["read.order", "read.order_items", "read.return", "read.policy"]
```

`implementation_revision` 도 `2026-08-20` → `2026-09-01` 로 올렸다.

## 검증

`tests/unit/teams/test_return_refund.py` 에 6건을 더했다(4 → 10).

- 다품목 주문이 **지어낸 금액을 받지 않는다**(escalate)
- 할인된 주문을 **정가로 계산하지 않는다**(escalate)
- 한 품목 여러 수량은 나누지 않고 **곱한다**
- 주문 수량을 넘는 반품은 거부
- 품목을 못 읽으면 escalate
- `allowed_tools` 에 `read.order_items` 가 있다

기본 픽스처를 2품목(합이 총액과 안 맞던 것)에서 **1품목 · 단가 합 == 총액**으로
바로잡았다. 옛 픽스처는 스스로 모순된 주문이었다(총액 10,000 · item_count 2 인데
품목 정보가 아예 없었다).

## 남긴 것

- D-001 문서는 **다른 세션이 편집 중**이라 손대지 않았다. 위 "새로 드러난 사실"
  (`returns` 에 품목 참조 없음)을 1-A 후속으로 반영하면 된다

  사람에게 넘어간다 — 자동화율은 떨어지지만 틀린 금액은 안 나간다
