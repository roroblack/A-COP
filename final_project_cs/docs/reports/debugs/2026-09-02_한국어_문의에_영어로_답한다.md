# 한국어 문의에 영어로 답한다 — procurement_order_payment

- 발견 경위: DoD-15 사람 라벨링 템플릿을 만들다가, holdout 24건 중 6건의
  `candidate_answer` 가 영어인 것을 보고 확인했다. 채점자가 볼 답변을
  들여다보지 않았으면 못 봤을 것이다.
- 판정: **실재, 미수정.** 담당 모듈(주문·결제·조달)이 다른 사람 소유라
  고객 응대 문구를 임의로 바꾸지 않았다.

## 무엇이 나가는가

```
문의: "주문번호 일부를 잊어버렸는데 주문을 찾으려면 어떤 정보를 준비해야 하나요?"
답변: "Order verified against the local order record."
```

holdout 24건 중 **6건**(전부 `order` intent)이 이렇게 나간다.

## 어디서

`app/modules/customer_ops/procurement_order_payment.py` 세 곳:

| 줄 | capability | 문자열 |
|---|---|---|
| 191 | `procurement.quote` | `f"Quote basis: {quote}"` |
| 208 | `order.verify` | `"Order verified against the local order record."` / `"No matching local order record was found."` |
| 293 | `payment.status` | `f"Current payment status: {payment}"` |

**이 팀만 그렇다.** 나머지 팀은 전부 한국어다:

```
return_refund          "제공된 주문·반품 이력·정책 근거상 반품 요청을 검토할 수 있습니다."
fulfillment_logistics  f"주문 이행 상태는 {phase}입니다. 조회된 배송 건은 {count}건입니다."
fulfillment_logistics  f"배송 상태는 {status}입니다."
voc_store_manager      "피드백을 확인했습니다. 접수된 의견은 운영 개선에 반영됩니다."
```

## 왜 고객에게 그대로 도달하는가

`TeamResult.answer` 는 장식이 아니라 **고객 응답 본문**이다.

```
Controller._event_for_result()  → EventType.COMPLETED,
                                  state_patch={"answer": result.answer}
                                       ↓
customer_cases.state_json.answer
                                       ↓
app/presentation/api/cases.py:152  "answer": case["state_json"].get("answer")
```

`response_generation_review` 팀이 켜져 있으면 이 초안을 한국어로 재작성한다
(stage3 학습 데이터에서 OpenAI 가 실제로 그렇게 했다). 그러나
`config/project.yaml` 의 `response_review.enabled` 는 **기본 `false`** 다 —
즉 **지금 설정에서는 영어 초안이 교정 없이 그대로 나간다.**

## 부수 피해 — 파인튜닝 학습 데이터에도 박혀 있다

`eval/finetune/sft_stage2.jsonl` 과 `sft_stage3.jsonl` 의 여러 행이 이
영어 문자열을 정답(assistant) 또는 입력(draft)으로 담고 있다. DoD-28
파인튜닝 모델은 그걸 학습했다. 데이터를 다시 만들지 않는 한 모델을 고쳐도
같은 영어가 재생산된다.

## DoD-15 에 미치는 영향 (이게 지금 중요하다)

사람 라벨 20건과 judge 의 agreement 를 재는 것이 DoD-15 이고, 그것이
RC 를 막는 유일한 항목이다. 그런데 채점 대상 24건 중 6건이 **이미 틀린 줄
아는 출력**이다. 이 상태로 라벨링하면:

- 사람은 `correctness` 를 낮게 준다(한국어 고객에게 영어로 답했으므로)
- judge 도 낮게 줄 수 있고 아닐 수도 있다
- 어느 쪽이든 **측정하려던 "judge 가 사람과 얼마나 맞는가"가 아니라
  "둘 다 이 알려진 결함을 잡아내는가"를 재게 된다**

★그래서 **라벨링 전에 정할 일**이다. 두 갈래다.

1. **먼저 고치고 holdout 재실행 후 라벨링** — 측정이 깨끗해진다.
   비용은 holdout 재실행(OpenAI 24건×3회) + 재채점.
2. **그대로 라벨링하고 한계를 적는다** — 비용 0. 다만 "6/24 가 알려진
   언어 결함을 포함한 표본"이라고 agreement 결과에 반드시 함께 적어야 한다.

어느 쪽이든 **조용히 넘기면 안 된다**(`CLAUDE.md` §4 "표본이 작으면 작다고
말한다"와 같은 성격의 문제다).

## 고칠 때 주의

- 테스트가 이 문자열을 단언하지 않는다(확인함) — 문자열 교체 자체는 안전하다.
- `order.verify` 는 `matches` 에 따라 두 문장으로 갈린다. 둘 다 필요하다.
- `f"Quote basis: {quote}"` 와 `f"Current payment status: {payment}"` 는
  값을 그대로 끼워 넣는데, `payment` 가 영문 상태값(`paid`·`pending`)이면
  한국어 문장에 영문 토큰이 남는다. 상태값 자체를 한국어로 옮길지는
  도메인 판단이라 여기서 정하지 않는다.
