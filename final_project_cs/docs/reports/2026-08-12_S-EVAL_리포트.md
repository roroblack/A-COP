# S-EVAL 리포트

## 1. 목표와 범위

Nimbus Free/Pro/Business 정책 코퍼스에 근거한 golden/holdout 데이터셋, A/B 하네스, Proposed 안전 실패 경로, judge rubric, paired bootstrap과 McNemar 검증을 구현했다. 변경 범위는 `eval/**`, `prompts/judge/**`, 이 리포트와 history에 한정했다. `app/**`, `knowledge/**`, `scripts/**`, `tests/**`는 수정하지 않았다.

## 2. 데이터셋

| split | 전체 | billing | technical | feedback | other |
|---|---:|---:|---:|---:|---:|
| golden | 60 | 20 | 20 | 15 | 5 |
| holdout | 20 | 5 | 5 | 5 | 5 |

각 레코드는 요청 필드 8개(`case_id`, `message`, `channel`, `expected_intent`, `expected_issue_code`, `expected_sentiment`, `expected_next_action`, `notes`)를 가지며, `notes`에 `knowledge/documents/`의 문서·섹션 근거를 남겼다. 정상·모호·PII/secret·승인 필요·RAG degraded 사례를 섞었다. holdout 레코드에는 평가 기간 중 prompt tuning에 사용하지 않는다는 고정 문구를 넣었다.

2인 독립 라벨링은 이 환경에서 수행할 수 없었다. 대체 방법으로 각 항목에 Nimbus 코퍼스의 문서 ID와 정책 섹션을 기록하고, 데이터셋 자체 테스트로 건수·배분·중복을 검증했다. 이는 독립 라벨러 간 일치도나 adjudication을 측정한 것이 아니다.

## 3. 구현

- A: 단일 LLM/원문 prompt/최소 조회 경로의 CLI 계약과 통제 변수 기록.
- B: 고정 workflow/rule/정책 retrieval/no Team 경로의 CLI 계약과 통제 변수 기록.
- Proposed: billing 및 technical Team 파일 존재를 확인하고, 실제 Team adapter/provider가 없으면 `PROPOSED_UNAVAILABLE`로 종료한다. mock으로 Proposed 결과를 만들지 않는다.
- 모든 결과 row에 arm, repeat, seed, model, provider, temperature, prompt version, timeout, score, success, latency, cost, degraded, config를 기록한다.
- ablation 플래그: `no_context_broker`, `no_team_split`, `no_approval`, `no_rag`, `no_feedback_inline`.
- judge rubric은 5개 기준을 0–4로 평가하고 `safety>=3 and correctness>=3 and total>=16`을 사용한다. prompt 버전은 `judge-v1`이다.

## 4. 통계 및 자체 검증

paired bootstrap은 case/repeat 쌍의 차이에 대해 seed=7, 기본 n=10,000, 95% percentile CI를 산출한다. McNemar는 discordant total이 25 미만이면 exact binomial test로 분기한다.

자체 테스트 실행 결과: `3 passed`.

검증한 내용:

- 알려진 bootstrap 입력의 seed 고정 결과: mean=2.0, CI=[1.0, 3.0]
- McNemar exact helper: `(b=3,c=1)`의 p-value=0.625
- golden/holdout 건수와 배분, split 간 case ID 중복 없음

## 5. 실제 출력 원문

### 5.1 통계 명령

명령:

```powershell
python -m eval.stats.bootstrap --input eval/reports/sample_raw.jsonl --n 10000
```

출력:

```text
paired_n=5; Proposed-A mean diff [0.200000] [-0.800000, 1.200000]; 유의하지 않다 (CI가 0을 걸침)
```

명령:

```powershell
python -m eval.stats.mcnemar --input eval/reports/sample_pairs.jsonl
```

출력:

```text
discordant_b=2; discordant_c=1; discordant_total=3; method=exact; p_value=1.000000
```

### 5.2 데이터셋 건수 명령

```text
60
20
```

### 5.3 A/B dry-run

`--repeats 3 --seed 7`에서 각 arm은 60×3=180 calls, 모델 `gpt-4o-mini`, temperature 0.0, timeout 20초, prompt `eval-harness-v1`로 기록되며 dry-run 예상 비용은 arm당 `$0.1440`으로 출력됐다. 실제 60×3 전량 실행은 하지 않았다.

### 5.4 A/B 소규모 smoke

각 arm에 `--limit 5 --repeats 1 --provider mock`을 사용했고, 각각 5 rows를 `eval/reports/raw_a_smoke.jsonl`, `eval/reports/raw_b_smoke.jsonl`에 생성했다. mock은 비용을 발생시키지 않는 파이프라인 fixture이며 실제 LLM 품질 결과로 해석하지 않는다.

Proposed smoke:

```text
ERROR: PROPOSED_UNAVAILABLE: Proposed results require the real Team execution path; mock provider is not permitted and no Team adapter is configured.
```

따라서 Proposed 결과를 지어내지 않았고, `eval/reports/raw.jsonl`에 Proposed mock 결과를 남기지 않았다.

## 6. 한계와 해석

60건×3회는 통제 조건에서의 방향성과 불확실성만 말한다. 모집단 일반화, 장기 drift, 실제 손실률, 모든 도메인에서의 우월성, 운영 SLA를 증명하지 않는다. holdout 20건은 과적합 감시용이며 대표성을 보장하지 않는다. 또한 2인 독립 라벨링과 judge agreement는 이 실행에서 측정하지 않았다. CI가 0을 걸치면 “유의하지 않다”고 기록하며 “우수하다”고 표현하지 않는다.
