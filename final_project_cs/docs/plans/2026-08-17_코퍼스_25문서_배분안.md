## 0. 게이트가 요구하는 것

| 항목 | 값 | 근거 |
|---|---|---|
| 문서 수 | **25** | `rag.document_count` |
| 총 섹션(청크) | **300~400** | `rag.chunk_total_min/max` |
| 문서당 섹션 | **12~16** | `rag.chunks_per_document_*` |

| ★전체 청크쌍 6-gram 중앙 유사도 | **≤ 0.25** | `MAX_GLOBAL_MEDIAN_JACCARD` |
| 절반 이상 청크가 공유하는 6-gram 종류 | **≤ 20** | `MAX_SHARED_GRAM_TYPES` |
| 한 섹션 제목의 문서 점유율 | **≤ 50%** | `MAX_SHARED_TITLE_RATIO` |
| 숫자 포함 문서 비율 | **≥ 90%** | `MIN_DOCS_WITH_NUMBERS` |

반복돼 자연히 비슷해진다. sample 에서 이 지점에 **4번 걸렸다**.

## 1. ★법정 기준 (웹 확인, 2026-08-17)

지어낸 숫자를 쓰면 코퍼스 자체가 틀린 답을 가르친다. 아래는 실제 법령이다.

★**초안의 법정 기준 4곳이 틀렸다.** Codex 교차검증에서 잡혔고 재확인해 고쳤다.
아래가 수정본이다.

| 항목 | 기준 | 비고 |
|---|---|---|
| 청약철회(단순변심) | **7일** | ★기산점은 **계약내용 서면을 받은 날**. 공급이 그보다 늦으면 공급받은 날 또는 공급 시작일 (법 §17①1) |
| 표시·광고와 다른 경우 | **공급받은 날부터 3개월 이내 + 안 날부터 30일 이내** | 단순변심 7일과 **별개로** 살아 있다 |
| 대금 환급 | **3영업일 이내** | ★기산점이 유형별로 다르다. 반품의 경우 **재화를 반환받은 날** 기준 (법 §18①) |
| 환급 지연이자 | ★**연 15%** | 법 §18②의 "연 40% 이내" 는 **상한**이고, 실제 요율은 **시행령 §21조의3 = 연 15%** |
| 반품 배송비 | 단순변심은 **소비자 부담** | 판매자 귀책이면 판매자 부담 |
| 청약철회 제한 | ★법 §17② 의 **6개 범주** | 복제 가능 재화의 포장 훼손은 그중 하나일 뿐이다. 나머지 범주와 §17⑥(표시·시험사용 조치), 주문제작 관련 시행령 §21 요건을 문서에 반영한다 |
| 불리한 특약 | **무효** | "반품 금지" 같은 조항은 효력 없음 |

### ★초안에서 틀렸던 것 (기록)

| 초안 | 실제 |
|---|---|
| 7일 기산점 = "공급받은 날" 로 단정 | 기본은 **서면 수령일**, 공급이 늦을 때만 공급일 |
| 지연이자 "연 40% 이내" 를 실제 요율처럼 배치 | 40% 는 **법률상 상한**, 실제는 **연 15%**(시행령) |
| 환급 3영업일의 기산점 생략 | 유형별로 다르며 반품은 **반환받은 날** |
| 청약철회 제한을 "포장 훼손" 중심으로만 제시 | **6개 범주**가 있다 |

★**법령 숫자는 그럴듯함으로 쓰지 않는다.** 조문 번호까지 확인하고 쓴다.
`MIN_CHUNK_CHARS` 를 채우려고 숫자를 바꾸지 않는다.
법정 기준과 다른 값을 쓰려면 그것이 **사내 정책이며 법정 기준보다 유리하다**는 것을
문장으로 밝힌다. 불리한 쪽으로 바꾸면 그 조항은 애초에 무효다.

## 3. 시나리오 근거 배치

`SCENARIO_PROBES` 5종을 **여러 문서에 나눠** 심는다. 한 문서에 몰면
그 문서가 죽었을 때 시나리오 전체가 근거를 잃는다.

| probe | 담을 문서 |
|---|---|
| 배송완료 표시와 미수령 | 01 |
| 조사 기한(숫자) | 01 · 04 |
| **반품/교환 수량 상한** | **14** · 12 |
| 진단 순서 | 01 · 09 · 24 |
| 승인 없이 실행 금지 | 01 · 08 · 20 |

시나리오 1 — 배송완료로 찍혔는데 고객이 받지 못했다 → 조사 → **분기**
시나리오 2 — 주문 수량(3개)보다 많은 반품(5개) 요청 → **대조에서 차단** → escalated

★**시나리오 1의 결말을 "환불" 로 고정하지 않는다.** 초안이 그렇게 적었는데 틀렸다 —
doc_01 자체가 재발송/환불을 **고객이 고른다**고 쓰고 있다. 조사 결과에 따라
재배송 · 환불 · 배송사 보상 · 추가 확인으로 갈린다. 계획서가 문서보다 단순하면
그 계획서를 보고 쓴 다음 문서가 분기를 잃는다.

★**시나리오 2는 대표 문의가 아니라 방어 테스트다.** 수량 초과 반품은 실제 고객
문의로 흔하지 않다. 데이터 무결성·권한 통제를 검증하는 엣지 케이스로서 가치가 있고,
그 목적으로만 쓴다. **대표 시나리오로 소개하지 않는다.**

대표성이 더 높은 후보(교차검증 제안, 다음 라운드에서 추가 검토):

- 오배송·파손 수령 → 증빙 확인 → 판매자 귀책 판정 → 무상 회수·교환 또는 환불
- 출고 전 취소와 출고 후 취소 → 주문 상태 대조 → 취소 또는 반품 절차로 분기
- 결제 승인 실패·중복 승인 → 결제 상태 대조 → 중복분 취소·환급과 재시도 안내

## 4. ★중복 게이트를 넘기는 전략

scope 마다 **어휘층을 분리**한다. 같은 말을 다른 자리에서 쓰지 않는다.

| scope | 주어·목적어 | 시간 단위 | 행위 동사 |
|---|---|---|---|
| order | 주문번호 · 품목 · 결제수단 | 마감시각 · 분 | 접수 · 변경 · 취소 |
| shipping | 운송장 · 물류센터 · 기사 | 영업일 · 경유지 | 스캔 · 출고 · 회수 |
| return | 반품접수번호 · 수량 · 사유코드 | 수령일 기준 일 | 회수 · 검수 · 판정 |
| exchange | 교환건 · 대체상품 · 재고 | 재출고 일정 | 대체 · 소진 · 전환 |
| refund | 승인번호 · 지급요청 · 잔액 | 카드사 영업일 | 산정 · 지급 · 대조 |
| support | 티켓 · 채널 · 담당자 | 응답 목표시간 | 배정 · 승급 |
| incident | 장애구간 · 공지 · 영향범위 | 복구 시각 | 탐지 · 공지 · 집계 |

### 금지 — 지표를 우회하는 방법

sample 에서 실제로 거부된 수법들이다. 반복하지 않는다.

- ❌ 무작위 토큰을 섞어 유사도를 낮춘다 (v3 거부 사유)
- ❌ 청크를 짧게 써서 겹치는 6-gram 수를 줄인다 (v4 거부 사유, 평균 56자)
- ❌ 섹션 끝에 의미 없는 짧은 문장을 덧붙여 글자 수만 채운다
- ❌ 게이트를 느슨하게 고쳐 통과시킨다

### ★어휘 분리만으로는 부족하다 (교차검증 결과)

Codex 반박이 옳다. 게이트는 **공백을 제거한 뒤 문자 6-gram** 을 만들기 때문에
`주문/배송/반품` 같은 명사만 바꿔도 **종결어미와 공통 업무 문구의 6-gram 은 그대로 남는다.**
`~할 수 있다`, `~확인한다`, 숫자+단위 표현이 구조적으로 겹친다.

또 계획서 초안이 게이트 구현을 잘못 적었다:

| 초안 | 실제 구현 |
|---|---|
| "전체 청크쌍" 중앙 유사도 | **seed 7 의 무작위 표본 최대 3,000쌍** 중앙값 |
| 검사가 유사도 하나 | 공유 6-gram 종류 · **30% 초과 청크의 14자 공통 문구** · 문서 내 반복 문장까지 |

★따라서 **global median 하나만 낮추는 어휘 치환은 다른 게이트에 걸린다.**

### 실제로 통할 방법

- 종결어미를 억지로 바꾸는 대신, 문서마다 **업무 객체·분기 조건·예외·입력값·판정 결과**를 다르게 설계한다
- 공통 안내문을 문서마다 복사하지 않는다. 공통 규칙은 **짧은 기준 문서 한 곳**에 두고
  각 문서는 **고유한 판단 절차와 실패 케이스**를 쓴다
- ★유사도가 **표본**이므로 같은 seed 결과만 보고 안심하지 않는다.
  여러 seed 또는 전체 쌍으로 따로 진단해 **우연한 통과**를 배제한다

### 작성 절차

★**5문서마다 게이트를 돌린다.** 25개를 다 쓰고 나서 걸리면 전부 다시 써야 한다.
sample 에서 그렇게 4번 버렸다.

```powershell
python -m scripts.check_corpus     # 5개 쓸 때마다
```

길이·공통 6-gram·14자 공통 문구·시나리오 probe 를 **함께** 확인한다.

## 6. 범위 밖 (이번에 넣지 않는 것)

쿠폰·적립금, 개인정보 변경, 세금계산서, 해외직구 통관, 정기구독.
