# 2026-08-30 21:00 — 모듈 토글 실효화 설계

## 왜 하나

`config/project.yaml` 의 모듈 여섯 개 중 **셋만 실제로 코드를 가른다.** 나머지 셋은
켜고 꺼도 아무 일이 일어나지 않는다. 화면에서 끄면 선언은 저장되는데 동작은 그대로다.

`docs/handoff/08_모듈_컴포넌트_목록.md` §2 가 이미 못박아 둔 것을 어긴 상태다.

> ★**모듈을 빼면 그것을 부르는 경로도 함께 빠져야 한다.** 남아 있으면
> `RULE.md` §3.2(폴백 금지)에 따라 **조용히 넘어가지 말고 명시적으로 실패**해야 한다.

같은 문서 §6 "빌드 시 실패시켜야 할 것" 4번도 마찬가지로 미구현이다.

> 4. 꺼진 모듈을 **부르는 경로가 남아 있다**

## 범위

계약(handoff/08 §2)이 이미 지정한 표면만 막는다. **새 기능을 만들지 않는다.**

| 모듈 | 끄면 사라져야 할 것 (계약 §2) | 이번에 막을 지점 |
|---|---|---|
| `mcp` | 개인 AI 의 read-only 접근(tool 3종) | `app/presentation/api/cases.py::_mcp_principal` |
| `voc` | 인라인 분류, 급증 alert / VOC 화면 | `build_classifier`, `run_daily_feedback`, `/ui/voc` 등록 |
| `graph_store` | 설명가능성 경로 질의 / 관리자 화면의 Graph 섹션 | `routes.py::_admin_snapshot` 의 직접 생성 제거 |

### 범위 밖 — 하지 않는 것

- **Graph 질의를 Context Broker 에 붙이지 않는다.** 계약이 요구한 적 없고
  전용 Graph Store 는 `docs/vision/VISION-02` 로 미룬 항목이다. `RULE.md` §3.3(YAGNI).
- **AGE·Neo4j 어댑터를 만들지 않는다.** Phase 2 다. Port 까지만 허용된다.
- **모듈을 새로 추가하지 않는다.** 여섯 개 그대로다.

## 설계 판단 — `voc` 를 끄면 앱이 기동하지 않는다

이게 이번 변경의 유일하게 껄끄러운 결과라 먼저 적어 둔다.

`voc` 를 끄면 `build_classifier()` 가 명시적으로 실패한다. 인라인 분류가 Case 생성
경로에 붙어 있으므로 `create_app()` 이 그 자리에서 터진다. 즉 **`voc: false` 로는
이 제품이 뜨지 않는다.**

이게 맞다고 본 이유는 두 가지다.

첫째, `CLAUDE.md` §1 이 **"인라인 분류는 선택 기능이 아니다"** 라고 못박았다.
분류를 조용히 건너뛰면 `intent` 와 `sentiment` 가 빈 채로 Case 가 만들어지고,
그 빈 값이 근거 조합을 거쳐 고객 답변까지 간다.

둘째, 계약 §6 검증기 4번이 요구하는 것이 정확히 이 동작이다. 부르는 경로가 남아 있는데
모듈만 꺼면 **실패해야 한다.** 조용히 도는 지금 상태가 결함이다.

바꿔 말하면 `voc` 는 지금의 이 제품에서 끌 수 없는 모듈이다. 그것을 선언에서
끌 수 있는 척하는 것이 문제였다. 앞으로 정말 끄고 싶으면 Case 생성 경로에서
분류를 떼는 별도 작업이 필요하고, 그건 이 계획의 범위가 아니다.

## 완료 기준

1. 여섯 모듈 각각에 대해, 끈 상태로 해당 경로를 부르면 `ProjectConfigError` 가 난다.
2. 켠 상태의 동작은 지금과 같다. 기존 테스트가 그대로 통과한다.
3. `/ui/voc` 는 `voc` 가 꺼져 있으면 404 다. 상단 메뉴에서도 사라진다.
4. 관리자 화면의 GraphStorePort 줄은 `graph_store` 가 꺼져 있으면 "모듈 꺼짐" 으로 뜬다.
   조용히 어댑터 이름을 보여 주지 않는다.
5. 새 테스트가 1~4 를 덮는다. 재현 명령과 출력을 `docs/evidence/` 에 남긴다.
