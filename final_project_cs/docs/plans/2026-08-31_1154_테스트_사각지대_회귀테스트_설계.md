## 0. 왜 하나

불변식을 어기는 최소 변경 39가지를 임시 사본에 적용해 전체 424개를 돌렸다.
21건은 테스트가 잡았고 **18건은 424개가 전부 통과했다.** 잡힌 21건이 대조군이므로
측정 절차나 도구의 문제가 아니다. 규칙은 문서에 있는데 그것을 지키는지 세는 곳이 없다.

★티켓에는 15건으로 적혀 있으나 그 뒤 후보를 31 → 39개로 늘려 18건이 됐다.

## 1. 범위

**테스트만 추가한다. `app/` 코드는 바꾸지 않는다.**
결함이 실재하는지 판정하는 것이 이 작업의 목적이 아니다. 규칙이 깨졌을 때
테스트가 우는지만 만든다. 실제 코드 수정이 필요한 것이 나오면 별도 결함 리포트로 넘긴다.

## 3. 완료 기준

1. 추가한 테스트가 기준 코드에서 **통과**한다.
2. 해당 결함을 적용하면 **실패**한다 — `acop_dojo` 등록 게이트로 재확인한다.
3. 전체 비-live 테스트가 회귀 없이 통과한다.
4. 검증 로그를 `docs/evidence/` 에, 결과를 `docs/reports/` 에 남긴다.

## 4. 이 계획에서 하지 않는 것

- `app/` 코드 수정. 규칙 자체가 잘못됐다고 판단되는 것이 나오면 리포트로만 남긴다.
- INV-STATE-001 의 실행마다 갈리는 현상의 원인 규명. 테스트를 추가하되 원인은 별건이다.

## 5. 범위 변경 — 2026-09-01

§1 에 "테스트만 추가한다. `app/` 코드는 바꾸지 않는다" 고 적었으나,
`app/core/transition.py` 에 **주석 5줄을 추가**한다. 사유는 다음과 같다.

INV-STATE-001 의 실패 회차 traceback 을 붙잡아 기제를 확인했다. 파이썬 쪽 version
대조는 SQL 과 중복이 아니라 **경합에서 진 쪽이 항상 `StateConflict` 를 받게 하는
장치**다. 이 사실이 코드 어디에도 적혀 있지 않아 다음 사람이 중복으로 보고 지울 수 있다.
지우면 같은 동시 전이가 어떤 날은 409 로, 어떤 날은 전이 위반으로 보고된다.

- 변경: 주석만. **동작 변경 없음.**
- 위치: `app/core/transition.py` 의 version 대조 바로 위
- 근거 문서: `docs/reports/debugs/2026-08-31_버전대조_가드_중복.md` §5-1
- 소유: `docs/handoff/05_분업_규칙.md` 상 Claude-Core. 사용자 지시로 이 세션에서 수행한다.
