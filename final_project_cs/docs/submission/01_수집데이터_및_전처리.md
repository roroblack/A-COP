# 수집데이터 및 전처리

## 코퍼스 구성

정책·FAQ 코퍼스는 25개 문서, 300개 청크로 구성했다. 작성 기준은 문서별 운영 주제와 경계조건을 분리하고, 섹션마다 절차·예외·고객 안내 등 구체 내용을 넣는 것이다. 문서당 길이 평균은 4,231자, 청크 길이는 공백 제외 평균 241자이며 최소 200자 미만 청크는 0/300이다.

| scope | 문서 수 |
|---|---:|
| billing | 5 |
| refund | 4 |
| subscription | 4 |
| entitlement | 5 |
| incident | 3 |
| technical | 2 |
| support | 2 |
| 합계 | 25 |

각 문서는 `##` 소제목을 경계로 나누어 청크화했다. 임베딩은 1536차원이며, 적재 후 `knowledge_documents=25`, `knowledge_chunks=300`, `vector_dims=1536`, `pending_chunks=0`을 확인했다.

## 코퍼스 품질 게이트

`scripts/check_corpus.py`는 건수만 세지 않는다. 문서·섹션 수와 scope 배분, 반복 문장·공유 제목, 전역 청크쌍 유사도, 청크 길이, 구체 수치·기한·절차 포함 여부를 검사한다. 이전 버전에서 보일러플레이트와 지표 우회가 건수 검사를 통과했던 결함을 발견했고, v5에서 재작성 후 전 항목 통과 판정을 받았다. v5 실측에는 중앙 유사도 0.002, 공유 6-gram 1종, 청크 길이 평균 241자·최소 200자라는 결과가 있다.

이 게이트는 검색 전에 코퍼스가 서로 다른 운영 지식을 담는지 검증하는 품질 경계다. 따라서 단순히 25건·300청크를 채우는 것과 검색 가능한 코퍼스를 만드는 것을 구분한다.
