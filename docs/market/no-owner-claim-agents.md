# 책임주체 없는 사건 × 에이전트 웹: 아이템 서바이벌 리포트

작성일: 2026-09-03 · 기준: 국내 시장, 오늘자 공개자료

---

## 0. 먼저, 반론에 대한 재반론

> "정말로 책임주체가 없는 사건은 자동화하기 어렵다. 더 좋은 시장은 책임주체가 여러 명인데 단계마다 바뀌는 시장이다."

절반만 맞다. 자동화 가능/불가능을 가르는 진짜 변수는 **책임주체의 유무가 아니라 증거 접근권이 누구 손에 있느냐**다.

지키미가 성립했던 이유를 분해하면:

| 조건 | 지키미 |
|---|---|
| 답을 가진 쪽이 답할 인센티브 | 보험사 = 음(-). 알려주면 보험금 나감 |
| 판단에 필요한 증거 | 약관 + 진료비 영수증/세부내역서 = **전부 고객 손에** |
| 판단의 성격 | 문서 × 규칙 해석 = LLM이 잘하는 일 |
| 결과 | 원화 금액으로 환산됨 |
| 청구 채널 | 법·제도로 이미 열려 있음 (보험사 협조 불필요) |

즉 **"책임주체 부재"는 수요의 조건이고, "고객측 증거 자족성(client-side evidence sufficiency)"은 공급의 조건**이다. 둘 다 있어야 자동화된다. 책임주체가 없어도 증거가 고객 손에 있으면 자동화된다 — 지키미가 증거다.

### 아이템 킬 필터 (이 문서에서 계속 쓰는 6개 테스트)

1. **미고지 테스트** — 답을 아는 쪽이 알려주면 자기 손해인가?
2. **증거 자족성** — 상대방 협조 0으로, 고객이 합법적으로 확보 가능한 문서만으로 판단이 서는가?
3. **채널 개방성** — 청구/이의제기 제도가 이미 법으로 열려 있는가? (없으면 우리가 제도를 만들어야 함 = 사망)
4. **금액 환산** — 결과가 "당신은 N원 받을 수 있다"로 나오는가?
5. **국가·플랫폼 대체 리스크** — 정부나 대형 플랫폼이 3년 내 직접 해줄 가능성. **여기서 대부분 죽는다.**
6. **자격사법 리스크** — 변호사법·세무사법·손해사정사법·노무사법 저촉. 2026년 3월 대법원: 빈칸채우기식 법률문서 자동작성은 합법, **생성형 AI 작성·유료 변호사 검토 연계는 위법 소지**. 설계 제약이 명확해졌다.

테스트 5와 6이 킬러다. 사람들이 1~4만 보고 뛰어들었다가 죽는다.

## 1. 에이전트 웹 관점에서 CS는 무엇이 되는가

에이전트끼리 연결되어 웹을 이룬다는 전제를 받아들이면, CS는 "상담 대화창"이 아니라 **클레임 프로토콜(claim protocol)** 이 된다. 3개 층으로 갈라진다.

```
L1  Claimant Agent  (고객 대리 에이전트)
    "내 돈 받아내라" — 증거 수집·자격 판정·청구서 제출·불복
                 ↕  구조화된 클레임 메시지 (근거·금액·조항 인용)
L3  Evidence / Adjudication Layer  (중립 증거·판정 기록)
    누가 무엇을 근거로 승인·거절했는가의 감사 가능한 로그
                 ↕
L2  Respondent Agent  (기업 대리 에이전트)
    분류·검증·승인·부분승인·거절 + 사유 생성   ← A-COP이 여기 있다
```

여기서 세 가지가 동시에 일어난다.

- **L1이 생기면 청구량이 폭증한다.** 지금 사람들이 청구를 안 하는 이유는 자격이 없어서가 아니라 절차가 귀찮아서다. 대리 에이전트는 안 귀찮다.
- **L2 수요는 L1 때문에 커진다.** 상대 에이전트가 24시간 근거를 붙여 청구를 밀어넣는데 사람 상담원으로 받으면 무너진다. **L1을 파는 회사가 L2를 파는 회사의 시장을 만들어준다.** 양면을 다 쥐면 이건 반칙에 가까운 포지션이다.
- **L3은 지금 아무도 안 한다.** 이게 "책임주체가 없는 사건"의 메타 버전이다. 에이전트 A와 에이전트 B가 다툴 때 누가 기록하고 누가 판정하나 — 규제도 표준도 공백이다.

프로토콜 층은 이미 깔리는 중이다. A2A v1.0(2026년 4월, Linux Foundation, 150개 이상 조직), AP2(Intent/Cart/Payment Mandate 서명), MCP 2026년 7월 업데이트, Google Cloud Next '26의 50개 이상 매니지드 MCP 서버. **배관은 남이 깔아준다. 우리가 만들 것은 그 위를 흐르는 "청구와 판정"이다.**

## 3. Round 2 — 생존자 심층 (Pain / Gap / Buyer / Build / Business)

### A. 비급여 진료비 환급 에이전트

- **Pain** — 환자는 비급여 100만 원을 내고도 그게 정당한지 알 방법이 없다. 병원은 알려줄 이유가 0(알려주면 토해내야 함). 심평원 진료비확인 제도가 있지만 존재 자체를 모르고, 알아도 서류·절차에서 이탈한다.
- **Gap** — 심평원 자가점검 서비스는 "직접 확인해 보세요"까지다. 항목별로 급여 대상인지 판정해주지 않는다. 심평원조차 2026년에야 자동전산심사 39개 항목을 도입했다 — 즉 **판정 자동화가 여기서 이제 막 가능해진 영역**이다.
- **Buyer** — 환자. 환급액의 성공보수 또는 정액 리포트비. 실손 가입자면 환급→보험금 재산정까지 연결되어 금액이 두 배로 보인다.
- **Build** — 진료비 영수증·세부산정내역서(환자가 발급 요구권 보유) + 심평원 공개 급여기준·고시 = **증거 자족성 만점**. 병원 협조 0으로 MVP 가능. 독점 데이터 불필요.
- **Business** — 1회성 성향이 강함. 다만 만성질환·가족 단위·장기입원에서 반복 발생.
- 리스크: 의료 도메인 오판정, 성공보수 구조의 법적 검토 필요.

### B. 근로자 임금 검증 에이전트

- **Pain** — 연장·야간·휴일수당, 연차미사용수당, 퇴직금 산정 오류. 2026년 4월 고용부 지침 이후 포괄임금 오남용 단속 강화 = 회사 쪽 불확실성도 커짐.
- **Gap** — 시중 도구(근로계산기, 급여 프로그램 4종 등)는 전부 **회사가 지급액을 계산하는 도구**다. 근로자가 "내가 받은 명세서가 맞는지"를 검증하는 제품은 사실상 없다. 이해충돌 때문에 기존 플레이어가 못 만든다.
- **Buyer** — 개인 지불의사는 낮다. → **노무법인·노동조합·법률구조 채널이 진짜 buyer.** 그들은 상담 1건에 사람 시간을 쓰고 있다.
- **Build** — 급여명세서(2021년부터 교부 의무) PDF/이미지 + 근로계약서 + 근로기준법 규칙집. 증거 자족성 높음.
- **Business** — B2B2C 시트/건당 과금이면 반복 매출. 개인 직판이면 1회성.
- 리스크: 테스트6. 대법 2026.3 기준 **"빈칸채우기식 서류 자동작성"까지만** 안전하고, 생성형 AI가 법률 판단문을 쓰면 위험.

### C. 격락손해·보험 미지급금 재청구

- Pain·Gap은 최상급(보험사 미고지 + 대법 승소 사례 존재). 그러나 **Buyer/Business에서 무너진다.**

### D. 에이전트-투-에이전트 클레임 증거·판정 레이어

- **Pain** — AI 에이전트가 잘못 샀을 때 "이건 승인된 거래인가?" 에 답하는 법이 없다. 차지백 체계는 인간 구매자와 에이전트 구매자를 구분하지 못한다. **오늘 기준 손실은 전부 판매자가 흡수한다.**
- **Gap** — 국내 CS 툴(채널톡 알프 v2: 800개사, 상담 30% 무인처리, 해결률 80.1%; 인터콤 Fin 76%)은 전부 **사람 문의를 받는 것**을 잘한다. **에이전트가 보낸 요청을 검증하고 그 판단 근거를 감사 가능하게 남기는 층은 아무도 안 만든다.**
- **Buyer** — 판매자/브랜드사. 이유가 명확하다: 지금 손실을 그들이 문다.
- **Build** — 주문 웹훅 + AP2형 mandate 로그 + 소명서 자동생성. 특수 인프라 불필요.
- **Business** — 거래량 기반 반복 과금. 구조적으로 SaaS.
- 리스크: 너무 이르다. 한국 에이전트 결제 거래량이 아직 작다.

### E. 부동산 미청구금 (장충금 + 관리비)

- 금액은 실재(수십~백만 원), 미고지 구조도 실재. 그러나 Round 3에서 본다.

## 4. Round 3 — 다시 죽인다

**12 B2B 미수금 — KILL.** 선점자가 있고, 우리 차별화 축(문서×규칙 해석)이 아니라 채권관리 워크플로 싸움이다.

**7 관리비 검증 — KILL.** E와 같은 이유 + 아파트아이가 유통을 이미 쥐었다.

**11 근로자 임금 검증 — 조건부 생존.** 개인 직판 버전은 죽인다(지불의사·규제). **노무법인/노조 대상 B2B2C 버전만 살린다.**

## 5. Round 4 — 살린 것을 다시 죽여본다

세 개를 서로 부딪혀 본다.

- A는 현금이 빨리 돈다. 대신 1회성이고 의료 리스크가 있다.
- B'는 반복 매출이지만 시장이 좁고 성장이 느리다.
- D는 시장이 크고 구조적이지만 **오늘 매출이 0이다.**

그런데 A와 B'를 나란히 놓으면 같은 엔진이다.

```
고객이 이미 가진 문서  ─┐
                        ├→ [규칙집 대조 판정] → 청구가능 금액 → 정해진 양식으로 제출 → 결과 추적
공개된 공적 규칙·고시  ─┘
   (진료비 영수증 / 급여명세서)   (급여기준 고시 / 근로기준법)
```

**이건 "아이템 3개"가 아니라 "클레임 엔진 1개 + 도메인 3개"다.** 도메인은 갈아끼우는 것이고, 자산은 엔진이다. 그리고 A-COP은 이미 이 엔진의 절반을 갖고 있다 — 분류(classify), 설명 생성(explain), 환불 제안(propose_refund), 가드레일, judge/eval. **판정의 근거를 남기고 채점하는 구조가 이미 코드에 있다는 게 핵심이다. 그게 L3다.**

그리고 D는 이 엔진의 반대편이다. A/B'가 청구를 보내는 쪽(L1)이면, A-COP은 받는 쪽(L2)이고, judge/eval은 그 판단을 기록하는 쪽(L3)이다.

**결정적 논리:** 실손24가 청구를 자동화할수록, 삼쩜삼류가 신청을 자동화할수록, 대리 에이전트가 늘어날수록 — **청구는 늘고 심사·소명 부담이 폭증한다.** 즉 우리를 죽였던 테스트5(국가·플랫폼의 자동화)가 **L2/L3 시장에서는 우리 편이 된다.** 이게 이 리포트의 결론이다.

## 6. 최종안

### 메인: "청구 에이전트 ↔ 응답 에이전트" 양면 클레임 플랫폼

| 단계 | 내용 | 목적 |
|---|---|---|
| 1 (0~6개월) | **비급여 진료비 환급 에이전트** (B2C) | 현금 흐름 + 클레임 엔진 학습 데이터 + "우리가 청구를 어떻게 미는지" 체득 |
| 2 (6~15개월) | **응답 측 자동화** — 병원 원무/보험사 심사팀 대상. A-COP 재사용 | 반복 매출(SaaS). 1단계가 만든 청구 압력이 그대로 영업 논리가 됨 |
| 3 (15개월~) | **클레임 프로토콜 + 증거·판정 레이어** — 양측 에이전트가 주고받는 근거·판정의 표준 기록 | 해자. 양면을 다 봤기 때문에 표준을 우리가 쓴다 |

5문항 최종 점검:

- **Pain** — 환자는 부당 비급여를 모르고 넘어간다. 심사자는 늘어나는 청구를 사람으로 받는다. 양쪽 다 지금 돈·시간을 쓰고 있다.
- **Gap** — 심평원은 "직접 확인하세요"까지, 병원은 알려줄 이유가 없다, 채널톡류는 사람 문의만 잘 받는다. 아무도 판정을 대신해주지 않는다.
- **Buyer** — 1단계는 환자(성공보수/리포트비), 2단계는 병원·보험사(월 구독+건당), 3단계는 양측(트랜잭션).
- **Build** — 환자가 가진 영수증 + 공개 고시. **제휴 0, 독점 데이터 0, 특수 인프라 0으로 MVP 가능.** A-COP 코드 재사용률 높음.
- **Business** — 1단계는 1회성이지만 2·3단계가 반복 매출. 단계 설계 자체가 이 리스크를 푼다.

### 헤지: 에이전트 커머스 분쟁 증거 패킷 (D)

지금 매출은 없지만 **가장 순수하게 "책임주체가 없는" 시장**이고, 오늘 손실을 무는 쪽(판매자)이 명확한 buyer다. MVP는 크지 않다 — 주문 시점의 에이전트 의도·장바구니·승인 로그를 서명해 보관하고, 분쟁이 오면 소명 패킷을 자동 생성하는 것. 웹훅과 로그 저장이면 된다. **1단계·2단계와 같은 엔진 위에서 도메인만 다르게 얹는 것이므로 별도 조직이 필요 없다.** 국내 에이전트 결제 거래량이 임계에 닿는 시점(네이버 쇼핑 에이전트가 베타를 벗는 시점)을 트리거로 잡고 감시한다.

## 7. 2주 검증 플랜

1. 비급여 영수증 30건 수집 → 심평원 급여기준 대조 → **환급 가능 항목 적중률** 측정. 30% 미만이면 A는 재검토.
2. 심평원 확인요청 실제 5건 제출 → 처리기간·환불률·이탈 지점 기록.
3. 병원 원무팀 5곳·보험 심사 담당 3명 인터뷰 → 2단계 지불의사 확인.
4. 네이버 쇼핑 에이전트 경유 주문의 반품·분쟁 처리 흐름을 판매자 3곳에서 청취 → D의 타이밍 판정.
5. 법률 검토 1건: 비급여 환급 성공보수 구조 + 대법 2026.3 판결선 안에서의 서류 자동작성 범위.

# 부록: 검증 라운드 (2026-09-03, 동일자 재조사)

## 0. 1차 리포트의 방법론 결함 (자기 검수)

1차 리포트는 **킬 필터 6개만 돌리고 시장 크기를 한 번도 계산하지 않았다.** 그리고 최종 승자로 뽑은 아이템(비급여 환급)에 대해서만 **국내 경쟁사 직접 검색을 생략했다.** 죽인 아이템은 경쟁사를 찾았는데 살린 아이템은 안 찾았다 — 확증 편향의 교과서적 형태다. 필터를 2개 추가한다.

- **테스트 7 — TAM**: 시장 전체 환급·거래액 × 우리 수수료 = 연 수백억 이상인가? 아니면 제품이 아니라 부업이다.
- **테스트 8 — 유통**: 삼쩜삼·토스·네이버가 이미 깔아둔 유통을 우리가 이길 방법이 있는가? 없으면 좋은 아이템도 그들 기능 하나로 끝난다.

## 1. 메인안 사망 — 비급여 진료비 환급

| 반증 | 출처 |
|---|---|
| **시장 전체가 연 15억** — 2023년 진료비확인 신청 25,513건 중 환급 4,123건, 환급액 총 15억 4,839만원. 수수료 20%를 다 먹어도 시장 전체 연 3억 | 언론 보도 |
| **삼쩜삼이 이미 하고 있다** — "병원비 환급" 정식 서비스. 심평원·보험사 데이터 연동으로 실손 미청구 + 본인부담상한제 미수령액 자동 조회, 대행 신청·서류취합·제출·추적까지. 조회 무료, 대행부터 수수료 | 3o3.co.kr, 2026.2 보도 |
| **토스도 하고 있다** — '병원비 돌려받기', 카드 연동해 병원 결제마다 실손 청구 알림. 실손24는 네이버·토스에도 탑재 | 토스 고객센터 |

테스트 7·8 동시 사망. **1차 리포트의 3단계 전략 중 1단계가 통째로 무효다.** 2·3단계 논리는 살아있지만, 진입점을 다시 찾아야 한다.

## 2. 서브안도 사망 — 근로자 임금 검증

**진정24**가 이미 존재한다. 증거 사진 업로드 → AI가 사실관계 추출 → 추가 질문 → 법률 양식 진정서 자동생성, 평균 10분. 내가 "공백"이라고 쓴 자리를 그대로 점유하고 있다. 1차 리포트에서 "근로자 편에 선 검증 도구는 사실상 없다"고 단정한 것은 **검색을 안 해서 나온 문장**이다.

## 3. 카테고리 전체 킬 — "미청구금 발굴" B2C

개별 아이템이 아니라 카테고리를 죽인다. 구조적으로 세 갈래로 갈리고 세 갈래 다 우리 몫이 아니다.

- 금액이 큰 것(본인부담상한제 미신청 5년 6개월 누적 3,617억, 숨은 보험금 1.6조) → **삼쩜삼·토스가 유통으로 이미 점유**
- 금액이 작은 것(장충금, 격락손해, 진료비확인) → **TAM 미달**
- 남는 것 → **국가가 계속 자동화**(실손24, 홈택스 원클릭, 공단 안내문)

지키미가 통했던 창은 닫혔다. 2024~2026년 사이에 정부·빅플랫폼이 이 층을 덮었다.

## 4. 그래서 무엇이 살아남았나 — 방향 전환

죽지 않은 것은 **에이전트가 고객으로 찾아오는데 기업이 맞을 준비가 안 된 상태**다. 오늘자 근거:

- **Cloudflare, 2026-09-15부터** 신규 사이트와 무료 고객의 **광고 노출 페이지에서 AI 학습봇·에이전트봇 기본 차단.** 검색 크롤러는 허용. Pay Per Crawl은 **Pay Per Use로 전환**(Ceramic.ai·You.com이 첫 파트너, 실제 인용 시 과금). → 에이전트를 **막고 과금하는 층은 생겼는데, 받아서 응대하고 거래를 성사시키는 층은 없다.**
- **국내 GEO/AEO는 전부 에이전시다** — 이비아이, 오픈타임, 리드젠랩, 잇다소프트. 수요는 검증됐으나 전부 수작업 컨설팅이고 **제품이 없다.** 그리고 이들은 "AI 검색에 노출되기"까지만 하고 **"에이전트가 문의·주문·반품을 걸어왔을 때"는 아무도 다루지 않는다.**
- **차지백 책임 공백** — 어느 나라도 규제 없음, 기본값은 판매자 전액 흡수.
- 국내 CS 시장은 전부 **사람 문의를 잘 받는 것**에 최적화 — 채널톡 알프(해결률 80.1%), CS쉐어링 등 CS 대행.

## 5. 수정된 최종안 — 정책 컴파일러 + 판정 증거 레이어

한 문장: **기업의 환불·교환·보증 정책은 지금 "사람이 읽는 문장"으로만 존재한다. 에이전트가 물어보면 저마다 다르게 해석하고, 그 해석 차이가 곧 분쟁이 된다. 정책을 실행 가능한 규칙으로 컴파일하고, 그 규칙으로 내린 판정을 서명해 남긴다.**

- **Pain** — 셀러는 교환·반품·환불 판정에 사람 시간을 쓰고, 상담원마다 답이 달라 재문의와 분쟁이 난다. 에이전트 경유 주문에서 오구매가 나면 손실은 전액 셀러가 문다.
- **Gap** — 채널톡류는 **대화 해결률**을 판다. GEO 대행사는 **노출**을 판다. **"판정의 일관성과 그 근거의 감사 기록"을 파는 곳은 국내에 없다.** 축이 다르다.
- **Buyer** — 셀러·브랜드사. 오늘은 인건비 절감으로 사고, 내년에는 분쟁 방어로 산다.
- **Build** — 정책 문서 + 주문/배송 데이터 + 웹훅. **제휴 0, 독점 데이터 0, 특수 인프라 0.** A-COP의 classify / propose_refund / guardrails / judge·eval이 그대로 엔진이다. 특히 judge·eval이 곧 증거 레이어다.
- **Business** — 월 구독 + 판정 건당. 구조적으로 반복 매출.

**타이밍 리스크는 실재한다.** 국내 에이전트 경유 거래량은 아직 작다. 그래서 1단계 가치는 에이전트와 무관하게 성립해야 한다 — 오늘의 상담원 판정 일관성으로 팔고, 에이전트 채널이 열리면 같은 엔진이 그대로 응답 측이 된다. **채널톡이 이 축으로 들어오면 죽는다. 그게 최대 단일 리스크다.**

## 6. 이번 라운드에서 확정된 반증 테스트 (2주)

1. 셀러 10곳: 환불·교환 판정에 쓰는 실제 사람 시간과 재문의율 측정. 월 40시간 미만이면 1단계 사망.

## 8. 교차검증 관련 고지

코덱스(Codex) CLI는 이 실행 환경에 설치되어 있지 않고 외부 모델 API 키도 없어, **다른 모델과의 교차검증은 실제로 수행하지 못했다.** 대신 1차 결론을 1차 자료로 반증하는 방식으로 검증했고, 그 결과 메인·서브 아이템이 모두 기각됐다. 별도 모델 교차검증이 필요하면 API 키 또는 CLI 접근이 필요하다.
