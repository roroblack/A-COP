## 5. 의존 그래프와 인터페이스

텍스트 의존 그래프는 다음과 같다.

`Gateway/API/MCP → Case Runtime Controller → TeamExecutorPort → Team Module → TeamResult → Shared State/CAS → observability/evaluation`

`Context Broker → ContextPack → Team Module`

`Team Module → ActionProposal → Core 1 Controller → Core 2 Action Gateway → approval/idempotency/provider → ActionResult → Core 1 Case state`

`Case/Policy/Action projection → GraphStorePort → Context Broker/evaluation`

코어 1과 코어 2의 접점은 다음 계약 한 쌍뿐이다.

```text
ExecuteAction(action_proposal, idempotency_key)
ActionResult(status, provider_ref, error_code)
```

Core 1은 승인·provider·Tool 내부를 import하지 않는다. Core 2는 Controller와 Team graph를 import하지 않는다. 모델 담당은 Core 2의 인터페이스를 보지 않으며 `ActionProposal`을 반환하는 데서 끝난다.

Message Broker는 Core 1이 정책과 Port를 소유한다. Infrastructure는 구현만 제공한다. at-least-once와 dedupe를 contract/integration test로 확인한다. Alembic은 단일 브랜치이며 revision 생성 전 main rebase를 gate로 둔다.

통과 조건은 ① 60+20 평가가 3회 재현되고 ② paired bootstrap 95% CI와 McNemar 결과가 산출되며 ③ contract/security/regression이 통과하고 ④ DoD evidence 경로가 존재하며 ⑤ 기능 동결 기록과 남은 P0/P1 목록이 일치하는 것이다. 미통과 시 10주차는 기능 추가가 아니라 P0/P1·계약·evidence 정정에만 사용한다. 수치가 개선되지 않아도 실행 조건과 한계를 정직하게 보고한다.

### 10주차 — DoD와 최종 인수

| 담당 | 산출물 | 주말에 동작해야 하는 것 | 다음 주 블로킹 조건 |
|---|---|---|---|
| 코어 1 | DoD 검증, Alembic gate, 운영 handoff | upgrade/downgrade와 replay·CAS·Port 검사 결과가 evidence로 남음 | main rebase 없는 revision 또는 evidence 누락 |
| 코어 2 | 배포·감사·API/MCP 점검 | 배포 설정, scope, approval, audit checklist가 재현됨 | 배포 경로에서 audit/approval 누락 |
| 모델 3명 | 시나리오·Team contract 동결 | 핵심 시나리오가 고정 prompt와 canonical 결과로 반복 실행됨 | 동결 후 schema drift |
| 검증 & 프론트 | 발표 화면, 최종 리포트, 운영 관측판 | Case·trace·approval·VOC report와 최종 수치가 한 흐름으로 보임 | 최종 수치와 화면 데이터가 불일치 |

## 7. 마일스톤 이후 통합 규칙

각 기능은 contract test, unit test, integration test, 관찰 가능한 log를 함께 낸다. M3 기능 동결 이후에는 P0/P1 결함 수정만 허용한다. merge 전 `python -m scripts.verify_dod`, `python -m pytest tests/contract -q`, `python -m pytest tests/security -q`를 실행한다. DoD 통과 주장은 `docs/evidence/DoD-*`가 있을 때만 한다.
