# 예제 카탈로그·스캐폴딩 CLI — 1층 실행계획

> 배경: `docs/vision/VISION-10_예제_카탈로그_스캐폴딩_CLI.md`가 정의한 두 층
> 중 1층(카탈로그+CLI)을 실행한다. 사용자가 `acop_basement`/`acop_composer`
> 분리(v0.3.0) 직후 "다양한 케이스별 예제 팀 모듈들과 A2A 모듈 등을 미리
> 구현해놓고 이중에서 선택해서 손쉽게 릴리즈할 프로젝트에서 구조 가져와서
> 프로젝트를 만드는 형태"를 제안했고, 2층(데이터로 점점 좋아지는 생성기)은
> 비전 문서에서 이미 보류 판정됐다(cs 하나뿐이라 일반화할 데이터가 없음).
> 이 계획은 **1층만** 다룬다. 사용자 지시: "계획서부터 작성하고 진행해...
> 코덱스 cli 5.6 써서 해야하는거 잊지말고" — 계획 확정 후 구현은 Codex
> CLI에 계약으로 발주하고, `RULE.md` §3.6-3에 따라 직접 재현·검증한다.

## 0. 지금 상태 (2026-08-19)

- `examples/customer_ops/`에 예시 Team 모듈이 **2개** 있다 —
  `billing.py`(`BillingSubscriptionTeam`), `technical.py`(`TechnicalEntitlementTeam`).
  둘 다 `examples/tests/test_team_scenarios.py`로 실제 동작이 검증된
  "예시로 보존"된 코드다(구현계획서 v8 §8-B에서 10주 착수 목록에선 빠졌지만
  Team 플러그인 구조가 실제로 동작한다는 증거로 남겨둔 것).
- 카탈로그 메타데이터가 **없다** — 어떤 예시가 어떤 케이스 유형·필요
  Port·필요 모듈 조합인지 사람이 코드를 읽어야만 안다.
- 새 프로젝트를 이 저장소에서 시작하려면 지금은 전부 수작업이다:
  `config/project.yaml`을 손으로 채우고, `app/modules/`에 뭘 넣을지
  `docs/handoff/10`을 읽으며 직접 판단한다.
- `acop_basement`는 이제 `pip install -e .`로 실제 설치되는 패키지다
  (v0.3.0). 스캐폴딩 CLI가 "설치+예시 복사+초안 생성"을 자동화할 토대가
  이미 갖춰져 있다.
- `config/project.yaml`의 실제 스키마(`teams:` 리스트, `implementation_ref`
  registry ID 형식 등)는 `acop_basement.core.project_config.load_project_config`가
  파싱한다 — CLI가 만드는 초안은 이 로더를 통과해야 "선언은 됐는데 기동하면
  죽는" 상태를 피한다(`docs/handoff/10` §1-3와 같은 원칙).

## 1. 범위 (1층만)

**포함**
- `examples/` 카탈로그 메타데이터 스키마 — 각 예시가 케이스 유형·필요
  모듈(vector_rag/graph_store/a2a_executor/mcp/voc)·필요 Port 조합을
  선언한다.
- 카탈로그 조회 CLI 명령 (`목록 보기`, `상세 보기`).
- 스캐폴딩 CLI 명령 — 고른 예시를 대상 디렉터리에 복사하고
  `config/project.yaml` 초안을 생성한다.
- 기존 2개 예시(billing, technical)를 카탈로그에 등록.

**제외 (2층, VISION-10이 이미 보류 판정)**
- 실제 프로젝트 데이터를 근거로 카탈로그를 자동 확장하거나 추천 품질을
  높이는 기능.
- `pip install acop_basement`를 CLI가 자동 실행하는 것 — pip 실행 자체는
  사용자 환경(가상환경 선택 등)에 관여하는 일이라 **CLI는 명령을
  안내만 하고 실행은 사용자가 한다**(구독·결제·설치처럼 되돌리기 애매한
  환경 변경을 대신 실행하지 않는다는 이 프로젝트의 일관된 원칙).

## 2. 카탈로그 메타데이터 스키마

`examples/catalog.py`에 선언형으로 정의한다(코드로 순회하는 대신 명시
목록 — `scripts/basement_manifest.py`의 `BASEMENT_COMPONENTS`가 채택한
"경계는 명시 선언, 크롤링 아님" 원칙을 그대로 따른다).

```python
@dataclass(frozen=True)
class ExampleEntry:
    example_id: str            # "billing_subscription"
    case_type: str             # "구독/결제"
    summary: str                # 한 줄 설명
    module_path: str            # "examples/customer_ops/billing.py"
    implementation_ref: str     # "app.modules.customer_ops.billing:BillingSubscriptionTeam"
    required_modules: tuple[str, ...]   # ("vector_rag", "mcp")
    required_ports: dict[str, str]      # {"team_executor": "local"}
    knowledge_scope: str | None         # RAG 범위 힌트, 없으면 None
```

각 필드는 `config/project.yaml`의 실제 스키마 필드명과 1:1 대응시킨다 —
카탈로그가 스키마와 따로 노는 별도 어휘를 만들지 않는다.

## 3. CLI 설계

`scripts/scaffold_project.py` (실행: `python -m scripts.scaffold_project <하위명령>`)

- `list` — 카탈로그 전체를 표로 출력 (`example_id`·`case_type`·`summary`).
- `show <example_id>` — 상세 메타데이터 + 필요 모듈/Port 출력.
- `new <example_id> --target <dir> [--team-id <id>]` —
  1. `examples/<module_path>`를 `<target>/app/modules/customer_ops/`로 복사
     (파일 복사만, import 경로는 손대지 않는다 — 대상 프로젝트가
     `app.modules.customer_ops`를 그대로 쓴다는 `docs/handoff/10` §1-3
     구조를 전제한다. 다른 경로를 쓰려면 사용자가 복사 후 직접 옮긴다).
  2. `<target>/config/project.yaml` 초안 생성 — 카탈로그의
     `required_modules`/`required_ports`/`implementation_ref`를 채운
     `teams:` 항목 하나를 만든다. **이미 파일이 있으면 덮어쓰지 않고
     에러로 멈춘다**(조용한 덮어쓰기는 다른 사람의 작업을 지운다 —
     `CLAUDE.md`의 "낯선 상태를 만나면 먼저 조사" 원칙과 동일 선상).
  3. 안내 메시지로 다음 수동 단계를 출력한다: `pip install -e
     path/to/acop_basement`, `python -m acop_basement.infrastructure.db.migrate`,
     `python -m pytest tests/architecture -q`. **CLI가 이 명령들을 대신
     실행하지 않는다**(§1 제외 사유).

   `new`는 실제 파일시스템에 쓰기 전에 대상 경로 존재 여부·덮어쓰기

     `acop_basement.core.project_config.load_project_config`를 실제로
     통과하는지 검증(스캐폴딩 산출물이 계약을 어기면 이 테스트가 잡는다).

## 5. 완료 기준

- `python -m scripts.scaffold_project list`가 billing·technical 2건을
  출력.
- `python -m scripts.scaffold_project new billing_subscription --target
  <임시경로>` 실행 후, 생성된 `project.yaml`이
  `load_project_config`를 통과 + 대상 경로에 `billing.py`가 복사됨을
  실측 확인.
- 같은 대상에 재실행 시 에러로 멈추고 기존 파일이 안 바뀜.
- `python -m pytest tests/unit/scripts/test_scaffold_project.py -q` 통과.
- 전체 회귀: `python -m pytest tests/architecture -q`,
  `python -m scripts.verify_dod` 결과가 이 작업 전후로 동일(카탈로그·CLI는
  DoD 항목을 새로 만들지 않는다 — 순수 부가 도구).
