# final_project_ui 실행계획 — 분리된 개발 콘솔

- 작성: 2026-08-17
- 작업 범위: ★**이 폴더 안.** 다른 폴더 참조는 매번 허가를 받는다

---

## 0. 왜 분리하나

제품(`/ops`)과 개발 콘솔(`/ui`)을 모듈 토글로 갈라 뒀지만, **토글은 라우트를 끄지
코드를 지우지 않는다.** 납품본에 콘솔 소스가 그대로 남는다.

그렇다고 콘솔을 **각 프로젝트에 심으면** 프로젝트마다 사본이 생기고,
수십·수백 개가 되면 사본이 각자 드리프트한다. 보수하러 돌아온 릴리스본마다
어느 버전 콘솔을 붙일지 맞춰야 한다 — 복사-붙여넣기 운영이다.

★그래서 **콘솔 하나가 여러 프로젝트를 가리킨다.** control plane / data plane 모델이다.

---

## 1. 무엇을 만드나

```
프로젝트 경로를 준다           →  그 프로젝트에 붙는다
같은 루트의 형제 폴더가 있다    →  스스로 찾아 목록으로 보여준다
```

읽는 것은 **데이터뿐**이다. 대상의 파이썬을 import 하지 않는다 —
그러면 남의 프로세스에서 실행해야 하고, 그건 불가능하다.

| 출처 | 있으면 | 없으면 |
|---|---|---|
| `config/project.yaml` | 모듈·Port·Team·revision | ★"프로젝트가 아님" 으로 본다 |
| `docs/evidence/DoD-*.md` | 판정 분포·막힌 항목 | "판정 없음" |
| `eval/reports/*.jsonl` | run·arm·provider | "평가 없음" |
| introspection HTTP | 조립 실측 | "대상이 떠 있지 않음" |
| DB 접속 정보 | 실행 이력 | "연결 안 함" |

★**없는 것을 0 으로 채우지 않는다.** 각 칸이 `missing` 인지 `0` 인지 구분한다.

---

## 2. 단계

### P1. 프로젝트 탐지 (지금)
- 경로를 주면 **그게 프로젝트인지** 판별한다 (marker: `config/project.yaml`)
- 부모 루트를 훑어 형제 프로젝트를 찾는다
- ★**아닌 폴더를 프로젝트라고 하지 않는다.** 판별 근거를 함께 낸다

### P2. 읽기 어댑터
- `project.yaml` · evidence · eval reports 를 각각 읽는다
- ★형식이 다르면 **여기서 깨진다.** 조용히 빈 값을 내지 않는다

### P3. 화면
- 프로젝트 목록 → 프로젝트 하나 → 조립·막힌 것·평가

### P4. 라이브 연결 (대상이 떠 있을 때)
- introspection HTTP 로 조립 실측
- `contract_version` 이 모르는 값이면 **모른다고 말한다**

---

## 3. 지키는 것

- ★**read-only.** 대상을 쓰지 않는다
- ★**대상 폴더를 개발 중에 열지 않는다** — 검증이 필요하면 허가를 받는다
- 화면은 실제로 띄워서 확인한다
