# S-RAG v4 코퍼스 재작성 리포트

- 작업일: 2026-08-12
- 대상: `knowledge/documents/*.md` 25개
- 방식: 섹션 할당량에 맞춰 문장을 채우지 않고, 운영 주제별 산문을 먼저 작성한 뒤 소제목을 실측했다.
- 상태: 인수 검사 통과

## 1. v1~v3 실패에 대한 대응

v1의 공통 소제목과 반복 꼬리 문장은 전면 제거했다. v2에서 사용한 제목별 정형 문장과 기록·확정 금지 꼬리도 다시 사용하지 않았다. v3에서 지표를 낮추기 위해 삽입했던 `(s1-625)`, `[제목 / ref-6024]`, `rule_6024`, `기준 토큰은 20초이다` 같은 무작위 식별자와 발명 용어는 넣지 않았다.

이번 버전은 billing, refund, subscription, entitlement, incident, technical, support의 실제 운영 흐름을 문서별로 분리했다. 결제 원장, 환불 승인, 플랜 전환, 권한 동기화, 장애 대응, 로그인/API 진단, 지원 승인처럼 주제가 바뀌는 지점에만 소제목을 두었다. 문장 구조도 설명, 조건, 진단 순서, 예외, 고객 안내를 섞었고 모든 섹션의 공통 마무리를 만들지 않았다.

## 3. 통일해서 사용한 수치 상수

- 시간·기간: 14일 환불 창구, 23:59 UTC 날짜 경계, 20초 권한 동기화 정상 지연, 5영업일 환불 반영·예외 검토, 90일 감사 자료 보존, 24시간 idempotency 키·링크 유효기간, 72시간 결제 실패 유예, 15분 복구 관찰.
- 결제·문서: 기준시각 10분 전 청구 큐, 승인 뒤 5분 청구서 생성, 결제수단 뒤 4자리 표시, 표시 지연 최대 15분, 월간 회차 종료 직전 5분 사용량 비이월.
- 상품: 7일 체험, Free/Pro/Business 플랜 구분, 연간 선불 갱신, 플랜 전환 차액은 잔여기간 기준.
- 운영 원칙: 동일 요청은 idempotency 키로 중복 방지, 환불·수동 권한 변경은 `action:approve` 승인 후 실행, 원문 결제 식별자와 비밀정보는 감사 기록에 남기지 않음.
