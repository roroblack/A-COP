## 1. 무엇을 했나

`scripts.seed_demo_cases` 로 만든 시나리오 1(환불 승인 대기 Case)을 실 브라우저로
열고 `/ui/approvals` 에서 승인 버튼을 실제로 눌러 종단(end-to-end) 흐름을 재검증했다.
그 과정에서 결함을 2건 발견하고 둘 다 그 자리에서 고쳤다.

### 결함 A — `verification_policy.py` 의 `ignored` 에 `"evidence"` 누락

승인 클릭이 `409 verification_failed` 로 막혔다. UI 표시용으로만 쓰는
`arguments_json.evidence` 키를 재검증 대조 어휘(`CUSTOMER_OPS_POLICY`)에 등록하지
않아, "선언되지 않은 필드는 거부한다"는 안전장치(v7 §9-E)가 이 표시용 키까지
막아버린 것이었다. `ignored` frozenset 에 `"evidence"` 추가로 수정.

### 결함 B — 승인 처리 자체가 승인 대기 큐에 유령 항목을 남김

결함 A 를 고친 뒤 다시 승인하니 이번엔 성공(303)했지만, 승인 감사 기록 행
(`action_type="action.approve"`)이 기본 `status="proposed"` 로 저장되면서
`/ui/approvals` 목록에 "새로 처리해야 할 항목"처럼 다시 나타났다 — 근거가 없으니
영구히 "근거 없어 잠김" 상태로. 상세 원인·위험도는
`docs/reports/debugs/2026-08-17_2250_UI승인큐_유령항목.md`.
`app/presentation/api/cases.py` 에서 이 행을 만들 때 `status=request.decision`
을 명시하도록 수정.

## 2. 검증 방법과 결과

```powershell
python -m pytest tests/integration/api/test_approval_audit_row_excluded_from_queue.py -q
# 2 passed

python -m pytest -q
# 297 passed, 2 deselected (기존 295 + 신규 회귀 테스트 2)
```

실 브라우저(`http://localhost:8099`, uvicorn 재기동으로 코드 반영 확인):
`/ui/approvals` 에서 승인 클릭 → `POST .../approve` 303 → 새로고침 →
"대기 중 1, 근거 없어 잠김 0" (수정 전에는 승인할수록 큐가 늘었다).
DB 직접 조회(`psql -d acop_cs`)로 `customer_cases.status='resuming', version=5`
및 새 `action.approve` 행의 `status='approved'` 확인.

승인으로 소모된 데모 상태는 `python -m scripts.seed_demo_cases` 재실행으로
`waiting_approval` v4 원복(재실행 안전성 재확인 겸함).
