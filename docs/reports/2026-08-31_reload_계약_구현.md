# 재기동 없는 반영(reload) 계약 구현 (2026-08-31)

## 왜 지금인가

`docs/reports/2026-08-19_Composer_reload_계약_설계검토.md` 는 후보 3(**재기동 요구**)을
골랐다. 그러면서 후보 1·2를 다시 볼 **트리거**를 적어 뒀고, 그 첫 항목이 이것이다:

> 실제 배포에서 customer 와 Composer 가 동일한 durable config store 또는 명시적
> config artifact 전달 경로를 사용하기로 결정된 때.

중앙 설정 저장소 결정(2026-08-30, `program/plan/A-COP_Composer_중앙설정저장소_결정.md`)이
바로 그 조건이다. 대상과 Composer 가 같은 `project_configs` 를 읽고 쓴다.
그래서 후보 2(관리자 신호)를 채택한다.

## 먼저 고친 것 — 조용한 성공 위장

★기능을 얹기 전에 **거짓 보고**부터 있었다. `/introspection` 은 요청마다 선언을
다시 읽어 `config_revision` 을 계산했다(`introspection/contract.py`). 그래서
Composer 로 선언을 바꾸면:

- 대상은 아직 **옛 조립**으로 요청을 처리하는데
- 화면에는 **새 revision** 이 이미 반영된 것처럼 보였다

설계검토 §3 이 "허용하지 않는다" 고 못 박은 상태다. 실측으로 확인했다.

## 무엇을 넣었나

| 것 | 어디 |
|---|---|
| 실행 중인 조립을 붙잡는 객체 + 프록시 | `acop_basement/application/runtime.py` |
| `active`/`desired`/`reload_state`/`reload_error` | `acop_basement/introspection/contract.py` (계약 **1.0 → 1.1**) |
| `POST /admin/reload` | `acop_basement/presentation/api/app.py` |
| scope `ops:reload` | `config/guardrails.yaml` |
| 조립에 쓴 선언을 그대로 받는 인자 | `app/composition.py` `build_controller(config=...)` |

### 지켜야 했던 성질

- **router 가 옛 Controller 를 붙잡지 않게** — `ControllerProxy` 가 매 접근마다
  지금 것으로 넘긴다. 교체는 참조 하나를 바꾸는 것이라 요청이 반쯤 옛것·반쯤
  새것을 보는 일이 없다
- **새 조립이 전부 성공한 뒤에만 교체** — 실패하면 옛 조립 그대로 두고
  `reload_failed` 를 드러낸다. 409 로 답하고, 그 사실이 이후 `/introspection`
  에도 남는다
- **`active` 를 관찰로 계산하지 않는다** — 조립할 때 받아 적는다. 다시 읽어
  계산하면 그건 저장소를 보는 것이지 실행 중인 것을 보는 게 아니다
- **모르면 `unknown`** — 한쪽 revision 을 모르면 `active` 도 `stale` 도 아니다.
  `stale` 로 적으면 없는 사실을 만든 것이고, `active` 로 적으면 반영 안 된
  상태를 정상으로 감춘 것이다
- **`ops:reload` 를 `composer:write` 와 분리** — 저장은 되돌릴 수 있지만
  반영은 그 순간 트래픽이 받는 것을 바꾼다

## 실측 (살아 있는 서버 8071)

in-process 테스트로는 "프록시가 교체를 따라간다" 까지만 증명된다. 실제로 뜬
프로세스에 HTTP 로 물었다:

```
[1] 지금       active=ea58fc7efe63 desired=ea58fc7efe63 state=active 계약=1.1
[2] 토글       a2a_executor: False → True · 200
[3] 토글 직후  active=ea58fc7efe63 desired=8e03cec7de54 state=stale     ← ★이게 없던 것
[4] reload     200 {'active_revision': '8e03cec7de54', ...}
[5] reload 후  active=8e03cec7de54 desired=8e03cec7de54 state=active a2a_executor=True
[6] 복구       active=ea58fc7efe63 state=active a2a_executor=False
```

★`[3]` 이 이 작업의 핵심이다. 전에는 여기서 `active` 라고 답했다.

## ★곁가지로 발견한 결함 — 선언에 `parameters: null` 이 쌓인다

실측 중 토글 한 번에 `config/project.yaml` 이 이렇게 바뀌는 것을 봤다:

```diff
   implementation_ref: app.modules.customer_ops.feedback_team:FeedbackAnalyticsTeam
+  parameters: null
```

코드형 Team 에는 뜻이 없는 키다. `revision` 은 내용 기준이라 흔들리지 않아
**의미 변화는 없지만**, 토글할 때마다 선언 파일에 한 줄씩 붙어 diff 가
지저분해진다. `acop_composer/api.py` 의 직렬화를 `_declaration()` 한 곳으로
모으고 `parameters is None` 이면 키를 만들지 않게 했다(`create` 경로 포함).
고친 뒤 전체 쓰기 왕복을 다시 돌려 **파일이 바이트 그대로**인 것을 확인했다.

## 콘솔(`final_project_ui`) 쪽

- 계약 기본 허용 버전을 `1.0` → `1.0,1.1` 로. 옛 대상도 그대로 붙는다
- Composer 화면 맨 위에 반영 상태를 적는다. `stale` 이면
  "★실행 중인 조립이 아직 옛 선언입니다", `reload_failed` 면 사유까지
- ★계약 1.0 대상은 이 필드가 없다 → **아무 말도 하지 않는다.** 모르는 것을
  "정상" 으로 적지 않기 위해서다
- 토글 결과의 `pending_restart` 문구에 reload 경로를 함께 적었다. 이 콘솔은
  `/admin/reload` 를 **부르지 않는다**(별도 scope 토큰이 필요하다) — 그래서
  "재시작하거나 `POST /admin/reload` 를 불러야" 라고 사실대로 적는다

## 콘솔의 [반영] 버튼 (같은 날 추가)

처음엔 상태만 보여주고 버튼은 미뤘다 — `ops:reload` 토큰을 콘솔 프로필에
들이는 판단이 필요해서였다. 사용자가 넣기로 정해서 넣었다.

- `CONSOLE_RELOAD_TOKEN` — ★`CONSOLE_INTROSPECTION_TOKEN`(조회)과 **다른
  토큰**이다. 대상이 scope 를 나눠 뒀기 때문이다
- 주소는 따로 받지 않고 `introspection_url` 에서 만든다(`reload_url_for`) —
  따로 받으면 서로 다른 대상을 가리켜 놓고 **남의 프로세스를 반영시키는**
  사고가 난다. 두 표면은 같은 프로세스의 것이다
- **어긋났을 때만** 버튼을 낸다(`stale`·`reload_failed`). 이미 같은데 버튼이
  있으면 이유 없이 살아 있는 조립을 다시 만들게 된다
- ★토큰이 없으면 **버튼 대신 왜 없는지**를 적는다. 버튼만 지우면 운영자는
  "이 대상은 반영 기능이 없나 보다" 로 잘못 읽는다
- 409(대상이 새 선언으로 조립 실패)는 "반영 실패 … 옛 조립이 그대로 돌고
  있습니다" 로 적는다. 404 는 "대상이 아직 reload 를 지원하지 않음(계약 1.0)"

실측(버튼을 실제로 눌러서):

```
[1] 시작        active=ea58fc7efe63 state=active
[2] 저장 후     active=ea58fc7efe63 desired=8e03cec7de54 state=stale
[3] 버튼 누른 뒤 active=8e03cec7de54 state=active a2a_executor=True
[4] 복구        active=ea58fc7efe63 state=active a2a_executor=False
```

누른 뒤 화면은 "반영됨 — 실행 중인 조립이 8e03cec7de54 로 바뀌었습니다" 를
띄우고, 상태 문구가 "실행 중인 조립 = 저장된 선언" 으로 바뀌며, **버튼이
사라진다**(더 이상 어긋나 있지 않으므로).

## 하지 않은 것
- **폴링(후보 1)** — 대상이 스스로 중앙을 들여다보게 하는 것. 여러 인스턴스의
  수렴·감시 주기·실패 표시가 따라붙는다. 트리거가 아직 아니다
- **여러 인스턴스** — 지금 계약은 프로세스 하나의 active 를 말한다. 같은
  대상을 여러 프로세스로 띄우면 각자의 active 를 따로 물어야 한다
- **분류기 교체** — reload 는 Controller 만 갈아 끼운다
