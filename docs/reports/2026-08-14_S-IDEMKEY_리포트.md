# S-IDEMKEY 구현 리포트

## 적용 내용

v5 §10-1 산식을 `app/core/idempotency.py`의 단일 함수로 고정했다.

```text
sha256(tenant_id + request_id + action_type + business_subject)
```

`billing.py`의 환불 제안은 더 이상 `task_id` 또는 run 식별자를 사용하지 않는다. Controller가 case 실행 문맥에 보존한 요청 ID와 case ID를 Team에도 전달하고, 직접 Team을 호출하는 경우에는 안정적인 case ID를 요청 ID fallback으로 사용한다. 해지 후 결제 환불의 `business_subject`는 `case_id`를 선택했다. 환불 제안이 다루는 업무 대상이 해당 고객의 특정 Case이고, 동일 Case를 다른 run에서 재실행해도 같은 환불 행위로 식별해야 하기 때문이다. 결제 식별자가 별도 계약 필드로 제공되지 않는 현재 모델에서 case ID가 감사·승인 흐름의 대상(action request의 `case_id`)과 일치한다.

`technical.py`는 ActionProposal을 생성하거나 action request를 기록하지 않는 read-only 진단 Team이다. 따라서 같은 task 기반 키 생성 구조는 없으며, 별도 기술 action 키를 추가하지 않았다. 이후 기술 지원 승인 action이 생기면 동일 Core 함수를 Controller 기록 경계에서 사용해야 한다.

## 서버 재계산

`app/application/controller.py::_event_for_result`에서 Team이 보낸 `proposal.idempotency_key`를 신뢰하지 않고, 서버가 `tenant_id`, 안정적인 `request_id`, `proposal.action_type`, `case_id`로 다시 계산한 키만 저장한다. API의 case 생성·승인 키도 같은 Core 함수를 사용한다.

DB의 기존 `UNIQUE(tenant_id, idempotency_key)` 제약을 활용하며, repository 삽입은 충돌 시 기존 action ID를 반환한다. 따라서 승인 후 새 run에서 같은 업무 행위가 다시 제안되어도 `action_requests` 행이 증가하지 않는다.

## 테스트

추가한 회귀 검증:

- 승인 후 Controller 재실행: `action_requests` 1행 유지
- Team이 임의 키를 제출해도 저장 키는 서버 재계산 값
- 다른 `case_id` 또는 `action_type`은 서로 다른 키
- SHA-256 결과 길이 64로 계약 범위 8~128 충족
- Core import isolation 유지

집중 실행 원문:

```text
python -m pytest tests\unit\teams\test_team_scenarios.py tests\integration\controller\test_controller_integration.py -q
18 passed, 1 warning
```

요청한 전체 실행 원문 요약:

```text
python -m pytest tests -q
129 passed, 3 failed, 1 deselected, 2 warnings
```

실패한 3건은 변경 코드가 아니라 `tests/integration/rag/test_rag_integration.py`의 OpenAI Embeddings 실 네트워크 호출이 현재 실행 환경에서 `WinError 10013`으로 차단된 건이다. 이 요청의 “실제 LLM·네트워크 호출 금지” 조건에 따라 해당 외부 호출을 우회하거나 테스트 단언을 약화하지 않았다.

RAG를 제외한 재실행 최종 원문은 다음과 같다.

```text
128 passed, 1 deselected, 1 warning
```

중간 재실행에서 `test_local_executor_is_identical_to_direct_team_call`의 timestamp 비교가 비결정적으로 1회 실패했지만 재실행에서는 통과했다. 전체 0 failed 조건은 이 환경의 외부 네트워크 차단 때문에 충족되지 않았다.
