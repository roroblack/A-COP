## 3. 실패한 테스트와 원인

가장 중요한 실패는 DoD-05 테스트다. 입력을 과다하게 넣었을 때 실제 `omissions`의 첫 항목은 `similar_cases:*`가 아니라 `policy_rag:low_score:low#c1`이었다. 현재 `ContextBroker.build()`가 policy/history를 similar_cases보다 먼저 처리하므로, 요구한 v5 §9-1의 “similar_cases 먼저” 관측 조건을 만족하지 않는다. 테스트 단언은 약화하지 않았다.

DB 의존 테스트 3종은 PostgreSQL 미기동으로 실행되지 않았다. `127.0.0.1:5433` 연결이 거부되어 fixture의 DB 연결 단계에서 대기하다 timeout 되었다. 전체 테스트도 동일한 이유로 중단되었다.

DoD-07은 제품 코드의 생성 경로가 `created` 이벤트 payload에 요청 `message`를 원문으로 넣는 것을 확인했다. 따라서 DB redaction 단언은 DB가 기동되면 실패할 가능성이 높다. 제품 코드는 지시대로 수정하지 않았다.

## 4. 테스트하지 못한 항목과 이유

- DoD-04 checkpoint/projection: PostgreSQL 미기동으로 실제 run과 projection 조회 불가.
- DoD-07 PII redaction: PostgreSQL 미기동으로 런타임 실패를 확정하지 못했으나, 현재 생성 이벤트 경로상 원문 저장 결함이 예상됨.
- DoD-10 VOC: PostgreSQL 미기동으로 실제 Case 집계 불가.
- DoD-18 UI: PostgreSQL 미기동으로 fixture Case와 HTML 응답 확인 불가.

기존 테스트의 통과/실패 총계 및 기존 109건 대비 회귀 여부도 전체 실행 timeout으로 확정하지 못했다.
