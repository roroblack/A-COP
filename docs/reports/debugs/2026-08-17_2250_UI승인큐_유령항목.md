# 결함 — 승인 처리 자체가 승인 대기 큐에 유령 항목을 남긴다

## 1. 위치

- `app/presentation/api/cases.py:183-184` (수정 전)
- 영향받는 조회: `app/presentation/ui/routes.py:70-72` (`_actions()`)

## 2. 재현

```powershell
python -m pytest tests/integration/api/test_approval_audit_row_excluded_from_queue.py -q
```

(수정 전 코드에서는 `test_approval_audit_row_does_not_appear_as_a_new_pending_item` 이
"승인 감사 기록이 대기 큐에 유령 항목으로 남았다" 로 실패한다.)

실 브라우저로도 재현했다: `/ui/approvals` 에서 대기 중이던 `refund.request`
제안을 승인 → 새로고침하면 "대기 중" 카운트가 그대로거나 늘고, 방금 승인한
항목이 아니라 **`action.approve` 타입의 새 항목**이 "근거 없어 잠김" 상태로
목록에 나타난다.

## 3. 원인

`POST /v1/cases/{case_id}/actions/{action_id}/approve` 는 사람의 결정을
감사 기록(audit trail)으로 남기려고 `action_requests` 테이블에
`action_type="action.approve"` 행을 하나 더 쓴다. 이때
`repository.create_action_request(...)` 를 `status` 인자 없이 호출해
기본값 `"proposed"` 로 저장됐다.

`/ui/approvals` 화면(`_actions()`)은 "무엇이 대기 중인가"를
`status IN ('proposed','pending_approval')` 으로 판단한다 — `action_type`
을 구분하지 않는다. 그 결과 "이미 결정이 끝난 기록"이 "새로 결정이
필요한 제안"과 똑같이 취급됐다.

이 유령 행에는 애초에 근거(evidence)가 없다(사람의 결정 자체를 감사
기록하는 행이지, Team 이 낸 제안이 아니므로). 그래서 화면에는 영구히
"근거 없어 잠김"으로 표시되고, 그 행을 다시 승인/거절해도 또 다른
`action.approve` 행이 같은 상태로 생겨 큐가 계속 는다.

## 4. 실측

- 실 데모 시나리오(`case_id=af8a48a3-db6b-5a72-bdd0-9a06e5376cdb`)에서
  승인 1회 → 유령 항목 1건 발생을 실측(수정 전).
  DB: `action_requests` 에 `action_type='action.approve', status='proposed'` 행 확인.
- 수정 후 동일 시나리오 재실행: 유령 항목 0건 (`대기 중 1`→기존 refund.request
  하나만, `근거 없어 잠김 0`).

## 5. 위험도

- **고객 답변·과금에는 직접 영향 없음** — 이 행 자체는 절대 다시
  승인/거절 대상으로 실행되지 않는다(어떤 코드도 `action_type="action.approve"`
  자체를 승인 API 로 다시 호출하지 않는다).
- **운영 신뢰도에는 영향 있다.** CLAUDE.md §0 이 요구하는 "승인 없이 실행하지
  않는다"의 반대편 — **운영자가 승인 큐를 못 믿게 만든다.** 승인할 때마다
  큐가 줄지 않고 늘어나면, 실제 신규 제안과 감사 기록 잔재를 구분할 수
  없어져 "이건 이미 처리한 거겠지" 하고 넘기는 습관이 생긴다. 그게 바로
  진짜 대기 항목을 놓치는 경로다.
- DoD-18(UI 시나리오 종단표시) 재검증 중 실 브라우저 클릭으로 발견.

## 6. 정정할 이전 보고 없음

이 결함은 이번 세션에서 처음 발견됐다. 이전에 "승인 UI 완료"로 보고한
상태표 행(`운영 UI` — 완료)은 화면이 뜨고 승인 자체가 동작하는지만
확인했을 뿐 반복 승인 후 큐 상태까지는 검사하지 않았다는 뜻이다.

## 7. 수정

`app/presentation/api/cases.py` 의 `create_action_request` 호출에
`status=request.decision` 을 명시해, 감사 기록 행이 처음부터 종결 상태
(`approved`/`rejected`)로 저장되게 했다. `action_status` enum 에 이미
두 값이 있어 스키마 변경은 필요 없었다.

회귀 테스트: `tests/integration/api/test_approval_audit_row_excluded_from_queue.py`
(승인·거절 각각 감사 행 status 확인 + 대기 큐 조회에서 배제 확인).
