## 4. 원인

### 결함 1 — 설정 단일 진입점 우회

`security.py` 가 `os.getenv("ACOP_TENANT_ID")` 등으로 설정을 읽는다.
**`.env` 는 `os.environ` 에 들어가지 않는다** — `app/core/settings.py` 의 pydantic-settings 가
`Settings` 객체로만 읽는다. 따라서 값이 항상 없고 `RuntimeError` 가 난다.

`RULE.md` §3.1 이 "설정은 `.env` + `app/core/settings.py` 로 일원화한다"고 정했는데
우회했고, **그 우회가 곧바로 전면 장애로 이어졌다.**

### 결함 2 — 오류 응답 자체가 500

`HTTPException` 의 dict `detail` 이 예외 핸들러에서 `status_code` 자리로 넘어간다.
**403/404/409/422 를 내려는 모든 경로가 500 이 된다.**

## 5. 왜 안 잡혔나 — 테스트가 정적 단언 3건뿐이다

| 파일 | 건수 | 내용 |
|---|---:|---|
| `tests/security/test_scope_contract.py` | 2 | guardrails scope 집합 비교, MCP tool 이름·메타데이터 비교 |
| `tests/integration/api/test_openapi_surface.py` | 1 | openapi path 집합 비교 |

**세 개 모두 HTTP 호출도 DB 접근도 하지 않는다.** 그래서 앱이 아예 안 도는데도 전부 초록이었다.

계약(`docs/handoff/_prompts/S-API.md` §2-7)이 요구한 것 중 **없는 것**:
unauthorized matrix 전수 · 동일 요청 10회→1행(DoD 11) · 남의 Case→404(DoD 14) ·
MCP write 미노출 **동작** 검증(DoD 13).

## 6. 위험도 — 매우 높음

DoD **11 · 13 · 14** 가 전부 미검증이다. 이건 v5 §12 의 신뢰 경계 그 자체이고,
v5 §18 리스크 레지스터에서 "MCP 권한 노출"을 **영향 매우 높음**으로 둔 항목이다.

★**route 가 5개 등록됐다는 사실이 endpoint 가 동작한다는 뜻이 아니다.**
구조 검사와 동작 검사를 같은 것으로 세지 않는다.

## 7. 배운 것

- **정적 단언은 "돌아간다"를 증명하지 않는다.** 계약에 "실제 HTTP 호출로"라고 못박아야 한다.
- **설정 우회는 사소해 보이지만 전면 장애가 된다.** 단일 진입점 규칙은 스타일이 아니다.
- Codex 산출물 3건 중 3건이 검수에서 걸렸다(S-RAG 범위, S-DB 건수, S-API 동작).
  **인수 전 독립 실행은 생략할 수 없다.**
