- 위험도: **매우 높음** — 정책 근거 검색은 이 프로젝트 차별화의 핵심이다

## 결함 1 — 질의 임베딩이 pgvector 리터럴 형식이 아니다

### 위치
`app/infrastructure/rag/retriever.py` — `search_policy()` 의 query embedding 바인딩

### 재현
```powershell
python -c "
import sys; sys.path.insert(0,'.')
from app.infrastructure.rag.retriever import search_policy
search_policy('demo','해지했는데 결제가 됐어요',['refund'])
"
```

### 실측 출력
```
psycopg.errors.InvalidTextRepresentation:
invalid input syntax for type vector: "(-0.00138282775878906,-0.021820068359375,...)"
DETAIL:  Vector contents must start with "[".
CONTEXT: unnamed portal parameter $1
```

질의 벡터를 **Python `tuple`** 로 넘겨서 psycopg 가 `(...)` 로 렌더링한다.
pgvector 는 `[...]` 를 요구한다. → **모든 검색 호출이 예외로 죽는다.**

### 영향
- `search_policy()` 가 **한 번도 성공한 적이 없다**
- Context Broker 가 정책 근거를 하나도 못 받는다 → 모든 ContextPack 이 `degraded`
- DoD 6 의 "top-k test", v5 §15-3 의 policy groundedness 측정이 **불가능**

## 결함 3 — 테스트가 데이터 없으면 조용히 skip 한다

적재가 0건인 상태에서 전체 테스트는 **`74 passed, 4 skipped`** 였다.
RAG 테스트 4건이 데이터 부재를 skip 으로 처리해 **실패를 감췄다.**

`CLAUDE.md` §3 — "조용한 스킵을 만들지 않는다. 세지 않으면 분모가 줄어
커버리지가 실제보다 좋아 보인다." 정확히 그 일이 일어났다.

데이터를 넣고 다시 돌리자 **3건이 실패**했다:
```
FAILED test_search_relevance[해지했는데 결제가 됐어요-doc_06]
FAILED test_search_relevance[Pro로 바꿨는데 기능이 안 보여요-doc_14]
FAILED test_tenant_isolation_and_scope_filter
3 failed, 75 passed
```

즉 **적재를 안 한 것이 곧 검색 결함을 가린 것**이다. 두 결함이 서로를 숨겼다.

## 정정 — 내가 직전 보고에서 말한 것

"RAG 적재가 돌고 있다"고 보고했는데, 실제로 완료된 것은 **코드 작성뿐**이었다.
적재 건수를 확인하기 전까지는 "적재됐다"고 쓰지 않았어야 한다.

## 대응

1. `retriever.py` 의 벡터 바인딩 수정 (`pgvector.psycopg.register_vector` 또는 `[...]` 문자열)
2. **테스트에서 skip 제거** — 데이터가 없으면 **실패**해야 한다
3. 검색 적합성·tenant 격리·scope 필터 테스트를 실제로 통과시키기
4. ★인수 기준에 **DB 건수 직접 조회**를 추가한다 (코드 존재 ≠ 적재 완료)

## 배운 것

- **"코드를 만들었다"와 "돌려서 데이터가 들어갔다"는 다른 사건이다.**
  지시서에 실행을 요구했어도 실행 여부를 **내가 DB 로 확인**해야 한다.
- **skip 은 통과가 아니다.** 테스트 요약의 `passed` 숫자만 보면 안 된다.
- 두 결함이 서로를 가리는 조합이 실제로 나온다. 하나를 고치면 다른 하나가 드러난다.
