- 상태: **미수정**. DoD-07 **미통과 확정**
- 위험도: **매우 높음** — 이 프로젝트가 스스로 정한 §0 안전 규칙 위반

## 1. 재현

```powershell
python -m pytest tests/security/test_pii_redaction_runtime.py -q
```

## 2. 실측 출력

```
E  assert '010-1234-5678' not in 'phone=010-1...classified"}'
E    '010-1234-5678' is contained here:
E      phone=010-1234-5678 card=4111 1111 1111 1111
E      api_key=sk-test-original-api-key payment=pay_original_987654
E      {"last_event": "classified"}
```

**네 가지가 전부 원문으로 저장된다:**

| 항목 | 저장된 값 |
|---|---|
| 전화번호 | `010-1234-5678` |
| 카드번호 | `4111 1111 1111 1111` |
| API key | `sk-test-original-api-key` |
| 결제 식별자 | `pay_original_987654` |

## 3. 무엇을 어긴 것인가

**v5 §9-3** — "원문 PII 는 저장 시 masking 하고, LLM 에는 masked text 만 전달한다.
audit log 에는 API key·결제 식별자 원문을 기록하지 않는다."

**설계 원칙 §1** — "PII 는 저장 시 masking, LLM 에는 masked 만."

★특히 **API key 원문과 결제 식별자 원문**은 v5 §12 가 audit 기록에서 **명시적으로 금지**한 항목이다.
그것이 Case 본문에 그대로 남는다.

## 4. 왜 지금까지 몰랐나

`app/presentation/security.py` 에 `masked` 함수가 **존재한다.** 그래서 DoD-07 실측 수집에서는
"masked 함수가 있다" 는 사실만 관측됐고, 나는 판정에서 이렇게 적었다:

> ★**함수가 있다는 것과 경로마다 실제로 적용된다는 것은 다르다.**
> 이 프로젝트에서 같은 종류의 착오를 이미 겪었다: route 가 등록됐다는 사실이
> endpoint 가 동작한다는 뜻이 아니었다.

**의심은 맞았고, 테스트가 그것을 확인했다.** DoD-07 을 "부분 통과"로 둔 판단이 옳았다 —
통과로 적었다면 거짓 보고가 됐다.

## 5. 고쳐야 할 것

1. **Case 생성 경로에서 메시지를 저장 전에 masking** 한다
   (`customer_cases.subject`/`state_json`, `case_events.payload_json` 모두)
2. **LLM 에 넘기는 텍스트도 masked** 여야 한다 (분류기·Team·평가 전부)
3. **API key·결제 식별자는 저장 자체를 하지 않는다** — 마스킹이 아니라 제거 또는 hash
4. 마스킹 규칙을 한 곳에 두고(전화·카드·이메일·키·결제 id 패턴), 테스트가 그 함수가 아니라
   **DB 에 실제로 남은 값**을 검사한다 (지금 테스트가 그렇게 하고 있다)

## 6. 이 테스트를 약화시키지 마라

고칠 때까지 이 항목은 미통과다.
