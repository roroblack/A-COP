# 결함 — S-RAG 코퍼스 300섹션이 사실상 보일러플레이트다

- 발견: 2026-08-12 16:00, Claude 검수(RULE.md §3.6-3)
- 상태: **미수정 → 재작업 지시함**. 산출물은 `legacy/S-RAG_v1_보일러플레이트/` 로 보존
- 산출자: Codex S-RAG 스트림 1차 (`docs/handoff/_prompts/S-RAG_corpus.md`)

## 1. 위치

`knowledge/documents/*.md` **25개 전부**.
대표 예: `knowledge/documents/06_refund_refund-after-cancel.md:11-57`

## 2. 무엇이 잘못됐나

계약(`docs/handoff/_prompts/S-RAG_corpus.md` §4)은 **"한 섹션 = 하나의 인용 가능한 근거"** 를 요구했다.
실제 산출물은 다음 구조다.

1. **25개 문서가 동일한 12개 섹션 제목 템플릿을 쓴다** —
   `적용 범위 / 정책 용어 / 적용 대상 / 처리 기준 시각 / 고객 확인 정보 / 정상 처리 기준 /
   예외 조건 / 담당 주체 / 승인 조건 / 기록 및 감사 / 고객 안내 / 판단 사례`
2. **각 섹션 본문은 "공통 보일러플레이트 + 그 문서의 주제 꼬리문장 2개"** 다.
   꼬리문장은 **한 문서 안에서 12개 섹션에 그대로 12번 반복**된다.
3. 그 결과 문서의 고유 정보는 사실상 **꼬리문장 2개**뿐이고, 나머지는 어느 문서에나 들어가도
   말이 되는 일반론이다.

## 3. 재현

```powershell
cd knowledge\documents
python -c "
import pathlib,re,itertools,statistics
from collections import Counter
docs={}
for p in sorted(pathlib.Path('.').glob('*.md')):
    parts=re.split(r'^## ',p.read_text(encoding='utf-8'),flags=re.M)[1:]
    docs[p.name]=[(s.split(chr(10))[0].strip(),' '.join(s.split(chr(10))[1:]).strip()) for s in parts]
for name,secs in list(docs.items())[:5]:
    tails=['.'.join([x.strip() for x in b.split('.') if x.strip()][-2:]) for _,b in secs]
    print(name, Counter(tails).most_common(1)[0][1], '/', len(secs))
def g(s,n=6): return {s[i:i+n] for i in range(max(0,len(s)-n+1))}
for title in ['적용 범위','정책 용어','적용 대상']:
    b=[dict(s).get(title,'') for s in docs.values()]
    sims=[len(g(x)&g(y))/len(g(x)|g(y)) for x,y in itertools.islice(itertools.combinations(b,2),60)]
    print(title, round(statistics.mean(sims),2))
"
```

## 4. 실측 (2026-08-12 16:00, 25문서 300섹션 전량)

| 측정 | 값 |
|---|---|
| 문서 수 | 25 (계약 충족) |
| 총 섹션 수 | 300 (계약 하한 충족) |
| scope 분포 | 계약 표와 **완전 일치** |
| manifest `section_count` 대 실측 | **불일치 0건** |
| ★문서 내 동일 꼬리문장 반복 | **평균 12.0 / 12 섹션** — 25문서 전부 |
| ★같은 제목 섹션의 문서 간 문자 6-gram Jaccard | **평균 0.44 ~ 0.50** (최대 0.55) |
| 정확 해시 기준 본문 중복 | 0% ← **이 지표는 이 결함을 못 잡는다** |

### ★내가 앞서 잘못 보고한 것의 정정

첫 검수에서 **"총 섹션 300 / 고유 본문 300 / 중복률 0.0%"** 라고 보고했다. **이 수치는 맞지만
결론이 틀렸다.** 정확 해시 비교는 "보일러플레이트 + 서로 다른 꼬리문장" 조합을 전부 고유로 센다.
근사 중복을 보려면 n-gram 유사도를 봐야 했다. **중복률 0% 는 이 코퍼스가 멀쩡하다는 근거가 아니다.**
(RULE.md §4.1-5)

## 5. 위험도 — **높음. RAG 주장 전체가 무의미해진다**

1. **검색이 변별력을 잃는다.** 300 청크의 절반가량이 같은 문장이면
   cosine top-k=8 은 질의와 무관하게 비슷한 점수를 준다. `06_가드레일_수치.md` §3 의
   top-k 검색이 정상 동작하는지 판정할 수 없다.
2. **groundedness 지표가 거짓으로 높아진다.** 어느 청크를 인용해도 "승인 없이 실행하지 않는다"
   같은 일반론이 들어 있어 근거처럼 보인다. v5 §15-3 의 policy groundedness 가
   실력이 아니라 보일러플레이트를 측정하게 된다.
3. **`no_rag` ablation 이 차이를 못 낸다.** RAG 를 꺼도 답이 비슷해지면
   v5 §15-6 ablation 이 "RAG 가 기여하지 않는다"는 **잘못된 결론**을 낸다.
4. **시나리오 근거가 얇다.** 계약이 요구한 구체 수치(예: 환불 요청 기한 일수)가
   `06_refund_refund-after-cancel.md` 에 **없다**. "정책의 기한·금액을 벗어난 요청"이라고만 쓰여 있다.

DoD 6(문서 25건·청크 300~400 적재)은 **건수로는 통과하지만 내용으로는 통과하지 않는다.**
건수만 세는 검증이 이 결함을 통과시켰다는 점 자체가 검증 설계의 구멍이다.
