## 4. ★Codex 산출물 검수 (RULE.md §3.6-3)

### 4-1. S-RAG 1차 — **인수 거부**

| 검사 | 결과 |
|---|---|
| ① 계약 위반 | 형식은 통과 (25문서/300섹션/scope 배분/manifest 정합 전부 일치) |
| ② **범위 삭감** | **해당** — 계약이 요구한 "구체적인 숫자·기한"이 사실상 없음 |
| ③ 잘못된 근거 | 해당 없음 |
| ④ 수치 불일치 | 해당 없음 |

★**핵심 결함**: 25문서가 같은 12개 섹션 제목 템플릿을 쓰고, 각 섹션이
"공통 보일러플레이트 + 문서별 꼬리문장 2개" 구조였다. 문서 내 동일 꼬리문장 **12/12 섹션 반복**,
문서 간 같은제목 섹션 6-gram Jaccard **0.44~0.50**.

→ 결함 리포트: `docs/reports/debugs/2026-08-12_1600_RAG코퍼스_섹션이_보일러플레이트로_채워짐.md`
→ 1차 산출물 보존: `legacy/S-RAG_v1_보일러플레이트/` (26파일)
→ 대응: `scripts/check_corpus.py` 신설 + 프롬프트 v2 로 개정 후 재발주

★**내가 처음 잘못 보고한 것**: 1차 검수에서 "고유 본문 300/300, 중복률 0.0%"라고 보고했다.
수치는 맞지만 **결론이 틀렸다** — 정확 해시 비교는 근사 중복을 못 잡는다.
n-gram 유사도로 다시 재서 결함을 확인했다.

### 4-2. S-DB 1차 — **부분 인수** (스키마 통과 / seed 거부)

**통과:**

- v5 §8 DDL 14개 테이블 정확 · UNIQUE 3종 전부 · 인덱스 3종 · extension 2종

## 5. 배운 것

- **건수 검증은 내용 검증이 아니다.** "25건 300섹션"을 만족시키는 가장 쉬운 길이 템플릿 채우기다.
- **검증되지 않는 요구는 지켜지지 않는다.** 프롬프트에 "구체적인 숫자를 넣어라"를 적었지만
  검증 명령에 넣지 않았다. v2 에서는 `check_corpus.py` 가 잰다.
- **정확 일치 중복 검사는 LLM 산출물에 거의 무력하다.**
