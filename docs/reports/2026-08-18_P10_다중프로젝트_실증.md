# P10 다중 프로젝트 실증 보고서

## 배경

지금까지 `final_project_ui`의 실연결 검증(P8)은 `final_project_sample` 하나만 대상으로
했다. 이 콘솔의 핵심 설계 목표는 "여러 프로젝트를 가리키는 하나의 콘솔"인데, 실제로
형제 프로젝트가 둘 이상 있는 상태에서 검증한 적이 없었다. `final_project_cs`가 이제
`config/project.yaml`을 가진 실제 프로젝트로 존재하므로 처음으로 실증했다.

## 발견한 것 — 서버 등록 경로 문제

`preview_start({name: "ui-console"})`로 `final_project_ui`의 launch 설정을 부르면
**엉뚱하게 `final_project_sample`의 `acop-ui`(실제 고객지원 플랫폼)가 떴다.**
원인: 이 세션의 기본 작업 디렉터리가 `final_project_sample`로 고정돼 있어, 이름 기반
launch 조회가 그 폴더의 `.claude/launch.json`만 본다. `final_project_ui/.claude/launch.json`은
다른 폴더라 이름으로 못 찾는다.

해결: `python -m console.web`을 백그라운드로 직접 띄우고, `preview_start`가 아니라
`navigate`로 실제 주소(`http://127.0.0.1:8060`)에 직접 붙였다. 탭 제목이
"프로젝트 · 개발 콘솔"로 뜨는 것으로 올바른 서버임을 확인했다.

## 검증

`http://127.0.0.1:8060/?root=<final_workspace>`:

- 훑은 폴더 8개 중 **프로젝트 2개**(`final_project_cs`, `final_project_sample`)만 정확히 판별
- 나머지 6개(`briefing`, `final_project_ui` 자기 자신, `personal`, `plan`, `research`, `team_branch`)는
  전부 "아님 — config/project.yaml 가 없다"로 근거와 함께 남음 (조용히 안 빠짐)

`final_project_cs`(도메인 전환 리팩터 중 — billing→order_shipping, technical→return_exchange)의
`/project` 화면:

- 500 없이 렌더링됨
- Team `order_shipping`·`return_exchange` 실제 반영
- 처음 보는 판정 코드(`DoD-EVAL-DATASETS` — "판정 없음")를 만나도 깨지지 않고 별도 칸으로 집계
- introspection·DB 환경변수를 안 줬으므로 "연결 안 함"을 정직하게 표시(0으로 안 채움)
- 평가 리포트 23개 중 6개만 표시하고 "17개는 화면에 없다"고 절삭 고지

## 결론

콘솔이 구조가 다른(구독형 vs 커머스형) 두 번째 실제 프로젝트에서도 코드 수정 없이
그대로 동작했다. 별도 코드 변경은 없었다 — 이번 작업은 검증과, 서버 등록 경로 결함
발견·회피뿐이다.

## 남은 것

- `preview_start`의 이름 기반 launch 조회가 세션 루트에 고정되는 문제는 `final_project_ui`
  자체의 결함이 아니라 harness 쪽 제약이다. 앞으로 `final_project_ui`를 열 때는 URL 직접
  지정 방식을 쓴다.
