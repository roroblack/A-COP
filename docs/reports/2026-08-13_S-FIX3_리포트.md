# S-FIX3 수정 리포트

## 결함 1 — PII 평문 저장

원인은 `masked()`가 실질적인 규칙을 적용하지 않았고, case 생성·전이·분류기 입력 경로가 원문을 직접 사용한 것이었다.

`app/presentation/security.py`에 전화번호, 카드번호, 이메일, API key, 결제 식별자 규칙을 단일화했다. API key(`sk-...`)와 결제 식별자(`pay_...`)는 `[REDACTED_*]`로 제거성 치환한다. `mask_json()`은 중첩 JSON에도 같은 규칙을 적용한다.

case subject/state와 case event payload는 DB 기록 전에 마스킹하고, REST/MCP 생성 경로 및 feedback classifier의 LLM 입력도 masked text만 전달하도록 수정했다.

검증: `tests/security/test_pii_redaction_runtime.py` 통과. DB와 audit payload에 원문 phone/card/API key/payment 식별자가 남지 않는 단언을 그대로 통과했다.

## 결함 2 — Context Broker omission 순서

원인은 `_fit_*` 함수 호출 순서가 `tool_facts → policy_rag → history → similar_cases`였고, 그 결과 policy omission이 similar omission보다 먼저 기록된 것이었다.

각 섹션의 내부 선택 규칙(최신 fact, 높은 similarity, 최신 history)을 유지한 채 section별 omission을 별도로 수집하고, 최종 기록만 guardrails의 전역 순서인 `similar_cases → history_detail → low_score_rag → duplicate_tool_facts`에 맞춰 병합했다. `system_instruction`과 `case_state`는 기존처럼 초과 시 `ContextBudgetError`를 발생시키며 제거하지 않는다.

검증: `tests/unit/core/test_context_budget.py` 통과. 실제 첫 omission은 `similar_cases:`이고 low-score policy omission도 유지된다.

## 결함 3 — 테스트가 잘못됨

구현의 급증 규칙은 변경하지 않았다:

```text
today >= max(5, 1.5 * avg7) AND today - avg7 >= 3
```

기존 테스트의 `today=5, avg7=1.0`은 `5 >= max(5, 1.5)` 및 `4 >= 3`을 모두 만족하므로 alert가 발생하는 것이 맞다. 따라서 테스트의 “경계에서 alert 없음” 데이터가 틀렸다.

테스트를 `today=4, avg7=1.0`이 되도록 수정했다. 이 값은 첫 조건 `4 >= 5`를 깨므로 alert가 없다.

검증: `tests/unit/voc/test_feedback_runtime.py` 통과.
