# Basement 관리자 화면 구현 리포트

## 1. 범위

`/ui/admin`에 읽기 전용 관리자 화면을 추가했다. 기존 서버 사이드 렌더링 방식을 유지했고, Team 활성/비활성이나 기타 쓰기 동작은 추가하지 않았다. 기존 `/ui/*` 네비게이션에 Admin 링크를 추가했다.

## 2. 화면 구성

### Agent Team Modules

`app.composition.build_registry()`를 요청 시 호출하고 `registry.manifests()`를 순회한다. 따라서 Registry에 등록된 Team이 추가되면 별도 화면 수정 없이 표시된다. 다음 manifest 필드를 표시한다.

`team_id`, `display_name`, `capabilities`, `accepted_case_types`, `allowed_tools`, `knowledge_scope`, `max_steps`, `active`, `supported_contract_versions`, `implementation_revision`

### Ports & Adapters

조립 경계와 동일한 구체 구현 객체를 만들고 `type(obj).__name__`으로 클래스명을 표시한다.

| Port/기능 | 표시 기준 |
|---|---|
| TeamExecutorPort | `LocalTeamExecutor` 런타임 타입 |
| MessageBrokerPort | `OutboxBrokerAdapter` 런타임 타입 |
| GraphStorePort | `SqlGraphAdapter` 런타임 타입 |
| Vector 검색 | retriever 모듈의 `search_policy` 함수명 |
| LLM | `OpenAITeamLLM` 런타임 타입, provider/model은 Settings 조회 |

LLM API 키는 원문을 출력하지 않고 설정값 존재 시 `sk-****`만 표시한다.

### Guardrails

`app.core.settings.get_guardrails().as_dict()`를 사용해 `config/guardrails.yaml`의 전체 구조를 화면에 렌더링한다. 토큰 예산 `12000`, reliability, RAG, VOC 급증식, security scopes, evaluation 설정이 설정 파일 값 그대로 표시된다.

### 시스템 현황

모든 조회는 현재 Settings의 `tenant_id`를 조건으로 한다.

- `knowledge_documents`: 문서 수
- `knowledge_chunks`: 문서와 JOIN하여 tenant별 청크 수
- `customer_cases`: 상태별 건수
- `outbox`: 상태별 건수(운영 중 `pending`, `dead_letter` 포함)

데이터가 없으면 빈 상태를 `없음` 또는 `0`으로 표시하며 더미 데이터를 만들지 않는다.

## 3. 정보 출처

| 정보 | 출처 | 방식 |
|---|---|---|
| Team manifest | `app.composition.build_registry()` → `TeamRegistry.manifests()` | 런타임 조회 |
| Port 구현 클래스 | composition에 사용되는 adapter 객체 | 런타임 타입 조회 |
| LLM provider/model/key 존재 여부 | `app.core.settings.get_settings()` | 런타임 Settings 조회, 키 마스킹 |
| Guardrails | `app.core.settings.get_guardrails()` | 설정 조회 |
| 운영 카운트 | PostgreSQL 기존 테이블 | tenant 조건부 read-only SQL |

## 4. 테스트

`tests/e2e/test_operations_ui.py`에 다음을 추가했다.

- `/ui/admin` 200 응답
- 기본 등록 Team `billing_subscription`, `technical_entitlement` 표시
- guardrails `token_budget=12000` 표시
- API 키 원문 미노출 및 `sk-****` 표시
- fake Team을 Registry에 추가했을 때 화면에 동적으로 표시

실제 LLM 및 네트워크 호출은 테스트에서 수행하지 않는다.

## 5. 출력 원문

검증 명령:

```text
python -m pytest tests/e2e/test_operations_ui.py -q
```

출력:

```text
.......                                                                  [100%]
7 passed, 1 warning in 8.41s
```

경고는 pytest cache 디렉터리 접근 권한 경고이며 테스트 실패가 아니다.

최종 검증에서 실제 Uvicorn 요청까지 수행했다. 전체 테스트 결과는 기존 RAG 통합 테스트가 외부 OpenAI Embeddings 호출을 시도해 네트워크 권한으로 실패했으며, 해당 변경과 무관하다.

```text
python -m pytest tests -q
127 passed, 3 failed, 1 deselected
admin=200
```

관리자 E2E는 `7 passed`이며, 실제 서버는 검증 직후 종료했다. 실패한 3건은 `tests/integration/rag/test_rag_integration.py`의 외부 `api.openai.com` 호출로 발생했다.

## 6. 노출하지 않기로 한 항목

- OpenAI/API 키 원문
- Case/customer 식별자 및 PII
- outbox payload와 오류 원문
- Team 실행 결과나 입력 내용
- 관리자 화면에서의 Team 활성/비활성 및 기타 쓰기 동작
