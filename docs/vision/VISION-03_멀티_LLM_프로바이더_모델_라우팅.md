# VISION-03. 멀티 LLM 프로바이더와 모델 라우팅 고도화

| 항목 | 내용 |
|---|---|
| 상태 | 보류 |
| MVP 포함 | 아니오 |
| 최종 갱신 | 2026-08-13 |

## 1. 무엇인가

여러 LLM 프로바이더와 모델을 Team·Case 유형·비용·지연·안전 요구에 따라 선택하고, 프로바이더 장애 시 failover하는 운영 계층이다.

## 2. 지금 하지 않는 이유

- MVP 평가에서는 model/provider를 고정해야 Baseline과 Proposed 비교가 성립한다.
- 모델을 섞으면 품질 차이와 프롬프트 차이의 원인을 분리하기 어렵고, 현재 평가 하네스의 통제 변수가 깨진다.
- 다만 Remote A2A Team이 늘면 Team별 프로바이더 선택과 장애 failover가 운영상 필수에 가까워진다.

## 3. 도입 트리거 (이 조건이 만족되면 재검토한다)

- 서로 다른 프로바이더를 요구하는 Remote Team이 2개 이상이거나 Remote Team이 3개 이상이면 검토한다.
- 단일 프로바이더 장애로 최근 7일 Case 실패율이 2%를 초과하거나 100건 중 3건 이상 실패하면 검토한다.
- 전체 LLM 비용이 월 1,000 USD를 초과하면 비용·품질 기반 라우팅을 검토한다. 이 금액은 도입 판단용 제안 기준이다.
- Team별 최적 모델 요구가 3개 Team의 평가에서 서로 다르게 판정되면 검토한다.

## 4. 도입 시 예상 비용

전제: 6인 팀이 AI 코딩 도구를 상시 사용한다. 아래는 인·일이 아니라 실소요 일수(wall-clock)다.
단축률은 이 저장소 실측(2026-08-12, 2시간 21분에 18,390줄·테스트 107건)에 근거한 추정이며 정밀한 값이 아니다.

| 구분 | 내용 | 실소요 | AI 단축 정도 |
|---|---|---:|---|
| 생성 | 프로바이더 포트·자격증명 분리, 모델별 라우팅 설정, failover와 비용·지연 계측 및 테스트 생성. 병목은 없다. | 1~1.5일 | 큼 |
| 검증·통합 | 모델·프로바이더별 평가를 재실행하고 품질·비용·지연, timeout·failover·unknown 경로를 비교. 병목은 모델별 평가 재실행 시간과 결과 판정이다. | 2~3일 | 작음 — 사람이 판단한다 |
| 대기 | 프로바이더 쿼터·계약·키 발급을 기다린다. 병목은 외부 프로바이더 일정이다. | 0.5~1일 | 없음 |
| **합계** | | **3.5~5.5일** | |

병목: 생성보다 모델별 평가 재실행 시간·비용과 failover 결과의 사람 판정이 지배적이다.

## 5. 선행 조건 (이게 먼저 있어야 도입 가능)

- 모델별로 결과를 분리 집계하는 평가 하네스
- prompt snapshot, model, provider, temperature, seed, dataset hash 기록
- 프로바이더별 timeout·재시도·실패·비용 지표
- failover 후에도 승인·unknown·escalate 규칙을 보존하는 계약 테스트

## 6. 폐기 조건 (이 조건이면 이 비전을 버린다)

- 6개월 동안 Remote Team이 1개 이하이고 단일 프로바이더 장애 Case 실패율이 1% 이하이면 멀티 프로바이더 라우팅을 폐기한다.
- 모델별 평가를 3회 수행해도 품질·비용·지연에서 5%p 또는 20% 이상 차이가 없으면 고도화 라우팅을 폐기한다.
- failover가 100건 테스트에서 원인 추적성을 보존하지 못하면 라우팅 자동화를 폐기하고 고정 프로바이더로 남긴다.
