# ESTIMATION_BASELINE — 견적 산정 기준 (실측)

> 이 문서는 `docs/vision/` 의 비용 산정과 앞으로의 모든 견적에 쓰는 **실측 기준선**이다.
> 감으로 인·일을 잡지 않기 위해 만들었다. 새 실측이 생기면 갱신한다.

최종 갱신: 2026-08-13

---

## 1. 왜 인·일을 쓰지 않는가

전통적인 인·일 추정은 **사람이 코드를 직접 치는 속도**를 전제한다.
이 팀은 AI 코딩 도구를 상시 사용하므로 그 전제가 성립하지 않는다.

실제로 처음 산정한 비전 항목 비용은 35~115인·일이었고, 실측 기준으로 재산정하니 2~10일이 되었다.
한 자리 수가 아니라 **비용의 성격 자체가 다르다.**

- 예전 비용 = 코드를 얼마나 짜느냐
- 지금 비용 = **무엇이 맞는지 판단하고 검증하는 데 얼마나 걸리느냐**

따라서 **인·일이 아니라 실소요 일수(wall-clock)** 로 적고, 생성·검증·대기를 나눠서 적는다.

## 3. 속도를 가르는 것은 코드량이 아니라 판단량

같은 1인 + AI인데 활동일당 생산량이 1,715 ~ 18,390 줄로 10배 넘게 갈린다.
그 차이는 **설계 판단이 끝나 있었느냐**다.

| 상황 | 활동일당 | 근거 |
|---|---:|---|
| 설계 확정 후 구현만 | 18,000줄 이상 | A-COP. v5 계획서가 완성돼 있었고 handoff 계약 6종을 먼저 깔고 시작했다 |
| 새로 쓰는 작업이 지배적 | 약 9,500줄 | MyKeyDict |
| 설계하면서 구현 | 약 3,500줄 | yok3x |
| 시행착오 반복 | 약 1,700줄 | jira_for_me |

**커밋당 줄 수가 더 정확한 신호다.** jira_for_me 는 커밋 105개에 24,019줄로 커밋당 229줄이다.
코드량이 적어서 느린 게 아니라 **고쳐 쓴 횟수가 많아서** 느렸다.

## 4. AI가 줄여주는 것과 줄여주지 못하는 것

| 구분 | AI 단축 정도 | 근거 |
|---|---|---|
| **생성** — 어댑터·스키마·마이그레이션·테스트·문서 | 큼 | 위 실측 |
| **검증·통합** — 결과가 맞는지 사람이 판정 | 작음 | 아래 3건 |
| **대기** — 외부 조직 연동, 프로바이더 쿼터·계약, 인프라 프로비저닝 | 없음 | 성격상 |

### 검증이 병목이라는 직접 증거 (같은 저장소)

1. **RAG 코퍼스가 5회차에 통과했다.** v1 보일러플레이트 / v2 중앙유사도 미달 /
   v3 **지표 우회**(무작위 토큰 주입) / v4 청크 평균 56자.
   만드는 것은 빨랐고 **걸러내는 데 시간이 들었다.**
2. **RAG 검색이 `::vector` 캐스트 누락으로 100% 실패하고 있었는데 한동안 발견되지 않았다.**
3. Controller 통합테스트에서 `resuming→completed` 결함이 뒤늦게 드러났다.

### 6명이라고 6배가 아니다

병렬 가능한 작업은 거의 나뉜다. 그러나 **생성량이 늘어난 만큼 검수 부하도 늘어난다.**
검수는 사람이 한다. `RULE.md` §3.6-2(두 Codex 스트림이 같은 디렉터리를 소유하지 않는다)가
이미 그 통합 비용을 다루고 있다.

또한 비전 항목 대부분은 **한 사람이 끝까지 봐야 하는 수직 기능**이다.
Graph Store 도입을 3명이 나눠서 하지 않는다.

## 5. 견적 낼 때 쓰는 형식

```markdown
| 구분 | 내용 | 실소요 | AI 단축 정도 |
|---|---|---:|---|
| 생성 | <구체적으로> | <0.5일 단위> | 큼 |
| 검증·통합 | <무엇을 어떻게 검증하는지> | <일> | 작음 — 사람이 판단한다 |
| 대기 | <외부 의존. 없으면 "없음"> | <일> | 없음 |
| **합계** | | **N~M일** | |

병목: <셋 중 무엇이 지배적인지 한 문장>
```

규칙 네 가지다.

1. **0.5일 단위로 쓴다.** 근거 없는 정밀도(3.5일 같은 소수점 둘째 자리)를 만들지 않는다.
2. **병목을 반드시 한 문장으로 쓴다.** 이게 이 표에서 제일 중요하다.
3. **선택지에 따라 비용이 갈리면 행을 나눈다.** 예: Graph Store 는 AGE 3~4일 / Neo4j 7~9일.
4. **설계 판단이 남아 있으면 상단값을 쓴다.** 남은 판단이 실소요를 지배한다.

- 활동일은 커밋 날짜 기준이라 커밋하지 않은 작업 시간은 잡히지 않는다. **실제 소요는 이보다 길 수 있다.**
