## 2. 무엇을 찾나 — 우선순위 순

### 2-1. ★진짜 버그 (최우선)
`console/*.py`를 **한 줄씩** 읽어라. 특히:
- 예외를 잡아서 잘못된 상태로 뭉개는 곳
- 경계 조건(빈 리스트, None, 빈 문자열, 0개 항목)에서 깨지거나 오해를 부르는 곳
- `console/web.py`의 HTML 생성에서 **escape 누락**(XSS) — 사용자가 준 값이
  escape 없이 HTML에 들어가는 경로가 있는지 전부 확인해라. 특히 `path` 쿼리
  파라미터, 대상이 준 config 값, DB에서 읽은 값
- 파일 경로를 다루는 곳에서 **경로 탈출**(`../`) 가능성
- `console/db.py`의 SQL에서 문자열 포매팅으로 값이 들어가는 곳(SQL injection).
  테이블명 등 식별자를 f-string으로 넣는 곳이 있는지 확인해라
- async/sync 혼용, 리소스 누수(파일·커넥션 안 닫힘)

### 2-2. 처음 보는 사람이 막힐 곳
- `README.md`대로 따라 하면 실제로 실행되는가? 빠진 단계가 있는가?
- 환경변수 이름이 코드와 문서에서 일치하는가? (`console/profiles.py`와 README 대조)
- 에러 메시지가 "무엇을 고쳐야 하는지" 말하는가, 아니면 원인만 말하는가?

### 2-3. 테스트가 거짓말하는 곳
- **항상 참인 단언**이 있는가? (`assert x or True`, 빈 리스트에 대한 `all()`,
  실행 안 되는 분기를 검사하는 척하는 것)
- 테스트가 실제로 실패할 수 있는지 의심스러운 것을 골라내라
- `tests/`가 검사한다고 주장하는 것과 실제 검사하는 것이 다른 곳

### 2-4. 인수인계 결격 사유
- 커밋되면 안 되는 파일이 저장소에 있는가?(비밀값, 개인 경로, 임시 산출물,
  캐시, 로그) — `.gitignore`로 걸러지는지도 확인
- 하드코딩된 절대 경로(`C:\Users\playdata2\...`)가 **소스 코드**에 있는가?
  (문서·프롬프트에 있는 건 괜찮다, `console/`과 `tests/`를 봐라)
- 특정 기계에서만 되는 가정(포트 고정, 로컬 DB 주소 하드코딩 등)
