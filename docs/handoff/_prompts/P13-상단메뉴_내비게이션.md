## 3. 만들 것

### 3-1. 상단 고정 메뉴 바

`console/web.py`의 `page()` 함수(지금은 `title`, `body`, `lede`만 받는다)를 확장해서
모든 화면 상단에 고정 메뉴 바를 그린다. 메뉴 항목:

```
프로젝트 목록     /
조립             /project?path={path}
Composer         /composer?path={path}
```

- `path`가 없을 때(`/` 화면 자체)는 "조립"·"Composer" 링크를 **비활성으로 표시**한다
  (href 없이 회색 텍스트, 또는 `path`가 있을 때만 클릭 가능) — 없는 프로젝트로 보내면 안 된다.
- 지금 보고 있는 항목은 `aria-current='page'` 속성을 달고 CSS로 강조한다
  (배경색 다르게 — 기존 `--accent` 계열 변수를 써라, 새 색을 만들지 마라).
- `/run`(실행 추적) 화면은 메뉴에 **넣지 않는다** — `run_id`가 있어야만 의미가 있는
  drill-down 화면이라 메뉴탭이 아니라 "조립" 화면의 실행 이력 표에서 링크로 들어간다
  (지금 방식 유지).

### 3-2. `page()` 시그니처 변경

```python
def page(title: str, body: str, *, lede: str = "", path: str = "", current: str = "") -> HTMLResponse:
```

- `path`: 지금 보고 있는 프로젝트 경로(없으면 빈 문자열 — 메뉴의 프로젝트별 링크가 비활성됨)
- `current`: 메뉴 중 강조할 href(`"/"`, `"/project"`, `"/composer"` 중 하나) — 라우트 핸들러가 넘긴다

### 3-3. 각 라우트 호출부 갱신

`/`, `/project`, `/composer`(GET·POST), `/run` 전부 `page()` 호출에 `path=`·`current=`를
추가해서 넘긴다. `/run`은 `current`를 안 넘겨도 된다(메뉴에 없으니 아무 것도 안 켜진다) —
단, `path`는 넘겨서 메뉴의 "조립"·"Composer" 링크가 그 프로젝트를 가리키게 한다.
