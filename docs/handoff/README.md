# docs/handoff — 계약 문서

여기 있는 것은 *"무슨 일이 있었나"*(reports)도 *"무엇을 할 것인가"*(plans)도 아니다.
**"무엇을 지킬 것인가"** 다. 여기를 어기면 다른 스트림의 작업이 깨진다.

- 파일명은 **연번** `NN_<제목>.md` — 시점이 아니라 순서로 읽는다.
- 갱신할 때 새 파일을 만들지 않는다. **같은 번호를 고치고** 문서 안 개정 이력에 남긴다.
- **계약을 코드보다 먼저 고친다** (`RULE.md` §3.5).

| 번호 | 문서 | 누가 지키나 |
|---|---|---|
| 01 | 계약 — Pydantic 모델 | 전 스트림 |
| 02 | DB 스키마 (DDL) | S-DB, Claude-Core |
| 03 | REST / MCP 인터페이스 | S-API, S-UI, S-EVAL |
| 04 | Team 모듈 계약 | S-TEAM, Claude-Core |
| 05 | 분업 규칙 — 스트림별 소유 디렉터리 | 전 스트림 |
| 06 | 가드레일 수치 (config/guardrails.yaml) | 전 스트림 |

`_prompts/` 에는 Codex 스트림에 그대로 넘기는 프롬프트 원문을 둔다.
프롬프트는 이 계약 문서를 **인용**하지, 내용을 복사하지 않는다 (복사하면 두 벌이 어긋난다).
