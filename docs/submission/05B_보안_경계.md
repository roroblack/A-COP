# 보안 경계

## 인증·권한

API key는 scope를 확인한다. scope 6종은 `case:read`, `case:write`, `subscription:read`, `technical:read`, `action:approve`, `mcp:read`다. REST는 5개 operation이고 MCP는 `get_my_cases`, `get_case_detail`, `open_support_case` 3개 read-only tool이다. 세 MCP tool 모두 `mcp:read`를 요구하며 write action이나 SQL tool은 없다.

남의 Case는 403이 아니라 404다. 403은 리소스가 존재하지만 권한이 없다는 사실을 노출할 수 있기 때문이다. tenant/customer 조건으로 조회 자체가 되지 않게 하여 존재 여부를 숨긴다.

## PII와 audit

저장 전 subject·event payload를 masking하고, LLM 입력에는 masked text만 전달하며, audit에는 API key와 결제 식별자 원문을 남기지 않는 것이 경계다. 이전 gap test에서 이 경계가 깨진 결함을 발견했으며, 수정 리포트에는 phone/card/API key/payment 식별자에 대한 runtime 검증 통과가 기록되어 있다. API key 회전·만료와 OAuth2/OIDC는 구현·검증 범위 밖이다.
