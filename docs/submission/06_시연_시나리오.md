# 시연 시나리오

## 시나리오 1 — 해지 후 추가 결제

Case 화면에서 `해지했는데 결제가 됐어요`를 생성하고 trace를 보여준다. 실제 관측 전이는 다음과 같다.

`classifying(1) → routing(2) → running(3) → waiting_approval(4) → resuming(5) → running(6) → resolved(7)`

`/ui/cases`에서 Case와 trace를 보여주고, 환불 action이 승인 대기 상태가 되면 `/ui/approvals`에서 rationale과 approve를 보여준다. 승인 뒤 `/ui/cases` trace에서 `resuming→running`을 확인하고 resolved를 보여준다.

## 시나리오 2 — Free/Pro 권한 불일치

`Pro로 바꿨는데 기능이 안 보여요`를 생성한다. 관측 전이는 `classifying(1) → routing(2) → running(3) → resolved(4)`다. `/ui/cases`에서 entitlement 근거와 종결 trace를 보여주며 승인은 발생하지 않는다.

## 시나리오 3 — 반복 VOC 급증

`/ui/voc`에서 tenant별 오늘·직전 7일 지표와 issue별 급증 alert를 보여준다. 급증 조건은 `today >= max(5, 1.5 * avg7) AND today - avg7 >= 3`이다. 실제 2026-08-12 실행 결과는 `reports=1`, `alerts=[]`였고, 임의의 급증 수치는 만들지 않는다.
