00 · Agent Test

판별 필터 — "이게 에이전트급인가?"

아래 모든 항목에 적용한 잣대. 셋 중 하나 이상을 충족해야 에이전트 기능이고, 아니면 규칙·배치·대시보드로 보낸다. "AI를 어디에 안 쓰는지도 설계했다"는 것 자체가 발표 차별화 포인트.

FILTER-1비정형 입력 해석

자연어, 사진, 영수증처럼 규칙으로 파싱할 수 없는 입력을 이해해야 하는가

FILTER-2규칙으로 못 적는 판단

예외·재량·맥락 판단이 필요해 if-else로 다 적을 수 없는가

FILTER-3상황별 도구 조합

여러 tool을 상황에 따라 골라 부르고 결과를 종합해야 하는가

01 · Adopted

채택 항목

ADOPTED

쿠폰 경제성 What-if + 기대효과 시뮬레이션

구조는 반으로 갈라 설계한다. 손익 계산(수수료율·원가·할인율 → 손익분기·재투자 비율)은 결정론적 계산 tool — LLM에게 산수를 시키지 않는다. 에이전트의 자리는 대화형 what-if 인터페이스: "이 상품에 3천 원 쿠폰 붙이면 남는 게 있어?" → config에서 원가·수수료 조회 → 계산 tool 호출 → 결과 해석("마진 12%, 플랫폼 쿠폰 중복 시 8%, 5천 원부터 역마진"). FILTER-3 충족.

1
입력 — 판매자: 온보딩 config에 원가 필드(선택 입력, 본인 조회 전용 명시) / 플랫폼: 수수료율·쿠폰 예산
2
계산 — 할인액별 손익분기, 재투자 비용 비율을 계산 엔진이 산출. 플랫폼 대시보드에는 "광고 동의 쿠폰 ○원 발행 시 수수료 수익 대비 재투자율 ○%" 형태로 표시
3
기대효과 시뮬레이션 — 판매량 증가를 예측하지 않고 가정 명시형으로: 슬라이더로 가정(+10%/+20%/+30%)을 움직이면 손익이 따라 움직임. 슬라이더 기본 프리셋(보수/중간/낙관)은 공개 데이터에서 추정한 참고 계수로 캘리브레이션 (아래 03 참고)
시스템 화면 고정 문구 (필수 표기):"본 수치는 가정 기반 예상치이며, 실제 결과를 보장하지 않습니다."참고 계수 출처(해외 리테일 데이터 기반, 국내 이커머스와 상이할 수 있음)도 함께 표기. 실데이터 연동 시 자사 거래 데이터로 계수 재추정 — 로드맵 한 줄로 명시.
ADOPTED

최저가 보상제 처리 에이전트

"타사가 더 싸다는 증빙을 가져오면 차액 보상" 프로그램의 접수·판정. 기존 부품의 재조합이라 새 인프라가 거의 없다: 증빙 사진 판독(영수증·캡처에서 상품명·가격·판매처·날짜 추출) = VLM 모듈(EXT-2)의 두 번째 고객 / 동일 상품 여부 판단(옵션·용량·구성 대조) + 보상 규정 대조(쿠폰가·중고·해외직구 제외 등) = L2 판정 파이프라인과 동일 구조 / 차액 지급 = 승인 기반 트랜잭션(HITL) / 반복 청구·조작 이미지 = 리스크 스코어링(M-4)의 어뷰징 감지. FILTER-1·2·3 모두 충족 — 프로모션 축에서 살아남은 유일한 에이전트 기능.

ADOPTED

미충족 수요 로깅 → 판매자 대시보드

포착은 에이전트, 집계는 배치. L0 상담 중 "혹시 ○○ 같은 건 없나요?" → 카탈로그 검색으로 실재 여부 확인 → 없으면 카테고리·원하는 속성·가격대 기대치를 구조화해 기록(FILTER-1, 추가 비용 ≈ 0). 유사 수요 묶기·건수 집계·대시보드 반영은 규칙 파이프라인.

연결 1: 판매자 모드 VOC 요약의 하위 항목("내 카테고리에서 최근 이런 상품을 찾는 문의 12건") — 새 기능 슬롯을 먹지 않음.

연결 2: 온보딩 시장 벤치마크에 "이 카테고리의 미충족 수요 시그널" 포함 — "뭘 팔지"까지 답하는 온보딩.

연결 3 (루프 완성): 해당 상품이 등록되면 문의했던 구매자에게 입고 알림(동의는 문의 시점에 수취) — 구매자의 말이 판매자의 입점을 부르고 다시 구매자에게 돌아오는 시연 마지막 장면 후보.

관계 주석: 팀원 기획안 트랙 C-②(미충족 수요 발견)와 신호 원천이 같음. 그쪽은 플랫폼 기획전 방향, 이쪽은 판매자 대시보드 방향 — 같은 파이프라인의 출구 2개로 상호 보강.

ADOPTED

맥락 승계 상담원 연결 (+ 시연 방법 확정)

에스컬레이션 시점에 케이스 요약(고객이 말한 것 / 시도된 조치 / 감정 상태 / 남은 쟁점 / 권장 조치)을 운영자에게 자동 브리핑. 고객이 같은 말을 두 번 하지 않게 하는 기능 — 대기업은 CRM·CTI 통합으로 일부 해결하지만 중소몰은 못 하는 영역을 LLM 요약 하나로 재현.

시연 방법: 별도 화면이 아니라 어차피 만들 HITL 운영자 승인 콘솔의 승인 대기 카드에 얹힌다. 발표는 2분할 화면 — 왼쪽 고객 챗, 오른쪽 운영자 콘솔. 에스컬레이션 순간 브리핑 카드가 실시간으로 뜨는 것을 보여주고, 옆에 "브리핑이 없었다면 읽어야 했을 원문 대화 30줄"을 대비로 노출. 멘트: "고객은 같은 말을 두 번 하지 않고, 운영자는 30초 만에 이어받습니다."

조건부 채택

CONDITIONAL

처리 상태 능동 알림 — 조건 걸어 채택

전면 알림(모든 상태 전이마다)은 역효과 검토됨: ① 알림 피로 ② 내부 단계 노출이 2차 문의 유발("승인 대기가 왜 이틀?") ③ 처리 지연의 실시간 노출은 운영 압박. 판단 이력으로 보존.

채택 형태: 고객에게 의미 있는 마디에서만 발송 — 접수됨 / 환불 확정 / 입금 완료 / 지연 발생 시 1회. 알림 수준은 고객이 설정 가능. 이것은 에이전트가 아니라 이벤트 트리거 배치임을 명시(판별 필터의 실례).

프로모션 운영 자동화 → 대시보드 항목으로 강등
