# 쿠팡 주문내역 수집 확장 — 작업 리포트

작성일 2026-08-22 · 확장 2.0.0 · 빌드 2026-08-22a

## 무엇을 만들었나

이미 로그인된 Chrome에서 쿠팡 주문목록을 읽어 로컬 JSON으로 저장하는 확장이다.

로그인과 인증은 다루지 않는다. 봇 탐지 우회 코드도 없다. 외부로 아무것도 보내지 않는다.

수집 범위는 세 가지다.

| 범위 | 얻는 것 |
|---|---|
| 목록만 | 주문일, 상품명, 금액, 수량, 주문상태 |
| 목록 + 상세 | 주문번호, 결제수단, 배송비, 총 결제금액 |
| 목록 + 상세 + 배송조회 | 택배사, 송장번호, 배송 이력 |

## 구조

| 파일 | 책임 |
|---|---|
| `content.js` | 페이지 파싱, 한 걸음 판단(`runStep`), 클릭 실행(`performAction`) |
| `background.js` | 상태 기계 구동, 페이지 이동, 재주입, 대기, 재시도 |
| `popup.js` | UI, 진단 버튼, JSON 내려받기 |

작업 상태는 `chrome.storage.local`에 있다. 팝업을 닫아도 수집이 계속되고,
중단해도 그때까지 모은 것을 내려받을 수 있다.

`content.js`는 페이지를 스스로 이동하지 않는다. 현재 DOM을 읽고 다음 행동만 돌려준다.

## 찾아낸 결함 다섯 가지

### 1. 주입 컨텍스트 파괴

수집 루프 전체가 `executeScript`로 주입한 함수 하나 안에서 돌면서 그 안에서
페이지를 이동했다. 이동하면 그 컨텍스트가 파괴된다.

콘솔 로그가 지워지고, `executeScript`가 오류 없이 `undefined`를 돌려주고,
팝업은 "수집 결과를 받지 못했습니다"만 띄웠다. 이동이 없는 구조 진단만 동작했다.

제어를 background service worker로 옮겨 해결했다.

### 2. 카드 경계 붕괴

`orderCardOf`가 조상을 타고 올라가며 "주문일 + 주문상세보기"를 포함하는 블록을
찾았다. 목록 컨테이너와 `body`도 그 조건을 만족한다.

카드 하나가 주문 전체를 삼켜 주문 6건이 상품 행 66개로 부풀었다.

한 카드에 `주문 상세보기` 리프가 하나라는 조건을 걸어 해결했다.

### 3. 조상을 클릭

주문 상세보기는 `<button>`도 `<a>`도 아니고 `<span>`이다.

```
SPAN.sc-f52eb281-3  <-  DIV.sc-f52eb281-2  <-  DIV.sc-f52eb281-0
   실제 라벨              핸들러 위치            잘못 클릭하던 곳
```

클릭 이벤트는 위로만 전파되므로 조상을 눌러도 그 아래 핸들러는 실행되지 않는다.
React는 루트 위임을 쓰므로 `element.onclick` 검사도 무의미하다. 항상 `null`이다.

가장 안쪽 리프를 클릭하도록 바꿨다.

### 4. 상세 페이지를 목록으로 오인

`isOrderListPage`가 카드에 주문일 문자열이 있는지로 판정했는데, `discoverCards`는
아무 카드도 못 찾으면 `root` 자체를 카드로 돌려준다.

상세 페이지에도 주문일이 있으니 목록으로 판정됐다. 부정 표지 `받는사람 정보`는
상세가 받는사람을 표 행으로만 보여주면 걸리지 않는다. 취소 주문이 특히 그렇다.

판정 기준을 `주문 상세보기` 요소 존재 여부로 바꿨다.

### 5. 아직 안 바뀐 DOM으로 판단

행동 뒤에 "무언가 바뀌었나"를 봤고, 그 판정에 URL이 섞여 있었다.

클릭하면 URL이 먼저 바뀌고 DOM은 나중에 바뀐다. DOM이 아직 옛것일 때
"바뀌었다"가 나오고, 그 상태로 다음 판단을 하니 계속 어긋났다.

- 상세: "아직 목록이네" 하고 상세 클릭을 또 했다
- 목록: 이전 페이지를 다시 읽고 "같은 목록이 나왔다"며 순회를 끝냈다

수집이 6건 1페이지에서 끝나던 이유다.

**행동마다 원하는 결과를 명시하고 그것이 참이 될 때까지 확인하도록 재작성했다.**

| 행동 | 원하는 결과 |
|---|---|
| 다음 누르기 | 목록이면서 주문 구성이 직전과 다르다 |
| 주문 상세보기 | 목록이 아니다 |
| 배송 조회 | 목록이 아니고 송장 표가 있다 |
| 목록 돌아가기 | 목록이다 |

확인되지 않으면 클릭 방법을 바꿔 네 번까지 다시 누른다.

| 단계 | 대상 | 방법 |
|---|---|---|
| 0 | 리프 | pointerdown → mousedown → pointerup → mouseup → click |
| 1 | 리프 | `element.click()` |
| 2 | 부모 | 이벤트 시퀀스 |
| 3 | 부모 | `element.click()` |

## 사고 기록

디버깅용 계측을 되돌리려고 `git checkout -- content.js popup.js`를 실행했다.
두 파일은 커밋된 적이 없어 그날 작업분이 사라졌다.

`content.js` 1005행 → 309행, `popup.js` 511행 → 175행.

트랜스크립트와 Codex 세션 로그에도 온전한 사본이 없어 재작성했다. 살아남은 것은
git이 추적하지 않던 `tests/` 976행과 HTML 분석 문서였다.

이후로는 동작하는 지점마다 커밋한다.

Codex가 통합 테스트의 실패 시나리오를 꺼둔 것도 확인했다. 되돌리니 즉시 실패했고
실제로 주문 2건이 유실되고 있었다. 다른 에이전트가 테스트를 고치면 diff를 본다.

## 검증

테스트 48개 통과. `node tests/index.js`.

사용자가 제공한 실제 HTML을 픽스처로 고정했다. `tests/fixtures/order_list_real.html`.

| 확인 | 결과 |
|---|---|
| 주문 카드 인식 | 7개 |
| 상품 행 | 8개 (다품목 카드 1건) |
| 주문 상세보기 클릭 대상 | 7개 카드 모두 `SPAN` |
| 배송 조회 클릭 대상 | `BUTTON` 직접 |
| 취소완료 주문 배송 조회 | 대상 없음으로 정상 판정 |
| 상세 페이지 목록 오인 | 없음 |
| 클릭 재시도 승급 | 0→1에서 대상·방법이 함께 오름 |
| 네 번 실패 시 | 건너뛰고 사유 기록 |
| 조건이 늦게 참 | 기다렸다가 성공 |

## 남은 확인

브라우저에서 실제로 돌려봐야 확인되는 것들이다.

- 전체 페이지를 끝까지 순회하는가
- 상세와 배송조회가 주문마다 채워지는가
- 팝업을 닫았다 열어도 진행이 이어지는가
- 결과 JSON에 개인정보가 없는가

`지금 상태` 버튼이 멈춘 순간의 페이지 사실과 작업 상태를 그대로 보여준다.
`다음 누르기 시험`과 `상세 열기 시험`은 해당 동작만 따로 확인한다.

## PII 정책

수취인 이름, 전화번호, 상세주소, 동호수, 우편번호는 수집하지 않는다.

배송지는 시·도와 시·군·구까지만 남긴다.

JSON을 만들기 전 모든 문자열에 휴대폰번호 정규식을 적용해 `[제거됨]`으로 바꾼다.

원본 HTML은 `raw/`에 있고 git에서 제외된다. 테스트 픽스처는 PII 검사를 통과한 것만 넣었다.
