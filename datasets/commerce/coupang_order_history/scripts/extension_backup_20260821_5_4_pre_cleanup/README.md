# 쿠팡 주문내역 추출 확장 프로그램

사용자가 제공한 주문목록, 주문상세, 배송조회 HTML을 기준으로 파서를 작성했다.

이미 로그인된 Chrome의 쿠팡 주문목록을 읽어 로컬 JSON 파일로 저장한다.

로그인 정보는 다루지 않는다.

외부 서버로 수집 결과를 전송하지 않는다.

## 동작 범위

확장은 사용자가 열어 둔 주문목록과 선택한 범위의 쿠팡 상세 페이지를 읽는다.

로그인과 인증을 자동화하지 않는다.

브라우저 식별 정보를 변경하지 않는다.

## 설치 방법

1. Chrome 주소창에 `chrome://extensions`를 입력한다.
2. 오른쪽 위의 **개발자 모드**를 켠다.
3. 왼쪽 위의 **압축해제된 확장 프로그램을 로드**를 누른다.
4. 파일 선택 창에서 이 `scripts/extension/` 폴더를 선택한다.
5. 확장 프로그램 목록에 **쿠팡 주문내역 추출**이 표시되는지 확인한다.
6. Chrome 도구 모음의 퍼즐 아이콘을 누른다.
7. **쿠팡 주문내역 추출**을 고정하면 이후에 쉽게 실행할 수 있다.

파일을 수정한 뒤에는 `chrome://extensions`에서 확장의 새로고침 버튼을 눌러야 한다.

## 사용 방법

1. 평소 사용하는 Chrome에서 쿠팡에 로그인한다.
2. `https://mc.coupang.com/ssr/desktop/order/list`로 이동한다.
3. 도구 모음에서 확장 아이콘을 누른다.
4. 수집 범위를 선택한다.
5. 최소 대기 시간과 최대 대기 시간을 확인한다.
6. **수집 시작**을 누른다.
7. 팝업을 닫아도 백그라운드에서 수집이 이어진다.
8. 현재 단계와 남은 건수를 확인한다.
9. 완료되면 **주문 JSON 내려받기**를 누른다.
10. 배송 이력이 있으면 **배송 JSON 내려받기**를 누른다.
11. 저장된 주문 파일을 `datasets/commerce/coupang_order_history/raw/`에 넣는다.

수집 범위는 다음 세 가지다.

- `목록만`: 기존 목록 필드만 빠르게 수집한다.
- `목록 + 상세`: 실제 주문번호, 주문일, 결제정보를 추가한다.
- `목록 + 상세 + 배송조회`: 택배사, 송장번호, 배송 이력을 추가한다.

수집 결과가 0건이면 **구조 진단**을 누른다.

진단 결과에는 각 안정 앵커의 매칭 수가 표시된다.

## 구조

수집 제어는 background service worker(`background.js`)가 갖는다.

수집은 두 단계로 분리된다.

1. 목록의 정확한 `__NEXT_DATA__.props.pageProps` 주문 도메인과 페이지네이션을 따라 모든
   목록 페이지를 먼저 읽고 체크포인트로 저장한다.
2. 목록 수집이 끝난 뒤 로그인된 수집 탭을 정상 문서로 이동해
   `주문상세 → 배송조회 → 다음 주문상세` 순서로 읽는다. 주문마다 목록으로 돌아가지 않는다.

상세·배송 HTML을 `fetch`로 요청하거나 비활성 보조 탭에서 대신 파싱하지 않는다. 쿠팡이
문서 탐색이 아닌 상세·배송 요청을 `HTTP 406`으로 거부했고, 보조 탭은 사라진 탭·이전 DOM
경합을 만들어 한 건 뒤 정체되는 원인이 됐다.

| 구성요소 | 책임 |
|---|---|
| `background.js` | 작업 체크포인트, 문서 이동 발행, 탭 로드·알람 재개, 중단/재시작 세대 관리 |
| `content.js` | 정확한 `__NEXT_DATA__`, 상세·배송 문서 검증과 파싱, 다음 상태 결정 |
| `popup.js` | UI와 내려받기만 담당 |

작업 상태는 `chrome.storage.local`의 `coupangJob`에 있다.

서비스 워커 하나만 수집 구동자로 사용한다. 영구 `while` 루프나 20초 keepalive로 워커를
붙잡지 않고 한 묶음의 상태 전이만 수행한 뒤 반환한다.

서비스 워커가 유휴 상태로 종료돼도 탭 로드와 주기 알람이 저장된 작업을 다시 깨운다.

팝업은 UI와 내려받기만 담당하므로 닫아도 수집이 이어진다.

중단해도 그때까지 모은 것을 내려받을 수 있다.

목록은 DOM 해시가 아니라 JSON 주문 키와 서버 페이지 좌표로 중복을 판정한다.

`다음 버튼으로 끝까지` 모드는 다음 URL에 `requestYear`를 강제로 붙이지 않는다.

각 문서는 목표 URL, 주문번호, 배송박스 번호와 필수 화면 표지를 확인한 뒤에만 성공으로
처리한다. 로드 실패는 항목별 세 번으로 제한하고 다음 항목으로 넘어가므로 한 건이 전체
페이지 수집을 막지 않는다.

## 선택자

styled-components 클래스는 빌드마다 바뀔 수 있다.

이 확장은 클래스 선택자를 사용하지 않는다.

| 항목 | 선택자 또는 추출 방법 |
|---|---|
| 주문 카드 | 상품명 링크를 포함하는 가장 가까운 `td`, `tr`, 블록 조상 순서 |
| 상품명 링크 | `a[href*="_product_title"]` |
| 상품명 | 상품명 링크 안의 마지막 `span` 텍스트 |
| 상품명 대체값 | 상품 이미지 링크의 `img[alt]` 중 뱃지 형식이 아닌 값 |
| 상품 이미지 링크 | `a[href*="MyCoupang_my_orders_list_product_image"]` |
| 상품 URL | 상품명 링크의 `href`를 `https://www.coupang.com` 기준으로 절대화 |
| 상품 식별자 | 상품 URL의 `vendorItemId` 쿼리 값 |
| 금액 | `span[translate="yes"]` 텍스트의 숫자 |
| 수량 | 금액 요소 뒤의 `span` 중 `N개` 형식 |
| 주문상태 | `span[style*="font-size:1.25rem"]` |
| 배송예정 안내 | `span[color="#008C00"]` |
| 다음 페이지 | 공백과 제로폭 문자를 제거한 버튼 텍스트에 `다음`이 포함되고 `이전`은 없는 버튼 |

상품명 링크에 `span`이 없으면 상품 이미지의 `alt`를 사용한다.

영문 대문자와 숫자와 밑줄만 있는 `alt`는 뱃지로 보고 제외한다.

## 상세와 배송조회

주문번호와 주문일은 우선 주문목록의 `__NEXT_DATA__`에서 얻는다.

상세 파싱에 성공하면 대체 `OrderId`를 실제 주문번호로 바꾸고 `_idSource`를 `orderNumber`로 바꾼다.

결제수단, 총 상품가격, 할인금액, 배송비, 총 결제금액은 수집 탭이 정상 문서로 연
`/ssr/desktop/order/{orderId}` HTML에서 얻는다. 한 주문에 배송박스가 여러 개여도 상세는
주문당 한 번만 파싱한다. 카드와 쿠팡캐시가 섞인 복합 결제는 `PaymentMethods`에도 나눠 담는다.

택배사와 송장번호는 목록 JSON에서 우선 얻고, 배송 이력은 `orderId`, `shipmentBoxId`,
`invoiceNumber`, 같은 배송박스의 모든 `vendorItemIds`로 만든 `/ssr/desktop/shiptrack` 문서를
정상 탐색해 얻는다. 송장번호가 아직 비어 있어도 배송박스 번호가 있으면 조회하며, 배송
JSON은 `(orderId, shipmentBoxId)`로 구분한다.

주문 파일은 `coupang_order_history_YYYYMMDD_HHMMSS.json`으로 저장한다.

시각은 내려받은 때가 아니라 수집을 시작한 때다.

같은 결과를 다시 받아도 이름이 같다.

주문 파일에는 택배사와 송장번호만 남긴다.

배송 이벤트는 `coupang_tracking_YYYYMMDD_HHMMSS.json`에 별도 배열로 저장한다.

각 배송 이벤트는 `kind`, `where`, `timeString`, `raw`를 포함한다.

진행 막대는 다섯 단계를 항상 다 그린다. 도달한 단계만 `DeliverySteps`에 담는다.

`DeliveryStep`은 현재 단계다. `DeliveryStepsAll`은 막대에 그려진 전체 단계다.

`오늘 HH:mm`과 `어제 HH:mm`은 수집 시각의 로컬 날짜를 기준으로 ISO 시각으로 바꾼다.

알 수 없는 시각 표기는 원문을 유지하고 `Warnings`에 기록한다.

로켓배송이 아닌 주문도 쿠팡 배송조회 표가 있으면 같은 방식으로 파싱한다.

표가 없으면 외부 택배사 API를 호출하지 않고 경고와 빈 이벤트 목록을 남긴다.

## Scrapling 검토

Scrapling은 Python·Playwright 계층이어서 MV3 확장 안에 직접 넣지 않는다. 별도 프로세스로
실행하면 현재 Chrome 로그인 세션을 다시 넘겨야 하므로 이 작업의 로그인 차단 문제도 되살아난다.

대신 적응형 수집기의 설계 원칙을 적용했다. 목록과 보강 단계를 분리하고, 항목별 안정 키와
체크포인트를 저장하며, 정확한 문서 표지가 없으면 제한 재시도 뒤 다음 항목으로 진행한다.
`capture_xhr`에 해당하는 네트워크 응답 가로채기는 수령지 같은 실제 XHR 진단에는 쓸 수 있지만,
핵심 상세·배송 데이터는 최상위 SSR 문서이므로 기본 수집 경로에는 넣지 않는다.

## PII 정책

다음 정보는 수집하지 않는다.

- 수취인 이름
- 전화번호
- 상세주소
- 동과 호수
- 우편번호

배송지는 받는주소 행에서 시·도와 시·군·구까지만 `DeliveryRegion`으로 잘라낸다.

우편번호와 나머지 주소는 저장하지 않는다.

결과 JSON 생성 전 모든 문자열에 일반 번호와 마스킹 번호를 잡는 휴대폰번호 정규식을 적용한다.

발견된 휴대폰번호는 `[제거됨]`으로 바꾼다.

## 주의

기본 대기는 0.3초에서 1.1초다.

여섯 번에 한 번쯤 1.1초에서 2초 사이로 더 쉰다.

간격이 일정하면 사람으로 보이지 않는다.

클릭이 한 번에 안 먹혀 다시 누를 때도 같은 대기를 넣는다.

연달아 누르지 않는다.

최소 대기 시간은 0.3초보다 작게 설정할 수 없다.

대기 시간을 지나치게 줄이지 않는다.

한 번에 과도하게 많은 주문 페이지를 조회하지 않는다.

수집기는 최대 200페이지에서 중단한다.

쿠팡 페이지 구조가 바뀌면 `SELECTORS`를 다시 확인한다.

이 확장은 로그인과 인증을 수행하지 않는다.

이 확장은 브라우저 식별 정보를 변경하지 않는다.
