### 사고: 커밋 안 된 파일 유실

디버깅용 계측을 되돌리려고 `git checkout -- content.js popup.js`를 실행했다.

두 파일은 커밋된 적이 없었다. 그날 작업분 전체가 사라졌다.

- `content.js` 1005행 → 309행(옛 커밋 상태)
- `popup.js` 511행 → 175행

트랜스크립트와 Codex 세션 로그에서 복구를 시도했으나 온전한 사본이 없었다.

살아남은 것은 `tests/`(git 미추적이라 `checkout` 영향을 받지 않음)와 `.tmp/`의 HTML 분석 문서였다.

**교훈: 커밋 안 된 작업물에 `git checkout`을 쓰지 않는다. 되돌리기 전에 사본을 만든다.**

### 재작성

테스트 976행이 유실된 구현의 행위 명세 역할을 했다. 이를 기준으로 다시 만들었다.

동시에 구조도 바꿨다. 아래 근본 원인 때문에 어차피 필요한 변경이었다.

### 근본 원인 1: 주입 컨텍스트 파괴

수집 루프 전체가 `chrome.scripting.executeScript`로 주입한 함수 하나 안에서 돌았다.

그 루프 안에서 페이지를 이동했다(상세 링크 클릭, `history.back()`, `location.href` 대입).

페이지가 이동하면 주입 컨텍스트가 파괴된다. 그래서:

- 콘솔 로그가 통째로 지워졌다
- `executeScript`가 오류 없이 `result: undefined`로 resolve 했다
- 팝업은 "수집 결과를 받지 못했습니다"만 띄웠다
- 이동이 없는 구조 진단만 정상 동작했다

해결: 제어를 background service worker로 옮겼다. `content.js`는 현재 DOM을 읽고
다음 액션만 즉시 반환한다. 이동은 background가 시킨다.

### 근본 원인 2: 카드 경계 붕괴

`orderCardOf`가 조상을 타고 올라가며 "주문일 + 주문상세보기"를 포함하는 블록을 찾았다.

목록 컨테이너와 `body`도 그 조건을 만족한다. 그래서 카드 하나가 주문 전체를 삼켰다.

증상: 주문 6건인데 상품 행 66개(카드당 11행), 구조 진단 `orderCards: 15`.

해결: 한 카드에는 `주문 상세보기` 리프가 정확히 하나라는 조건을 걸었다.
다른 카드를 통째로 포함하는 후보도 제외한다.

검증: 실측 HTML에서 카드 7개, 상품 행 8개(다품목 1건). `tests/real-page.test.js`.

### 근본 원인 3: 조상을 클릭

주문 상세보기는 `<button>`도 `<a>`도 아니고 `<span>`이다.

```
SPAN.sc-f52eb281-3  <-  DIV.sc-f52eb281-2  <-  DIV.sc-f52eb281-0  <-  카드
   실제 라벨              핸들러 위치            잘못 클릭하던 곳
```

`actionIn`이 카드의 직계 자식까지 올라가서 헤더를 클릭했다.

클릭 이벤트는 위로만 전파되므로 그 아래 핸들러는 실행되지 않는다.

React는 루트 위임을 쓰므로 `element.onclick` 검사도 소용없다. 항상 `null`이다.

해결: 가장 안쪽 리프를 클릭한다. 안 먹히면 조상을 한 칸씩 올려가며 재시도한다.

이 함수는 재작성 과정에서 새로 생긴 것이다. 유실 전 코드에는 없던 버그다.
