- `content.js` 1005행 → 309행(옛 커밋 상태)
- `popup.js` 511행 → 175행

트랜스크립트와 Codex 세션 로그에서 복구를 시도했으나 온전한 사본이 없었다.

살아남은 것은 `tests/`(git 미추적이라 `checkout` 영향을 받지 않음)와 `.tmp/`의 HTML 분석 문서였다.

**교훈: 커밋 안 된 작업물에 `git checkout`을 쓰지 않는다. 되돌리기 전에 사본을 만든다.**

### 재작성

테스트 976행이 유실된 구현의 행위 명세 역할을 했다. 이를 기준으로 다시 만들었다.

동시에 구조도 바꿨다. 아래 근본 원인 때문에 어차피 필요한 변경이었다.

### 근본 원인 1: 주입 컨텍스트 파괴

수집 루프 전체가 `chrome.scripting.executeScript`로 주입한 함수 하나 안에서 돌았다.

그 루프 안에서 페이지를 이동했다(상세 링크 클릭, `history.back()`, `location.href` 대입).

페이지가 이동하면 주입 컨텍스트가 파괴된다. 그래서:

- 콘솔 로그가 통째로 지워졌다
- `executeScript`가 오류 없이 `result: undefined`로 resolve 했다
- 팝업은 "수집 결과를 받지 못했습니다"만 띄웠다
- 이동이 없는 구조 진단만 정상 동작했다

해결: 제어를 background service worker로 옮겼다. `content.js`는 현재 DOM을 읽고
다음 액션만 즉시 반환한다. 이동은 background가 시킨다.

### 근본 원인 2: 카드 경계 붕괴

`orderCardOf`가 조상을 타고 올라가며 "주문일 + 주문상세보기"를 포함하는 블록을 찾았다.

목록 컨테이너와 `body`도 그 조건을 만족한다. 그래서 카드 하나가 주문 전체를 삼켰다.

증상: 주문 6건인데 상품 행 66개(카드당 11행), 구조 진단 `orderCards: 15`.

해결: 한 카드에는 `주문 상세보기` 리프가 정확히 하나라는 조건을 걸었다.
다른 카드를 통째로 포함하는 후보도 제외한다.

검증: 실측 HTML에서 카드 7개, 상품 행 8개(다품목 1건). `tests/real-page.test.js`.

### 근본 원인 3: 조상을 클릭

주문 상세보기는 `<button>`도 `<a>`도 아니고 `<span>`이다.

```
SPAN.sc-f52eb281-3  <-  DIV.sc-f52eb281-2  <-  DIV.sc-f52eb281-0  <-  카드
   실제 라벨              핸들러 위치            잘못 클릭하던 곳
```

`actionIn`이 카드의 직계 자식까지 올라가서 헤더를 클릭했다.

클릭 이벤트는 위로만 전파되므로 그 아래 핸들러는 실행되지 않는다.

React는 루트 위임을 쓰므로 `element.onclick` 검사도 소용없다. 항상 `null`이다.

해결: 가장 안쪽 리프를 클릭한다. 안 먹히면 조상을 한 칸씩 올려가며 재시도한다.

이 함수는 재작성 과정에서 새로 생긴 것이다. 유실 전 코드에는 없던 버그다.

### 근본 원인 4: 아직 안 바뀐 DOM으로 판단

`waitForPageChange`는 `pageSignature`(URL + 주문 내용 해시)가 달라지면 성공으로 봤다.

상세보기를 누르면 URL이 먼저 바뀌고 DOM은 나중에 바뀐다. 그 틈에 `runStep`이 돌면
아직 목록 DOM이므로 "상세로 못 갔네" 하고 **상세 클릭을 또** 한다. 무한 반복이다.

페이지네이션도 같다. `다음`을 누르면 URL이 먼저 바뀌고, 그 사이에 목록 내용을 읽으니
이전 페이지와 같다. 그래서 "같은 주문 목록이 다시 나왔다"고 판단하고 그 연도를 마쳤다.

실제 수집 결과가 6건 1페이지에서 끝나고 모든 연도에 같은 경고가 붙은 이유다.

해결: `wait` 액션을 만들었다. 아직 안 바뀌었으면 최대 6번까지 기다린다.
그래도 안 바뀌면 그때 다시 누르거나(상세) 마지막 페이지로 본다(목록).

### 연도 탭은 필요 없다

사용자 확인: `다음`만 계속 눌러도 2021년 주문까지 나온다. 목록은 연도로 나뉘어 있지 않다.

연도 탭은 필터일 뿐이다. 기본값을 `다음 버튼으로 끝까지`로 바꿨다. 연도 탭은 건드리지 않는다.

### callCollector 반환값 이중 언랩

`callCollector`는 이미 `results[0].result`를 반환하는데 `executeAction`이 다시
`outcome?.[0]?.result`를 했다. 클릭 실패 사유가 항상 undefined였다.

### 근본 원인 5: args에 undefined를 넣어 매번 예외

이것이 처음부터의 진짜 원인이다. 앞의 진단들은 대부분 이 결함의 그림자였다.

```
Error at property 'args': Error at index 1: Value is unserializable.
```

`callCollector(tabId, method, argument)`는 인자가 없으면 `args: [method, undefined]`를
보냈다. Chrome은 `undefined`를 직렬화하지 못하고 호출 자체를 거절한다.

`pageFacts`와 `pageSignature`는 인자가 없다. 그래서 **페이지 상태를 읽는 호출이
한 번도 성공한 적이 없다.** 페이지 변화 확인이 전부 실패했고, 그 위에서 내린
모든 판단이 어긋났다.

팝업 버튼들은 `args: [method, 배열]`로 항상 정의된 값을 넘겨서 정상 동작했다.
수집만 실패하고 시험 버튼은 되던 이유가 이것이다. 두 경로의 차이는 서비스 워커가
아니라 인자 모양이었다.

해결: `undefined`는 `null`로 바꿔 보내고 저쪽에서 인자 없이 호출한다.
중첩된 `undefined`도 깨뜨리므로 JSON 왕복으로 한 번 거른다.

테스트가 이걸 못 잡은 이유는 가짜 `chrome`이 아무 값이나 받아줬기 때문이다.
이제 진짜처럼 `undefined`를 거절한다.

### 근본 원인 6: document.textContent 는 null 이다

상세 페이지에 들어간 뒤 진행이 멈추던 원인이다.

`compact(root)`와 `text(root)`에 `root`로 `document`를 넘겼다. Document 노드의
`textContent`는 `null`이다. 그래서 페이지 전체 텍스트 검사가 전부 빈 문자열을 봤다.

`isOrderListPage`의 부정 표지 `주문목록 돌아가기`와 `받는사람 정보`가 한 번도
걸린 적이 없다. 상세 페이지가 계속 목록으로 판정됐다.

`지금 상태`가 `표지 돌아가기=false`로 찍어준 것이 이것이다. 버튼은 화면에 있었다.

여기에 더해 상세 페이지의 `주문 상세` 제목이 `/^주문상세(보기)?$/`에 걸려
상세보기 버튼으로 잡혔다. 그래서 긍정 표지까지 참이 됐다.

해결: Document를 만나면 `body`로 내려가서 읽는다. 리프 판정은 `주문상세보기`로만
한다.

테스트가 못 잡은 이유는 `parseFragment`가 요소를 돌려주기 때문이다. 요소는
`textContent`가 정상이다. 이제 Document로 감싼 테스트를 함께 돌린다.

사용자가 `raw/find.md`에 상세 페이지 HTML을 이미 적어 두었다. 그걸 픽스처로
만들었다. 받는사람 이름과 우편번호는 대체했다.

### 근본 원인 7: body.textContent 에는 script 안의 문자열도 들어온다

앞의 수정으로 Document를 body로 내려 읽게 하자 이번엔 반대가 됐다.
목록 페이지에서 표지가 전부 참이 되어 목록을 상세로 봤다.

쿠팡 SSR 페이지는 `<script>`에 JSON 데이터를 심는다. `body.textContent`는 그
문자열까지 포함한다. 거기에 `주문목록 돌아가기`, `받는사람 정보`, `결제 정보`,
`주문번호`, `송장번호`, `배송 조회`가 전부 들어 있다.

페이지 통짜 텍스트로 표지를 찾는 방식 자체가 틀렸다.

해결: 요소 단위로 찾는다. `script`, `style`, `noscript`, `template`는 건너뛴다.

- 버튼·제목처럼 라벨만 있는 것은 요소의 텍스트가 정확히 일치하는지 본다
- `주문번호 16102427880443`처럼 라벨과 값이 한 요소에 붙은 것은 리프에서 찾는다

픽스처에 `<script>`가 없어서 테스트가 못 잡았다. 이제 script를 넣은 경우를 함께 돌린다.
