# 주문상세 클릭 구현 계획

## 실측 구조 (raw/find.md)

```html
<div class="sc-2dee486c-0">              <!-- 주문 카드 -->
  <div class="sc-f52eb281-0">            <!-- 헤더 -->
    <div class="sc-f52eb281-1">2026. 8. 21 주문</div>
    <div class="sc-f52eb281-2">          <!-- 클릭 핸들러가 붙는 곳으로 추정 -->
      <span class="sc-f52eb281-3">주문 상세보기</span>
      <svg>...</svg>
    </div>
  </div>
  ...상품 표...
</div>
```

배송 조회는 `<button>배송 조회</button>`이다. 주문 상세보기는 `<button>`도 `<a>`도 아니다.

## 진단

`actionIn`은 리프에서 조상으로 올라가며 `BUTTON`/`A`/`onclick`을 찾고, 못 찾으면
**카드의 직계 자식**을 반환한다. 그래서 `sc-f52eb281-0`(헤더)을 클릭한다.

React 핸들러는 `sc-f52eb281-2` 또는 `span`에 붙는다. 클릭 이벤트는 위로만 전파되므로
헤더를 눌러도 그 아래 핸들러는 실행되지 않는다.

`onclick` 속성 검사도 소용없다. React는 DOM 속성이 아니라 루트 위임으로 처리하므로
`element.onclick`은 항상 `null`이다.

## 체크리스트

- [x] 1. 클릭 대상을 리프로 바꾼다. 리프를 누르면 조상 핸들러까지 모두 전파된다.
- [x] 2. 리프가 안 먹히면 조상을 한 칸씩 올려가며 재시도한다(카드까지, 최대 4단계).
- [ ] 3. 재시도 단계는 `action.attempt`로 전달한다. background의 정체 횟수를 그대로 쓴다.
- [ ] 4. 클릭은 `pointerdown → mousedown → mouseup → click` 순서로 보낸다.
      일부 컴포넌트는 `click`만으로는 반응하지 않는다.
- [ ] 5. `executeAction`이 예외를 던져도 정체 횟수를 올린다. 지금은 예외 시 무한 반복이다.
- [ ] 6. 실측 HTML로 검증한다. 카드 7개 각각에서 클릭 대상이 `span.sc-f52eb281-3`이어야 한다.
- [ ] 7. 배송 조회는 `<button>`이므로 리프 클릭이 곧 버튼 클릭인지 확인한다.
