# 제어부 재작성 계획

## 남길 것과 버릴 것

파서는 실측 HTML로 검증됐다. 그대로 둔다.

- `parseDocument`, `parseProduct`, `parseDetailPage`, `parseTrackingPage`
- `discoverCards`, `orderCardOf`, `actionCandidates`, `isOrderListPage`
- `buildExportPayloads`, `sanitizeValue`

제어부는 패치가 쌓여 서로 얽혔다. 다시 짠다.

- `runStep`의 `wait` 단계, `stalls`, `forceSkip`, `seenKeys`, `restore`
- background의 `waitForPageChange`, `executeAction`

## 지금 구조가 틀린 이유

행동 뒤에 **"무언가 바뀌었나"** 를 봤다. 서명은 URL과 내용을 섞은 값이다.

클릭하면 URL이 먼저 바뀌고 DOM은 나중에 바뀐다. 그래서 "바뀌었다"는 판정이
DOM이 아직 옛것일 때 나온다. 그 상태로 다음 판단을 하니 계속 어긋났다.

기다림을 덧대서 막으려 했지만, 기다림 횟수라는 상태가 또 늘어 얽혔다.

## 새 원칙

**행동한 뒤에는 원하는 결과가 실제로 나올 때까지 확인한다.**

"무언가 바뀌었나"가 아니라 "내가 원한 상태가 됐나"를 본다.

| 행동 | 원하는 결과 |
|---|---|
| 다음 누르기 | 목록이면서 주문 구성이 직전 페이지와 다르다 |
| 주문 상세보기 | 목록이 아니다 |
| 배송 조회 | 목록이 아니고 송장 표가 있다 |
| 목록 돌아가기 | 목록이면서 주문 구성이 떠나기 전과 같다 |

확인되지 않으면 **클릭 방법을 바꿔 다시** 한다. 기다리기만 하지 않는다.

## 클릭 재시도 순서

한 가지 방법이 안 먹히는 페이지가 있다. 순서대로 올린다.

| 단계 | 대상 | 방법 |
|---|---|---|
| 0 | 리프 | pointerdown → mousedown → pointerup → mouseup → click |
| 1 | 리프 | `element.click()` |
| 2 | 부모 | 이벤트 시퀀스 |
| 3 | 부모 | `element.click()` |

네 단계가 다 실패하면 그 주문을 건너뛰고 사유를 남긴다.

## 체크리스트

- [x] 1. `content.js`에 `pageFacts()`를 만든다. 목록 여부, 주문 구성 키, 송장 표 유무를 한 번에 준다.
- [x] 2. `performAction(action)`이 `attempt`로 대상과 방법을 함께 올린다.
- [x] 3. background에 `awaitCondition(tabId, check, timeout)`을 만든다. 조건이 참이 될 때까지 폴링한다.
- [x] 4. `executeAction`을 조건 기반으로 바꾼다. 실패하면 `attempt`를 올려 최대 4회 재시도한다.
- [x] 5. `runStep`에서 `wait`, `stalls`, `forceSkip`, `seenKeys`를 걷어낸다.
- [x] 6. 모든 분기에서 작업 상태를 저장한다. 지금은 성공 분기에서 저장하지 않아 카운터가 안 줄어든다.
- [x] 7. 마지막 행동 결과를 항상 저장해 `지금 상태`에서 보이게 한다.
- [x] 8. 실측 HTML 회귀 테스트를 유지하고, 조건 기반 재시도 테스트를 추가한다.

## 검증

`node tests/index.js` 전부 통과.

새로 추가할 테스트

- 클릭 0단계가 안 먹히면 1단계로 올라가는가
- 네 단계가 다 실패하면 건너뛰고 다음 주문으로 가는가
- 조건이 늦게 참이 되면 기다렸다가 성공으로 보는가
- 성공하면 재시도 단계가 0으로 돌아가는가
