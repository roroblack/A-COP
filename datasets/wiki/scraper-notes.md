# 스크래퍼 관측 기록

`[실측]` `datasets/commerce/coupang_order_history/docs/` 2건에서 이관. **원본은 그대로 있다.**

**바깥 화면을 관측한 기록이다.** 우리가 만든 게 아니라 상대가 바꾸면 낡는다.

## ★ PII — 수집하지 않는다

받는사람 정보 표에 다음이 있다. **마스킹돼 있어도 수집하지 않는다.**

```
받는사람 : 최*우
연락처   : 010****7059
받는주소 : (06725) 서울특별시 서초구 남부순환로339길 ** ***호
```

### 주소가 필요하면 시·구만

```regex
(서울특별시|...)\s+([가-힣]+(시|군|구))
```

**앞부분만 취하고 나머지는 버린다.**

**우편번호·번지·동호수는 저장하지 않는다.**

`[실측]` **그런데 자유입력이 새는 자리가 하나 더 있었다.** 쿠팡 `DeliveryRequest`의 `기타사항 (…)` — 공동현관 비밀번호는 쿠팡이 가려 주지만 이 칸은 안 가린다. 팀 제출본 합본에서 **집 열쇠 위치가 51건** 발견돼 `build_team_merged.py`가 가린다(`_masked`에 이름을 남긴다). → [distribution.md](distribution.md)

`[실측]` **마스킹된 값도 안 받는 게 규칙이다.** `010****7059`도 다른 데이터와 붙이면 좁혀진다. → [`auth-boundary.md`](../../final_project_cs/wiki/external/auth-boundary.md)의 join key 분리

## 폐기된 DOM 방식의 관측 — 목록은 이제 DOM을 안 읽는다

`[실측]` 확장 5.4.1(2026-08-21)부터 **목록은 `__NEXT_DATA__` JSON, 상세·배송은 같은 탭의 문서 이동**으로 읽는다. 주문 카드 selector · `다음` 버튼 클릭 · 연도 탭 순회는 전부 **삭제된 레거시**다. 왜 버렸는지는 [coupang-extension.md](coupang-extension.md). 아래는 JSON 경로가 막혔을 때 되살릴 관측이라 남긴다.

| 관측 (2026-08-21 이전) | 지금 |
|---|---|
| 취소완료 주문은 상품 링크에 `href`가 없어 selector가 통째로 놓쳤다 | 목록이 JSON이라 해당 없음 |
| 마지막 페이지에서 `disabled` 다음 버튼을 눌러 10초 timeout | `orderPagination`의 `hasNext`로 판정 |
| 연도 필터 기본값이 최근 6개월이라 3건만 나왔다 → 2021~2026 탭 순회 | 탭 클릭은 화면만 바꾸고 `__NEXT_DATA__`는 그대로다. URL `requestYear`로 직접 연다. 사용자 확인으로 **`다음`만 눌러도 2021년까지 나온다** — 연도는 필터일 뿐 |
| 클래스명은 해시라 배포마다 바뀐다 → `img[alt]`(접근성 속성이라 안정)·`span[translate="yes"]`·인라인 `font-size`로 잡았다 | 목록엔 안 쓴다. **상세 결제 표·배송조회 표 파싱엔 실측 HTML(`docs/실제HTML_주문상세_배송조회.md`)이 여전히 근거다** |
| 목록 카드엔 주문번호·주문일시·판매자·배송비·총액·택배사·송장·배송지가 없다 | 주문번호·주문일·택배사·송장은 목록 JSON에, 결제·배송비·요청사항은 상세 문서에 |

`[실측]` `docs/README.md`의 "확장의 선택자는 전부 이 자료에서 나왔다"는 **주문카드·페이지네이션 두 자료에 대해선 낡았다** — REPORT가 "과거 `docs/`의 클릭 관련 문서는 폐기된 방식의 원인 분석 기록"이라 적었다.

## 배송 화면 세 형태

| 형태 | 상태 | 송장번호 | 이력표 |
|---|---|---|---|
| A | 상품준비중 | **빈 문자열** | 없음 |
| B | 배송중 | 있음 | 있음 |
| C | 배송완료 | 있음 | 있음 + 도착안내 |

### 결론 — 이력표 부재는 오류가 아니다

**배송 전에 이력이 없는 건 정상이다.** 아직 발송 전이라 데이터 자체가 없다.

`[실측]` **이걸 오류로 처리하면 정상 주문을 수집 실패로 센다.**

### 축을 둘로 나눈다

```
발송 여부      ×    배송 완료 여부
```

**하나의 상태값으로 뭉치지 않는다.**

## 상대 시각 주의

`오늘` · `어제` 같은 표기가 나온다.

```
수집 시점 기준 절대시각으로 변환
+ 원문도 함께 보존
```

**원문을 남기는 게 중요하다.** 변환이 틀렸을 때 되돌릴 수 있다.

## 주문 상세에는 택배사·송장번호가 없다

**목록과 상세의 `sourceType` 이 다르다.** 상세만 보면 배송 정보를 못 얻는다.

## 배송요청사항

**주문별로 값이 다르다.** 고정값으로 가정하지 않는다.

## ★ [2026-09-04] 배송이력 5건 중 4건만 수집 — 원인 확인됨

`[실측]` `preprocess_stats.json` 이 이미 계산해 둔 값이었다. 열어보지 않아서 "미확인"으로 남아 있었다.

```
unique_order_ids: 8
tracking_rows:    4
excluded.cancelled_tracking_boxes:        3   (취소 주문 — 배송 자체가 없다)
excluded.tracking_number_missing_boxes:   1   (송장번호 미기재)
```

**8건 중 취소 3건은 배송조회 대상이 아니다.** 남은 5건 중 1건은 송장번호가 없어 배송 이력을 못 얻었다. **5건 중 4건 수집**은 이 1건 때문이다 — 스크래퍼 결함이 아니라 원본 화면에 송장번호가 비어 있는 경우([위 배송 화면 A형](#배송-화면-세-형태): 상품준비중은 송장번호가 원래 빈 문자열)다.

**결론 — 추가 조치 불필요.** 데이터 결손이 아니라 정상 동작이다.

## 네이버 주문 4건 누락 — 사용자: 수정됨, REPORT만 낡음

`[실측]` 2026-09-06 사용자가 "저번에 수정했다"고 정리해 닫는다. 아래는 `datasets/commerce/naver_order_history/REPORT.md` §"알려진 문제"가 아직 적고 있는 옛 상태다 — REPORT 재생성 때 같이 본다. **cyw 계정 실제 72건 중 68건만 수집.** 나머지 3명 제출본(101·44·57건)도 각자 실제 주문 수와 대조되지 않아 270건 전체가 "전량"인지 확인 안 됨.

**원인 후보 — 링크 없는 주문을 화면에서 식별하는 방법이 안 정해졌다.** 로그인 상태의 실제 DOM이 있어야 진행 가능 — 코드만으로는 못 고친다.

## ★ [2026-09-06] 택배 조회 도구 — 이것도 바깥 화면 관측이다

`[실측]` [courier_tracking/README.md](../commerce/courier_tracking/README.md)에서. 쿠팡 확장과 같은 성격이다 — **네이버 택배조회 내부 API를 쓰므로 상대가 바꾸면 낡는다.**

| 무엇 | 어떻게 |
|---|---|
| 인증 | 로그인 없음. 네이버 검색 페이지 HTML에서 `passportKey`를 얻어 재사용 |
| 호출 | **`fetch`를 쓰지 않는다.** 같은 페이지에 JSONP `<script>` 태그를 주입한다 |
| 키 갱신 | `timeout`·`script_error`·`key_expired`가 **연속 3회**면 다음 조회 전에 키를 다시 받는다 |
| 간격 | 조회마다 **0.8~2.0초** 사이에서 새로 뽑는다(`--delay-min`·`--delay-max`, **최소 0.5초**) — `scripts/track.py`. `[정정 2026-09-10]` 「2.0~5.0초, 최소 1.0초」로 적혀 있었다 |
| 택배사 | `courier_codes.json`. 이름은 공백·문장부호·대소문자를 지운 뒤 비교 |

### 오류 여섯 가지 — `no_history`는 오류가 아닐 수 있다

| 값 | 뜻 |
|---|---|
| `no_history` | 응답은 `Y`인데 이력이 없음 — **보관기간 만료 가능성.** 위 "이력표 부재는 오류가 아니다"와 같은 축 |
| `not_found` | 응답이 `N` |
| `unsupported_courier` | 코드 목록에 택배사가 없음 |
| `timeout` | JSONP 응답이 12초 안에 안 옴 |
| `script_error` | 스크립트 로드 또는 응답 파싱 실패 |
| `key_expired` | `passportKey` 만료·무효 |

**뒤 셋은 재시도 대상이고 앞 셋은 아니다.** 통계에서 "이력 없음"을 실패로 세면 보관기간이 지난 옛 주문이 전부 실패로 잡힌다.

### 저장하지 않는 것

배송 이벤트는 `kind`·`where`·`timeString`·`time`·`level`만 남긴다. **전화번호·기사 이름·사진, 발송인·수취인 이름·주소는 저장하지 않는다.** 상품명(`itemName`)은 `item_name`으로 남긴다.

결과는 `raw/tracking_YYYY-MM-DD.jsonl`에 한 줄씩 즉시 붙이고, `--resume`이 당일 파일의 송장번호를 건너뛴다. 테스트는 네트워크·Playwright 없이 돈다.
