# 소스를 왜 이걸로 골랐나

`[실측]` 2026-08-20. 원본 셋을 합쳤다.

```
_codex_independent_research_2026-08-20.md    독립 조사
_완결성점검_codex_2026-08-20.md               빠진 게 없나
PLAN.md                                      선택 근거
```

**`REPORT.md` 는 "무엇을 찾았나"만 적고 "왜 이걸 골랐나"가 없었다.** 그 자리를 메운다.

## 결론 — 더 찾을 게 아니라 정리할 때다

> **대규모 공개 원문 학습데이터 확보라는 기준에서는 현재 목록이 실질적으로 충분하다.**

**다만 "완결"을 한정해서 말한다.**

| 축 | 근거 |
|---|---|
| **양** | 쇼핑 리뷰 **45만 건 이상**, 민원·상담 QA/라벨링 **수백만 건** |
| 과업 커버리지 | 리뷰 감성 · 속성/BIO · 의도·개체명 · 상담 QA · 소비자 피해·분쟁 · FAQ |
| 도메인 다양성 | 쇼핑 리뷰 + 홈쇼핑/e-commerce 콜센터 + 금융·통신·공공 민원 |
| 한국어성 | 핵심은 한국어. **영어·KR3·KOTE 는 보조·검증으로 분리** |
| 공개성 | AI Hub·공공데이터는 출처·이용조건 추적 가능 |

**세 번째가 중요하다.** 도메인이 갈려 있어야 **분포 이동과 hard negative** 를 만들 수 있다.

### 그래서 지금 할 일은 셋이다

```
① 30716·위해위험의 쇼핑몰 분리
② 데이터 계보·중복·라이선스 관리
③ 실제 A-COP 상담 로그로의 도메인 적응
```

**신규 수집이 아니다.**

## 30716 쇼핑몰 subset — 점검이 요구한 것과 실제로 한 것

`[실측]` `_완결성점검_codex_2026-08-20.md` §2.1은 **공식 코드-의미 매핑표가 없으니** "이 표가 만들어지기 전까지 30716 온라인쇼핑몰 subset은 확정 데이터셋으로 세지 않는다"고 못 박았다. 요구한 절차는 다섯이다.

```
① 원본 메타(기관·출처·업무분야·상담유형·파일분할)의 고유값을 먼저 집계
② K쇼핑으로 명시된 출처·기관·파일 파티션을 우선 추출 — 코드는 같은 레코드의 기관명과 대조한 뒤 내부 표 생성
③ "주문·배송·반품" 키워드만으로 쇼핑몰을 확정하지 않는다 — 금융·다산콜에도 같은 단어가 나온다. 기관 provenance가 1차 조건
④ 기관 × 업무분야 × intent 교차표 + 무작위 표본 사람 검수, 경계 샘플은 uncertain
⑤ 내부 매핑표에 원본 파일/열/코드/표시값/근거 레코드 수/검수자/검수일
```

`[실측]` 08-28 `aihub_30716_callcenter_qa/REPORT.md`가 실제로 한 것 — **②는 파일명으로 됐다.** 3개 배치 중 `라벨링데이터_231222_add`에만 K쇼핑이 있고 zip 이름 자체가 `…_K쇼핑_{AS,결제,교환,반품,배송,업무처리,주문}_Training.zip`이라 provenance가 파일 파티션으로 잡힌다. 그러나 **issue_code 매핑은 카테고리당 300건 샘플의 키워드 규칙이고 90%+가 `*_other`**로 떨어졌으며 REPORT 스스로 "사람 검수 필요"라 적었다. ④·⑤는 안 됐다. 그러니 [catalog.md](catalog.md)의 "완료 — K쇼핑 subset 추출·매핑"은 **도메인 분리 완료**이지 **intent 매핑 확정**이 아니다.

같은 문서 §2.2의 위해위험(15098320) 필터 3단계 — ① 거래경로·접수경로·판매처·품목 열의 코드-표시값 전수 추출 ② 사건 제목·내용에서 `온라인쇼핑몰`·`통신판매`·`오픈마켓` 등 명시 표현 탐지(단 "온라인에서 정보를 봤다"와 "온라인 거래"를 구분) ③ 둘의 교집합을 positive, 충돌은 사람 검수, `online_shop=positive/negative/uncertain`과 근거 span 저장 — 은 **아직 안 했다.** catalog.md의 `SALES_METHOD_CODE` 매핑표 미확보가 ①에서 막힌 상태다.
