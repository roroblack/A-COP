## 3. 사안 3건 — 각각 "어떻게 고칠지" 구체안을 내라

### A. Composer POST 에 CSRF 방어가 없다 ← 가장 중요
콘솔이 켜져 있는 동안 개발자가 악성 웹페이지를 열면, 그 페이지가
`127.0.0.1:<port>/composer` 로 form POST 를 보낼 수 있다. 폼 POST 는 CORS
preflight 대상이 아니라 브라우저가 막지 않는다. 응답은 못 읽지만 **부작용
(대상 config `apply`)은 일어난다** — 서버 환경변수의 issuer secret 으로.

★이 앱에는 **쿠키도 세션도 없다.** 그 전제에서 어떤 방어가 맞는지 답하라.
고려해볼 것: CSRF 토큰 / `Origin`·`Referer` 헤더 검사 / 커스텀 헤더 요구 /
apply 를 CLI 로 분리. **각각의 한계도 같이 적어라**(예: 헤더가 없는 요청은?
curl·스크립트로 쓰는 경우는 어떻게 되나?).

### B. 임의 경로를 읽을 수 있다
`/project?path=<아무 경로>` 로 저장소 밖 어디든 열 수 있다.
★이건 **의도된 기능**이다 — "프로젝트 경로만 주면 그 프로젝트에 붙는다" 가
이 프로그램의 존재 이유다(`CLAUDE.md` 첫 줄). 기능을 없애는 안은 받지 않는다.

물어보는 것: **localhost 밖으로 노출될 때를 대비한 안전장치**를 지금 넣어둘
가치가 있는가? 있다면 어떤 형태인가(허용 루트 allowlist 환경변수? 비-localhost
바인딩 감지 시 거부? 아무것도 안 하고 문서화만?). **과한 설계인지도 판단해서
말하라** — 안 넣는 게 낫다면 그렇게 답해도 된다.

### C. async 핸들러 안에서 blocking HTTP 호출
`/composer` POST 는 `async def` 인데 안에서 동기 `urlopen()` 을 부른다
(`console/composer.py`). 대상이 느리면 이벤트 루프가 막힌다.

★주의: 이 핸들러는 `await request.form()` 을 쓰므로 그냥 `def` 로 못 바꾼다.
그 제약을 감안한 안을 내라. `httpx.AsyncClient` 로 전면 교체 / starlette
`run_in_threadpool` / 그대로 두기 — 각각의 비용과 이득을 적어라.
`console/composer.py` 는 `tests/test_composer.py` 가 실제 HTTP 서버로 검증하고
있다는 점도 감안하라(어느 안이 그 테스트를 얼마나 깨는가).
