## ★고친 결함 5건 (전부 실측으로 재현 후 수정)

### 1. `.gitignore` 가 인수인계 브랜치에 아예 없었다
`final_project_ui` 는 상위 워크스페이스의 `.gitignore` 에 의존하고 있었는데,
`project-final_project_ui` 브랜치는 이 폴더만 떼어낸 것이라 **그게 안 따라온다.**
클론한 팀원은 `.gitignore` 가 하나도 없는 저장소를 받는다 → `__pycache__`·
`.pytest_cache` 가 그대로 커밋될 판이었다.
→ `final_project_ui/.gitignore` 를 만들었다(양쪽 모두에서 동작한다).

### 2. 대상이 이상한 응답을 주면 콘솔이 **500 으로 죽었다**
대상이 `config: null`·배열·문자열을 주면 `.get()`/`.items()` 에서 터졌다.
이 프로젝트의 존재 이유("대상이 없거나 이상해도 콘솔은 뜬다", `CLAUDE.md` §1)를
정면으로 어기는 결함이었다. 게다가 500 화면은 **어느 대상이 뭘 잘못 줬는지도**
안 알려준다.
→ 형태를 검사해서 "대상이 준 config 를 읽지 못했습니다 — 객체가 아니라 X 입니다"
로 적는다. `console/web.py` 두 곳(화면 렌더·POST 핸들러).

### 3. 조작된 POST 가 500 을 만들었다
`remove_team=abc` → `int()` 에서 예외 → 500. (음수·범위초과는 이미 방어돼 있었다)
→ 숫자가 아니면 아무 행도 지우지 않고 화면만 다시 그린다.

### 4. 경로에 `&`·`#` 가 있으면 **링크가 엉뚱한 곳을 가리켰다**
`esc()` 는 HTML 이스케이프일 뿐 URL 인코딩이 아니다. 폴더 이름 `a&b#c`(둘 다
파일명으로 합법) 는 `path=...\a` 로 잘리고 `#c` 는 서버에 오지도 않았다.
→ `qs()` 헬퍼 추가(URL 인코딩 → HTML 이스케이프 순서), 링크 생성 7곳 전부 적용.

### 5. `/project` 만 파라미터 없으면 **raw JSON 422** 를 냈다
주소창에 `/project` 만 치거나 쿼리 없는 북마크로 들어오면 화면이 아니라 JSON이
떴다. 다른 라우트(`/`·`/run`·`/composer`)는 전부 안내 화면을 낸다.
→ 안내 화면으로 통일.

### (부수) 검사하는 척하던 테스트 1건
`test_project_screen_links_to_the_composer_screen` 이
`... in body or "/composer?path=" in body` 였다. P13 상단 내비게이션이 모든
화면에 `/composer?path=` 를 넣으므로 **`or` 뒤쪽이 항상 참**이었고, 본문 링크가
통째로 사라져도 통과했다(`CLAUDE.md` §2 가 금지하는 바로 그것).
→ 엄격한 쪽만 남겼다. ★그 덕에 이번 URL 인코딩 수정 때 이 테스트가 **실제로
변화를 잡아냈다** — 검사가 살아있다는 증거다.

## 설계 사안 3건 — Codex 교차검증 후 처리 (2026-08-19 추가)

처음엔 "팀원이 판단할 것"으로 남겼으나, 사용자 지시로 **Codex와 교차검증한 뒤
A·C를 구현하고 B는 의도적으로 두기로 결론냈다.** 셋 다 Codex와 내 판단이 일치했다.

### A. Composer POST 의 CSRF 방어 → ★구현함
콘솔이 켜져 있는 동안 개발자가 **악성 웹페이지를 열면**, 그 페이지가
`127.0.0.1:<port>/composer` 로 form POST 를 보낼 수 있다. 폼 POST 는 CORS
preflight 대상이 아니라서 브라우저가 막지 않는다. 응답은 못 읽지만 **부작용
(대상 config `apply`)은 일어난다** — 서버 환경변수의 issuer secret 으로.

**채택안(Codex 추천 = 내 판단):** 프로세스마다 만드는 CSRF 토큰을 hidden field
로 넣고 POST 에서 검증. `Origin` 검사는 보조.
- 토큰이 주 방어인 이유: 공격자 페이지는 **동일출처 정책 때문에 그 값을 읽을 수
  없다.** 내 원안은 `Origin` 단독이었는데, Codex 가 "헤더 없는 요청을 허용할지
  애매하다"고 지적한 것이 맞다 — 토큰을 필수로 하면 그 모호함이 사라진다.
- `Origin` 을 남긴 이유: 브라우저는 cross-origin POST 에 **반드시** 붙인다.
  토큰이 어떤 경로로 새더라도 한 겹 더 막는다.
- ★**대상에 아무것도 보내기 전에** 막는다(테스트가 이걸 직접 단언한다).
- 부작용: `POST /composer` 는 이제 **화면을 거쳐야만** 쓸 수 있다. 스크립트
  자동화는 대상의 `/composer/*` 를 직접 부르는 게 맞다 — 원래 계약이다.
- 실서버 검증: `final_project_cs` 를 띄우고 정상 흐름(검증 성공)·토큰 없는
  공격·다른 출처 공격 셋을 실제로 넣어 확인했다.

### C. async 핸들러 안 blocking 호출 → ★구현함
`starlette.concurrency.run_in_threadpool` 로 `read_current`·`validate_candidate`·
`apply_candidate` 를 감쌌다. Codex 와 내 판단이 같았다 — `await request.form()`
때문에 핸들러를 `def` 로 못 바꾸고, `httpx.AsyncClient` 전면 교체는 인증·오류
매핑·실 HTTP 테스트를 전부 다시 써야 해서 이번 범위에 과하다.
`console/composer.py` 와 그 테스트는 **한 줄도 안 바꿨다.**

### B. 임의 경로를 읽을 수 있다 → ★일부러 안 고침 (Codex 도 같은 결론)
`/project?path=<아무 경로>` 로 저장소 밖 어디든 열 수 있고, 그 안의
`config/project.yaml`·문서·평가 결과를 읽는다.
★이건 **의도된 기능**이다 — "프로젝트 경로만 주면 그 프로젝트에 붙는다"가
이 프로그램의 존재 이유다(`CLAUDE.md` 첫 줄). `127.0.0.1` 바인딩이라
지금은 로컬 사용자만 쓸 수 있다.

Codex 도 allowlist 도입을 **기각**했다 — "핵심 기능을 제한하고, 프로젝트가 여러
위치에 있을 수 있어 환경변수 설정 누락이 곧 기능 장애가 된다." 지금 없는 공격면을
막으려고 실제 기능을 깨는 셈이다.

→ 대신 **문서화**했다. `127.0.0.1` 밖으로 노출하는 변경이 생기면 그때 허용 루트
제한·인증을 **먼저 설계**해야 한다. 이 조건이 사라지는 순간 위험이 현실화된다.

## Codex 지적 중 **기각**한 것

- **"DB 예외 원문을 화면에 노출"** — 이건 이 프로젝트의 의도다.
  `CLAUDE.md` §0.4·§2 가 "못 읽었으면 왜 못 읽었는지 적는다", "조용한 스킵
  금지"를 요구한다. 로컬 개발 콘솔이고, 원인을 숨기면 운영자가 못 고친다.
  단, §B 처럼 **외부 노출 시에는 재검토** 대상이다.
- **"`limit=0` 이 전체를 표시"** — `read_eval_runs(limit=0)` 을 부르는 곳이
  코드에 없고(호출부는 `limit=6` 고정), `limit` 은 내부 파라미터다.
  실제로 도달하지 않는 경로라 이번엔 안 고쳤다.

## ★v2/v3 병행 결정과 UI 쪽 준비 (2026-08-24 추가)

사용자가 `A-COP_Composer_v3_불일치_해소안.md`의 6개 미결 질문에 대해 **안 C(병행)**
로 결정했다 — 기존 v2(`/composer/current`·`/validate`·`/apply`)는 그대로 두고
`/composer/toggle`을 추가한다. 안 A(전면 교체)·안 B(v2 정본화)는 채택하지 않았다.

### 이 세션이 하지 않은 것 — 범위 경계 재확인

v3 설계 문서(§6)가 지목하는 실제 구현 대상은 **`final_project_sample`**
(`acop_composer/api.py`·`service.py`)이고, `final_project_cs`는 그 결과를 이식받는
릴리즈 대상이다(워크스페이스 루트 `CLAUDE.md`). 사용자가 세션 도중 이 경계를
직접 정정했다 — ★"셈플에서 해야 하는 게 맞는데 지금 그걸 니가 할 수는 없는
작업... 넌 지금 ui 프로젝트만 쓰도록 해야 하니까". 그래서 `final_project_sample`·
`final_project_cs` 어느 쪽에도 이번 세션에서 코드를 쓰지 않았다(`CLAUDE.md` §0.1).
실제로 `final_project_cs`에는 오늘 다른 세션이 introspection·composer 관련 파일을
이미 손대고 있는 상태였다(`git status`로 확인, 커밋 전 상태라 내용은 열지 않았다).

### UI 쪽에서 지금 할 수 있는 만큼만 미리 준비함

대상의 계약이 아직 확정되지 않았으므로(v3 설계 §5: "v2 작업이 끝난 뒤 담당
세션에서 이 v3 제안과 계약 내용을 대조해 반영해야 한다") **화면은 아직 연결하지
않았다.** 대신 v3 설계 §2.2 제안 형태 그대로 어댑터 함수만 추가해 뒀다 —
나중에 대상 계약이 확정되면 화면 배선만 남도록.

- [`console/composer.py`](../../console/composer.py) `toggle_target()` 신규 —
  기존 `read_current`·`validate_candidate`·`apply_candidate`와 같은 `_call()` 헬퍼를
  재사용해 `POST /composer/toggle`을 호출한다(`target_type`·`target_id`·`active`·
  `base_revision`·`reason`). ★필드명·경로는 잠정이라고 docstring에 명시했다.
- [`tests/test_composer.py`](../../tests/test_composer.py) 3건 추가 — 성공,
  revision 충돌(409→"충돌"), 미등록 ID(422→"검증 실패"). 로컬 stub HTTP 서버로
  실측(모킹 아님), 기존 테스트와 같은 방식.
- 화면(`console/web.py`)에는 **아직 연결하지 않았다.** 대상이 없는 상태에서
  화면부터 만들면 v3 설계 §6 순서(1 계약 확정 → 2 introspection 확장 확인 →
  3 cs 구현 → 4 UI 화면)를 건너뛰는 것이고, 대상 계약이 필드명이라도 바뀌면
  헛수고가 된다.

### 결과 — "비어버리는 구간" 없이 다음 단계로 이어지는 지점

v2 Composer 화면은 지금 이대로 계속 동작한다(무엇도 안 건드림). 나중에 대상이
`/composer/toggle`을 실제로 내놓으면, 이 어댑터를 그대로 호출하는 화면 배선만
추가하면 된다 — v2 화면을 걷어내거나 잠깐 멈추는 전환 이벤트가 필요 없다.
