# P8 실연결 검증 보고서

## 배경

P7 보고서는 "실제 DB 서버 기동 확인은 실행 정책에 의해 차단되어 수행하지 못했다"고 남겼다.
이번 작업은 그 갭을 메운다 — `final_project_sample`을 실제로 띄우고, `final_project_ui`가
그 `/introspection`과 PostgreSQL에 진짜로 연결되는지 확인했다.

`final_project_sample`을 참조하는 작업이라 `final_project_ui/CLAUDE.md` §0.1에 따라
사용자 허가를 먼저 받았다.

## 발견한 결함

`final_project_sample`의 `GET /introspection`은 `require_scope("ops:introspect")`로 잠겨 있다
(`app/presentation/api/app.py:50`). 그런데 `console/live.py`의 `read_introspection()`은
`Authorization` 헤더를 아예 보내지 않고 있었다 — 실서버에 붙이니 항상 `401`이 났고,
고치기 전 코드는 이걸 `대상이 응답하지 않음`으로 뭉쳤다. 대상은 응답했다, 인증이 안 됐을 뿐이다.
mock 서버로 짠 기존 테스트는 인증을 요구하지 않았으므로 이 결함을 잡지 못했다.

## 수정

- `console/profiles.py` — `Profile.introspection_token` 필드 추가, `CONSOLE_INTROSPECTION_TOKEN`
  환경변수에서 읽는다. 파일에 남기지 않는다(기존 원칙 유지).
- `console/live.py` — `read_introspection(url, versions, token=None)`이 토큰이 있으면
  `Authorization: Bearer <token>` 헤더를 보낸다. `401`/`403`은 `대상이 응답하지 않음`과 분리해
  `인증 실패`로 보고한다 — 사실을 다르게 전하지 않는다(`CLAUDE.md` §3).
- `console/web.py` — `/project` 라우트가 `profile.introspection_token`을 넘긴다.

## 실연결 검증

`final_project_sample`을 `--reload`로 기동(`http://localhost:8071`)하고, `final_project_ui`
콘솔을 `CONSOLE_INTROSPECTION_URL`·`CONSOLE_INTROSPECTION_TOKEN`·`CONSOLE_CONTRACT_VERSIONS=1.0`·
`CONSOLE_DATABASE_URL=postgresql://postgres@127.0.0.1:5433/acop`로 기동해 브라우저로
`/project?path=<final_project_sample>`을 열었다.

- **조립 실측**: `읽음` — `contract_version=1.0`. 모듈 6/7(`a2a_executor` 꺼짐), Team 3/3,
  guardrails `token_budget=12000`이 실제 응답과 일치했다.
- **실행 이력**: `읽음` — `전체 0개 중 0개 표시`(아직 실행이 없다, `0`을 "모른다"로 뭉개지 않았다).
- **상태 분포**: `customer_cases` — `new 3 · waiting_approval 1 · resolved 1 · escalated 1`.
  `CLAUDE.md`의 발표 시나리오 seed(시나리오1은 `waiting_approval`에서 멈춰 둠)와 일치한다.
- 판정·평가 파일도 실제 `docs/evidence/`·`eval/reports/` 파일을 읽어 화면에 냈다
  (DoD 부분통과 4·통과 24, 최근 평가 리포트 6개 + "전체 24개 중 18개는 화면에 없다" 절삭 고지).

토큰 없이 접근하면 새 `인증 실패` 상태가 뜨는 것도 확인했다(회귀 테스트로 고정).
