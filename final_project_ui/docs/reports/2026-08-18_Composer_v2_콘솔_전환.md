# Composer v2 콘솔 전환 보고서

## 변경

- Composer read/validate/apply가 각각 `composer:read`, `composer:validate`,
  `composer:write` 단일 scope로 `/auth/token`에서 access token을 발급받는다.
- issuer secret은 `CONSOLE_COMPOSER_ISSUER_SECRET`으로 분리했다.
- 토큰 발급 실패는 `토큰 발급 실패`, 실제 API의 인증 실패는 `인증 실패`로 구분한다.
- 테스트는 최소 HTTP 서버에서 `/auth/token`과 Composer 엔드포인트를 모두 제공하며,
  살아있는 `final_project_sample`에는 apply하지 않는다.
