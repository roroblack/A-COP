# 콘솔을 **실제 릴리스 대상(final_project_cs)** 에 붙여 검수 (2026-09-05)

## 왜 했나

이 콘솔은 지금까지 **`final_project_sample` 로만** 검수했다. 그런데 릴리스 대상은
`final_project_cs` 다(루트 `CLAUDE.md`). 둘은 계약 수준이 다르다:

| | sample | cs |
|---|---|---|
| introspection 계약 | **1.1** (`active_revision`·`reload_state` 등) | **1.0** |
| `POST /admin/reload` | 있음 | **없음** |
| Composer v3 카탈로그·인스턴스 CRUD | 있음 | **없음** |
| Composer v2 (`current`/`validate`/`apply`) · 토글 | 있음 | 있음 |

콘솔은 "없는 것을 없다고 말한다" 를 원칙으로 만들었는데, **그게 실제로 되는지는
안 봤다.** 화면 코드가 sample 의 풍족한 응답에만 맞춰져 있을 수도 있었다.

## 결과 — 통과

`/composer?path=<cs>` 를 실제로 열었다.

- **빠른 토글 카드**: 등록 12건(모듈 6 + Team 6)을 상태와 함께 그린다
- **v2 편집 폼**: 모듈 6 · Port 3 · Team 6 · 실행 순서 9단계 · 컴포넌트 7종
- ★**카탈로그 카드 없음** — cs 에 v3 카탈로그가 없다. 조용히 빠지고 나머지는 동작
- ★**reload 상태 문구 없음** — cs 는 계약 1.0 이라 그 필드가 아예 없다.
  **없는 것을 "정상" 으로 적지 않았다**
- 태그가 글자로 새는 곳 없음(`<code>`·`&lt;` 검사)

자동 검사에 "있으면 안 되는 것" 을 넣어 고정했다(`capture_cs.py`) — 나중에 누가
1.0 대상에 reload 상태를 그리기 시작하면 붉어진다.

## ★검수 중 내가 틀린 것

처음에 화면 하단이 `HTTP 401: invalid credentials` 였다. 제품 결함으로 보였지만
**내 환경변수 매핑이 틀린 것**이었다.

cs 는 Composer 비밀키가 **둘**이다:

    composer_issuer_secret   `/auth/token` 을 부를 때 제시하는 것 ← 콘솔이 쓰는 것
    composer_jwt_secret      발급된 JWT 를 서명·검증하는 것

내가 후자를 콘솔에 넘겼다. 바로잡으니 화면이 1161자 → 2081자로 늘며 전부 그려졌다.

★곁가지로 확인한 것: `issue_token()` 이 `if not expected or ...` 로 **빈 비밀키를
모두 거부**한다(fail-closed). 설정이 비어 있을 때 통과시키는 구멍이 아니다.

## 관찰 — 결함은 아니지만 갈라진 것

`revision` 문자열 길이가 두 저장소에서 다르다.

| | 방식 | 예 |
|---|---|---|
| sample | `sha256(...)[:12]` | `ea58fc7efe63` |
| cs | `sha256(...)` 전체 | `6cca23ee13b8cb7e97117563966a136c472162e7dfa4730641a515c8a0e17e3f` |

둘 다 **내용 기반**이라 동작은 맞고, 각 저장소 안에서 CAS 도 정상이다. 화면도
깨지지 않는다(캡처 확인). 다만 계약 문서(`docs/handoff/13`)가 형식을 규정하지
않아 갈라진 것이라, 맞출지 말지는 계약 소유자가 정할 일이다. **여기서 한쪽을
바꾸면 진행 중인 `base_revision` 이 무효가 되므로 손대지 않았다.**

## 재현

```
python -m uvicorn app.presentation.api.app:app --port 8042   # final_project_cs 에서
# 콘솔 (scratchpad/run_console_cs.py 가 cs .env 에서 키를 읽어 환경으로 넘긴다)
python run_console_cs.py    # → http://127.0.0.1:8075/composer?path=<cs 경로>
```
