## 결함 1 — 적용에 사유(reason)가 안 실려 간다

### 증상

Composer 화면에서 사유를 적고 [적용]을 눌러도 대상이 422로 거부한다.

### 원인

`console/composer.py`의 `apply_candidate()`가 본문에 `config`와 `base_revision`만
담았다. 대상의 `ApplyPayload`는 `reason`을 `min_length=1`로 필수 요구한다.

화면(`console/web.py`)은 사유를 입력받고 비었는지 검사까지 했다. 그런데 그 값을
클라이언트에 넘기지 않았다. 검사만 하고 안 보낸 것이다.

같은 파일의 `toggle_target()`은 `reason`을 제대로 보내고 있었다. 두 함수가
달랐던 것을 아무도 못 봤다.

### 고친 것

- `apply_candidate(..., *, base_revision, reason)` — `reason`을 keyword-only
  **필수** 인자로 만들었다. 빠뜨리면 그 자리에서 `TypeError`로 깨진다.
- 본문에 `reason`을 넣는다.
- `console/web.py`의 호출부가 화면에서 받은 사유를 넘긴다.

### 왜 테스트가 못 잡았나

`tests/test_composer.py`의 가짜 서버가 요청 본문을 읽지 않고 200만 내줬다.
무엇을 보내든 통과했다. `CLAUDE.md` §2의 "검사하는 척하는 검사"였다.

가짜 서버가 받은 본문을 `composer_server.received`에 기록하게 고치고,
본문에 사유가 들어 있는지 실제로 확인하는 테스트를 넣었다.

## 결함 2 — 계약 버전 기본값이 어긋난다

### 증상

`CONSOLE_CONTRACT_VERSIONS`를 손으로 설정하지 않으면 조립 실측과 빠른 토글 카드가
조용히 안 뜬다. 화면은 아무 말도 안 한다.

### 원인

`console/profiles.py`의 기본값이 `v1`이었다. 대상이 실제로 내는
`contract_version`은 `1.0`이다. **`v1`을 내는 대상은 하나도 없다.**

2026-08-17 P8 실연결 검증 때 이미 `CONSOLE_CONTRACT_VERSIONS=1.0`으로 맞춰서
확인했었다. 그때 기본값을 같이 안 고쳤다.

### 고친 것

기본값을 `1.0`으로 바꿨다. 환경변수로 넓히는 것(`1.0,1.1`)은 그대로 된다.

### 왜 테스트가 못 잡았나

기본값을 확인하는 테스트가 없었다. 버전 검사 로직 자체는
`test_an_unknown_contract_version_is_not_drawn` 등으로 잘 덮여 있었지만,
"기본값만으로 대상을 읽을 수 있는가"는 아무도 안 물었다.

두 개를 넣었다 — 기본값이 `1.0`을 포함하는지, 환경변수로 넓혀지는지.

## 결함 3 — 토글 상태를 못 읽어 버튼이 하나도 안 그려진다

### 증상

빠른 토글 카드는 뜨는데 모든 항목의 상태가 `모름`이고, 버튼이 하나도 없다.
카드가 있으나 아무것도 못 바꾼다.

### 원인

`_toggle_state()`가 `{id: {"enabled": bool}}` 한 가지 형태만 기대했다.
이건 v3 설계 §2.2의 **제안** 형태고, 대상이 실제로 내는 형태가 아니다.

| 종류 | 대상이 실제로 내는 형태 | 코드가 기대한 형태 |
|---|---|---|
| `modules` | `{"vector_rag": true}` (boolean map) | `{"vector_rag": {"enabled": true}}` |
| `teams` | `[{"team_id": "voc", "active": true}]` (객체 list) | `{"voc": {"active": true}}` |

`_toggle_row()`는 상태를 모르면 버튼을 안 그린다. 반대값을 만들려면 지금 값을
알아야 하기 때문이다. 그래서 상태를 못 읽으면 카드 전체가 장식이 된다.

### 고친 것

`_toggle_state()`가 세 형태를 모두 읽는다 — boolean map, 객체 list, 객체 map.
셋 다 아니면 `None`을 돌려주고 화면은 `모름`이라고 적는다. 지어내지 않는다(§0.4).

객체 map(제안 형태)도 계속 읽는 이유는, v3 계약이 아직 잠정이라 나중에 그 형태로
갈 수도 있기 때문이다. 셋 다 받으면 어느 쪽으로 확정돼도 안 깨진다.

### 왜 테스트가 못 잡았나

`test_toggle_card_shows_registered_items_with_current_state`가 제안 형태만 넣었다.
그 형태를 내는 대상이 없으니, 통과해도 아무것도 보장하지 못했다.

대상이 진짜 내는 형태를 넣는 테스트를 추가했다. 버튼 개수(`끄기` 2개, `켜기` 1개)와
`모름`이 없다는 것까지 확인한다.

### 화면 실측 (`CLAUDE.md` §3)

대상 없이는 Composer 편집 화면이 안 뜨므로, 대상의 Composer 계약만 흉내 내는
가짜 대상을 세워 브라우저로 왕복했다. 이 가짜는 **대상과 똑같이 사유가 없거나
비면 422를 낸다** — 그래야 사유가 진짜 실려 갔는지 증명이 된다.

콘솔은 `CONSOLE_CONTRACT_VERSIONS`를 **일부러 설정하지 않고** 띄웠다.
기본값만으로 되는지가 결함 2의 확인 항목이기 때문이다.

| 확인 | 결과 |
|---|---|
| 빠른 토글 카드가 뜨는가 (환경변수 없이) | 떴다 — `등록 3건 · revision rev-1` |
| 항목 상태가 읽히는가 | `vector_rag 켜짐`, `a2a_executor 꺼짐`, `voc_store_manager 켜짐` |
| 버튼이 그려지는가 | `끄기` 2개, `켜기` 1개. `모름` 0개 |
| 사유를 적고 [적용] | `적용됨 — 새 revision rev-2` |
| 대상에 실제로 반영됐는가 | `GET /composer/current` → `revision: rev-2` |

가짜 대상은 세션 임시 폴더에만 두고 저장소에 넣지 않았다. 검증 후 콘솔과 가짜
대상 프로세스를 모두 종료했다.

## 검증 중에 겪은 것 — uvicorn `--reload`

고친 코드가 화면에 반영이 안 돼서 한참 헤맸다. 원인은 코드가 아니라 실행 방식이었다.

`python -m console.web`은 `reload=True`로 뜬다. 파일을 고치면 WatchFiles가
"Reloading..."을 찍는데, **새 자식 프로세스가 안 뜨고 옛 자식이 계속 응답했다.**
부모를 죽여도 자식이 포트를 잡고 살아남았다.

같은 코드를 `TestClient`로 in-process 호출하면 정상이었다. 이 차이가 힌트였다.

화면으로 검증할 때는 `reload=False`로 띄우고, 끝나면 남은 python 프로세스를
확인해서 정리한다. 고아 자식이 포트를 물고 있으면 다음 검증이 옛 코드를 본다.

## 남은 것

- v3 toggle 계약은 아직 잠정이다. 대상이 필드명·경로를 확정하면 어댑터와 화면을
  다시 맞춘다.
- `registered_ids.ports`는 대상이 빈 목록을 낸다. Port는 아직 토글할 수 없다.
- 저장(desired)과 실제 동작(effective)을 화면이 구분해 보여주지 않는다.
  대상이 시작할 때 한 번 조립하므로 Team 추가·삭제는 재시작해야 반영된다.
