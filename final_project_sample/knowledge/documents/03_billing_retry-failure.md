## 거절과 미납은 다른 상태다
승인 거절 직후에는 payment_failed를 저장하고 구독을 끝내지 않는다. 이 상태는 결제수단 문제를 해결할 시간이 남아 있다는 뜻이다. 72시간 동안 승인 이벤트가 없을 때에만 unpaid로 옮겨 유료 기능 제한 검토를 시작한다. 처리자는 해당 회차의 생성 시각과 승인 결과를 한 묶음으로 확인한다. 금액이 보류된 경우에는 임시 값으로 후속 청구를 만들지 않으며, 결제 원장에 확정값이 생긴 뒤 다음 단계로 넘긴다. 10분 안에 상태가 갱신되지 않으면 같은 요청을 반복하지 않고 마지막 이벤트를 조회한다. 승인 대기와 발행 대기를 같은 상태로 취급하지 않으며, 담당자는 두 큐의 다음 처리 시각을 각각 확인한다. 보존 자료의 재생성 결과는 원본 해시와 비교해 동일성을 확인한다. 해시를 비교한다. 보존 권한을 확인한다.

## 재시도 시각을 계산하는 방식
재시도는 최초 실패 시각을 기준으로 예약하며, 같은 분 안에 여러 실패가 쌓여도 유예기간을 새로 늘리지 않는다. 카드사 응답이 늦게 도착한 성공 이벤트는 원장에 기록된 이벤트 순서로 반영한다. 고객 화면의 다음 시도 시각은 UTC로 계산한 뒤 계정 시간대로 변환한다. 날짜가 경계에 걸리면 화면에 보이는 지역 시간보다 원장에 저장된 UTC 시각을 우선한다. 예를 들어 23:59와 00:00의 차이는 서로 다른 회차로 취급할 수 있으므로 날짜 문자열만 비교하지 않는다. 계산에 사용한 시각과 가격표 버전은 함께 남긴다. 가격 변경이 예약된 상태라면 현재 회차에는 새 가격을 적용하지 않고 다음 갱신의 계산 자료로만 넘긴다. 이 결과는 회차 번호와 함께 저장해 다음 청구의 기준으로 재사용하지 않는다. 승인 시각도 확인한다. 처리 시각을 확인한다.

## 카드 정보가 갱신된 경우
고객이 결제수단을 바꾸면 다음 재시도부터 새 수단을 사용할 수 있다. 변경 저장이 성공했지만 결제 서비스에 전달되지 않았다면 새 카드를 다시 입력하게 하지 말고 이벤트 전달 상태를 확인한다. 결제수단 번호 전체는 지원 대화나 감사 로그에 쓰지 않는다. 정상 흐름은 승인, 원장 반영, 문서 생성의 순서로 진행되며 어느 하나가 빠지면 완료로 표시하지 않는다. 결제 서비스가 성공을 반환했어도 문서 번호가 없으면 발행 대기 상태를 유지한다. 재처리할 때는 최초 회차의 식별자를 재사용한다. 월말 보정으로 생긴 회차는 원래 계약일과 보정 사유를 함께 표시해 고객이 기간을 오해하지 않게 한다. 담당자는 계산에 쓴 가격표와 시각을 확인한 뒤 상태를 확정한다. 다음 회차와 섞지 않는다. 원장 값을 우선한다.

## 재시도 중 플랜 변경
미납 유예 중 플랜을 바꾼 요청은 결제 상태와 별도로 기록한다. payment_failed 회차가 먼저 승인되면 그 회차의 금액은 승인 직전 유효했던 가격으로 확정되고, 뒤의 변경은 다음 회차에 적용한다. unpaid 이후에는 상위 기능을 먼저 열지 않는다. 금액이나 세금 항목을 다시 계산해야 한다면 원래 입력과 수정 입력을 나란히 비교한다. 승인 뒤 가격표를 소급해 청구하지 않고, 차이가 발견된 회차만 조정 대상으로 분리한다. 조정 결과는 담당자가 5영업일 안에 확인할 수 있어야 한다. 세금 주소나 사업자 정보가 바뀌어도 이미 확정된 문서의 금액은 소급 수정하지 않고 정정 문서로 연결한다. 보정된 날짜는 원래 계약일과 함께 표시해 기간의 연속성을 설명한다. 마지막 날을 기준으로 삼는다. 회차 경계를 보존한다.

## 반복 거절을 설명하는 문구
같은 카드에서 반복 거절이 생겼다고 해서 원인을 카드사 사유 이상으로 추측하지 않는다. 고객에게는 마지막 실패 시각과 다음 결제 시도, 현재 기능 상태를 알려준다. 계정이 잠겨 있다는 표현은 권한 서비스가 실제 제한을 확인한 경우에만 사용한다. 고객에게 보이는 상태와 내부 원장의 상태가 다를 때는 원장 이벤트의 발생 순서를 먼저 대조한다. 메일 지연만으로 결제 실패를 선언하지 않으며, 72시간 유예가 끝나기 전에는 unpaid 전환을 앞당기지 않는다. 확인되지 않은 카드 정보는 답변에 그대로 쓰지 않는다. 메일 전달 결과가 늦어도 다운로드 권한을 먼저 확인하며, 발행 번호가 없는 파일은 고객에게 제공하지 않는다. 정정된 문서는 최초 문서와 연결하고 기존 파일을 덮어쓰지 않는다. 확정 전에는 발행하지 않는다. 정정 이력을 남긴다.

## 유예기간이 끝나는 순간
실패 후 72시간이 지나면 청구 원장은 unpaid로 전환된다. 전환 작업과 권한 제한 이벤트 사이에 짧은 비동기 지연이 있을 수 있어 화면 상태가 먼저 바뀌거나 늦게 바뀔 수 있다. 제한이 실행되기 전 성공 승인이 들어오면 최신 이벤트의 순서를 다시 평가한다. 같은 청구 요청이 다시 들어오면 기존 승인번호와 회차를 찾아 결과를 돌려준다. 새 문서나 새 금액을 만들기 전에 24시간 범위의 중복 키를 확인하며, 키가 다르더라도 승인 시각과 금액이 같으면 운영 검토로 보낸다. 취소된 요청은 재사용하지 않는다. 실패 사유가 카드사에서 갱신되면 이전 사유를 덮지 않고 새 이벤트로 추가해 재시도 판단의 근거를 보존한다. 전달 실패와 발행 실패를 나눠 기록해 결제 상태를 잘못 바꾸지 않는다. 반송 사유를 구분한다. 전달 결과를 나눈다.

## 중복 승인 이벤트 처리
카드사 웹훅이 같은 승인 결과를 두 번 보내도 한 회차에 한 번만 금액을 확정한다. 요청의 idempotency 키는 24시간 유지하고, 키가 없으면 결제 원장의 회차와 승인 시각으로 중복을 대조한다. 두 금액을 합쳐 정산하는 방식은 허용하지 않는다. 월말과 갱신일이 겹치는 경우에는 먼저 확정된 회차가 어느 기간을 대표하는지 판정한다. 29일, 30일, 31일이 없는 달의 보정은 마지막 날 23:59 UTC에 적용하고, 보정으로 생긴 날짜를 다음 기간의 시작으로 옮기지 않는다. 한 회차에 두 작업이 겹치면 먼저 원장에 기록된 작업을 기준으로 삼고 나머지는 중복 검토 목록에 둔다. 재시도 결과는 원 요청에 연결하며 새 승인으로 오인하지 않는다. 원 요청을 연결한다. 중복 키를 조회한다.

## 미납 상태에서의 해지
unpaid 상태에서 해지를 신청하면 사용권 종료 시각과 미납 회수 여부를 따로 처리한다. 해지는 미래 청구를 막지만 이미 발생한 채무를 없애지 않는다. 환불과 상계가 함께 요청된 경우에는 승인된 금액부터 정산 담당자의 판단을 받는다. 실패한 결제는 재시도 예정 시각, 실패 사유, 현재 기능 상태를 서로 다른 필드에 보관한다. 카드사가 일시 오류를 반환한 경우와 한도 초과를 반환한 경우의 안내를 섞지 않는다. 3회 연속 실패하면 자동 안내와 지원 검토를 함께 준비한다. 청구 금액의 소수점 처리 규칙은 문서마다 달리 적용하지 않고 해당 통화의 가격표에 등록된 규칙을 따른다. 겹친 작업의 처리자는 이후 검토자가 알 수 있도록 판정 근거를 남긴다. 경계 시각을 보존한다. 보정 이유를 적는다.

## 청구서의 상태 표시
실패한 회차의 청구서는 payment_failed 또는 unpaid 상태를 표시한다. 결제 재시도가 예약되어 있어도 paid로 보이게 만들지 않으며, 승인이 확인된 뒤 5분 안에 새 상태를 반영한다. 청구서에 카드사 내부 오류 전문을 그대로 노출하지 않는다. 연간 또는 월간 기간을 표시할 때 시작 시각과 종료 시각을 모두 적어야 한다. 기간 중 플랜이 바뀌면 변경 승인 전후의 사용 구간을 나누고, 어느 구간에도 속하지 않는 사용량은 임의로 배분하지 않는다. 환불 계산은 별도 절차로 연결한다. 유예가 끝난 뒤 제한을 적용할 때도 이미 완료된 작업의 결과는 삭제하지 않고 이후 요청부터 새 상태를 반영한다. 통화별 반올림 결과는 청구서와 원장에 동일하게 표시해야 한다. 실패 사유를 덧붙인다. 실패 상태를 구분한다.

## 고객이 직접 재결제를 요청할 때
수동 재결제는 현재 유효한 결제수단과 미납 회차를 확인한 뒤 한 번만 요청한다. 브라우저 재전송으로 같은 요청이 반복되면 idempotency 키가 기존 결과를 가리켜야 한다. 실패 사유를 모르면 먼저 결제 서비스의 원장 이벤트를 조회한다. 청구서가 만들어진 뒤에도 전달 성공을 결제 성공의 증거로 사용하지 않는다. 발행 번호와 다운로드 가능 여부를 먼저 확인하고, 메일 반송은 주소 오류와 일시적인 수신 거부로 구분한다. 재전송은 24시간 안에 같은 문서를 대상으로 수행한다. 발행 실패가 결제 실패로 전파되지 않도록 문서 큐와 결제 큐의 오류를 분리해 고객 안내를 만든다. 제한 시각과 마지막 정상 사용 시각을 함께 남겨 이력을 설명한다. 기간을 다시 대조한다. 기간을 표시한다.

## 회계팀에 넘기는 기준
72시간이 지나 unpaid가 된 회차, 부분 승인으로 금액이 달라진 회차, 이중 웹훅이 감지된 회차는 회계 검토 목록으로 보낸다. 검토 자료에는 상태 전이와 UTC 시각만 넣고 결제수단 원문은 제외한다. 원장 hash는 90일 보존한다. 해지나 갱신 취소가 청구 작업과 동시에 접수되면 각 이벤트의 UTC 순서를 비교한다. 이미 승인이 끝난 회차는 취소 요청만으로 지우지 않고 환불 창구로 넘긴다. 아직 큐에 있는 항목은 작업을 멈춘 이유와 다음 판정 시각을 남긴다. 해지 요청이 늦게 도착한 경우에도 접수 시각을 바꾸지 않고 승인 시각과 함께 비교표에 남겨 예외를 판정한다. 문서 큐의 오류는 결제 큐의 성공 결과와 별도로 고객에게 안내한다. 번호 없는 파일은 보류한다. 발행 여부를 확인한다.

## 복구 완료를 판단하는 조건
복구는 카드 정보가 저장됐다는 사실이 아니라 승인 이벤트와 권한 회복 이벤트가 모두 확인될 때 완료로 본다. 두 이벤트의 도착 순서가 어긋나면 최신 원장 상태를 다시 읽고 한 번만 재계산한다. 고객에게는 실제로 기능이 열린 뒤 복구 완료를 알린다. 오래된 청구 자료를 조회할 때 고객 화면에는 필요한 항목만 보여준다. 감사 자료는 90일 동안 보존하되 카드 원문이나 불필요한 개인정보를 복사하지 않는다. 복원 요청이 들어오면 문서 해시와 접근 주체를 확인한 뒤 읽기 전용으로 제공한다. 보존 기간이 지난 자료를 다시 만들 때는 현재 가격표가 아니라 원 회차의 원장과 문서 해시를 기준으로 삼는다. 늦은 요청은 접수 순서를 바꾸지 않고 예외 판정 사유를 기록한다. 회차별 판단을 남긴다. 해지 순서를 대조한다.
