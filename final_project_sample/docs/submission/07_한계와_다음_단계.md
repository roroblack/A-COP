# 한계와 다음 단계

## 현재 판정이 통과가 아닌 항목

| 항목 | evidence 판정 | 정직한 의미 |
|---|---|---|
| DoD-04 checkpoint/projection 분리 | 부분 통과 | 구조·정적 검증은 있으나 checkpoint 실행 관측은 미측정 |
| DoD-05 ContextPack | 부분 통과 | 12,000 예산·degraded 규칙은 통과, 실제 절삭 종단 관측은 미측정 |
| DoD-07 tenant/PII | 부분 통과 | tenant/customer·RAG 격리는 통과, evidence 시점 PII 종단 검증은 미통과 기록 |
| DoD-09 인라인 분류 | 미통과 기록 | 당시 API 기본 분류기 미연결; 이후 wire 수정 리포트가 있으나 evidence 판정 자체를 소급 변경하지 않음 |
| DoD-10 일일 배치 | 부분 통과 | 로직 테스트는 통과, DoD-09 영향으로 운영 데이터 집계 종단은 제한 |
| DoD-11 approval/unknown | 부분 통과 | idempotency는 통과, approval·unknown은 미검증 |
| DoD-15/16 평가 | 미측정 | 인용 검증은 적용했지만 정식 전량 실행 결과는 진행 중 |
| DoD-17 milestone | 부분 통과 | M1 도달, M2 도달, M3 미도달 |
| DoD-18 UI | 부분 통과 | 화면·smoke는 확인했으나 evidence에 종단 운영 경계가 남음 |

M3의 60건×3회 평가는 아직 완료 결과가 없다. 따라서 정확도·우월성·비용·SLA 수치를 쓰지 않는다. 60건×3회가 증명하지 않는 것은 모집단 일반화, 장기 drift, 실제 손실률, 모든 도메인에서의 우월성, 운영 SLA다. holdout의 대표성, 2인 독립 라벨러 일치도, judge agreement도 `미측정`이다.

## Phase 2

OAuth2/OIDC, 실결제 provider, Redis Streams, hybrid BM25+rerank를 미룬다. Graph 저장소 본체도 미룬다. 신 계획서 §9-D의 판단처럼 현재 규모에서는 관계형 JOIN이 더 적합하므로, 그래프를 도입했다는 수치를 만들지 않는다.

## 다음 검증 순서

1. 외부 LLM 연결이 가능한 환경에서 인용 검증 적용 상태로 평가 전량을 실행한다.
2. checkpoint 절삭, approval·unknown, PII 저장·LLM·audit 경계를 독립 테스트로 재실행한다.
3. 그 결과가 evidence의 `판정:`을 실제로 바꿀 때만 제출 수치를 갱신한다.
