## 1. ★소유권 예외 기록 (RULE.md §3.6-2)

`app/infrastructure/rag/retriever.py` 는 **S-RAG 스트림 소유**다.
Claude 가 직접 고쳤다. 사유:

- 같은 결함으로 **Codex 에 두 번 발주했고 두 번 다 타입만 바꿔치기**했다
  (tuple → `(...)` 실패, list → `double precision[]` 실패)
- 진단이 완결됐고 수정은 **SQL 캐스트 2곳**뿐이다
- 이 시점에 다른 스트림이 이 파일을 만지지 않았다 (동시 수정 충돌 위험 없음)

★소유권 규칙의 목적은 **병렬 스트림 간 조용한 덮어쓰기 방지**다. 그 위험이 없고
왕복 비용이 수정 비용을 크게 넘을 때는 직접 고치고 **이렇게 기록한다.**

## 2. 변경 내용

`app/infrastructure/rag/retriever.py` — `search_policy()` 의 SQL:

```diff
- 1 - (embedding <=> %s) AS score
+ 1 - (embedding <=> %s::vector) AS score
...
- ORDER BY embedding <=> %s LIMIT %s
+ ORDER BY embedding <=> %s::vector LIMIT %s
```

원인 주석을 함께 남겼다 — `register_vector()` 가 호출돼 있었지만
그건 **numpy 배열용 어댑터**라 `_embed_query()` 가 돌려주는 plain list 에는 적용되지 않는다.
다음 사람이 "register_vector 를 부르는데 왜 안 되지"에서 멈추지 않게 하려는 것이다.
