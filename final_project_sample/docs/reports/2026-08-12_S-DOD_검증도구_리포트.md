# DoD 전수 검사 도구 리포트

## 1. 범위

`scripts/verify_dod.py`를 추가했다. 도구는 DoD-01부터 DoD-18까지 `docs/evidence/DoD-NN_*.md`를 읽기만 하며, 각 문서에 다음 세 조건이 있는지 검사한다.

- 재현 명령을 담은 fenced code block
- 실제 출력 또는 실측 결과를 담은 fenced block
- 허용된 판정(`판정: 통과`, `판정: 부분 통과`, `판정: 미통과`)

그 뒤 `python -m pytest tests -q`를 실행한다. skipped가 있으면 경고하고 통과로 세지 않으며, evidence의 판정이 `통과`가 아니거나 테스트가 실패하면 exit code 1을 반환한다.

## 2. 현재 evidence 현황

| 상태 | 항목 |
|---|---|
| 통과 | DoD-01, DoD-02, DoD-03, DoD-12 |
| 부분 통과 | DoD-11 |
| evidence는 있으나 허용된 판정 없음 | DoD-06 |
| 미작성 | DoD-04, DoD-05, DoD-07, DoD-08, DoD-09, DoD-10, DoD-13, DoD-14, DoD-15, DoD-16, DoD-17, DoD-18 |

따라서 현재 evidence는 6/18이며, 전 항목 통과가 아니다.

## 3. 구현 중 확인한 보정

첫 실행에서 Windows 기본 코드페이지로 pytest 출력을 읽어 도구가 중단됐다. subprocess 출력을 UTF-8(`errors="replace"`)으로 읽도록 수정한 뒤 재실행했다. evidence 파일은 생성·수정하지 않았다.

## 4. 테스트 결과 요약

`python -m pytest tests -q`를 별도로 실행한 결과는 `104 passed, 3 failed, 0 skipped`이다. 실패 3건은 `tests/integration/rag/test_rag_integration.py`의 임베딩 요청이 `api.openai.com`에 연결되지 않아 발생했다(`WinError 10013`).
