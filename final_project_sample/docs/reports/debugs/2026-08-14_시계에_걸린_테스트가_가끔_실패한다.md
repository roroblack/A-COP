# 결함 — 시계에 걸린 테스트가 가끔 실패한다

- 발견: 2026-08-14 · 배포 직후 전체 실행
- 증상: `tests/unit/ports/test_team_ports.py::test_local_executor_is_identical_to_direct_team_call` 1건 실패
- 판정: **진짜 결함** (테스트 쪽). 프로덕션 코드는 정상

## 어떻게 드러났나

배포(`scripts/publish_public.py --push`) 직후 전체 실행에서 처음 실패했다.

```
FAILED tests/unit/ports/test_team_ports.py::test_local_executor_is_identical_to_direct_team_call
1 failed, 157 passed, 1 deselected
```

★**처음엔 배포 스크립트의 스크럽이 파일을 되돌리지 못한 것으로 의심했다.**
스크럽은 워킹 트리를 고쳤다가 `checkout -f` 로 복구하므로 그럴 만했다.
그러나 `git status --porcelain` 이 비어 있었고, 같은 테스트를 **단독으로 돌리니 통과**했다.

```
python -m pytest tests/unit/ports/test_team_ports.py -q   →  3 passed
python -m pytest tests -q  × 3회                          →  전부 158 passed
```

**재현되지 않는다 = 없는 문제가 아니다.** 간헐 실패는 그대로 두면 다음에 진짜 회귀가
났을 때 "또 그거겠지" 로 넘기게 된다.

## 원인

테스트가 Team 을 **두 번** 실행해 결과를 통째로 비교한다:

```python
assert (await LocalTeamExecutor(registry).execute(task)).model_dump() == (
        await team.execute(task)).model_dump()
```

그런데 `Team.execute()` 가 매 호출마다 새 Evidence 를 만들면서
`observed_at=datetime.now(UTC)` 를 찍었다.

★**두 호출이 클럭 틱을 사이에 두고 갈리면 `observed_at` 만 달라져 실패한다.**
사이가 마이크로초 단위라 거의 항상 같은 값이 나오고, 아주 가끔 아니다.

## 왜 프로덕션 결함이 아닌가

`LocalTeamExecutor` 는 정상이다. 실패한 것은 **비교 방법**이다.
이 테스트가 재는 것은 *"LocalTeamExecutor 가 Team 호출을 그대로 통과시키는가"* 이지
*"두 호출의 시계가 같은가"* 가 아니다. 시각이 비교 대상에 섞여 있었다.

## 수정

fixture 의 시각을 고정했다.

```python
FIXED_OBSERVED_AT = datetime(2026, 8, 14, 0, 0, 0, tzinfo=UTC)
```

전체 실행 4회 연속 `158 passed`.

## 남기는 교훈

★**결과 전체를 `model_dump()` 로 비교할 때는 비결정 필드가 섞여 있는지 본다.**
시각·UUID·순서가 대표적이다. 이 프로젝트에서 `deadline_at` 은 task 에 한 번만 찍혀
문제가 없었고, `observed_at` 만 호출마다 새로 찍혀 걸렸다.

★**간헐 실패를 "환경 탓" 으로 닫지 않는다.** 이번엔 배포 스크립트를 의심했고
그게 맞았다면 배포 절차 결함이었을 것이다. 단독 실행과 반복 실행으로 갈라 봐야
어느 쪽인지 정해진다.
