## 3. ★가장 큰 구멍 — §9-E 할루시네이션 방어

v7 §9-E 는 이 결정을 **"v6에 이미 있었던 것으로 간주하지 않는다. 이번 v7에서 정한다"** 로 시작하고,
방어층 표에서 핵심 두 줄의 "v6에 있나" 를 **없음**으로 적어 두었다.

### 지금 있는 것 — 내부 정합성 검사뿐

`app/core/contracts.py:283-289`

```python
known = {e.evidence_id for e in self.evidence}
for proposal in self.action_proposals:
    unknown = set(proposal.rationale_evidence_ids) - known
    if unknown:
        raise ValueError(...)
```

이것은 **"제안이 자기 결과 안의 evidence 를 가리키는가"** 를 볼 뿐이다.
그 evidence 가 **현실과 맞는지는 보지 않는다.**

### 없는 것 — 현실 대조

`app/application/controller.py:171-178`

```python
for proposal in result.action_proposals:
    ...
    self.repository.create_action_request(
        conn, ..., action_type=proposal.action_type,
        arguments=proposal.arguments,       # ← ★그대로 저장한다
        idempotency_key=server_key, status="pending_approval")
```

`proposal.arguments` 가 **아무 대조 없이** `action_requests` 로 들어간다.

★**실제 결제액이 30,000원인데 LLM 이 "50,000원 환불" 을 제안하면 그대로 통과한다.**
v7 §9-E 가 예시로 든 바로 그 상황이 지금 막히지 않는다.

없는 검증(v7 표 기준): `order_id` · `payment_id` · `subscription_id` 실재/소유권,
`amount` 최신 결제액·환불 가능 잔액, `quantity` 취소 가능 수량,
`evidence_ids` 의 source digest, **실행 직전 재검증**(2회 검증 중 두 번째).

### degraded 는 "부분" 이다 — 강제가 아니라 자율

`app/modules/customer_ops/billing.py:56` · `technical.py:42`

```python
if task.context.degraded:
    return TeamResult(..., outcome="escalated", failure_code="degraded_context", ...)
```

두 Team 이 **각자 스스로** 검사한다. Core 가 강제하지 않는다.
★**새 Team 이 이 검사를 빠뜨리면 아무도 막지 않는다.**
v7 §9-E 는 "Controller 가 … 실행하지 않는다" 로 **플랫폼 강제**를 요구한다.

> 검사하지 않는 규칙은 지켜지지 않는다. 지금은 Team 의 선의에 기대고 있다.

## 4. ★테스트가 v7이 없앤 제약을 강제하고 있다

`tests/integration/api/test_openapi_surface.py`

```python
def test_v1_surface_matches_contract_exactly() -> None:
    assert actual == CONTRACT_V1_PATHS      # ★집합 완전 일치
```
docstring: `★/v1/ 아래에 6번째 경로가 생기면 그것이 위반이다.`

그런데 v7 §0 은 **"5는 당시 MVP 범위 숫자이며 상한이 아니다"** 로 바꿨고,
v7 DoD-13 은 **"5가 상한이 아님을 문서·추가 endpoint fixture 로 검증"** 하라고 한다.

**지금 테스트는 그 반대를 강제한다.** endpoint 를 하나 늘리는 순간 실패한다.

★이것은 **composer 기본값 때와 똑같은 실패 유형**이다 —
그때도 테스트가 "저장소 기본값 = 꺼짐" 을 강제해서, 정작 쓰려는 기능이 계속 404 였다.
**테스트가 검사하는 것이 지금도 의도한 성질인지** 확인하지 않으면
테스트가 제품을 낡은 방향으로 붙잡는다.

고칠 방향: 완전 일치 대신 **"계약에 있는 경로가 전부 있다"(⊆) + 새 경로는
scope·idempotency·audit·평가 fixture 를 갖췄는지** 검사로 바꾼다.

## 6. 평가 지표도 늘었다

v7 §9-E 는 평가에 5개 지표를 **추가**하라고 한다 —
근거 정합률 · 근거 초과율 · 적절한 기권율 · 과잉 기권율 · 스키마 준수율.
각각 **분모와 fixture 를 함께** 기록해야 한다.

현재 rubric 은 `correctness · policy_grounding · next_action · safety · personalization` 5종이다.
**다섯 지표 모두 없다**(검색 0건). fixture 도 없다 —
존재하지 않는 `order_id`, 불일치 금액, degraded Context, 인젝션 입력.
