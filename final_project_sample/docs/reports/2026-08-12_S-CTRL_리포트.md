# S-CTRL 구현 리포트

## 1. 목표

Controller 실행 루프, Team Registry, WAIT/RESUME 토큰 정책, Outbox worker와 checkpoint 경계를 소유 범위 안에 추가했다.

## 2. 변경 파일

- `app/core/registry.py`
- `app/application/controller.py`
- `app/application/case_service.py`
- `app/infrastructure/messaging/{ports,outbox,worker}.py`
- `scripts/run_outbox_worker.py`

기존 `transition_case()`, reducer, Team 구현, API, DB 모듈은 수정하지 않았다.

## 3. 구현 요약

- Registry는 주입받은 Team만 등록하며 capability를 유일 Team으로 해석한다. 계약 버전은 같은 major만 허용한다.
- Controller는 routing → ContextBroker → Team execute → `transition_case()` 순서로 실행한다.
- RAG 예외는 빈 결과로 대체하지 않고 `retrieval_failed=True`로 ContextBroker에 전달한다.
- WAIT token은 `secrets`로 생성하고 SHA-256 hash, 만료 시각, 사용 여부만 projection state에 저장한다.
- Outbox는 `SKIP LOCKED` claim, dedupe key, delivered/dead_letter/unknown 상태를 사용한다. provider timeout은 성공으로 처리하지 않는다.
- checkpoint는 case/run/revision/node와 최소 runtime state만 가진다.

## 4. 실제 검증 출력 원문

### 계약·단위 테스트

```text
python -m pytest tests/contract tests/unit -q
...................................................................      [100%]

```

### 전체 테스트

```text

92 passed, 4 failed
```

실패는 다음 기존 범위의 문제였다.

- `tests/integration/api/test_openapi_surface.py`: UI route가 OpenAPI에 포함됨
- `tests/integration/rag/test_rag_integration.py` 3건: `api.openai.com` embedding 호출이 환경 네트워크 정책으로 `[WinError 10013]` 차단됨


저장소에 해당 디렉터리/테스트가 아직 없어 실행할 테스트가 없었다.

### Outbox worker 및 DB 상태

```text

tenants=1
new=3
```

## 5. 시나리오 상태 전이

Controller의 전이 경로는 다음과 같다. API가 이미 생성/분류를 수행한 Case를 입력으로 한다.

- 해지 후 추가 결제: `routing → running → waiting_approval`; 승인 이벤트 후 `resuming → running → resolved`
- Free/Pro 권한 불일치: `routing → running → resolved`

실제 DB에서 해당 두 시나리오를 재생한 상태·version 목록은 Controller 통합 테스트 fixture 부재로 산출하지 못했다.

## 6. 미검증/후속

Controller 통합 fixture와 fake Team/LLM, 실제 approval endpoint와 Controller resume 연결은 다음 스트림 또는 테스트 fixture 보강이 필요하다. 기존 UI·RAG 파일은 소유 범위 밖이므로 수정하지 않았다.
