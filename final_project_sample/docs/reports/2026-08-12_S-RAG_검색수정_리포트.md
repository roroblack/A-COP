# S-RAG 검색 수정 리포트

## 1. 수정 내용

- `app/infrastructure/rag/retriever.py`의 질의 임베딩을 `tuple`이 아닌 `list[float]`로 유지했다. ingest 경로와 같은 `register_vector(conn)` 어댑터가 pgvector 리터럴을 `[...]`로 직렬화한다.
- tenant/scope에 해당 문서가 하나도 없으면 임베딩 API를 호출하지 않고 즉시 `[]`를 반환하도록 했다.
- `tests/integration/rag/test_rag_integration.py`의 corpus fixture에서 데이터 부재 시 `pytest.skip`하던 로직을 assertion failure로 변경했다.
- `knowledge/documents/*.md`와 적재 데이터는 수정하지 않았다.

## 2. 코퍼스 기대값 확인

manifest와 원문을 직접 확인했다.

| 기대 문서 | 원문 파일 | scope | 확인 내용 |
|---|---|---|---|
| `doc_06` | `06_refund_refund-after-cancel.md` | `refund` | 해지 후 발생한 청구의 환불 정책 |
| `doc_14` | `14_entitlement_plan-matrix.md` | `entitlement` | 플랜별 권한과 한도 표, Pro 기능 묶음 |

따라서 테스트 기대값 `doc_06`, `doc_14`는 코퍼스와 일치한다.

## 4. top-8 검색 결과

이 실행 환경에서는 외부 OpenAI 임베딩 호출이 차단되어 두 자연어 질의의 실제 query embedding 기반 top-8을 생성할 수 없었다. 결과를 임의로 만들지 않기 위해 실제 질의의 top-8은 `API 연결 차단으로 미생성`으로 기록한다.

저장된 corpus 벡터를 query vector로 주입한 probe로 검색 SQL, top-k, tenant 조건, scope 조건이 실제 DB에서 실행되는 것은 확인했다. 아래는 **자연어 질의의 의미 검색 결과가 아니라 pgvector 바인딩·필터 검증용 probe top-8**이다.

## 5. 미완료 조건과 원인

코드 수정 및 DB 적재 상태 확인은 완료했지만, 이 환경의 네트워크 정책 때문에 요구된 자연어 임베딩 기반 3개 통합 테스트의 최종 통과는 확인하지 못했다. 이는 코퍼스 적합성이나 scope 필터가 아니라 질의 임베딩 API 연결 차단이다. OpenAI embedding endpoint가 접근 가능한 환경에서 전체 pytest를 재실행해야 최종 DoD를 판정할 수 있다.
