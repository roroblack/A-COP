# S-CONSOLE P4·P5·P6 구현 리포트

## 1. 범위

핸드오프가 허용한 `app/presentation/ui/console.py`, `tests/e2e/`, `docs/reports/`만 수정했다. `theme.py`와 금지된 API·라우팅·도메인·평가 소스는 수정하지 않았다.

## 2. 구현 결과

- `/ui/quality`: `docs/evidence/DoD-*.md`를 읽어 DoD 28개를 모두 행으로 표시한다. 판정과 근거 문서, 재현 명령 블록 유무, 실제 출력 유무를 분리한다.
- Quality 게이트는 pytest나 검증 스크립트를 실행하지 않고 `docs/reports/`에 남은 기록만 읽는다. 기록이 없으면 `측정값 없음`을 표시한다.
- `/ui/experiments`: `eval/reports/*.jsonl`을 run 파일 단위로 표시하고 arm·dataset·provider·행수·ablation·holdout을 구분한다. 비용·토큰·latency는 `observed`·`mock`·`missing` 상태로 표시한다.
- 평가 화면은 최근 6개만 보여주며 `전체 M개 중 M-N개는 화면에 없다`를 표시한다.
- `eval/defense_metrics.py`와 `eval/datasets/attack_fixtures.jsonl`, ablation 5종의 연결을 표시하되 화면에서 평가를 실행하지 않는다.
- `/ui/runs/{run_id}`: `agent_runs → team_tasks → llm_calls (prompt FK) → case_events` 최소 trace를 읽기 전용으로 표시한다. span 검색·실시간 tail·세션 분석·대시보드 빌더는 만들지 않았다.
- `console_ui: false`에서는 Quality·Experiments도 라우터 자체가 등록되지 않아 404가 된다.

## 3. 추가 테스트

`tests/e2e/test_console_dashboard.py`에 다음 4개를 추가했다.

- Quality의 DoD 28·기록 게이트·콘솔 관객 경계
- Experiments의 측정 상태·절삭 고지·방어지표 연결
- console_ui 비활성 시 Quality·Experiments 404

관련 e2e 결과: `12 passed`.


## 5. 검증 결과 및 발견한 결함

정적 컴파일 및 관련 e2e:

```text
12 passed
```

전체 테스트:

```text
308 passed, 3 failed, 1 deselected
```

실패한 3건은 `tests/integration/rag/test_rag_integration.py`의 검색 관련 테스트다. `api.openai.com` 임베딩 호출이 실행됐고, 샌드박스 네트워크 권한 오류(`WinError 10013`)로 실패했다. 이번 콘솔 변경이 RAG 코드를 수정하거나 해당 호출을 추가한 것은 아니다. 기존 기록의 `308 passed`를 화면에서 임의로 보정하지 않고 파일에 남은 최신 기록인 `172 passed`를 표시한 것도 확인했다.

추가로 기존 테스트의 `test_mock_runs_are_marked_as_not_real_performance`에는 기존 `pytest.skip`이 남아 있다. 핸드오프의 소유 범위와 “기존 테스트 단언을 고쳐서 통과시키지 말라”는 규칙에 따라 이 기존 테스트를 바꾸지 않았다.

## 6. 만들지 않은 것

span 검색, 실시간 tail, 세션 분석, 대시보드 빌더, 화면 내 pytest·평가 실행은 만들지 않았다. P6의 목적은 한 run의 최소 provenance를 확인하는 것이고, 이 기능들은 IA 검토에서 현재 범위에 비해 과하다고 명시된 항목이기 때문이다.
