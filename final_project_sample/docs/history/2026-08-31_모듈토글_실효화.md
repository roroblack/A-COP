# 2026-08-31 — 모듈 토글 실효화 (cs 에서 이식)

## 무엇을

선언에서 모듈을 꺼도 아무 일이 일어나지 않던 것을 고쳤다. 여섯 모듈 중 `mcp` 와
`voc` 에 게이트가 아예 없었다. 운영 화면에 남아 있던 `SqlGraphAdapter` 죽은 import 도 지웠다.

## 왜

`final_project_cs` 에서 2026-08-30 에 같은 결함을 고쳤다. 이 저장소는 cs 가 가져다
쓰는 참고 구현체이므로, 여기를 안 고치면 다음 이식 때 cs 의 수정이 덮인다.

`mcp` 가 제일 무거웠다. 도입 기업이 개인 AI 접근을 안 열기로 하고 껐는데
실제로는 tool 3종이 그대로 동작했다.

## 어떤 결과로

- 여섯 모듈 전부가 선언에 따라 실제로 코드를 가른다. 선언을 바꿔 가며 확인했다
  (`python -m scripts.verify_module_toggles`).
- 계약 테스트 8건 신규. 전체 461 → 469 통과, 회귀 0건.
- `/ops/voc` 를 브라우저로 열어 확인했다. `voc` 를 끈 상태는 앱이 안 뜨므로
  `mount_ui()` 를 직접 불러 화면과 메뉴가 함께 빠지는 것을 확인했다.

## cs 와 다르게 한 것

- **메뉴를 기동 시점에 한 번 정한다**(`configure_nav(config)`). cs 는 요청마다 선언을
  다시 읽는데, 그러면 라우터와 메뉴가 어긋날 수 있다. cs 쪽도 이 방식으로 바꾸는 것을
  다음 작업으로 넘긴다.
- basement 안의 게이트는 basement 자신의 로더를 쓴다. product 를 최상위에서
  import 할 수 없기 때문이다.

## 틀렸던 것

- 계획서에 "운영 화면이 SqlGraphAdapter 를 직접 만든다" 라고 적었다가 실측하고 고쳤다.
  cs 가 그랬으니 여기도 그럴 것이라 짐작한 것이다. 실제로는 쓰지도 않는 import 였다.
- 회귀 테스트를 "basement 는 app 을 아예 import 하지 않는다" 로 짰다가 6건이 걸렸는데
  전부 의도된 지연 import 였다. "최상위 import 금지" 로 고쳤다.
