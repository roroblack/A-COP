## ★0. v1 이 왜 거부됐는지 먼저 읽어라

`legacy/S-RAG_v1_보일러플레이트/06_refund_refund-after-cancel.md` 를 **열어 봐라.**

12개 섹션이 전부 이렇게 생겼다:

```
## 적용 범위
(어느 문서에나 들어가도 말이 되는 일반론) + (그 문서 주제 문장 2개)
## 정책 용어
(어느 문서에나 들어가도 말이 되는 일반론) + (똑같은 주제 문장 2개)
## 적용 대상
(어느 문서에나 들어가도 말이 되는 일반론) + (똑같은 주제 문장 2개)
...
```

같은 꼬리문장이 **한 문서 안에서 12번** 반복됐고, 25문서가 **같은 12개 섹션 제목**을 썼다.
같은 제목 섹션끼리 문서 간 문자 6-gram Jaccard 가 **0.44~0.50** — 절반이 같은 글이다.

**이게 왜 치명적인가.** RAG 검색은 청크끼리 얼마나 다른지로 작동한다.
300 청크의 절반이 같은 문장이면 top-k=8 이 질의와 무관하게 아무거나 집어 온다.
그러면 이 프로젝트의 핵심 주장(정책 근거 기반 답변, groundedness 측정, no_rag ablation)이
전부 무의미해진다. **건수를 맞추는 것이 목표가 아니다.**

## 5. ★이번에 바뀐 것 — 작성 규칙

### 5-1. 섹션 제목은 문서마다 달라야 한다

★**공통 섹션 템플릿을 쓰지 마라.** `적용 범위 / 정책 용어 / 담당 주체` 같은 제목을
25문서에 돌려 쓰면 **자동 거부**된다(`check_corpus.py`: 한 제목이 문서의 50% 초과 사용 시 실패).

섹션 제목은 **그 문서에서만 말이 되는 것**이어야 한다.

- ❌ `## 적용 범위` `## 예외 조건` `## 담당 주체`
- ✅ `## 해지 효력 시각과 청구 큐의 시차` `## 이미 발생한 청구의 환불 판정 기준`
  `## 사용량이 있는 경우의 일할 정산` `## 환불 불가 사유와 대체 조치`

### 5-2. 같은 문장을 두 번 쓰지 마라

★**한 문서 안에서 같은 문장이 두 섹션에 나오면 자동 거부**된다.
문서 전체를 관통하는 요약을 매 섹션에 붙이지 마라. 각 섹션은 **다음 섹션이 이어받는다**고 보고 쓴다.

### 5-3. 섹션마다 새로운 사실을 담아라

한 섹션 = **하나의 인용 가능한 근거**. 답변에 `doc_06#c04` 로 인용된다.
"이 섹션을 인용하면 고객에게 무슨 말을 해 줄 수 있나?"에 답이 나와야 한다.
답이 "일반적으로 정책을 지켜야 한다" 뿐이면 그 섹션은 지워라.

### 5-4. ★구체적인 숫자를 넣어라 (이번엔 검사한다)

`check_corpus.py` 가 잰다: **문서의 90% 이상**, **섹션의 40% 이상**이
`\d+(일|영업일|시간|분|초|%|원|건|회|개월|년)` 형태의 수치를 가져야 한다.

- ✅ "환불 요청은 결제일로부터 **14일 이내**에 접수해야 한다"
- ✅ "권한 동기화는 정상 시 **60초**, 지연 시 **최대 15분**까지 걸린다"
- ✅ "월간 구독 해지는 신청 즉시가 아니라 **당월 청구주기 종료일 23:59 UTC** 에 효력이 발생한다"
- ✅ "Pro 플랜 멤버 한도 **25명**, Business **200명**"
- ❌ "빠른 시일 내에", "정책이 정한 기한 내에", "적절한 절차에 따라"

**수치는 문서 간에 서로 모순되면 안 된다.** 한 문서에서 14일이라 했으면 다른 문서도 14일이다.
플랜 한도·동기화 시간·환불 기한을 **미리 정해 놓고** 일관되게 써라.

### 5-5. 문서 형식

```markdown
---
document_id: doc_06
title: 해지 후 발생한 청구의 환불
scope: refund
version: "1.0"
pii_class: none
effective_from: 2026-01-01
source_uri: internal://nimbus/policy/refund/refund-after-cancel
---

## 해지 효력 시각과 청구 큐의 시차

(200~600자. 이 섹션에서만 알 수 있는 사실을 구체적인 수치와 함께)

## (이 문서에서만 말이 되는 다음 제목)
...
```

- 섹션 수: 문서당 **12~16개** (총 300~400)
- 각 섹션 **200~600자**
- PII 금지. `pii_class` 는 `none` 또는 `masked` 만

## 6. 시나리오 근거 필수 (검사한다)

`check_corpus.py` 가 정규식으로 존재를 확인한다. 아래가 **어느 섹션엔가 구체적으로** 있어야 한다.

| 검사 항목 | 무엇이 있어야 하나 |
|---|---|
| 해지 후 추가 결제 | "해지 … 추가 결제/결제가 발생/청구" 가 이어지는 문장 |
| 환불 기한 (숫자) | `N일 이내` 또는 `N영업일 이내` 형태 |
| 권한 동기화 지연 (숫자) | 동기화와 `N분`/`N초`/`N시간` 이 같은 문장 안에 |
| 진단 순서 | "진단 순서" 또는 "확인 절차" 라는 말과 함께 **번호 붙은 단계** |
| 승인 없이 실행 금지 | "승인 없이 … 실행하지 않는다" 취지의 문장 |

## 7. ★완료 조건 — 이 명령이 통과해야 끝이다

```powershell
python -m scripts.check_corpus
```

**exit code 0 이 나올 때까지 고쳐라.** 이 스크립트가 검사하는 것:

| 항목 | 기준 |
|---|---|
| 문서 수 / 총 섹션 / 문서당 섹션 | 25 / 300~400 / 12~16 |
| scope 배분 | §4 표와 정확히 일치 |
| ★문서 내 동일 문장 반복 | **최대 1회** (2회 이상이면 실패) |
| ★섹션 제목 공유 | 한 제목이 **문서의 50% 초과 사용 시 실패** |
| ★문서 간 같은제목 섹션 유사도 | 6-gram Jaccard 평균 **< 0.25** |
| ★구체 수치 | 문서 **90%** 이상 / 섹션 **40%** 이상 |
| 시나리오 근거 5종 | 전부 존재 |
| manifest | 파일 수·document_id 유일성·section_count 실측 일치 |

★**스크립트를 고쳐서 통과시키지 마라.** `scripts/` 는 당신 소유가 아니다.
기준이 불합리하다고 판단되면 **고치지 말고 리포트에 사유를 적어라.**
