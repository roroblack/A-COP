## 0. 무엇을 잘못 잡고 있었나

`/ui/*` 를 **최종 고객사 CS 운영 화면**처럼 만들었다. 그게 아니다.

★**이 콘솔의 사용자는 "CS 제작 플랫폼을 굴리는 우리"다.**
모듈을 붙였다 뗐다 하고 → 샘플을 굴려 보고 → 결과를 점검하고 → 이 모듈화 프로젝트를 관리한다.
Composer 가 여기 있는 이유가 그것이다.

`cases`·`approvals`·`voc` 는 **샘플 런타임을 들여다보는 창**일 뿐이다.

## 2. ★Codex 교차검증에서 뒤집힌 것

내 초안은 `quality`·`experiments`·`sample` 을 **독립 지표 페이지**로 뒀다. 그게 문제다.

> 화면의 기준을 "메뉴별 지표" 가 아니라
> **프로젝트 구성과 그 구성에서 나온 검증·평가·샘플 실행의 추적성**으로 바꾸라.

즉 하나의 흐름이어야 한다:

```
구성 revision → 검증 결과·증거 → 평가 run(arm·dataset·prompt snapshot) → 샘플 case·trace
```

이 연결이 없으면 **"마지막 실행 결과"가 어느 조립 상태에서 나온 것인지 알 수 없어 재현성이 사라진다.**

### ★하지 말라고 지적받은 것 (전부 수용)

| 하지 말 것 | 이유 |
|---|---|
| DoD 28 → **점수 하나** | 부분통과·미작성의 위험이 가려진다. 상태 분포 + blocker 목록이 먼저다. 점수를 낸다면 **계산식·분모·판정 시각·구성 revision** 을 함께 |
| 평가 540행 **평균**을 최신 품질로 | arm·dataset hash·prompt snapshot·holdout 여부 없는 평균은 비교 불가 |
| 비용·토큰·latency 를 **운영 KPI** 처럼 | mock 실행의 $0·p95 를 실제 성능처럼 띄우면 안 된다. `observed`/`estimated`/`mock`/`missing` 을 분리 |
| Langfuse식 **전체 trace** | 지금 필요한 건 case event ↔ agent run ↔ team task ↔ prompt/LLM call ↔ evidence 최소 연결 |
| Backstage식 **전체 카탈로그** | 선언이 하나다. 소유자·revision·수명주기·검증 상태만 |
| Composer 에서 **바로 실행·배포** | 미검증 구성으로 샘플을 돌릴 수 있으면 `unvalidated` 를 강하게 표시하고 승인 경로와 분리 |
| Admin 을 **설정 변경 화면**으로 | Composer 와 책임이 겹친다. Admin 은 읽기 전용 실측 |

## 3. ★관객은 둘이다

| # | 관객 | 무엇을 하나 | 범위 |
|---|---|---|---|
| 1 | **플랫폼 운영자 (우리)** | 모듈 조립·검증·평가·프로젝트 관리 | **전체** — 구성·DoD·평가·모든 tenant |
| 2 | **B2B 고객사 (쇼핑몰 운영자)** | 자기 CS 를 본다 — Case·승인·VOC | ★**자기 tenant 만** |

★**내가 처음 만든 `cases`·`approvals`·`voc` 는 버릴 것이 아니라 2번이다.**
"샘플 런타임 창" 이라고 규정한 것이 틀렸다 — 그건 **고객사에 납품되는 제품 화면**이다.

### ★한때 이걸 셋으로 잘못 쪼갰다

"우리가 고객사 화면을 들여다보는 것" 을 3번 관객으로 뒀다. **아니다.**

- 그건 관객이 아니라 **권한**이다. 같은 화면을 넓은 scope 로 보는 것뿐이다
- 원인: "샘플 런타임 창" 이라는 옛 규정을 고치면서 **틀린 칸을 지우지 않고 새 이해를 덧붙였다**
- 교훈: **보는 사람의 권한을 화면의 정체성으로 착각하지 않는다.**
  화면이 나뉘는 기준은 *누가 보느냐* 가 아니라 *무엇에 답하느냐* 다

### 경계

```
/ui/**      개발 콘솔      플랫폼 운영자 전용. ★고객사에 노출되지 않는다
/ops/**     고객사 대시보드  tenant 범위. ★자기 tenant 밖은 보이지 않는다
```

★이건 화면 배치가 아니라 **보안 경계**다. 기존 tenant 격리(`403` 아닌 `404`)가
그대로 여기에 걸린다. **테스트로 강제한다** — 고객사 화면이 tenant 조건 없는 조회를 하면 실패.

★모듈도 갈린다: `ops_ui`(고객사) / `console_ui`(개발 콘솔).
쇼핑몰로 복사하면 **`console_ui` 를 끄고 납품**한다.

## 4. 확정 IA

### 개발 콘솔 — `/ui/**` (플랫폼 운영자)

```
/ui/                 대시보드 — 현재 구성·막힘·최근 실행
 ├ /ui/composer      선언 편집 + 구성 후보 검증        (기존 유지)
 ├ /ui/quality       DoD·게이트·증거
 ├ /ui/experiments   평가·ablation·방어지표
 ├ /ui/tenants       ★진입점일 뿐 — 어느 tenant 의 /ops 로 갈지 고른다. 별도 화면군이 아니다
 └ /ui/admin         실제 조립 결과·런타임 실측        (읽기 전용)
```

### 고객사 대시보드 — `/ops/**` (쇼핑몰 운영자)

```
/ops/                내 CS 현황 — 처리 대기·에스컬레이션·오늘 유입
 ├ /ops/cases        Case 목록·상세·trace
 ├ /ops/approvals    승인 (되돌릴 수 없는 행위)
 └ /ops/voc          VOC 리포트·급증 alert
```

★고객사 화면에는 **DoD·평가·모듈 조립이 보이지 않는다.** 그건 우리 사정이다.
반대로 개발 콘솔에는 **개별 고객 메시지 원문이 보이지 않아야** 한다(PII).

## 4. 단계별 실행 (RULE.md §3 — 하나 고치면 그것만 검증하고 다음으로)

### P1. 구성 revision — 추적성의 뿌리
`config/project.yaml` 의 **내용 해시**를 계산해 모든 화면이 같은 revision 을 표시한다.
이게 없으면 나머지 연결이 전부 허공이다.

- `app/core/project_config.py` 에 `revision` (sha256 앞 12자) 추가
- 완료 조건: 선언을 바꾸면 revision 이 바뀌고, 안 바꾸면 그대로

### P2. 관객 분리 — `/ops/**` 와 `/ui/**`
`cases`·`approvals`·`voc`·`trace` 를 **`/ops/` 로** 옮긴다. 옛 경로는 리다이렉트.
모듈을 `ops_ui`(고객사) / `console_ui`(개발 콘솔)로 가른다.

- 완료 조건: 기존 e2e 가 새 경로로 통과 · 옛 경로 살아 있음
- ★**경계 테스트**: `console_ui: false` 면 `/ui/*` 가 전부 404 이고 `/ops/*` 는 200
- ★**PII 경계 테스트**: 개발 콘솔 화면에 고객 메시지 원문이 없다

### P3. `/ui/` 대시보드
사람이 가장 자주 묻는 것에 답한다 — **"지금 조립이 뭐고, 무엇이 막혀 있고, 마지막 실행은?"**

- 현재 구성(revision·모듈·Team·Port) + `unvalidated` 여부
- ★**막힌 것 목록** — 부분통과 DoD, 미착수, 실패 게이트. 점수 대신 **blocker**
- 최근 실행 — run 단위, arm·dataset 표기

### P4. `/ui/quality`
DoD 28 을 **상태 분포 + 근거 링크**로. 28칸 초록 카드가 아니다.
`verify_dod` 가 구분하는 evidence 존재·재현 블록·실제 출력·판정을 **그대로** 보여준다.

### P5. `/ui/experiments`
평가 run 단위로 arm·dataset·prompt snapshot·holdout·ablation·방어지표.
★비용·토큰·latency 는 `observed`/`estimated`/`mock`/`missing` 을 구분해 표시.

### P6. 최소 trace 연결
case event ↔ agent run ↔ team task ↔ llm_call ↔ evidence.
★span 검색·실시간 tail 은 만들지 않는다.
