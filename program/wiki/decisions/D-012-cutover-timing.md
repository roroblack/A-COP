# D-012 전환은 중간발표 후에 한다

`[실측]` 2026-09-03 결정.

## 결정

> **`program/wiki/` 를 실제 저장소로 옮기는 것은 중간발표(2026-09-15) 이후에 한다.**

**그때까지 두 구조가 공존한다.** `CLAUDE.md` 와 `docs/` 가 계속 정본이다.

## 왜

**발표 전에 옮기면 잃을 게 크고 얻을 게 없다.**

| | 발표 전 | 발표 후 |
|---|---|---|
| 진입 경로가 바뀐다 | **발표 준비 중에 팀이 헤맨다** | 여유가 있다 |
| 링크 89곳 · 코드 경로 83곳 | 깨지면 발표 자료가 막힌다 | 고칠 시간이 있다 |
| 얻는 것 | **없다** — 발표에 wiki 구조는 안 나온다 | 다음 사이클부터 쓴다 |

**발표는 제품을 보여주는 자리이지 문서 구조를 보여주는 자리가 아니다.**

## 그때까지 하는 것

`[실측]` **대조는 계속한다.** 전환을 앞당기지는 않지만 **원본을 고치는 값이 있다.**

지금까지 **9번 대조에 9건**이 나왔고 그중엔 이런 게 있었다.

> 법정 지연이자를 **연 40%(상한)를 실제 요율처럼** 적고 있었다. 실제는 **연 15%**.

**그대로 답하면 고객에게 2.7배를 약속하는 셈이다.** 발표 전에 잡는 게 맞다.

| 하는 것 | 안 하는 것 |
|---|---|
| 남은 대조 33건 | **저장소로 옮기기** |
| 검사기 유지 | `CLAUDE.md` 진입점 추가 |
| **경로 재작성 스크립트 준비** | **그 스크립트 실행** |
| 낡음 검사 | 분할 결과 적용 |

**세 번째가 중요하다.** 도구는 미리 만들어 두고 **실행만 미룬다.** 발표 후에 만들기 시작하면 또 미뤄진다.

## 전환 시점에 정해야 할 것 셋

`[미확보]` **아직 안 정했다.** 발표 후에 정한다.

1. **놓을 자리** — `<저장소>/wiki/` 인가 `docs/wiki/` 인가
2. `docs/` 와의 읽기 순서
3. 팀에 알릴 시점

→ [../governance/cutover.md](../governance/cutover.md)

## 되돌릴 조건

`[실측]` **발표 전에 전환해야 하는 경우가 하나 있다.**

> **발표 자료가 wiki 문서를 근거로 인용해야 할 때.**

그러면 "이 문서가 어디 있나"를 답해야 하고, `program/` 은 답이 안 된다.

`[미확보]` **발표 자료가 무엇을 인용할지 안 정해졌다.**
