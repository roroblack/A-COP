## ★ 왜 정반대인가 — 폴더가 아니라 형식이다

| | `program/research/` | `docs/evidence/` |
|---|---|---|
| 일치율 | **7.7%** | **100%** |
| 문서 형식 | 없음 | **강제됨** |

`docs/evidence/` 의 35개 판정본은 전부 같은 골격이다.

```
## 재현 명령      ## 실제 출력
## 판정 근거      ## 한계
```

**형식이 강제된 곳에서는 정규식이 맞는다.** 형식이 없는 곳에서는 폴더 이름밖에 볼 게 없고, 그건 틀린다.

**이게 6·7차와 8차를 같이 설명한다.** 휴리스틱의 성능은 문서 집합의 성질이지 휴리스틱의 성질이 아니다.

## ★ `_raw/` 를 통째로 제외하면 안 된다 — 6차 판정을 뒤집는다

`[실측]` **6차 표본 5번에서 나는 이렇게 적었다.**

> `_raw/` 는 통째로 제외 대상

**틀렸다.** 판정본이 `_raw/` 를 실측 원문으로 **인용한다.**

```
DoD-05_ContextPack_토큰예산.md:5
  재측정: 2026-08-14 · 실측 원문 `docs/evidence/_raw/DoD-05_v4.md`
```

**끊으면 근거 사슬이 끊긴다.** 판정본에 남는 건 "통과"라는 결론뿐이고, 그 아래 실제 명령과 출력이 사라진다.

### 인용 여부로 갈린다 — 24건 중 11건

`[실측]` 세어 봤다.

| | 건수 | 무엇 |
|---|---|---|
| **인용됨** | **11** | 판정본이 가리킨다. **유지** |
| 고아 | 13 | 중간판(v2·v3). **제외** |

```
인용됨: DoD-04_v3 · 05_v4 · 07_v2 · 08 · 09_v2 · 10_v4
        11_v3 · 13 · 14 · 17 · 18
```

**`DoD-05` 는 v1·v2·v3·v4 가 다 있는데 v4 만 인용된다.** 중간판 셋은 재측정 과정의 흔적이다.

### 스크립트에 넣었다

```python
if "/evidence/_raw/" in n:
    verdict = "유지" if base in cited else "제외"
```

`cited` 는 형제 판정본에서 `_raw/…\.md` 를 정규식으로 뽑는다. **사람이 세지 않는다.**

**이 규칙은 맨 마지막에 온다.** 길이 하한보다 뒤다 — 실측 원문은 명령과 출력만 담아 원래 짧고, 40줄 하한이 먼저 걸리면 근거 사슬이 "판정필요"로 묻힌다.

```
판정필요 76 → 60건   (인용된 11건이 유지로 확정)
```

## ★ 고아 하나가 코드의 이상한 부분을 설명한다

`_raw/DoD-18_v3.md` 는 인용되지 않는다. **그런데 판정본에 없는 관측이 있다.**

> trace 본문 검색의 `case_id_exact` 와 `case_id_prefix` 는 **모두 `False`** 였다.

**Trace 화면에 case_id 가 아예 없었다는 뜻이다.** 판정본은 같은 항목을 **"통과"**로 적고 있다.

`[실측]` 현재 코드를 봤더니 **고쳐져 있었다.**

```python
# app/presentation/ui/routes.py:88
data["trace_identity"] = {"case_id": str(data["case_id"]), "subject": …}
data["events"][0]["payload"] = {"trace_case": data["trace_identity"], **…}
```

**이 필드가 왜 있는지는 v3 를 읽어야만 안다.** 첫 이벤트 payload 에 Case 정보를 밀어 넣는 건 그것만 보면 중복이다.

`[추정]` **고아 13건을 다 제외하면 이런 설명이 같이 사라진다.** 제외는 삭제가 아니므로 원본은 남지만, wiki 에서 닿을 길이 없어진다.
