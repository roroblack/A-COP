# 응답 모델 후보를 고르는 기준

`[실측]` 2026-09-03 작성.

## 왜 필요한가

**저장소 전체에 모델 후보를 비교한 문서가 없다.**

`[실측]` `Qwen/Qwen2.5-3B-Instruct` 를 쓴 이유로 기록된 것은 **크기 결정 하나뿐**이다.

> 3B 모델은 12GB VRAM 에 **양자화 없이도** 들어가서 이 우회가 가능했다 **(7B였다면 막혔을 것).**

**Windows 페이징파일 버그로 4-bit QLoRA 가 안 돌아서 bf16 이 강제됐고, 그래서 3B 가 강제된 것이다.**

> **"Qwen2.5 를 골랐다"가 아니라 "3B 급이 강제됐고 그중 Qwen2.5-3B 를 썼다"이다.**

**왜 그 자리에 Qwen 인지는 안 적혀 있다.**

## ★ 전제가 바뀌었다

`[실측]` 2026-09-03 x600 실측.

| | 당시 전제 | 오늘 |
|---|---|---|
| 측정된 Free | 12GB 가정 | **6.17GB** (데스크톱이 5.8GB 점유) |
| 3B bf16 | 들어간다 | **가중치만으로 거의 다 참** |

→ [../business/infrastructure-cost.md](../business/infrastructure-cost.md)

**3B 조차 빠듯할 수 있다.** `[미확보]` 축출 여부에 달렸다.

## 기준 — 통과선과 측정 방법

### 1. 메모리 (탈락 조건)

| | |
|---|---|
| 가중치 + KV 캐시가 들어가야 한다 | 안 들어가면 **탈락** |
| 측정 | `nvidia-smi` 로 로드 후 실사용량 |

`[미확보]` **선이 6.4GB 인지 12GB 인지 아직 모른다.**

오늘 `Free 6,169 MiB` 를 쟀는데, **같은 기계에서 3B bf16(가중치 6.2GB) 학습이 완료된 기록이 있다.** WDDM 이 데스크톱 메모리를 축출하는 것일 수 있다.

> **이 선이 안 정해지면 후보를 못 거른다.** 6.4GB 면 Gemma 4 E4B 가 유리하고, 12GB 면 둘 다 들어간다.

`[실측]` **2026-09-03 — 원격으로는 못 잰다는 것까지 확인했다.** SSH 는 Windows 세션 0 이고 GPU 메모리가 **2.25GB 로 제한된다.** **사람이 x600 에 직접 로그인해야 한다.** → [../business/gpu-limits.md](../business/gpu-limits.md)

`[실측]` **입력이 중앙 8,909 토큰이다.** KV 캐시를 무시할 수 없다.

`[미확보]` **헤드리스로 5.8GB 가 회수되면 이 선이 12GB 가 된다.** 먼저 확인해야 한다.

### 2. 스키마 준수율 (핵심)

**파인튜닝이 실제로 고치는 것이 이것이다.** → [finetuning.md](finetuning.md)

| | |
|---|---|
| 재는 것 | `verdict`·`cited_clauses`·`policy_evidence` 가 파싱되는 비율 |
| **통과선** | **95% 이상** |
| 기준값 | `[실측]` Qwen2.5-3B FT 가 **97.2%** 를 냈다 |

**97.2% 가 이 프로젝트의 유일한 성공 지표였다.** 형식은 지켰다.

### 3. 근거 인용 정합률

| | |
|---|---|
| 재는 것 | 인용한 조항이 **넘겨준 근거에 실재하는가** |
| **통과선** | **95% 이상** — 지어낸 인용 5% 미만 |

→ [../../final_project_cs/wiki/actions/evidence-check.md](../../final_project_cs/wiki/actions/evidence-check.md)

**이건 한국어 능력이 아니라 지시 준수 능력이다.** 작은 모델이 잘할 수도 있다.

`[실측]` **기준값이 오염돼 있다.** 결함 2건에 눌린 값이다. → [dod28-rerun.md](dod28-rerun.md)

**D-010 이 정해진 뒤에 재측정한 값을 기준으로 쓴다.**

**자체호스팅이 이걸 못 넘으면 체감이 나빠진다.**

**자체호스팅·상용 배포가 가능해야 한다.** 안 되면 탈락 — 그게 이 제품의 차별점이다.

## 후보 (2026-09-03 조사)

`[외부]` **웹 검색으로 확인한 것이고 직접 안 돌려 봤다.**

| 후보 | 메모리 | 한국어 | 비고 |
|---|---|---|---|
| **Gemma 4 E4B** | **~3~4GB** | `[미확보]` | Edge 용. PLE 로 실제 점유가 파라미터 수보다 작다 |
| Gemma 4 E2B | ~3GB | `[미확보]` | 더 작다 |
| **Qwen2.5-3B** (현행) | ~6GB bf16 | **CJK 특화 학습** | 지금 쓰는 것 |
| Gemma 4 26B MoE | 16GB Q4 | | **6.4GB 에 안 들어간다 — 탈락** |

`[외부]` **Gemma 4 는 2026-04-07 공개**됐고 E2B·E4B·26B MoE·31B Dense 네 종이다. QAT 체크포인트가 있어 4-bit 에서도 정확도를 유지한다고 한다.

`[외부]` **다만 한국어는 Qwen 이 낫다는 자료가 있다** — CJK 특화 학습.

> **메모리는 Gemma 4 E4B 가 유리하고 한국어는 Qwen 이 유리하다.**

**그래서 재봐야 한다.** 일반 벤치마크는 우리 과제가 아니다 — 우리가 재는 건 **스키마 준수·근거 인용**이고, 그건 한국어 유창성과 다른 능력이다.

## 어떻게 재나

**모델만 갈아끼우면 된다.** 골든셋·judge·채점 스크립트가 이미 있다.

```bash
python -m eval.finetune.score_ft --input eval/finetune/ft_predictions.jsonl \
       --output eval/reports/<날짜>_<모델>.jsonl
```

| 순서 | |
|---|---|
| 1 | **헤드리스 VRAM 회수 여부 확인** — 6.4GB 인지 12GB 인지 |
| 2 | **D-010 결정** — 채점식이 안 정해지면 뭘 재도 다시 재야 한다 |
| 3 | 후보 2~3개를 **같은 판**에서 측정 |
| 4 | 위 6개 기준으로 비교 |

**1·2 가 3을 막는다.**

## ★ 하나로 고정하지 않는다

`[실측]` **지금까지 모델이 하나로 고정돼 있었고 그게 비교 없이 정해진 것이었다.**

**DoD-28 을 어차피 다시 재야 하므로**, 그때 후보 2~3개를 같이 돌린다. 추가 비용은 실행 시간뿐이다.
