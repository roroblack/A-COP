## v3 (지금)

- 낱장을 HTML 로 그린다. 글자를 긁고 검색할 수 있다.
- 낱장 오른쪽에 누적 패킷 칸을 붙였다. 이번 단계에서 생긴 것만 색이 들어간다.
- 열두 칸 지도는 진행바의 단추를 눌러야 덮어 뜬다.
- 낱장마다 `이 흐름이 만드는 파일 / 읽는 파일 / 파일이 생기는 다른 경로` 를 적는다.
- 낱장 내용은 그림을 그리는 `trace/steps.py` 에서 그대로 가져온다.
- 파일이 4.6MB 에서 2.0MB 로 줄었다. 낱장 PNG 열두 장을 안 넣기 때문이다.
  그 PNG 는 `trace/images/` 에 그대로 있고 영상이 쓴다.

## v4 에서 더한 것 (2026-09-01)

- **줄마다 설명.** 줄에 마우스를 올리면 그 줄만의 말풍선이 뜬다.
  낱장의 문서 두 칸, 누적 칸의 덩어리, 코드 덮개의 코드 전부.
  덩어리 53개 · 줄 411개 · 설명 붙은 줄 370개.
- **문서 칸마다 설명.** 제목 옆 물음표에 마우스를 올리면 그 칸이 무엇이고
  왜 그렇게 생겼는지 뜬다. 누르면 고정된다. 24칸, 평균 128자.
- **생명주기 상태를 영어 그대로 적는다.** 진행바 위와 열두 칸 지도에
  `classifying v1`, `running v3`, `resolved v4` 처럼 붙였다. 코드와 DB 에
  그 글자로 들어 있으므로 한국어로 옮기면 오히려 찾을 수 없다.

본문은 코덱스가 쓰고 `apply_line_notes.py` 와 `apply_doc_says.py` 가 검사한다.
검사기가 실제로 물린 것: 줄 수가 하나 어긋난 조각(손으로 다시 씀),
sha256 을 "암호화" 라고 쓴 여섯 군데(해시는 암호화가 아니다),
문서 칸 24개 중 23개가 같은 어미로 끝난 첫 판(틀을 베낀 것이라 통째로 물림).

### 사실로 확인되어 고친 것

| 무엇 | 어떻게 확인했나 | 어떻게 고쳤나 |
|---|---|---|
| 두 출처의 4번 단계 제목이 갈라져 있었다 | 두 목록을 나란히 찍어 봄 | 제목을 낱장 쪽에 맞추고, 번호·제목·색을 대조하는 `check()` 를 둠 |
| `steps` 를 먼저 import 하면 수집이 0건 | 순서를 바꿔 돌려 봄. **PNG 12장을 조용히 다시 그리고 나서** 실패했다 | 전역 `draw.step` 바꿔치기를 버리고, `draw` 와 `steps` 를 전용 이름으로 따로 읽는다 |
| 마지막 단계에서 자동 재생을 누르면 1번을 건너뛴다 | `cur=0` 만 하고 다시 그리지 않음 | `go(0)` 으로 바꿈 |
| 코드 덮개를 열어도 타이머가 돈다 | 재생 중 열어 보니 뒤에서 단계가 바뀜 | 덮개를 열 때 멈춘다 |

| 키를 문서 전체에서 뺏는다 | Space·Home·End·위아래를 다 막고 있었다 | 좌우만 어디서나. 나머지는 글자 넣는 곳이 아닐 때만. 조합키는 무시 |

### 받아들이지 않은 것

- **`steps.py` 를 순수 데이터로 다시 쓰기.** 지적한 실패 방식은 전부 전역 상태와
  import 순서에서 나왔고, 그것은 전용 이름으로 따로 읽는 것으로 사라진다.
  실제로 순서를 바꿔 돌려 확인했다. 350줄을 다시 쓰는 것은 지금 얻을 것에 비해
  크고, 낱장 내용은 함수 호출 형태가 읽기 쉽다. 다만 인자 순서가 계약이라는
  지적은 맞으므로, `steps.py` 의 `step()` 서명을 바꿀 때는 `sheet_data._collect`
  도 같이 바꿔야 한다.
- **접근성 전부(모달 초점 가두기, `aria-live`, `role="dialog"`).** 맞는 말이지만
  이 파일은 팀 안에서 도는 학습 자료다. 지금은 키보드 범위와 움직임 줄이기
  (`prefers-reduced-motion`)와 그림 대체 설명까지만 했다.
- **`cut()` 을 AST 기준으로 바꾸기.** 지적이 맞다. 끝 줄이 밀리면 조용히 잘린다.
  다음 판에서 함수 이름으로 찾도록 바꾼다. 지금은 첫 줄 앵커가 잡아 준다.
- **산출물 신선도 검사(PNG·HTML·MP4 를 한 명령으로).** 맞는 말이다.
  아직 안 했다.
