01누가 판단하고 누가 실행하는가

Team 은 판단만 한다. 실행은 Action 층이 하고, 그 사이에 사실 대조와 사람 승인이 있다. v1 전체도에는 이 둘이 없었다.

v1 에서 고친 것. v1 도해에는 제안 사실 대조와 사람 승인이 없었다 — Team 에서 Action 층으로 화살표가 바로 갔다. 그래서 「승인 없이는 아무것도 실행되지 않는다」는 이 제품의 핵심 약속이 그림에서 안 보였다. 그리고 CORE · KEEP 배지를 내렸다 — 사실이 아니고, 그건 개발 변경 범위이지 실행 책임이 아니다.

02Team 이 받을 수 있는 일과 돌려줄 수 있는 것

v1 에는 accepted_case_types 가 한 번도 안 나온다. 그런데 그것이 팀을 고르는 축이다. 「역할을 적었다」와 「범위를 검사한다」는 다르다.

v1 의 「여섯 팀이 똑같이 돈다」를 내렸다. _base.py 첫머리가 execute() 를 대신 실행하지 않는다고 못박았다. 상속만으로 호출 순서가 보장되지는 않는다. 정확히는 「공통 계약 부품을 쓴다」이다.

06아직 보장하지 못하는 것

v1 은 이것을 배지 하나로 흘려 놓았다. 「완료 확인 기준」을 같이 적는다 — 무엇을 보이면 상태가 바뀌는지 적어야 다음 사람이 닫을 수 있다.

항목지금 지금 근거완료 확인 기준
도구 호출 예산코드 확인 전달(_base.py:78)과 예외 정의(ToolBudgetExceeded) 다른 인자로 반복 호출해도 상한에서 멈추고, 호출자에게 정해진 결과로 돌아옴
전체 반복 제한미확인 — 도구를 부르지 않는 생성 반복과 재계획 반복의 종료 조건
제안 사실 대조호출 확인 정책 선택과 대조 호출이 있다(controller.py:332). 대조 규칙의 내용과 「불일치가 나면 실제로 막히는지」는 확인 못 했다 잘못된 제안이 실행 전에 막히는 경로
실행 직전 재대조문서 기재 주석에 설계가 적혀 있다. 실행 연결은 확인 안 했다 승인 대기 중 사실이 바뀐 건이 실행 직전에 다시 걸리는 경로
고객 답변·대안 검증미확인 response_review.enabled: false. 켜면 기동이 막힌다 근거 없는 답변과 재판정 안 된 대안이 나가지 않는 경로
select_capability미구현 넷 중 하나만 있다. Mobility 만 구현했고, capability 둘 이상인 팀 넷에 필요하다. 나머지 셋은 default_capability 로만 간다 Activity · Dining · Booking Handoff 에 구현
멱등 키의 「대상」미구현 결정은 났고 코드가 안 따라왔다. v11 §4-E 가 대상 객체 id 로 정했는데 controller.py:374 는 Case id 고정이다. 팀이 붙인 키(_base.py:169)는 서버가 버린다 서버가 확인한 대상 객체 id 가 키에 들어감
무예약 활동 판정미구현 넣으면 두 번 막힌다. 예약이 없으면 activity.py:76 에서 「모름」으로 끝나고, 규정이 없어도 :78 에서 또 끝난다 판정 입력이 「예약」이 아니라 「일정 항목」으로 (v11 §5-D)
Place Verification문서 기재 원격 Agent 는 있으나 지금 안 쓴다. travel_remote_agent.py 202줄이 있지만 a2a_executor.enabled: false · team_executor: local 이고, 실제 장소 원장에도 안 붙는 시뮬레이터다 제품 범위 결정 — 왕복·계약 증명으로 둘지, 실제 조회를 붙일지
Dining 조건 판정확인 필요 안 되는 조건에 걸렸을 때의 실패 분기가 없다(dining.py:81~96). 일부만 충족해도 「모두 만족」으로 답할 수 있다 — 05장 불충족 조건이 성립 판정을 못 통과하는 것. v11 §8 의 「필수 조건 위반 0건」이 이걸 잰다
Booking 변경 준비미구현 v11 §5 는 「대안·차액을 정리한다」인데 규정 존재만 보고 위약금·대안·차액을 계산하지 않는다(booking_handoff.py:77~94) 변경 링크에 바뀔 항목·대안·차액이 담기는 것 (v11 DoD-17)
기상 불가 판정미구현 날씨로 「불가」를 만들지 않는다. 임계치를 넘어도 주의 문구만 붙는다 (activity.py:156~180) — 05장 대표 시연(v11 §8-A)이 우천으로 활동을 깨뜨리려면 이 판정이 필요하다
응답 검토 Team미구현 여행판이 아직 없다. 커머스판은 구현과 함께 걷어냈다. enabled: false 이고, 켜면 기동이 막힌다 — project_config.py:92 의 validate_response_review_owner 가 등록된 활성 팀에 없는 owner 를 거부한다. ★끈 상태는 통과시킨다 — 도메인 교체 중 옛 이름이 남는 것까지 막으면 교체를 못 한다 등록된 활성 팀으로 만들고 enabled: true 로 기동

07이 문서를 읽을 때

규칙왜
줄수로 성숙도를 말하지 않는다 v1 은 「Activity 가 204줄로 가장 크다」고 적었다. 줄수는 성숙도가 아니고, v1 어긋남의 절반이 줄수였다. 이 판의 줄수는 파일을 식별하기 위한 것이다
등록 · 범위 · 검증은 다른 축이다 「등록됐다」가 「기능이 다 된다」가 아니고, 「기능이 된다」가 「검증됐다」가 아니다. v1 의 LIVE·STUB·OPEN 은 이 셋을 섞었다
삭제된 코드를 인용하지 않는다 v1 은 커머스 여섯 팀의 가드 통계를 인용했는데 그 구현이 저장소에서 나갔다. 인용하려면 커밋 해시를 같이 적는다
「확인 못 했다」를 적는다 확인 범위를 안 적은 단정이 v1 에서 가장 많이 틀렸다
한국어와 영어만 쓴다 v1 도해에 다른 문자가 섞여 들어간 자리가 있었다. 코드 식별자 외에는 한국어로 적는다
