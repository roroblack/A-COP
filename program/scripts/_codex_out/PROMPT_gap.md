# 작업 — 원본 문서의 내용이 wiki 에 반영됐는지 대조한다

## 왜 이 일을 하나

`program/wiki/` 와 `program/final_project_cs/wiki/` 는 기존 문서들의 내용을
옮겨 담아 만들었다. 그런데 **"이미 반영됨"이라고 생각한 문서를 실제로 대조했더니
7번 중 7번 빠진 절이 나왔다.**

실제로 빠졌던 것들:
- 사업성 문서의 리스크 13종과 우선순위 절 통째로
- 페인포인트 문서의 타깃 도메인 모순 수정 (wiki 에 타깃 도메인 서술 자체가 없었다)
- 실행계획서의 8스트림 소유 디렉터리 표
- 평가 harness 결함 2건 (wiki 는 "원인 조사가 안 됐다"고 적고 있었는데 원인이 있었다)

**"옮겼다고 생각한 것"을 믿으면 안 된다. 세어야 한다.**

## 무엇을 하나

아래 원본 10건 각각에 대해:

1. 원본의 **모든 `##`·`###` 절 제목**을 나열한다.
2. 각 절의 내용이 `program/wiki/` 또는 `program/final_project_cs/wiki/` 의
   어느 문서에 반영돼 있는지 찾는다.
3. **반영 안 된 것을 표시한다.**

## ★ 판정 기준

- **반영됨**: 그 절의 핵심 주장·숫자·표가 wiki 어딘가에 있다. 문장이 달라도 된다.
- **일부**: 절의 일부만 있다. **무엇이 빠졌는지 적는다.**
- **누락**: wiki 에 없다.

★**"비슷한 주제 문서가 있다"는 반영이 아니다.** 그 절의 **구체적 내용**(숫자, 표의 행,
  결론 문장)이 있는지를 본다. 주제가 겹친다고 반영됐다고 판정하면 이 작업이 무의미해진다.

★**애매하면 "일부"로 판정하고 이유를 적어라.** 반영됐다고 낙관하지 마라.


## 출력 형식

문서마다 이렇게 낸다. 표 하나로 끝낸다.

```
===== DOC: _평가harness_결함_2026-08-29.md =====

| 절 | 판정 | 어디에 / 무엇이 빠졌나 |
|---|---|---|
| 지금 나오는 숫자 | 누락 | wiki 에 A/B 수치 자체가 없다 |
| 결함 1. Proposed 페널티가 죽은 코드다 | 반영 | evaluation/metrics.md |
| ... | | |

**빠진 것 요약:** <한 문장. 없으면 "없다">
```

마지막에 전체 요약 표를 하나 더 낸다.

```
===== 전체 =====

| 원본 | 절 수 | 반영 | 일부 | 누락 |
|---|---|---|---|---|
```

다른 설명은 붙이지 마라.
