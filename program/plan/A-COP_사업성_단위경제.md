## 1. 요약 — 숫자 세 개

이 문서 전체가 이 세 줄로 압축된다.

| | 값 | 근거 |
|---|---|---|
| 사람이 문의 1건 처리하는 비용 | **4,100~4,846원** | 두 방법이 일치 (§4-2, §2-2) |
| A-COP 병행 시 건당 총비용 | **약 1,133원** | 사람 시간 72% 감소 (§4-2) |
| 그중 LLM 비용 | **4.06원** — 전체의 **0.36%** | `[실측]` (§3-1) |

**그래서 결론은 "LLM 비용으로 팔면 안 된다"이다.** 도입 후에도 **비용의 99.6%는 여전히 사람**이다. LLM 단가를 절반으로 깎아도 건당 2원이 줄 뿐이다. 의미 있는 건 **사람 시간을 줄이는 것**과 **오류를 줄이는 것** 둘뿐이다.

그리고 **72% 절감을 인원 72% 감축으로 말하면 안 된다.** 골든셋에서 39%가 승인·입력 대기로 사람에게 되돌아오고 5%는 구조적으로 사람 몫이다. `[실측]` 인력은 계단식으로만 줄어들고, 실제로는 감축보다 처리량 증가로 흡수되는 쪽이 흔하다. (§4-2-(4))

진짜 팔 것은 §4의 **오류 비용**이다.

그리고 인프라에서 두 가지가 더 나온다.

> **하나.** 자체호스팅 원가는 경로에 따라 갈린다. 클라우드 GPU 임대는 API보다 10.5배 비싸지만(손익분기 상담원 98~289명),
> **온프레미스는 2.7배이고 손익분기가 상담원 약 32명**이다. 규제·보안이 1차 논거, 원가는 32명 이상에서 보조 논거다. (§3-4)
>
> **둘.** 그런데 **팀 최고 사양이 RTX 4070 SUPER 12GB인데 우리 입력이 중앙값 10,670토큰이다.**
> 저장소 기록상 12GB에서 학습은 1,024토큰으로 깎아야 겨우 돌았다. **원가 이전에 장비가 워크로드를 못 받는다.** (§3-4)

### 3-2. 이 표가 말하는 것

Windows WDDM의 "느린 실패"도 따로 적어 둔다. Linux는 즉시 OOM으로 죽는데 Windows는 25분을 끌다 죽는다. **운영 환경으로 Windows를 쓰면 장애 판정이 느려진다.** 자체호스팅을 제품으로 팔면 Linux를 전제해야 한다.

#### 학습과 추론은 다르다 — 추론은 되는가

위 기록은 전부 **학습**이다. 학습은 활성값·옵티마이저 상태·그래디언트가 얹혀 추론보다 훨씬 무겁다. 추론만 보면 계산이 다르다. `[추정]`

```
Qwen2.5-3B (36층, KV 헤드 2, head_dim 128, bf16)
KV 캐시 = 2(K,V) × 36 × 2 × 128 × 2바이트 = 36 KB / 토큰

건당 12,038 토큰 → 433 MB / 시퀀스
가중치 bf16     → 6.18 GB
WDDM 예약       → 약 1 GB

12 − 6.18 − 1 − 0.5(활성값) ≈ 4.3 GB  →  동시 약 10 시퀀스
4-bit 양자화 시 가중치 1.9GB → 동시 약 20 시퀀스
```

**추론은 12GB에서 된다. 배치 10 정도가 상한이다.** 다만 이건 계산이지 측정이 아니다. `eval/finetune/serve.py`로 실측해야 한다(§3-7).

#### 온프레미스 비용 — 4070 SUPER 기준 `[추정]`

| 항목 | 계산 | 월 비용 |
|---|---|---|
| 하드웨어 상각 | 4070 SUPER 시스템 160만원 ÷ 36개월 | 44,444원 |
| 전력 (산업용) | 평균 150W × 720h = 108kWh × 179원 | 19,332원 |
| 회선 (기업용 대칭) | | 50,000원 |
| **합계** | | **약 114,000원** |

4090(400만원, 300W)에서 4070 SUPER(160만원, 150W)로 바뀌면서 **월 20만원 → 11.4만원으로 내려간다.** 장비가 약해서 오히려 원가는 유리해졌다.

**주택용 전기로 돌리면 계산이 깨진다.** 주택용에만 누진제가 있다. 108kWh를 기존 가정 사용량(월 300kWh 가정)에 얹으면 408kWh가 되어 3단계(400kWh 초과, kWh당 307.3원)에 걸린다. `[외부]`

```
산업용 179원  →  108kWh × 179   = 19,332원
주택 3단계    →  108kWh × 307.3 = 33,188원  (+72%)
주택 최고구간 →  108kWh × 736.2 = 79,510원  (+311%)
```

절대액은 4090 때보다 작지만 **비율은 그대로 튄다.** 온프레미스는 사업 계산에 넣되 **사업자 전기 계약이 전제**라고 명시한다. 상시 가동은 소음·발열·회선 업로드 제약도 따라온다.

`[외부]` 2026-04-16부터 산업용 요금제가 개편되어 낮(11~15시) kWh당 최대 16.9원 인하, 밤 5.1원 인상이다. **배치 처리를 낮으로 옮기면 유리해진다** — 야간 배치가 관행인데 이 개편은 반대 방향이다.

#### 손익분기

```
손익분기 월 처리량 = 월 인프라 비용 ÷ API 건당 비용(4.06원)
```

| 경로 | 월 비용 | 손익분기 월 건수 | 환산 상담원 규모 |
|---|---|---|---|
| **온프레미스 4070 SUPER (산업용)** | 114,000원 | **28,100건** | **약 32명** |
| RunPod 4090 | 347,200원 | 85,500건 | 약 98명 |
| RunPod A40 | 449,400원 | 110,700건 | 약 127명 |
| AWS g5.xlarge | 1,027,600원 | 253,100건 | 약 289명 |

환산 규모는 §2-2의 10,500건/인·년 기준이다.

**모델 조직(상담원 12명, 월 10,500건) 기준 건당 비교.**

| | 월 비용 | 건당 | API 대비 |
|---|---|---|---|
| API (gpt-4o-mini) | 42,630원 | 4.06원 | 1.0배 |
| **온프레미스 4070 SUPER** | 114,000원 | **10.9원** | **2.7배** |
| RunPod A40 임대 | 449,400원 | 42.8원 | 10.5배 |

**결론이 경로마다 갈린다.**

- **클라우드 GPU 임대는 답이 아니다.** API보다 10.5배 비싸고 손익분기가 상담원 98~289명이다. 규제 요건이 없으면 선택할 이유가 없다.
- **온프레미스는 생각보다 가깝다.** 손익분기가 **상담원 약 32명**이다. 중견 CS 조직에서 흔한 규모다. 12명 조직에서도 2.7배 차이면 "데이터를 안 내보내는 값"으로 설명 가능한 수준이다.

**그래도 자체호스팅을 원가 절감으로 팔면 안 된다.** 32명 미만에서는 여전히 API가 싸고, 무엇보다 §3-4 앞부분의 **12GB 제약이 아직 안 풀렸다.** 원가가 맞아도 장비가 워크로드를 못 감당하면 의미가 없다.

이 구분을 v8 §1-1에 명시해야 한다. **규제·보안 요건이 1차 논거, 원가는 32명 이상에서만 보조 논거다.**

#### gPUteer — 이 제약에 대응하는 별도 프로젝트

팀이 [`test_workspace/gPUteer`](../../../test_workspace/gPUteer/gputeer_master_plan_FINAL.md)에서 사설 GPU 풀 플랫폼을 별도로 만들고 있다. 자기 정의는 이렇다.

> 팀원 개인 PC·연구실 서버·클라우드 GPU를 하나의 사설 Compute Pool로 묶고, 각 노드의 성능·자원·가용시간·신뢰성·보안 등급을 기준으로 작업을 자동 배치하며, 노드 장애 시 지속 보존된 상태로 다른 GPU에서 작업을 이어가는 GPU 오케스트레이션 플랫폼

이 문서 §3-4가 말하는 문제 상당수가 gPUteer의 문제 정의와 겹친다. 특히 **"한 GPU가 놀아도 다른 팀원이 쓰기 어렵다"**와 **"GPU 유휴 시간이 진짜 비용"**은 같은 말이다.

| 이 문서의 문제 | gPUteer가 푸는가 |
|---|---|
| GPU 가동률이 낮으면 건당 원가가 뛴다 | **푼다** — 여러 작업을 한 풀에 모아 가동률을 올린다 |
| 노드가 꺼지면 작업이 유실된다 | **푼다** — 체크포인트 보존 후 다른 GPU에서 이어감 |
| 이질 장비를 섞어 쓰기 어렵다 | **푼다** — 노드 계층·자동 배치 |
| **12GB에 10,670토큰이 안 들어간다** | **못 푼다** |

마지막 줄이 중요하다. gPUteer 문서가 스스로 **"GPU 메모리를 물리적으로 합치는 기술"이 아니라고 명시**한다(§3.2). 즉 **VRAM 천장은 gPUteer로 안 뚫린다.** 12GB 문제는 다른 수단으로 풀어야 한다.

| 12GB 천장을 푸는 수단 | 효과 | 비용 |
|---|---|---|
| 4-bit 양자화 (AWQ/GPTQ) | 가중치 6.18GB → 1.9GB, 배치 2배 | 정확도 손실 `[미확보]` |
| 컨텍스트 축소 | 이미 `_shrink_evidence()`로 하고 있음 | 근거 누락 위험 |
| 더 큰 VRAM 확보 | 근본 해결 | 장비 구입 또는 임대 |
| 텐서 병렬 (다중 GPU) | 근본 해결 | 노드 간 대역폭 필요 — **gPUteer 범위 밖** |

**사업 문서로서의 결론.** gPUteer는 **우리 개발·학습 인프라 비용을 낮추는 프로젝트**지, A-COP 고객사의 자체호스팅 문제를 푸는 제품이 아니다. 둘을 섞어서 설명하면 심사에서 혼선이 생긴다. A-COP 사업성 계산에는 gPUteer를 **개발 단계 비용 절감 요인**으로만 넣는다.

### 3-5. 네트워크 트래픽 — 텍스트에서는 반올림 오차다

| 항목 | 값 |
|---|---|
| 건당 토큰 | 12,038 (입력 9,612 + 출력 2,426) `[실측]` |
| 건당 바이트 | 약 50KB (한글 토큰당 ~2.5바이트 + HTTP/JSON 오버헤드) `[추정]` |
| 모델 조직 연간 | 126,000건 × 50KB = **6.3 GB/년** |
| AWS egress ($0.09/GB, 첫 100GB 무료) | **연 800원 미만** `[외부]` |

**100배 규모(연 1,260만 건)로 키워도 630GB, 연 8만원이다.** 텍스트 LLM 워크로드에서 트래픽 비용은 의사결정에 영향을 주지 않는다. 계산에는 넣되 리스크로 다루지 않는다.

`[외부]` AWS 서울 리전은 미국·유럽($0.09/GB)보다 비싸다. 정확한 단가는 확인하지 못했으나 배수가 1.5배여도 결론이 바뀌지 않는다.

**단, 음성이 들어오면 완전히 달라진다.** 골든셋 채널에 phone이 9건(12.5%) 있다. `[실측]` 음성은 분당 약 1MB이고 STT·TTS 비용이 별도로 붙는다. 텍스트 기준 결론을 음성으로 연장하면 안 된다. **음성 채널은 이 문서의 범위 밖이며 별도 산정이 필요하다.**

### 3-6. 인프라 결론 네 줄

1. **12GB VRAM 천장이 원가보다 먼저 걸린다.** 팀 최고 사양 4070 SUPER에서 우리 워크로드(중앙값 10,670토큰)가 학습 기준으로 안 돌았다. 이게 안 풀리면 아래 세 줄은 의미가 없다.
2. **클라우드 GPU 임대는 답이 아니다.** API보다 10.5배 비싸고 손익분기가 상담원 98~289명이다.
3. **온프레미스는 손익분기가 상담원 약 32명으로 가깝다.** 다만 사업자 전기 계약과 Linux가 전제다.
4. **트래픽은 무시해도 되고, GPU 유휴 시간이 진짜 비용이다.** API는 쓴 만큼 내지만 GPU는 놀아도 낸다. 이 유휴 문제가 gPUteer가 푸는 것이고, VRAM 천장은 gPUteer가 못 푸는 것이다.

### 3-7. 아직 안 잰 것

| 항목 | 왜 필요한가 | 방법 |
|---|---|---|
| **4070 SUPER에서 추론이 되는가** | §3-4의 KV 캐시 계산(배치 약 10)은 계산이지 측정이 아니다. 학습은 이미 12GB에서 막혔다 | `eval/finetune/serve.py` 부하 측정 |
| **4-bit 양자화의 정확도 손실** | 12GB 천장을 푸는 가장 값싼 수단인데 대가를 모른다 | AWQ/GPTQ 적용 후 골든셋 72건 재평가 |
| Qwen2.5-3B 처리량 (tok/s, 배치) | 손익분기표는 GPU가 그 물량을 소화한다고 가정한다 | 동 |
| 자체호스팅 지연 | API가 이미 p50 20~34초다. 3B가 더 느리면 제품이 안 된다 | 동 |

**첫 줄이 전부를 막고 있다.** 학습이 12GB에서 안 돌았다는 건 실측이고, 추론이 된다는 건 아직 계산일 뿐이다. 이 하나를 재면 §3-4·§3-6·§4-5·§5가 동시에 확정된다.

**둘째 줄이 그다음이다.** 4-bit로 가중치를 1.9GB까지 줄이면 배치가 두 배가 되고 온프레미스 손익분기가 절반으로 내려간다. 대신 정확도가 떨어지면 §4-3의 오류 비용 절감이 깎인다. **원가와 정확도가 같은 손잡이에 달려 있다.**

## 4. 고객의 이윤 — 오류 비용이 축이다

### 4-1. 모델 조직

정미라 페르소나(CS팀장, 상담원 12명)를 기준 조직으로 둔다.

```
연 처리량 = 12명 × 10,500건 = 126,000건 / 년
```

### 4-2. 축 1 — 건당 처리 비용, 사람 vs A-COP

#### (1) 상담원 1인을 고용하면 실제로 얼마인가

급여만 보면 안 된다. 사업주 부담을 전부 쌓는다. 기준 급여는 콜센터 상담원 평균 연봉 **2,876만원**이다. `[외부]`

| 항목 | 요율·근거 | 연간 |
|---|---|---|
| 급여 | 평균 연봉 `[외부]` | 28,760,000원 |
| 4대보험 사업주 부담 | 10.67% `[외부]` | 3,068,692원 |
| 퇴직금 | 8.33% (1/12) | 2,395,708원 |
| **인건비 소계** | | **34,224,400원** |
| 좌석 (사무실·PC·헤드셋·회선) | `[추정]` 월 30만원 | 3,560,000원 |
| 채용·교육 | `[추정]` 이직률 40% × 1인 200만원 | 800,000원 |
| 관리자 오버헤드 | `[추정]` 팀장 1인이 12명 관리 | 4,460,000원 |
| **총계** | | **43,044,400원 / 인·년** |

4대보험 사업주 부담 10.67%의 내역이다. `[외부]` 2026년 기준

```
국민연금 4.75  +  건강보험 3.595  +  장기요양 0.4724
+  고용보험(실업급여) 0.9  +  고용안정·직능개발 0.25  +  산재(사무직) 0.7
= 10.67%
```

**채용·교육이 만만치 않다.** 컨택센터 상담원 연평균 이직률은 **30~45%**이고(Medallia 조사), 국내 일부 현장은 그보다 훨씬 높다는 보도도 있다. `[외부]` 위 표는 40%로 보수적으로 잡았다. 이직률이 높으면 이 줄이 커진다.

```
건당 인건비 = 43,044,400원 ÷ 10,500건 = 4,100원 / 건
```

**두 방법이 서로 맞는다.** §2-2의 산업 매출 역산은 4,846원, 여기 직접 고용 적산은 4,100원이다. 아웃소싱이 더 비싼 건 벤더 마진이 붙기 때문이라 앞뒤가 맞는다. **건당 사람 비용은 4,100~4,846원 구간으로 본다.**

#### (2) A-COP은 사람을 얼마나 덜 쓰게 하는가

**여기서 정직해야 한다. A-COP은 상담원을 대체하지 않는다.** 골든셋 후속 동작 분포가 그렇게 말한다. `[실측]`

| 후속 동작 | 비율 | 사람이 하는 일 | 건당 소요 `[추정]` |
|---|---|---|---|
| respond | 56% | 초안 검토 | 2분 |
| wait_for_approval | 21% | 승인 판단 | 3분 |
| wait_for_input | 18% | 거의 없음 (고객 재입력 후 자동 재처리) | 1분 |
| escalate + handoff | 5% | 처음부터 사람이 처리 | 8.6분 (전량) |

```
사람만    : 실가동 6시간 ÷ CPH 7 = 8.57분 / 건
A-COP 병행: 0.56×2 + 0.21×3 + 0.18×1 + 0.05×8.57 = 2.36분 / 건
             ────────────────────────────────────
             건당 사람 시간 72% 감소, 처리 능력 3.6배
```

#### (3) 건당 총비용 비교

| | 사람 시간 | 인건비 | LLM·인프라 | **건당 총계** |
|---|---|---|---|---|
| **A. 상담원만** | 8.57분 | 4,100원 | 0원 | **4,100원** |
| **B. A-COP + 상담원** | 2.36분 | 1,129원 | 4.06원 (API) | **1,133원** |
| B'. 온프레미스 자체호스팅 | 2.36분 | 1,129원 | 10.9원 | 1,140원 |
| C. 완전 자동화 (이론상) | 0분 | 0원 | 4.06원 | 4원 |

```
A → B  절감 : 건당 2,967원 (72%)
모델 조직 연간 : 126,000건 × 2,967원 = 3억 7,384만원
```

**C는 도달 불가능하다.** 최소 5%(escalate·handoff)는 구조적으로 사람이고, 21%는 승인 경계가 일부러 사람에게 보내는 것이다. C를 사업 계획에 넣으면 안 된다.

#### (4) ★ 이 표를 읽을 때의 함정

**72% 절감이 인원 72% 감축을 뜻하지 않는다.** 세 가지 이유다.

첫째, **인력은 계단식으로만 줄어든다.** 12명이 3.3명이 되지 않는다. 조직 개편 없이는 12명이 그대로 있고 처리량이 늘 뿐이다.

둘째, **실제 도입에서는 감축보다 처리량 증가로 흡수되는 경우가 많다.** 같은 12명이 45만 건을 처리하게 되는 쪽이 현실적이다. 그러면 절감액이 아니라 **매출 대응 능력**이 결과물이 된다.

셋째, **2.36분이 전부 `[추정]`이다.** 네 줄의 소요 시간을 아무도 안 쟀다. 여기가 이 표에서 가장 약한 부분이다.

그래서 **이 표는 상한선으로만 제시하고, 사업 논거는 §4-3의 오류 비용으로 세운다.** 인원 감축을 약속하면 도입 후 12명이 그대로 있을 때 신뢰를 잃는다.

#### (5) 세 줄 요약

1. 사람이 문의 1건 처리하는 데 **4,100~4,846원**이 든다. 급여는 그중 67%뿐이고 나머지는 보험·퇴직금·좌석·이직·관리다.
2. A-COP을 넣으면 건당 사람 시간이 8.57분 → 2.36분으로 줄어 **건당 1,133원**이 된다. 그중 LLM 비용은 **4원**, 전체의 0.36%다.
3. **비용의 99.6%는 여전히 사람이다.** 그래서 LLM 단가를 깎는 최적화는 의미가 없고, **사람 시간을 줄이거나 오류를 줄이는 것**만 의미가 있다.

### 4-3. 축 2 — 오류 비용 ★ 이게 우리 축

```
연간 오류 비용 = 연 처리량 × 오류율 × 오류 1건당 손실
```

| 입력 | 값 | 상태 |
|---|---|---|
| 연 처리량 | 126,000건 | 파생 |
| 오류율 (도입 전) | 1.0% | `[추정]` |
| 오류율 (도입 후) | 0.3% | `[추정]` |
| 오류 1건당 손실 | 30,000원 | `[추정]` |

```
도입 전 : 126,000 × 1.0% × 30,000원 = 3,780만원 / 년
도입 후 : 126,000 × 0.3% × 30,000원 = 1,134만원 / 년
차이    :                              2,646만원 / 년
```

**LLM 비용 51만원을 써서 2,646만원을 아낀다.** 이게 우리가 팔 문장이다. 배수로는 약 52배다.

세 입력이 전부 `[추정]`이라는 점을 숨기지 않는다. 다만 **구조는 옳다.** 그리고 셋 중 둘은 채울 수 있다.

| 입력 | 어떻게 채우나 |
|---|---|
| 오류율 (도입 후) | **우리가 이미 잰다.** §15 `근거 정합률`·`근거 초과율`이 그 지표다 |
| 오류 1건당 손실 | `datasets/voc/ecmc_dispute_casebook_2024` — 분쟁조정까지 간 실제 사례의 금액 |
| 오류율 (도입 전) | `[미확보]` 도입 기업의 사내 데이터 필요 |

### 4-4. 오류 1건이 3만원이라는 가정의 근거

세 겹으로 쌓인다. `[추정]`

| 겹 | 예시 | 크기 |
|---|---|---|
| 직접 손실 | 환불 금액 오차 (앞서 확인한 2,500원 사례) | 수천 원 |
| 재처리 | 재문의 → 확인 → 정정 → 사과. 최초 응대의 3~5배 | 약 2만원 |
| 신뢰 손실 | 이탈, 리뷰, 분쟁 | `[미확보]` |

**직접 손실만 보면 작다.** 재처리가 대부분이다. 그래서 "금액을 조금 틀렸을 뿐"이 아니라 **한 건이 네 번의 접촉으로 불어나는 것**이 비용의 실체다. 이 설명이 §2-A 페인 층 2(상담원)와 정확히 이어진다.

### 4-5. 축 3 — 도입 기업이 추가로 쓰는 비용

| 항목 | 값 | 상태 |
|---|---|---|
| LLM API 비용 | 51만원/년 | `[실측]` 파생 |
| 승인 대기 인건비 | 126,000 × 21% × 승인 1건 소요시간 × 단가 | `[실측] 21% / [미확보] 나머지` |

## 5. 우리 가격 — 세 안

v8 §1-1은 "제공 방식과 가격 정책은 아직 정하지 않았다"이다. 결정하지 않고 안만 놓는다.

| 안 | 구조 | 장점 | 약점 |
|---|---|---|---|
| **A. 좌석당 구독** | 상담원 1인당 월 정액 | 고객이 예측 가능, 업계 관행 | 자동화가 늘수록 좌석이 줄어 **우리 매출이 줄어든다** — 유인이 반대로 걸림 |
| **B. 건당 과금** | 처리 Case당 | 사용량과 매출이 비례 | 고객이 문의를 줄이려 하는데 우리는 늘길 바람. 역시 유인 충돌 |
| **C. 연간 라이선스 + 규모 구간** | 처리량 구간별 정액, 자체호스팅 | 자체호스팅과 맞음. 유인 충돌 없음 | 초기 가격 근거를 대기 어려움 |

**C를 권한다.** 이유는 세 가지다.

첫째, **자체호스팅과 구조가 맞는다.** 우리가 건당 호출을 세지 않아도 되고, 고객 데이터가 우리 쪽으로 안 온다. 이게 v8 §1-1의 차별점과 일관된다.

다만 §3-4에서 자체호스팅이 원가로는 불리하다는 게 나왔으므로, **구간을 두 갈래로 나눠야 한다.**

| 구간 | 배치 | 근거 |
|---|---|---|
| 일반 (상담원 32명 미만) | API 경유 (우리가 대행) | 원가가 2.7~10.5배 유리 |
| 규제·보안 요건 | 자체호스팅 (온프레미스) | 데이터 반출 금지가 유일한 이유 |
| 대규모 (상담원 32명+) | 자체호스팅 (온프레미스) | 원가도 뒤집힘 |

**클라우드 GPU 임대는 어느 구간에도 넣지 않는다.** 손익분기가 상담원 98~289명이라 온프레미스보다 항상 불리하다.

자체호스팅 구간에 **인프라 비용을 고객이 직접 부담**하게 하면 우리 가격은 소프트웨어 값만 남아 깔끔해진다.

둘째, **A와 B는 유인이 반대로 걸린다.** 우리가 파는 것은 "안전하게 자동화 범위를 넓히는 것"인데, A는 자동화가 성공할수록 매출이 줄고 B는 문의가 줄수록 매출이 준다. 제품이 잘 작동할수록 우리가 손해 보는 가격 구조는 오래 못 간다.

셋째, **Team 플러그인 구조와 맞는다.** v8 §8-B의 Registry 등록형 구조 덕에 도입 기업이 자기 Team을 추가해도 Core가 안 바뀐다. 구간을 Team 수나 처리량으로 나누면 확장이 자연스럽게 상위 구간으로 이어진다.

**가격의 상한은 축 2가 정한다.** 모델 조직 기준 연 2,646만원을 아낀다면, 그 일부가 우리 몫이다. `[추정]`에 기반한 값이므로 숫자를 지금 못 박지 않는다.
