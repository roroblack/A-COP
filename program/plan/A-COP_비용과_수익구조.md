# 비용과 수익 구조 — 얼마 들고 얼마 받아야 하나

`[2026-09-10]` 기준선 [v11](A-COP_구현계획서_v11.md) §11-A 의 본문이다.
팀장 결정 8번(**"현재 어느 정도 비용이 예상되고 얼마나 받으면 수익이 나는지까지만.
수익화 전략이 더 중요하다"**)에 답한다.

★**원가 실측치는 [`A-COP_사업성_단위경제.md`](A-COP_사업성_단위경제.md) 에서 가져온다.**
다만 **그 문서는 커머스 상담센터 B2B 기준**이고 이 문서는 **여행 B2C** 다. 무엇을
그대로 쓰고 무엇을 못 쓰는지 §0-A 에 적는다.

★**등급 없는 숫자를 쓰지 않는다** — `[실측]` 이 저장소에서 잰 것 · `[외부]` 공개 자료 ·
`[추정]` 근거 있는 가정 · `[미확보]` 모른다.

**환율은 1 USD = 1,400원으로 고정한다** `[추정]` — 단위경제 문서와 같은 값을 쓴다.

---

## 0. 결론 먼저 — 네 줄

1. **기계 원가는 여행 한 건에 수십~수백 원이다.** 59,000원 상품에서 **0.1% 안쪽**이다.
   `[추정]` 분모는 v11 §1 의 기준 상품 가격.
2. **손익을 정하는 것은 기계가 아니라 사람 손이다.** 자동 처리가 막혀 사람에게
   넘어가는 건이 **여행 한 건에 한 번만 붙어도 기계 원가 전체보다 크다.**
3. **그래서 「얼마 받아야 하나」의 답은 가격이 아니라 자동화율이다.**
   지금 그 비율을 모른다 `[미확보]` — 파일럿에서 잴 첫 번째 수가 이것이다.
4. **수익 모델은 넷 중 하나를 고르는 문제가 아니다.** 우리 고객이 **여행자**인지
   **에이전트 사업자**인지에 따라 갈리고, **그중 하나는 제품의 약속과 충돌한다**
   (광고·제휴 — §2-A).

34초를 기다릴 수 있다.

## 1. 여행 한 건의 원가 — 쌓아 보기

기준 상품은 **7일·4인·2도시 59,000원(VAT 포함)** 이다 `[v11 §1]`.

`[미확보]` **v11 §9-A 의 MVP 범위는 국내 1도시(서울)다.** 파는 상품과 만드는 범위가
다르다 — v11 §0-3 에 남겨 둔 항목이다. **아래는 「7일 여행 한 건」 기준이며 도시
수와 무관한 항목만 센다.**

### 1-1. LLM — 부르는 횟수부터 센다

★**감시가 도는 횟수와 LLM 을 부르는 횟수는 다르다.** v11 §6-A 가 정한 대로
**감시 루프는 Case 를 만들기만 하고 판정하지 않는다.** LLM 은 **Case 가 생겼을 때**
불린다.

| 언제 Case 가 생기나 | 7일 여행에서 몇 번 | 등급 |
|---|---|---|
| 일정 제출 검증 | **1** | `[v11 §9-A]` 확정 |
| 감시가 변화를 잡음 (기상·휴무·지연) | **0~5** | `[추정]` |
| 고객이 조정을 거부하거나 물어봄 | **0~3** | `[추정]` |
| **합** | **1~9** | |

감시 자체는 훨씬 자주 돈다 — 출발 전날 1회 + 매일 아침 7회 + 각 예약 2시간 전
`[v11 §9-A]`. **그 조회들은 LLM 을 안 부른다.**

```
여행 1건 LLM 비용 = Case 수 × Case당 LLM 비용
                  = (1 ~ 9) × (3.03 ~ 4.06원)
                  = 3원 ~ 37원                    [추정]
```

★**Case당 단가는 커머스 실측치를 빌려 쓴 것이다.** 여행 Case 는 Trip 맥락(일정·예약·
조건)을 싣기 때문에 **더 클 수 있다.** 여행 골든셋으로 다시 재야 한다 — v11 §8 의
평가에서 나온다.

★**가정이 틀리면:** 감시가 잡는 변화가 7일에 5번보다 훨씬 잦으면(예: 장마철)
Case 수가 두 자릿수가 되고 LLM 비용도 그만큼 는다. **그래도 백 원 단위다.**

### 1-2. 외부 API

| 소스 | 과금 | 여행 1건 호출 | 등급 |
|---|---|---|---|
| 기상 (기상청·open-meteo) | **무료** | 감시 주기마다 | `[v11 §7]` |
| 관광정보 (TourAPI) | **무료** | 항목 수만큼 | `[v11 §7]` |
| Google Places (영업시간) | **유료** — 캐싱·표시 조건 있음 | 항목 수 × 확인 횟수 | 단가 `[미확보]` |
| Routes (이동 시간) | **유료** — 출발×도착 **요소** 단위 | 구간 수 × 재계산 횟수 **+ ★출발 안내 호출** | 단가 `[미확보]` |

★**단가를 모르므로 금액을 만들지 않는다.** 대신 **호출을 줄이는 구조**가 이미 있다 —
v11 §9-A 가 "소량 호출 또는 Mock" 으로 두었고 §7 이 캐싱 조건을 적었다.

★★**여기가 진짜 기계 원가일 수 있다.** LLM 이 수십 원인데 Places·Routes 는
**항목 수 × 확인 횟수**로 는다. 7일·4인 여행이면 항목이 20~40개 `[추정]` 이고,
매일 아침 다시 확인하면 **호출이 곱셈으로 커진다.** **단가 확인이 §7 의 다음 일이다.**

★`[2026-09-10 오후 추가]` **출발 안내가 Routes 호출을 하나 더 얹는다.** v11 §6-B ③이
**각 항목의 출발 시각에 경로를 그때 조회한다** — 낡은 경로로는 *"지금 나가면 된다"* 를
말할 수 없기 때문이다.

```
출발 안내 Routes 호출 = 항목 수 = 20 ~ 40회 / 여행     [추정]
```

★**곱셈이 아니라 덧셈인 것이 중요하다.** 감시 주기마다 부르는 것이 아니라 **항목마다
한 번**이다. 그래서 여행 길이가 아니라 **항목 수**에만 비례한다.

★**단가를 모르므로 금액은 아직 못 만든다.** 다만 **Routes 단가가 확인되면 이 줄이
기계 원가에서 가장 큰 항목이 될 수 있다** — LLM(3~37원)보다 클 가능성이 있다.

### 1-3. 인프라

v11 §9-A 는 **로컬 실행 + 외부 LLM API** 다. MVP 동안 서버비는 **0에 가깝다** `[추정]`.

★**자체호스팅은 여행에서도 막혀 있다.** 단위경제 §3-4 의 결론 그대로 — 팀 최고
사양이 12GB 이고 우리 워크로드가 안 들어간다 `[실측]`. **원가 이전에 장비가 못
받는다.** 운영으로 넘어가도 API 경유가 답이다.

### 1-4. 사람 손 — ★여기가 손익을 정한다

v11 은 **자동 처리 한계에서 사람에게 넘긴다**(§3 목표 5, DoD-10). **그 비율을 모른다.**

| 사람에게 넘어가는 비율 | 여행 1건에 붙는 사람 시간 | 등급 |
|---|---|---|
| 0% | 0분 | 이상적이고 현실적이지 않다 |
| 10% (Case 9건 중 약 1건) | **5~15분** | `[추정]` |
| 30% | **15~45분** | `[추정]` |

★**시간당 인건비를 곱하면 기계 원가가 반올림 오차가 된다.** 최저임금 시간급
10,320원 `[외부, 2026]` 으로만 잡아도 **15분 = 2,580원**이고, 이건 §1-1 의 LLM 비용
전체(3~37원)의 **70~860배**다.

```
여행 1건 원가 ≈ (수십~수백 원 기계)  +  (인계 건수 × 처리 시간 × 인건비)
                 ↑ 무시해도 되는 값       ↑ 이것이 전부를 정한다
```

`[미확보]` **인계 비율도, 인계 1건 처리 시간도 안 쟀다.** 커머스 골든셋에서 39%가
승인·입력 대기로 사람에게 돌아왔다는 `[실측]` 이 있지만 **여행은 다른 도메인이고
그 수를 옮겨 쓰면 안 된다.**

## 2. 수익 모델 — 네 안

★**먼저 물어야 할 것은 「누가 내나」다.** v11 §1 은 접점을 **개인 에이전트**로
못박았다 — **돈을 내는 쪽은 아직 안 정했다.**

| | **A. 단품** | **B. 구독** | **C. 원가 + 제휴·광고** | **D. 종량 API** |
|---|---|---|---|---|
| **누가 낸다** | 여행자 | B-1 여행자 / **B-2 에이전트 사업자** | 여행자(거의 안 냄) + 업체 | 에이전트 사업자 |
| **언제** | 여행 시작 전 1회 | 매달 | 여행 전 소액 | 호출할 때마다 |
| **얼마** | 59,000원/여행 `[v11 §1]` | `[미확보]` | 원가 + α `[미확보]` | 호출당 `[미확보]` |
| **성립하려면** | 여행 1건의 값이 59,000원어치로 느껴져야 | **여행을 자주 가야**(B-1) / 사업자가 고객을 많이 물어야(B-2) | 업체가 노출에 돈을 내야 | 에이전트 쪽에 이 기능 수요가 있어야 |
| **가장 큰 약점** | **한 번 쓰고 끝난다.** 재구매 주기가 여행 주기다 | **B-1 은 여행 빈도가 낮아 안 맞는다** — 1년에 두세 번 가는 사람이 월정액을 안 낸다 | ★**제품의 약속과 충돌한다**(§2-A) | 우리가 **에이전트 쪽 수요에 종속**된다 |

### 2-A. ★C안은 제품의 약속과 충돌한다

**돈을 내는 업체를 추천에 끼우는 순간 판정의 중립성이 의심받는다.**

v11 이 파는 것은 **"이 계획이 성립하는지 검증한다"** 이다(§0-1). 그런데 대안을
만들 때(§5 재계획) **제휴 업체가 먼저 뜨면** 그 대안이 *검증 결과*인지 *광고*인지
고객이 구분할 수 없다. §4-D 가 "사실과 생성을 분리한다"고 못박은 자리가 여기다.

★**그렇다고 C 가 불가능한 것은 아니다.** 성립하려면 셋이 필요하다.

| | |
|---|---|
| **판정과 추천을 분리한다** | 성립·불성립 **판정에는 제휴가 개입하지 않는다.** 제휴는 대안이 **여럿일 때 순서**에만 |
| **표시한다** | 제휴 항목임을 고객이 보는 자리에 적는다. §4-D 의 근거·확인 시각 표시와 같은 자리다 |
| **되돌릴 수 있게 둔다** | 제휴 대안을 거부해도 다른 대안이 남아야 한다. 하나뿐이면 그건 광고가 아니라 강요다 |

★**셋을 못 지키면 C 를 넣지 않는다.** 검증 신뢰성이 이 제품이 파는 전부다.

### 2-B. B-2(에이전트 사업자 구독)가 구조와 가장 잘 맞는다

★**우리는 이미 에이전트하고만 만난다**(§1). 그러면 **돈도 그쪽에서 받는 것**이
접점과 일치한다.

| | |
|---|---|
| **왜 맞나** | 자체 앱을 안 만들므로 여행자에게 청구할 화면이 없다. **에이전트가 이미 고객과 정산 관계**를 갖고 있다 |
| **유인이 맞나** | 맞는다. 잘 검증할수록 그 에이전트의 상품이 좋아지고 사업자는 계속 쓴다. **커머스 안에서 문제였던 유인 충돌**(잘할수록 매출이 주는)이 여기서는 안 생긴다 |
| **약점** | **에이전트 사업자가 아직 없다.** OpenClaw·Hermes 는 v11 §0-1 이 예로 든 것이지 계약 상대가 아니다 `[미확보]` |

## 3. 섞은 안 둘

### 3-A. **B-2 + D** — 기본 구독 + 초과 종량 `[권한다]`

```
에이전트 사업자  →  월 기본료(여행 N건까지)  +  N건 초과분은 건당
```

| | |
|---|---|
| **왜 이 조합인가** | §1 이 보여준 원가 모양과 맞는다 — **고정비는 거의 없고 변동비가 여행 건수에 비례**한다. 기본료가 고정비를, 종량이 변동비를 받는다 |
| **원가 연동이 된다** | 사람 손이 많이 드는 여행이 늘면 그만큼 건수로 회수된다 |
| **오늘 못 정하는 것** | 기본료와 건당 단가 `[미확보]`. **§1-4 의 인계 비율을 재야 정해진다** |

### 3-B. **A + C(제한형)** — 여행자 직접 구매 + 표시된 제휴

```
여행자  →  59,000원 단품  +  대안 순서에만 붙는 제휴 (표시 의무)
```

| | |
|---|---|
| **왜 이 조합인가** | 에이전트 사업자가 안 잡힐 때의 대비책이다. **B-2 가 상대에 의존하는 반면 이건 우리 혼자 굴린다** |
| **위험** | §2-A 의 셋을 지켜야 한다. 못 지키면 C 를 빼고 A 단독으로 간다 |
| **오늘 못 정하는 것** | 59,000원이 수용되나 `[미확보]` — 파일럿 몫이다 |

★**둘 중 하나를 지금 고를 필요는 없다.** **원가 구조는 같고 청구 대상만 다르다** —
어느 쪽이든 §1 의 계산이 그대로 쓰인다. 고를 시점은 **에이전트 사업자와 이야기가
붙느냐**가 갈리는 때다.

## 4. 오늘 답할 수 있는 것과 없는 것

| | 무엇 | 근거 |
