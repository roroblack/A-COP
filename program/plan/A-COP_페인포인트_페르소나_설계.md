## 2. 페인포인트 [v8 §2-A 초안]

### 2-1. 데이터가 먼저 말하는 것

골든셋 72건의 감정과 후속 동작 분포다. `[실측]`

```bash
python -c "import json,collections;rows=[json.loads(l) for l in open('final_project_cs/eval/datasets/golden.jsonl',encoding='utf-8')];print(collections.Counter(r['expected_sentiment'] for r in rows));print(collections.Counter(r['expected_next_action'] for r in rows))"
```

| 감정 | 건수 | 비율 |
|---|---|---|
| worried (불안) | 21 | 29% |
| neutral | 20 | 28% |
| confused (혼란) | 15 | 21% |
| frustrated | 9 | 13% |
| negative | 7 | 10% |

| 후속 동작 | 건수 | 비율 |
|---|---|---|
| respond (즉답) | 40 | 56% |
| wait_for_approval (승인 대기) | 15 | 21% |
| wait_for_input (입력 대기) | 13 | 18% |
| escalate | 3 | 4% |
| handoff | 1 | 1% |

여기서 두 가지가 나온다.

**첫째, 고객의 주된 감정은 분노가 아니라 불안이다.** worried + confused가 36건으로 절반이다. frustrated + negative는 16건(22%)에 그친다. 불안과 혼란은 **달래서 풀리지 않고 정확한 답으로만 풀린다.** 응대 톤을 다듬는 제품과 근거를 대조하는 제품 중 어느 쪽이 필요한지를 이 분포가 가른다.

**둘째, 열 건 중 네 건은 즉답이 안 된다.** 승인 대기 15 + 입력 대기 13 = 28건(39%)이다. 이 케이스들은 한 번의 응답으로 끝나지 않고 **상태를 들고 기다렸다가 다시 이어져야 한다.** v8 §2가 "보류·승인·재처리를 표현하기 어렵다"고 쓴 기술 문장의 실제 무게가 이 39%다.

## 3. 비용 [v8 §2-B 초안]

### 3-1. 절감액으로 팔면 자기모순이다

v8 §1-1은 자동화율을 앞세우지 않겠다고 선언했다. 그런데 비용 절감을 "자동화율 × 건당 인건비"로 주장하면 **결국 자동화율로 파는 것**이 되어 포지셔닝과 충돌한다.

그래서 비용을 세 축으로 나누고, **축 2를 우리 축으로 삼는다.**

| 축 | 산식 | 누구의 관심 | 우리 축인가 |
|---|---|---|---|
| 축 1 · 처리 비용 | 건당 처리시간 × 인건비 단가 | CS 팀장 | 보조 |
| **축 2 · 오류 비용** | **오류율 × 건당 오류 손실** | **운영 책임자·법무** | **★ 주력** |
| 축 3 · 도입·운영 비용 | LLM 비용 + 승인 대기 인건비 + 인프라 | 예산 결정자 | 우리가 받는 값 |

### 3-2. 축 2 — 오류 1건의 비용

오류 1건은 세 겹으로 비용이 된다.

| 겹 | 내용 | 측정 가능성 |
|---|---|---|
| 직접 손실 | 잘못 안내한 금액의 차액, 잘못 승인한 환불 | 사내 데이터로 즉시 산출 가능 |
| 재처리 비용 | 재문의 → 확인 → 정정 → 사과. 최초 응대의 몇 배 | 티켓 재오픈 로그로 산출 가능 |
| 신뢰 손실 | 이탈, 리뷰, 분쟁 조정 | `[미확보]` 대리지표 필요 |

**우리 코드에서 나온 실제 사례가 있다.** `[실측]`

`final_project_cs`의 환불 계산은 `orders.total_cents × 반품수량 ÷ item_count`다. `orders` 테이블에는 금액 칸이 `total_cents` 하나뿐이라 정가와 실결제액이 구분되지 않는다. 할인·포인트·쿠폰이 붙는 순간 이렇게 된다.

```
30,000원 주문 · 5,000원 쿠폰 사용 → 실결제 25,000원
2개 중 1개 반품

우리 안내:  30,000 × 1 ÷ 2 = 15,000원
실제 입금:  25,000 × 1 ÷ 2 = 12,500원
                              차액 2,500원 — 고객에게 잘못 말한다
```

지금은 포인트·쿠폰이 없어서 안 터지지만 검증 쇼핑몰에 할인이 하나라도 붙으면 그날 터진다. **이 한 건이 축 2가 추상적 우려가 아니라는 증거다.**

근거 위치와 조치안은 [`A-COP_결제소유_경계.md`](A-COP_결제소유_경계.md) §5에 있다. 계산식은 [`return_refund.py:139-144`](../../final_project_cs/app/modules/customer_ops/return_refund.py), 금액 칸이 하나뿐인 스키마는 [`002_domain_commerce.sql:17`](../../final_project_cs/app/infrastructure/db/migrations/002_domain_commerce.sql)이다.

## 4. 페르소나 [v8 §6-A 초안]

### 4-1. 원칙 — 장식이면 넣지 않는다

페르소나를 인물 소개로 끝내면 발표 슬라이드 한 장으로 남고 설계에 아무 영향이 없다. 이 프로젝트는 pytest와 실측 트레이스가 판정하는 문화를 갖고 있으므로, **페르소나도 검증 대상에 물린다.** §5에서 골든셋 72건을 페르소나별로 배분한다. 그러면 "페르소나 A 케이스에서 근거 정합률이 낮다" 같은 문장이 측정 결과로 나온다.

각 페르소나는 §2의 페인 층 하나와 1:1로 대응한다. 인물을 새로 늘리지 않는다.

### 4-2. 박선영 — 문의하는 고객 (페인 층 1)

| | |
|---|---|
| 배경 | 34세 직장인. 온라인 쇼핑 주 2회. `[추정]` |
| 상황 | 반품·환불 금액이 안내와 다르게 들어왔다 |
| 감정 | worried / confused — 골든셋의 50% `[실측]` |
| 원하는 것 | 화를 풀어 주는 것이 아니라 **왜 그 금액인지** |
| 성공 조건 | 답변에 붙은 근거로 스스로 납득한다 |
| 실패 조건 | "확인 후 연락드리겠습니다"를 두 번 듣는다 |

**이 인물이 던지는 설계 요구.** 답변은 결론만이 아니라 근거를 함께 낸다 → §9-E, §15 `groundedness`.

### 4-3. 김도현 — 상담원 (페인 층 2)

| | |
|---|---|
| 배경 | CS 2년차. 정규 상담원. `[추정]` |
| 상황 | 문의 하나에 화면 서너 개를 오간다 |
| 감정 | 시간 압박 + 오답 책임 부담 |
| 원하는 것 | 판단에 필요한 자료가 **한자리에** 모여 있는 것 |
| 성공 조건 | ContextPack만 보고 답을 쓴다 |
| 실패 조건 | AI 초안을 믿을 수 없어 결국 처음부터 다시 확인한다 |

**이 인물이 던지는 설계 요구.** 초안은 검토 가능해야 한다. 근거 없는 문장이 섞이면 검토 비용이 작성 비용보다 커진다 → §15 `근거 초과율`이 이 인물을 위한 지표다.

`[추정]` 김도현의 실패 조건은 AI 도입 실패의 흔한 형태지만 우리 데이터로 확인한 것은 아니다. §8에서 교정한다.

| 감정 | 판단 근거 없음에서 오는 불안 |
| 원하는 것 | **어디까지 자동으로 보내도 되는지** 선을 수치로 아는 것 |
| 성공 조건 | 승인 경계를 근거를 갖고 조정한다 |
| 실패 조건 | 사고 한 번에 전체 자동화를 되돌린다 |

**이 인물이 던지는 설계 요구.** 자동/승인 경계가 설정 가능하고 그 근거가 측정돼야 한다 → §15 `적절한 기권율`·`과잉 기권율`, §1-1 human-on-the-loop.

**세 명 중 돈을 내는 사람은 정미라다.** v8이 기술 심사에는 충분하고 사업 심사에 약한 이유가 여기 있다. 계획서 전체가 김도현의 편의를 설명하고 정미라의 판단 근거를 설명하지 않는다. 이 절을 넣으면 §26에 사업 질문을 추가할 근거도 함께 생긴다.

### 4-5. 넣지 않는 페르소나

| 후보 | 왜 빼나 |
|---|---|
| 개발자 / 도입 엔지니어 | v8 §8-B·§21이 이미 충분히 다룬다. 계획서 전체가 사실상 이 사람 대상이다. |
| 경영진 | 10주 범위에서 접점이 없다. 가격 정책도 미정(§1-1). |
| Personal AI 사용자 | §9에 경로가 있으나 MVP 검증 대상이 아니다. 확장 시 추가한다. |

## 7. §26 심사 질문 보강안
