# 여행 전환 — 밤새 한 것과 당신이 정해야 하는 것

`[2026-09-10]` 주무시는 동안 진행한 것을 한 장으로 정리한다.
**결론 먼저, 근거는 각 문서에.**

---

## 0. 세 줄 요약

1. **설계는 100% 에 도달했다.** 혼자 정할 수 있는 것은 전부 정했다 —
   미확보 24건 → **혼자 못 정하는 7건**만 남았다.
2. **코드는 30% 그대로다.** 남은 7층은 코드 세션 몫이고 제 담당이 아니다.
   대신 **적용이 기계적이 되도록** 값·규칙·확인 방법까지 못박아 뒀다.
3. **가장 급한 것은 하나다** — 지금 **여행 Case 가 Team 에 도달하지 못한다.**
   분류기 어휘가 아직 쇼핑몰이라 여섯 팀이 다 놀고 있다.

---

## 1. 당신이 정해야 하는 것 — 7건

혼자 정할 수 없는 것만 남겼다. **각각 왜 혼자 못 정하는지**를 같이 적는다.

| # | 무엇 | 왜 당신이 정해야 하나 | 어디 |
|---|---|---|---|
| 1 | **슬러그 다섯을 v10 에 올릴지** | 제가 `itinerary_submit` 등으로 정했는데 **v10 §5-A 는 한국어만 적어 뒀다.** 두 곳에 다르게 적히면 그게 다음 드리프트다 | [분류어휘 명세 §2](A-COP_여행_분류어휘와_라우팅_명세.md) |
| 2 | **`business_subject` 사양** — ①한 Case 에 같은 종류 하나 / ②서버가 대상 객체 id 를 키에 | 제품이 무엇을 약속하느냐의 문제다. **②를 권했고 이유 셋을 적었지만**, ①이면 "여러 예약을 바꿀 땐 Case 를 나눈다" 가 사양이 된다 | [전환현황 §4](A-COP_여행전환_현황_2026-09-09.md) |
| 3 | **알림 전달 계약** — 기한·수신 확인·실패 시 처리 | **외부 에이전트와 맞춰야 한다.** 우리 혼자 정할 수 없다 | [설계결정 §3](A-COP_여행MVP_설계결정_6건.md) |
| 4 | **Activity 쇼핑 제외 21종** | 대형마트가 들어 있어 재검토가 필요하다고 루트 `CLAUDE.md` 가 이미 적어 뒀다 | [구성안](A-COP_여행Team모듈_구성안.md) |
| 5 | **무료·무예약 활동 판정 규칙** | 경복궁처럼 취소 기한·위약금이 없는 활동을 무엇으로 판정할지 — **업무 규칙이라 제가 못 만든다** | 동 |
| 6 | **감시 소스 실제 연결 대상** | 기상청은 공개인데 **액티비티 운영 공지는 공급자마다 다르다.** 도시를 정해야 표본을 뽑는다 | 동 |
| 7 | **강사가 말한 "에이전트"** | 우리가 말하는 Team 과 같은 것인지 확인이 필요하다 | [설계질문 5건](A-COP_여행MVP_설계질문_5건.md) |

★**1·2 가 급하다.** 나머지 다섯은 코드가 도는 것과 무관하지만, 이 둘은
**적용 순서의 맨 앞**이라 안 정하면 뒤가 다 막힌다.

## 2. 밤새 정한 것 — 근거를 적어 결정했다

**실측으로 닫은 것 일곱**

| 무엇 | 답 |
|---|---|
| `Classification` 이 코어 계약인가 | **아니다.** `app/core` 에 없고 쓰는 곳도 한 곳. 그래도 칸은 안 늘린다 |
| `issue_code="other"` 의 escalate 경로 | **이미 있다.** `controller.py:171` 이 잡아 `ROUTING_FAILED` 로 보낸다 |
| 운영 UI 뼈대 | 라우트 8개 중 **승인·추적이 실물**, 목록이 뼈대. 새로 만들 화면은 **「일정」 하나** |
| capability 훅이 필요한 팀 | capability 둘 이상인 **넷**. 그중 하나(`mobility`)만 있다 |
| 과거 기상 재생 | **안 된다.** `open_meteo.py:94` 가 과거 날짜를 `None`(모름)으로 돌려준다 |
| 프롬프트에 커머스 어휘 | **박혀 있다.** `feedback.py:81` 이 리터럴로 쓴다 |
| 항목 수준 조건 존재 | **있다.** `activity.py:129` 가 `party_size` 를 예약에서 읽는다 |

**근거를 적어 결정한 것 여덟**

라우팅 축(두 축 다 쓴다) · 조건 보존(한 표에 「무엇에 붙는가」 칸) ·
감시 소스 자리(`config/`) · 검증 시점(CI·기동 둘 다) · 알림 수신 주체(에이전트) ·
시연 기상(Mock 기본 + 재생 표시) · 알림 채널(디스코드 하나만) ·
대상 객체 id 규칙(`action_type` 접두 → 인자 키, 없으면 거부)

## 3. 검토에서 뒤집힌 것 하나

★막히는 것은 검토에 부치라고 하셔서, **동의가 아니라 반박을 요구하는 방식**으로
두 번 돌렸다. **여섯 결정 중 하나가 뒤집혔다.**

**「정규화할 때 동행 조건을 안 넣어도 된다」 — 틀렸다.**

`dining.py` 한 줄(조건을 Case 상태에서 읽는다)을 보고 "조건은 Trip 수준" 이라
단정했다. 같은 폴더 `activity.py:129` 에 반례가 있었다 — `party_size` 를
**예약(항목)에서** 읽는다.

검토자 말 그대로 — *"입력 조건을 잃으면 필수 조건을 위반한 일정을 정상 판정한다.
MVP 의 핵심인 검증 신뢰성을 직접 무너뜨린다."*

★**좁게 확인하고 넓게 단정했다.** 나머지 다섯도 전부 "조건부" 였고,
**내가 안 본 것이 하나씩** 있었다. 검토가 짚은 것 중 검증 가능한 셋은
**직접 열어 확인한 뒤** 반영했다.

## 4. 코드 쪽 — 제 담당이 아닌 것

**여행 전환 10층 중 3층(30%)** 이고 밤새 안 바뀌었다. 남은 일곱은 코드 세션 몫이다.

★**1순위 하나만 고치면 루프가 돈다** — 분류 어휘 두 줄(`feedback.py:48,51`)과
컨트롤러 두 줄(`controller.py:71,167`), 가드 테스트 하나.
값은 [분류어휘 명세](A-COP_여행_분류어휘와_라우팅_명세.md)에 다 있고,
**시뮬레이션으로 17/17 라우팅 성공까지 확인해 뒀다.**

★**가드 테스트는 "통과하는지" 로 확인하면 안 된다.** 지금 것이 통과하면서
못 잡고 있었다 — 등록조차 안 된 팀 하나만 보기 때문이다.
**일부러 깨뜨려 빨간 것을 본 뒤에** 고쳐야 가드인지 안다.

## 5. 밤새 찾은 결함 하나 — 잠재적이지만 여행에서 커진다

**한 Case 에 같은 종류 제안이 둘이면 두 번째가 조용히 사라진다.**

살아 있는 DB 에서 재현했다(트랜잭션 롤백, 남긴 것 없음) —
예약 두 건이 **한 행**이 되고 `bk-002` 가 없어진다. 오류도 경고도 없다.

★**지금은 잠재 결함이다.** 검토가 짚었고 맞는 지적이다 — 여행 Team 은 전부
제안을 하나씩만 돌려준다. **다만 `TeamResult` 계약이 여럿을 허용하고,
승인 화면·실행 직전 재검증이 「저장된 행」을 읽어서 못 되살린다.**

★**`case_id` 를 고른 데는 근거가 있었다** — 결제 식별자가 계약 필드로 없던
모델에서 내린 선택이다(`2026-08-14_S-IDEMKEY_리포트`). **여행이 그 전제를 깬다** —
Trip 하나에 예약이 여럿이고 `booking_id` 는 있다.

→ 위 §1 의 결정 2번이 이것이다.
