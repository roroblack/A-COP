# 문서관리 전략

이 문서는 `_colleagueskill_적용검토_2026-08-18.md`와 `_openwiki_검토_2026-08-18.md`를 통합한 현재 전략 문서다.

## 결론

전면적인 OpenWiki식 파일 분할보다 `research/index.md`를 현재 근거의 얇은 입구로 강화한다. 규칙·불변식은 코드 지침에, 계획·계약은 v8에, 근거·상세 설계·작업 기록은 research/archive를 포함한 지식층에 둔다. 파일을 늘리는 것만으로 정합성 비용이 사라지지 않으며, 기준선·정본·확인일·모순 표시가 핵심이다.

## 현재 구조와 위험

- 계획서 v8은 42개 최상위 절과 계약·DDL·평가·일정 명세를 포함하는 정본이다. 전체를 공통 헌법처럼 매번 읽히지 않는다.
- research는 살아 있는 근거와 작업 기록을 구분해야 하며, 색인의 파일 수가 실제 디렉터리와 어긋날 수 있으므로 색인 자체도 검증 대상이다.
- 과거 사례로 존재하지 않는 `§337` 참조, Response 팀 누락, 옛 팀명 병존, DoD 18→28→29 드리프트가 있었다.

## 병합·갱신 규칙

1. 변경 전 정본과 보존본을 먼저 확인한다.
2. 새 내용은 보완·중복·모순으로 분류한다.
3. 보완만 정본에 추가하고 중복 문장은 만들지 않는다.
4. 모순은 사람 확인 항목으로 남기며 최신 파일이라는 이유만으로 덮어쓰지 않는다.
5. 모든 절 번호·Team명·DoD 수·일정·Docker 단계는 실제 정본 heading/표와 대조한다.

## 운영 주기

2·4·6·8·10주차에 정본·코드·제출물의 반복 사실을 대조한다. 변경 경로, 기준선 링크, Team 집합, DoD 수, 존재하지 않는 절 번호를 검색하고, 불일치는 `정본 / 충돌 문서 / 판정 / 확인자 / 날짜`로 기록한다.
