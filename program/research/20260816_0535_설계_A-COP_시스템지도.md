### 이 표에서 읽을 것

**고정(컴포넌트) 14개는 끌 수 없다.** 상태·계약·안전 경계가 여기 있다. 하나라도 빼면 A-COP이 아니다.

**모듈 11개는 켜고 끈다.** Adapter와 표면이 여기 속한다. Port는 고정이고 그 Adapter가 모듈이다 —
`GraphStorePort`는 못 끄지만 `SqlGraphAdapter`는 Age·Neo4j로 바꿀 수 있다.

**인스턴스 5개는 개수가 바뀐다.** Agent Team이 전부 여기다. Registry 등록만으로 늘어나고
Controller·`TeamExecutorPort`·`TeamResult` 계약은 바뀌지 않는다. 늘리는 일이 리팩토링이 되면 설계가 잘못된 것이다.

**지금 비어 있는 자리** — Commerce MCP(없음), A2A 실행·Remote Team·응답 검증·방어층(골격만).
할루시네이션 방어층이 골격만인 것이 가장 시급하다. 쓰기 권한을 여는 전제 조건이기 때문이다.

## 1. 고객 메시지가 들어온다
- **REST `/v1`** — 고정 · 쓰기 경로 · 끌 수 없음: Case 생성의 외부 진입점이다
- **MCP** — 모듈 · 켜짐 · 개인 AI 접속 · `cs.*` / `commerce.*` 표면 · 끄면 개인 AI의 Case·Commerce 접근이 깨진다

## 2. `customer_cases`를 직접 UPDATE하지 않는다 — 여기가 유일한 문이다
- **`transition_case()`** — 고정 · 단일 진입점 · 끌 수 없음: 상태 전이의 유일한 문이다
- **`case_events`** — 고정 · append-only · 끌 수 없음: 이력·감사의 원천이다
- **Contract models** — 고정 · `extra='forbid'` · 끌 수 없음: 입력·출력 계약을 강제한다

## 3. 실패하면 `classification_failed`를 남기고 `escalated`로 간다
- **인라인 분류** — 고정 · intent · issue · sentiment · 끌 수 없음: 라우팅 전 분류 실패를 기록해야 한다
- **VOC** — 모듈 · 켜짐 · 일일 집계 · 급증 탐지 · 끄면 VOC 집계·급증 탐지와 위임 제안이 깨진다

## 4. 12,000 토큰 예산. 축소하면 `degraded`와 `omissions`를 남긴다
- **Context Broker** — 고정 · 예산 · 제거 순서
- **vector_rag** — 모듈 · 켜짐 · 정책 검색 — 빼면 grounding 0
- **graph_store** — 모듈 · 켜짐 · 관계 조회 — 빼면 graph 관계 조회가 깨진다

## 5. capability로 Team을 고른다
- **Team Registry** — 고정 · `allowed_tools` 강제 · 끌 수 없음: capability와 권한의 단일 경계다

## 6. 현재 `team_executor = local`
- **`TeamExecutorPort`** — 고정 · 교체점 · 끌 수 없음: Controller와 실행 위치의 계약이다
- **`LocalTeamExecutor`** — 모듈 · 켜짐 · 같은 프로세스 · 끄면 LOCAL Team 실행이 깨진다
- **`a2a_executor`** — 모듈 · 꺼짐 · 원격 Team 실행 · 끄면 `execution_type: A2A` Remote Team 위임이 깨진다

## 7. 개수가 바뀌는 유일한 자리 — 지금 2개 라우팅
- **`billing_subscription`** — 인스턴스 · 켜짐 · 라우팅됨
- **`technical_entitlement`** — 인스턴스 · 켜짐 · 라우팅됨

## 8. Team은 side effect를 실행하지 않는다. 제안까지다
- **Controller** — 고정 · 실행 루프 · WAIT/RESUME · 끌 수 없음: 장기 실행과 재계획을 조정한다
- **Case service** — 고정 · 중복 실행 방지 · 끌 수 없음: Case 일관성과 재처리를 보장한다
- **Human Approval** — 고정 · `action:approve` scope 필요 · 끌 수 없음: 고위험 Action의 승인 경계다

## 9. 전이와 같은 트랜잭션에서 쌓고, 워커가 따로 보낸다
- **Outbox** — 고정 · 원자성 · dedupe · 끌 수 없음: 전이와 전달의 원자성을 보장한다
- **Settings / guardrails** — 고정 · 수치의 단일 출처 · 끌 수 없음: 안전 기준의 분산을 막는다

## 10. 돌아가는 것을 본다 / 무엇을 조립할지 정한다
- **ops_ui** — 모듈 · 켜짐 · cases · approvals · voc · admin · 끄면 운영자 감독 화면이 깨진다
- **composer_ui** — 모듈 · 켜짐 · 조립 화면 · 끄면 모듈 조립·상태 확인 화면이 깨진다

## 11. v7 Runtime의 고정 경계와 교체 모듈

Port는 고정 계약이고, Adapter는 그 계약의 교체 가능한 모듈이다. Port 자체를 끄지 않는다.

| 항목 | 분류 | 현재/교체 구현 | 끄면 무엇이 깨지나 |
|---|---|---|---|
| `MessageBusPort` | 고정 | InMemory / Outbox / Redis / RabbitMQ Adapter | 끌 수 없음: Task·Event 전달 계약이 사라진다 |
| `MessageBus` Adapter | 모듈 | 현재 코드는 `OutboxBrokerAdapter` | 빼면 비동기 전달·재처리·dedupe가 깨진다 |
| `GraphStorePort` | 고정 | `SqlGraphAdapter` / Age / Neo4j | 끌 수 없음: 관계 조회 교체 계약이 사라진다 |
| Graph Adapter | 모듈 | 현재 `SqlGraphAdapter` | 빼면 graph 관계 조회가 깨진다 |
| `TeamExecutorPort` | 고정 | `LocalTeamExecutor` / `A2ATeamExecutor` | 끌 수 없음: Controller가 Team 실행 위치를 분리하지 못한다 |
| `LocalTeamExecutor` | 모듈 | 현재 LOCAL | 빼면 내부 Team 실행이 깨진다 |
| `A2ATeamExecutor` / A2A Adapter | 모듈 | 원격 Task·상태·Artifact 교환 | 빼면 원격 Team 실행이 깨진다 |
| Context Broker | 고정 | 예산·제거 순서·ContextPack 조합 | 끌 수 없음: 예산·scope·grounding 통제가 사라진다 |
| 할루시네이션 방어층 | 고정 | ActionProposal 근거 대조·실행 직전 재검증 | 끌 수 없음: 잘못된 대상·금액·수량의 실행 차단이 사라진다 |
| Response Generation & Review | 모듈 | 응답 생성·스키마/근거 검증, side effect 없음 | 빼면 응답 생성·검증 및 안전한 고객 답변이 깨진다 |
| Contract / Case transition / Outbox | 고정 | 단일 전이·append-only·원자성 | 끌 수 없음: 상태 일관성과 재처리 경계가 사라진다 |

`MessageBusPort`는 v7 명칭이다. 샘플 코드의 실제 계약명은 `MessageBrokerPort`이며 Core와 Infrastructure에 중복 정의되어 있어 정리가 필요하다.

## 12. 두 도메인 팩과 두 표면

| 항목 | 분류 | 범위 | 끄면 무엇이 깨지나 |
|---|---|---|---|
| CS Pack (Billing / Technical / VOC, 10주) | 모듈 | CS 지식·정책·응대·분석 | 빼면 CS 라우팅·응대·VOC가 깨진다 |
| Commerce Ops Pack (vision) | 모듈 | 재고·가격·발주·배송·정산 Team과 정책/Adapter | 빼면 전면 Commerce Ops 자동화가 깨진다. 제한 Commerce 표면은 별도다 |
| CS MCP `cs.*` | 모듈 | 본인 Case 조회·문의 접수 | 빼면 개인 AI의 CS 접근이 깨진다 |
| Commerce MCP `commerce.*` | 모듈 | 상품·장바구니·주문·배송 리소스 | 빼면 개인 AI의 Commerce 접근이 깨진다 |
| `Catalog & Verification` Remote Team | 인스턴스 | `execution_type: A2A`, 검증 보고서·evidence artifact | 빼면 SKU/variant 원격 검증 왕복이 깨진다 |

팩은 교체 가능한 모듈이고, 그 안의 Team은 Registry에 등록되는 인스턴스다. Team을 늘리는 일이 리팩토링이 되면 설계가 잘못된 것이다. 새 Team은 Registry 레코드·config·golden case를 늘리고 Core 계약은 바꾸지 않는다.

## 13. 인스턴스 축 — 개수가 바뀌는 것

- Agent Team: `billing_subscription`, `technical_entitlement`, VOC 및 향후 Commerce Team
- Remote Agent/Team: `Catalog & Verification` 등 `execution_type: A2A` 등록 대상
- Tool: `allowed_tools`에 등록되는 read/action 도구
- 정책 문서·knowledge 문서·prompt 버전
- golden case / holdout case / 평가 fixture
- tenant·customer·Case·Task·Action·승인·worker

고정 Core와 Port는 개수 축이 아니다. Team 추가는 Controller·Port·ActionProposal·평가 하네스를 리팩토링하지 않고 Registry와 평가 자산만 확장해야 한다.
