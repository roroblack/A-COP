# 번역 모델 비교 검증 방법론

정리 기준일: 2026-08-19

## 문서의 결론

대부분의 번역 모델 비교표는 언어 부분집합, 테스트셋, 지표, 평가 방향이 같다는 조건을 확인하지 않으면 믿을 수 없다. 같은 조건이 확인된 표만 순위 비교가 성립한다.

이번 검증에서는 외부에서 받은 번역 모델 TOP 15 성능표 두 건을 대조했다. 한 건은 논문에 존재하지 않는 숫자가 다수 포함된 조작 표였다. 예를 들어 MiLMMT-46-12B의 영→한 XCOMET-XXL(번역 품질 평가 모델) 점수를 97.85로 적었지만 실제 논문 값은 89.07이었다. 진짜 숫자에 부풀린 값을 섞는 방식이었다.

## 검증 절차

검증에는 다음 절차를 적용했다.

1. arXiv HTML 원문 5건을 로컬에 내려받았다.
2. 서브에이전트가 LaTeXML(LaTeX 문서를 XML로 변환하는 도구) 표 마크업에서 셀을 직접 파싱해 추출했다.
3. Codex가 같은 로컬 파일에서 독립적으로 다시 추출했다. 두 추출자는 서로의 결과를 모르는 상태였다.
4. 두 추출본을 대조했다. 가장 중요한 영→한 표는 사람이 원문 HTML에서 세 번째로 직접 확인했다.
5. 불일치가 나온 항목은 원문을 다시 열어 판정했다.

원문 HTML은 `.tmp/mt_papers/`에 보관 중이다. 임시 폴더이므로 영구 보관을 전제로 하지 않는다.

## 검증에 사용한 원문

- arXiv 2602.11961 — Xiaomi, MiLMMT-46, 2026-02-12
- arXiv 2605.22064 — Tencent, Hy-MT2, 2026-05-21
- arXiv 2506.17080 — Unbabel, Tower+, 2025-06-20
- arXiv 2511.07003 — NiuTrans, LMT-60, v1 2025-11-10 / v2 2026-04-24
- Hugging Face 모델카드 — yanolja/YanoljaNEXT-Rosetta-12B-2510

## 비교가 성립하는 조건

### 1. 언어 부분집합이 같아야 한다

MiLMMT-46 논문은 각 baseline을 MiLMMT와 겹치는 언어에서만 평가했다고 명시한다. 따라서 21, 26, 28, 31, 46은 표의 컬럼이 아니다. 이 숫자들은 서로 다른 평가 집단이다.

대부분의 모델은 한 평가 집단에만 등장한다. Tower-Plus-9B의 86.80은 21개 언어 값이다. MiLMMT-46-12B의 85.09는 46개 언어 값이다. 두 값을 나란히 놓고 9B가 더 낫다고 결론 내릴 수 없다. 분모가 다르다. 포함된 언어의 난이도도 다르다.

같은 함정은 Tower+ 논문 자체에도 있다. Table 1은 7개, 15개, 24개 언어 컬럼으로 구성된다. 72B의 15개 언어 값 83.29와 9B의 24개 언어 값 84.38을 비교하면 틀린 결론이 나온다.

같은 컬럼끼리 비교하면 고자원 7개 언어에서는 72B가 86.68로 9B의 86.25보다 앞선다. 전체 24개 언어에서는 9B가 84.38로 72B의 83.74보다 앞선다.

### 2. 지표 이름을 끝까지 확인해야 한다

같은 COMET(자동 번역 평가 계열)이라는 이름이 붙어도 XCOMET-XXL, COMETKiwi, COMET-22는 서로 다른 모델이다. 값의 범위도 다르다. 조작 표는 이 이름을 바꿔 적는 수법을 사용했다.

MiLMMT-46 논문에서 XCOMET는 XCOMET-XXL을 뜻한다. COMETKiwi는 wmt23-cometkiwi-da-xxl을 뜻한다. FLORES+ 쪽 COMET은 wmt22-comet-da를 뜻한다.

LMT-60 논문은 COMET-22와 SacreBLEU를 사용한다. Hy-MT2 논문은 XCOMET-XXL, CometKiwi, GEMBA 세 지표를 사용한다.

### 3. 셀 안의 슬래시를 해석해야 한다

Hy-MT2 논문의 `89.45 / 78.97 / 88.89`는 FLORES-200, WMT25, Mandarin-Minority 세 벤치마크 점수가 아니다. 이 값은 FLORES-200 ZH⇔XX의 한 셀 안에 있는 세 지표다. 순서대로 XCOMET-XXL, CometKiwi, GEMBA다.

표 각주를 확인하지 않으면 한 셀의 여러 지표를 여러 벤치마크로 오독할 수 있다.

### 4. 지표끼리 서로 다른 결과를 낼 수 있다

Hunyuan-MT-7B는 영→한 XCOMET에서 92.21로 1위다. 같은 논문의 FLORES+ 영→한 spBLEU에서는 24.57로 하위권이다. 같은 줄의 COMET은 90.67로 상위권이다.

이 차이는 출력 문체가 레퍼런스와 달라서 생긴 현상으로 보인다. 한 지표만 보고 모델을 고르면 안 되는 근거다.

### 5. 논문이 보고하지 않은 값은 추정하지 않아야 한다

Hy-MT2 논문에는 부록이 없다. 언어별 표도 없다. 따라서 한국어 성능은 미공개다. 33개 언어 평균으로 한국어 성능을 추정하면 안 된다.

TranslateGemma-27B는 MiLMMT 논문에 등장하지 않는다. 해당 논문에서 `27B`는 0회 등장한다.

### 표 C. Hy-MT2, FLORES-200 33개 언어, XCOMET-XXL / CometKiwi / GEMBA

출처는 arXiv 2605.22064 Table 2다. 값은 XX⇔XX 전체 방향 평균 컬럼이다. 한국어 단독 점수는 논문에 없다.

| 모델 | FLORES-200 XX⇔XX |
|---|---|
| Hy-MT2-30B-A3B | 87.47 / 76.34 / 88.79 |
| Hy-MT2-7B | 86.89 / 76.03 / 87.23 |
| Hy-MT2-1.8B | 79.77 / 73.41 / 78.64 |

같은 표에서 Tower-Plus-72B는 XX⇔XX가 70.02 / 65.53 / 67.85다. Tower+는 24개 언어만 지원한다. 33개 언어로 평가하면 성능이 무너진다.

모델의 지원 언어 범위를 벗어난 평가는 그 모델에 불리하게 나온다.

## WMT25 자기 보고와 공식 사람 평가

외부 자료는 Hunyuan-MT가 WMT25에서 31개 중 30개 카테고리 1위라고 주장했다. 이 숫자는 Tencent 자체 논문 arXiv 2509.05209 초록의 자기 보고다.

WMT25 공식 findings 논문 ACL Anthology 2025.wmt-1.22는 30개 언어쌍과 60개 시스템을 다뤘다. 공식 사람 평가인 ESA 프로토콜은 15개 언어쌍을 평가했다. 전체 최고는 Google Gemini 2.5 Pro였고 15개 중 14개에서 승자군에 들었다.

Tencent의 실제 출전작 Shy-hunyuan-MT는 constrained 부문 최고였다. 15개 중 11개에서 승자군이었다.

자기 보고 수치와 제3자 평가 결과는 다르다. 수치를 읽을 때 자기 보고인지 제3자 평가인지 구분해야 한다.

## Tencent 번역 모델 계보

Tencent 번역 모델 계보는 Hunyuan-MT(2025-09, WMT25 출전) → HY-MT1.5(2025-12-30) → Hy-MT2(2026-05-21)다.

세대가 다르다. 이름이 비슷하다는 이유로 같은 모델로 묶으면 안 된다.

## 로컬 벤치마크 결과의 라벨 오류

같은 저장소의 `datasets/mt/olist_reviews_mt_bench/REPORT.md`(작성 당시 경로는 `program/research/archive/2026-08-20/mt_bench_results/`였으나 이후 재구성되었다)에는 로컬 GPU에서 실행한 포르투갈어→영어(PT→EN) 벤치마크가 기록되어 있다. Olist 리뷰 300쌍을 대상으로 GGUF Q4_K_M 양자화 모델 15개를 실행했고, sacrebleu BLEU와 chrF2를 측정했다. 아래 지적은 REPORT의 "결과 1 — PT → EN" 절에 대한 것이며, 이후 추가된 "결과 2 — PT → KO" 절은 hangul_ratio 기반이라 해당하지 않는다.

이 REPORT의 마지막 두 열은 이 문서의 표 A에 있는 값을 가져다 썼지만 라벨이 잘못 붙었다. 첫째, `원 리더보드 COMET-22`가 아니라 XCOMET-XXL이다. 둘째, `원 리더보드 BLEU`가 아니라 COMETKiwi다. 셋째, 그 값은 영→한 결과인데 REPORT의 나머지 결과는 PT→EN 결과다. 예를 들어 Hunyuan-MT-7B의 92.21 / 87.24, Tower-Plus-9B의 86.78 / 84.44, MiLMMT-46-12B의 89.07 / 86.01이 표 A의 XCOMET-XXL / COMETKiwi 값과 각각 일치한다.

이 라벨 오류는 Hunyuan-MT-7B가 리더보드 BLEU 87.24에서 우리 테스트 BLEU 26.53으로 폭락했다는 착시를 만든다. 실제로 이 문서에 기록된 Hunyuan-MT-7B의 FLORES+ 영→한 spBLEU는 24.57이다. 영→한 spBLEU 24.57과 PT→EN BLEU 26.53을 직접 비교할 수는 없다. 다만 자릿수가 같으므로 두 결과가 서로 어긋난다고 볼 근거는 없다.

이 사례가 로컬 벤치마크 자체의 가치를 낮추는 것은 아니다. REPORT는 깨진 출력 3건의 원인을 확인했고, LMT-60-8B의 thinking 모드 문제를 찾아 `think:false`로 해결했다. 다만 양자화 방식과 언어쌍이 다르므로 논문이나 원 리더보드의 값과 직접 비교할 수 없다는 점도 REPORT 스스로 밝히고 있다.

이 문서에서는 위 라벨 오류만 지적하며 `REPORT.md`는 수정하지 않았다. 다른 사람이 만든 산출물이므로 원본은 그대로 둔다.

## 검증의 한계

TranslateGemma 자체 기술보고서 arXiv 2601.09012는 arXiv에 HTML 판이 없다. 따라서 표를 추출하지 못했다. 이 문서의 TranslateGemma 수치는 전부 Xiaomi 논문이 재평가한 값이다.

LMT-60의 0.6B와 1.7B는 본문 집계표에 없다. 두 모델의 값은 부록 언어별 표에서만 확인했다.

이 문서의 수치는 2026-08-19 기준이다.

## 실무 결론

한국어 용도라면 현재 공개 근거상 Hunyuan 계열이 가장 강하다. 공개된 근거에는 7B 모델과 경량 1.8B 모델이 포함된다.

Hy-MT2는 가장 최신 모델이다. 한국어 근거가 공개돼 있지 않으므로 직접 테스트 없이 도입을 판단하면 안 된다.

어떤 모델이든 도입 전에 자체 데이터로 재평가해야 한다. 논문 수치는 해당 논문의 테스트셋을 기준으로 한다.
