# S-TRACE-VIDEO. 케이스 추적 영상을 유튜브에 올릴 품질로

## 무엇을 만드나

A-COP 이라는 고객 응대 시스템에 **취소·환불 문의 한 건**이 들어와서 답이 나갈 때까지,
내부에서 무슨 일이 일어나는지 보여 주는 **설명 영상**을 만든다.

지금 있는 것은 정지 그림 17장을 이어 붙이고 장면 사이만 겹쳐 넘긴 2분 10초짜리다.
내용은 맞지만 **읽을 시간을 주는 슬라이드쇼**지 영상이 아니다. 그걸 유튜브에 올려도
되는 수준으로 다시 만든다.

## 지금 있는 재료

| 경로 | 무엇 |
|---|---|
| `program/onboarding/trace/images/*.png` | 정지 그림 17장. 1920 폭 기준으로 만들어져 있다 |
| `program/onboarding/trace/draw.py` | 그림 그리는 함수들 (matplotlib) |
| `program/onboarding/trace/steps.py` | 단계 12장의 내용 |
| `program/onboarding/trace/finale.py` | 마무리 3장의 내용 |
| `program/onboarding/trace/make_trace_images.py` | 지도 2장 + 실행 진입점 |
| `program/onboarding/trace/make_trace_video.py` | 지금의 영상 생성기 |
| `program/onboarding/trace_refund_case.html` | **내용의 원본.** 열두 단계 전문 |

환경에 `ffmpeg 9.0.1`, `matplotlib`, `numpy`, `Pillow`, `opencv 4.10`, `imageio` 가 있다.
한글 폰트는 `Malgun Gothic` 이다.

## 무엇이 부족한가

지금 영상의 문제를 그대로 적는다.

1. **움직임이 없다.** 장면이 통째로 겹쳐 넘어갈 뿐, 화면 안에서 아무것도 안 움직인다.
   데이터가 왼쪽 상자에서 오른쪽 상자로 **흘러가는** 것이 이 영상의 핵심인데 그게 안 보인다.
2. **시선을 안 이끈다.** 한 장에 정보가 많은데 어디를 먼저 볼지 알려 주지 않는다.
3. **소리가 없다.** 자막도 없다.
4. **도입과 마무리가 없다.** 바로 지도부터 시작해서 갑자기 끝난다.
5. **읽는 속도를 고려 안 했다.** 초를 손으로 적었다.

## 만들어야 할 것

### 필수

- **화면 안에서 움직인다.** 최소한 이 셋은 움직여야 한다.
  - 왼쪽 문서에서 오른쪽 문서로 데이터가 흘러가는 것
  - 새로 생기거나 바뀐 줄이 나타나는 것 (한 번에 다 뜨지 않는다)
  - 위쪽 진행바가 한 칸씩 차오르는 것
- **시선 유도.** 지금 말하고 있는 곳만 밝고 나머지는 가라앉는 식으로.
- **한국어 자막.** 화면에 태워 넣는다(하드섭). 별도 `.srt` 도 같이 낸다.
- **도입 10초 안팎, 마무리 10초 안팎.**
- **1920x1080, 30fps, H.264, yuv420p, +faststart.**
- 길이는 **3분에서 6분 사이**. 지금 2분 10초는 짧다.

### 하면 좋은 것

- 배경 음악. **저작권 문제가 없는 것만.** 못 구하면 넣지 말고 넣지 않았다고 적는다.
- 챕터 구간(유튜브 타임스탬프)을 텍스트로 같이 낸다.
- 썸네일 이미지 한 장.

### 하지 말 것

- **내용을 지어내지 않는다.** 숫자·코드 경로·필드 이름을 새로 만들지 않는다.
  `trace_refund_case.html` 과 기존 그림에 있는 것만 쓴다. 확인이 안 되면 빼고,
  뺐다고 리포트에 적는다.
- **줄표(em dash)와 화살표 문자를 쓰지 않는다.** 이 저장소의 규칙이다.
  `-` 나 `=` 나 말로 푼다.
- 음성 합성(TTS)으로 내레이션을 만들지 않는다. 목소리는 나중에 사람이 넣는다.
  대신 **내레이션 대본**을 텍스트로 낸다.
- 기존 그림 17장을 지우지 않는다. 새 것을 옆에 만든다.

## 내용에서 틀리면 안 되는 것

영상을 만들다 보면 요약하게 되는데, 아래는 요약하다 틀리기 쉬운 지점이다.

- **단계 12개와 상태 12개는 다른 축이다.** 둘 다 열둘이라 같은 것처럼 보이지만
  겹치지 않는다. 1번 신원 확인과 2번 중복 확인은 Case 가 생기기 전이라 상태가 없다.
- **Team 은 실행하지 않는다.** 환불이 맞다고 판단해도 환불하지 않고 제안만 돌려준다.
  실행은 승인 경로에서 한다.
- **9번 검토 단계는 지금 꺼져 있다.** `response_review.enabled = false` 다.
  켜져 있는 것처럼 그리면 안 된다.
- **"취소" 라고 썼는데 intent 는 return 이다.** 이게 이 케이스의 핵심 장면이다.
- 이 케이스는 전부 통과한 길이다. 갈리는 경우가 아홉 가지 있고 마지막 장에 있다.

## 완료 기준

1. 영상 파일이 재생된다. `ffprobe` 로 코덱·해상도·프레임률·길이를 확인해 리포트에 적는다.
2. 위 "필수" 여섯 가지가 전부 들어 있다. 안 넣은 것이 있으면 이유를 적는다.
3. 자막 `.srt` 와 내레이션 대본이 따로 있다.
4. 다시 만드는 명령이 한 줄이다. 중간 산출물을 손으로 만들지 않는다.
5. 기존 그림 17장이 그대로 있다.
6. 리포트를 `program/research/_리포트_S-TRACE-VIDEO.md` 에 쓴다.
   무엇을 만들었는지, 무엇을 못 했는지, 왜 못 했는지를 적는다.
