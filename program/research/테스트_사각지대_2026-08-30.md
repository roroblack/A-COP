# (대체됨) 테스트 사각지대 — 손으로 쓴 초판

이 문서는 [`테스트_사각지대_실측.md`](테스트_사각지대_실측.md)로 대체됐다.
초판은 결함 4건만 돌려 3건을 찾은 상태였고, 이후 31건까지 늘려 15건을 찾았다.
정본은 자동 생성본이다 — `python -m acop_dojo report` 로 다시 만든다.

## 자동 생성본이 담지 못하는 것 하나

`INV-STATE-001`(`app/core/transition.py` 의 버전 대조를 `!=` 에서 `<` 로 바꾸는 것)은
**실행마다 결과가 갈렸다.** 세 번 돌려 두 번은 424개가 전부 통과했고, 한 번은
테스트 하나가 깨졌다. 같은 결함, 같은 코드인데 결과가 달랐다.

그래서 이 결함은 학습 문제로 쓰지 않는다. 학습자가 같은 문제를 두 번 풀었을 때
다른 답이 나오면 안 된다. 다만 원인은 아직 모른다. 전체 테스트가 같은 PostgreSQL 을
공유하므로 앞선 테스트가 남긴 상태가 영향을 줬을 가능성이 있고, 그렇다면 이건
결함 카탈로그의 문제가 아니라 **테스트 격리의 문제**다. 확인이 필요하다.

낙관적 동시성은 사고가 나면 재현이 어려운 자리라, 이 불안정성 자체를 따로 볼 값이 있다.

## 불안정한 테스트 두 건 (2026-08-31 추가)

DB 를 쓰는 테스트 두 개가 간헐적으로 흔들린다. 둘 다 재현이 안 돼 원인을 못 밝혔다.

| 테스트 | 관찰 | 재현 시도 |
|---|---|---|
| `test_same_expected_version_has_one_success_and_one_state_conflict` 계열 | `INV-STATE-001` 결함을 세 번 돌려 두 번은 안 잡히고 한 번은 잡혔다 | 3회 중 1회 |
| `test_approval_rerun_does_not_create_action_request_again` | 결함을 고친 뒤 전체 테스트에서 한 번 실패. 같은 조건 2회 재실행에서는 통과 | 2회 모두 실패 안 함 |

두 테스트 모두 같은 PostgreSQL 을 공유하고 승인·동시성처럼 상태에 민감한 자리를 본다.
앞선 테스트가 남긴 행에 기대고 있을 가능성이 크다. 그렇다면 이건 결함 카탈로그가 아니라
**테스트 격리**의 문제다.

확인 방법 하나를 적어 둔다. `acop_dojo` 의 안정성 검사는 결함마다 지정 테스트를 3회
반복해 같은 실패 집합이 나오는지 본다.

```
python dojo.py stability --repeats 5
```

지금 낼 수 있는 결함 16개는 3회 기준으로 전부 안정적이었다. 반복 수를 올려 다시 보면
흔들리는 자리가 더 드러날 수 있다.
