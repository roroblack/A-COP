`항목`인 표는 개정 기록 표로 보고 통째로 뺀다 — 항목을 뽑는 바로 그 표라서다.

**남는 한계는 구조적이다.** 어떤 결정이든 그 결정을 정의하는 절에는 그 말이 나온다.
§8-D의 Composer 항목 넷이 그렇다. 이건 오탐이 아니라 **확인할 자리**이고, 사람이
"같은 말인가 반대말인가"를 읽어야 한다. 자동으로 지울 수 없다.

### 실행

```bash
python program/scripts/check_drift.py
```

세 가지를 본다. (1) 개정 표의 각 항목이 본문 어디에서 개정 표시 없이 언급되는지,
(2) `CLAUDE.md` 들이 기준선의 어느 절을 인용하는지, (3) 코드 주장이 실제와 맞는지를
**AST 로** — 문자열 검색은 주석과 docstring 에 낚인다(2026-09-01 실측).

★**이 도구는 모순 후보를 찾아 줄 뿐 어느 쪽이 맞는지 판정하지 않는다.** v6/v7/v7.1
개정 기록을 읽고 "v7 이 뒤집은 근거가 없다" 를 찾는 일은 사람 몫이다. 종료 코드
0 은 확인할 것 없음, 1 은 사람이 볼 것 있음이다.

아직 안 보는 것은 `v8 ↔ program/wiki/` 대조다. wiki 이관이 진행 중이라
([이관 범위 목록](../wiki/governance/migration-scope/index.md)) 대상이 확정된 뒤에 붙인다.
이관이 끝나면 같은 내용이 두 벌이 되므로 이번과 똑같은 드리프트 면이 새로 생긴다.

### 언제 도는가

기준선 문서를 개정할 때마다, 그리고 개정 표에 항목이 늘 때마다 4번을 돌린다.
1~3번은 문서 병합 작업 때 함께 본다.
