# 브리핑 HTML 2차 개선 검토 기록

| 구분 | 반영 내용 |
|---|---|
| 실행 순서 | 3-2를 `Controller → TeamTask → TeamResult(ActionProposal) → Controller → Tool/Action Layer → ActionResult → Shared State`로 정렬했다. 4-3은 `ActionProposal 생성`으로 바꾸고 Team의 직접 Tool/read 호출 인상을 제거했다. |
| ERD | `agent_runs.team_id`를 `team_id (registry ref)`로 바꾸고, `action_approvals`를 추가했다. `owner_team_id`와 실행 선택 Team의 의미를 구분했다. |
| 관계선 범례 | 실선=FK/소유, 보라 점선=실행 시 참조, 회색 파선=근거 참조로 정리했다. |
| 그림 캡션 | 3-1, 3-2, 4-1~4-6, 8 ERD, 9-A, 9-B 아래에 `이 그림에서 읽을 것` 문장을 추가했다. |
| 번호 동기화 | 3-4=계획서 8-C, 9-A=계획서 8-B, 9-B=계획서 9-D를 병기했다. |
| GraphRAG 결정 | 문서 추출형과 정형 관계 질의를 구분하고, MVP는 `GraphStorePort → SqlGraphAdapter`로 시작한다. Phase 2의 AGE/Neo4j 비교와 판단 기준표를 반영했다. |
| 범위 조정 | 컴포넌트 사전·데이터 필드·기술 스택을 브리핑 수준으로 요약하고, 로드맵의 버리는 순서를 명시했다. |
| 역할 경계 | Team은 읽기/쓰기 Tool을 직접 호출하지 않고 Context Pack과 ActionProposal을 사용한다는 Core 1/Core 2 접점을 추가했다. |
| 출처 | 수치·표준 관련 문구에 외부 리서치 인용임과 확인일 2026-08-12를 footer 위에 표시했다. |

## 남은 판단 필요 항목

- 외부 리서치 인용의 발표용 원문 URL과 최종 출처명은 발표 전 확정한다.
- 8~9주차 비교 실험에서 사용할 질의 세트와 합격 기준은 구현계획서·평가 하니스에서 확정한다.
- PostgreSQL JOIN/재귀 CTE와 AGE·Neo4j Adapter의 실제 비교 범위는 일정에 따라 결정한다.
