# 제출표 v2 작성 리포트

## 변경 사항

- 기존 엑셀 요약을 전면 재작성하고, 첫 문장에 B2B 구축·판매 대상과 고객사의 기존 에이전트 접점을 배치했다.
- 프로젝트 주제 설명을 제공 형태, 소비자 접점, 처리 구조, 안전 경계, 검증, 운영, 배포로 분리했다.
- v7 §16의 코어 1·코어 2·모델·검증&프론트 역할에 기술을 매핑하고 MVP 필수와 Phase 2를 분리했다.
- 주제 선정 이유를 에이전트 트래픽·에이전트 쇼핑·시장·운영화 공백·경쟁 공백·자체 호스팅 수요·결론 순으로 재배치했다.
- 근거 데이터 A~H를 주제별 표로 옮기고 모든 행에 근거번호, 출처기관, 1차/2차 등급, URL을 넣었다.
- B7은 “추정”, C3은 “2차·원출처 미확인”으로 표시했다.
- 경쟁 포지셔닝의 주장 셀에 G 근거번호를 넣고, 근거가 없는 칸은 “확인 필요”로 표시했다.
- 자동화율·성능·비용 절감 등 아직 측정하지 않은 프로젝트 성과는 주장하지 않는다고 명시했다.
- `program/research/에이전트팀_구성.md`는 읽기만 했고 수정하지 않았다.

## 자체 검증

검증 스크립트는 문서의 숫자 토큰을 훑고, 근거번호가 붙은 통계 문장과 출처 목록 URL을 대조하도록 실행했다.

| 점검 항목 | 결과 |
|---|---|
| 제출표 파일 생성 | 통과: `A-COPilot_제출표_v2.md` |
| 작성 리포트 생성 | 통과: 본 파일 |
| 모든 근거 데이터 행의 근거번호·기관·등급·URL | 통과 |
| B7·C3 약한 근거 경계 표시 | 통과 |
| 경쟁표 셀별 G 근거번호 또는 확인 필요 | 통과 |
| 근거 없는 프로젝트 자동화율 주장 | 없음 |
| URL 개수 대조 | Python 정규식 기준 원문 33회·고유 28개, 신규 문서 84회·고유 28개. 반복 인용은 늘었지만 고유 URL 집합은 일치 |
| 숫자 점검 | Python으로 URL을 제외한 숫자 토큰을 스캔했다. 통계 숫자는 해당 A~H 근거번호와 함께 표기했고, URL·근거 ID·문서 구조 번호·기술명에 포함된 숫자는 사실 수치가 아님 |

## 판단이 필요한 항목

- Commerce MCP는 시스템 지도 실측상 없음이다. 제출표에서는 제품 방향과 제공 형태로 설명하되, 구현 완료로 표현하지 않았다.
- A2A 실행·Remote Team·응답 검증·방어층은 시스템 지도에서 골격만으로 확인된다. 따라서 기능 설계와 실측 완료를 분리했다.
- B7은 기관이 특정되지 않은 추정치라 선정 이유의 핵심 논리에서 사용하지 않았다.
- C3은 원출처 미확인이라 국내 시장 규모를 확정 수치로 사용하지 않았다.
- 기술 스택의 Phase 2 항목은 v7 §28과 시스템 지도의 교체 가능 Adapter·배포 프로파일을 기준으로 정리했으며, 실제 구현 완료를 뜻하지 않는다.
