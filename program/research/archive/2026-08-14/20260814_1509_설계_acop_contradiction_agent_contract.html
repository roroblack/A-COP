모순판정 — Record Consistency Guard

고객 주장을 시스템 자신의 기록과 대조해 모순·일치·판정불가 세 갈래로 분류하는 검증 모듈의 계약 명세.

한 줄 요약 — "누구 말이 맞는가"를 AI가 판결하지 않는다. 고객의 주장을 시스템 자신의 append-only 이벤트 로그와 대조해서 모순 / 일치 / 판정불가 세 갈래로만 분류한다. 별도 Team이 아니라 ORD·LOG가 공유하는 검증 모듈이며, 정답셋은 case_events에서 자동으로 생성되므로 사람이 라벨링할 필요가 없다.

1. 전제 조건 — 이벤트 타입 5종

case_events가 에이전트 자신의 출력만 담으면 정답셋이 될 수 없다. 자기 출력으로 자기를 채점하는 순환 구조이기 때문이다. 아래 5종을 구분해야 한다.

이벤트 타입의미
claim_asserted고객이 자연어로 주장한 내용
system_recorded시스템이 실제로 기록한 사실
agent_proposed에이전트의 제안 (판정 대상 아님)
action_approved사람의 승인
action_completed실제 처리 완료

2. 판정 규칙 — 세 갈래 예시

모순
고객 주장"환불이 완료됐다고 안내받았다"
시스템 기록refund_approved만 존재, refund_completed 없음
일치
고객 주장"환불 승인 후에도 안 됐다"
시스템 기록refund_approved만 존재, refund_completed 없음 — 미완료 상태로 뒷받침됨
판정불가
고객 주장"상품을 실제로 받지 못했다"
시스템 기록배송완료 이벤트 존재 — 운송 기록일 뿐 실수령의 증거는 아님

세 번째 갈래를 "고객 거짓"으로 밀어붙이지 않는 것이 이 설계의 핵심이다. 지우면 임의의 외부 진실을 다시 지어내는 함정에 빠진다.

3. 3기준 검증

기준판정근거
정답셋 존재통과이벤트 시각·상태·정책 버전으로 규칙 기반 라벨이 자동 생성됨
임의배정 비의존통과판정 대상은 주문 ID·이벤트 관계로 결정되며 지어낸 배정이 없음
코어루프 필요통과근거수집→제안→검토→승인→종결 전 단계에 직접 쓰임

4. Contract 명세

입력

ContradictionCheckInput
  case_id: UUID
  claim: ClaimAssertion            # claim_asserted 이벤트에서 파싱된 구조
    - claim_type: Literal["refund_status","delivery_status","policy_eligibility", ...]
    - asserted_at: datetime
    - raw_text: str
  candidate_events: list[SystemEvent]   # case_events 중 관련 이벤트만 (system_recorded)
  policy_context: PolicyVersion | None  # 정책 시행일 버전 (해당 시)

출력

ContradictionCheckResult
  verdict: Literal["contradicted", "consistent", "indeterminate"]
  matched_events: list[EvidenceRef]     # 판정 근거가 된 이벤트만 (전체 아님)
  rationale: str                        # 템플릿 기반 — 근거 이벤트 나열, LLM 자유생성 아님
  indeterminate_reason: str | None      # 판정불가일 때만: 왜 시스템 기록이 증명하지 못하는지
  next_action: Literal["respond","escalate","reopen_case","no_action"]

다음 조치 매핑

verdictnext_action의미
모순escalate | reopen_case시스템 기록과 어긋남 — 사람 검토 또는 케이스 재오픈
일치respond근거 기반 안내로 종결 가능
판정불가escalate외부 사실 확인이 필요 — 시스템이 임의로 단정하지 않음

5. 금지 사항

  • 판정불가를 거짓으로 격하하지 않는다. 시스템 기록이 증명하지 못하는 것과 고객이 틀린 것은 다르다.
  • claim_asserted / system_recorded 구분이 없으면 실행하지 않는다. 구분 없는 로그로는 자기 출력을 자기가 채점하는 순환이 된다.
  • 판정 결과가 직접 환불·제재를 실행하지 않는다. ActionProposal만 생성하고, 실행은 항상 사람 승인을 거친다.
  • 모순 판정이 곧 귀책 판정은 아니다. "기록과 다르다"까지만 말하고 "누구 잘못이다"는 말하지 않는다.

6. 확장 후보 (같은 원리, 별도 문서)
