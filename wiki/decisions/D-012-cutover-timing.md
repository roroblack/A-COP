# D-012 전환은 중간발표 후에 한다

`[실측]` 2026-09-03 결정.

## ★ [2026-09-03] 이 결정의 근거가 틀렸다

**"발표 전/후 어느 쪽?"이라고 물어 "후"라는 답을 받았지만, 왜 검증하는지를 못 읽고 세운 결정이다.**

`[실측]` **검증은 전환을 미루려고 한 게 아니라 전환을 앞당기려고 한 것이다.**

> **가능하면 빨리 전환해야 해서 지금 검증하고 있다.**

**그래서 "발표 후"라는 시점 고정을 뗀다.** 전환은 **준비가 끝나고 사용자가 부를 때** 한다.

### 지금 막는 것 셋 — 둘은 결정이다

| # | | 상태 |
|---|---|---|
| 1 | **놓을 자리** — `<저장소>/wiki/` vs `docs/wiki/` | **★ 2026-09-06 결정: `<저장소>/wiki/`** (사용자, 권고안 그대로) |
| 2 | 경로 재작성 — dry-run 기준 **링크 516곳 + 코드 참조 419곳**(2026-09-07) | ~~스크립트 준비 완료. 가드만 풀면 실행~~ **`[실측 2026-09-07]` 틀렸다.** `cutover_rewrite.py`(101줄)는 **계획만 낸다** — 파일 이동도 링크 재계산도 구현돼 있지 않고 `--apply`는 거부 메시지만 찍는다. `check_wiki.py`의 `ROOTS`도 `program/` 경로에 고정돼 있어 전환 뒤엔 검사가 안 돈다. 실행하려면 둘을 먼저 만들어야 한다 |
| 3 | `CLAUDE.md` 진입점 | 한 줄 |

`[실측]` **검증은 끝났다** — 문서 대조 22/22 · 236건 · 검사 통과 · 미작성 링크 0.

### 권고 — `<저장소>/wiki/`

| | |
|---|---|
| **`<저장소>/wiki/`** | `docs/` 와 별개 트리. **`RULE.md` 4.2 파일명 규칙과 안 부딪힌다** |
| `docs/wiki/` | 한 트리에서 `YYYY-MM-DD_HHmm_` 과 kebab-case 가 섞인다 |

**`docs/` 는 작업 기록이고 `wiki/` 는 현재 지식이다.** 성격이 다르니 트리도 나눈다.

### 전환할 때 같이 해야 하는 것

`[실측]` `check_drift.py` 가 적어 둔 경고.

> 이관이 끝나면 **v8 과 wiki 가 같은 내용을 두 벌** 갖게 되므로 **똑같은 드리프트 면이 새로 생긴다.**

**오늘 이미 한 번 났다** — `core-vs-team.md` 가 v8 §7 재판정을 안 따라갔다.

**전환하면서 검사 4(v8 ↔ wiki)를 같이 붙인다.** → [../governance/review-policy.md](../governance/review-policy.md)

## 결정

> **~~중간발표 이후에 한다~~ → 준비가 끝났고, 사용자가 부를 때 한다.**

**그때까지 두 구조가 공존한다.** `CLAUDE.md` 와 `docs/` 가 계속 정본이다.

## 왜

**발표 전에 옮기면 잃을 게 크고 얻을 게 없다.**

| | 발표 전 | 발표 후 |
|---|---|---|
| 진입 경로가 바뀐다 | **발표 준비 중에 팀이 헤맨다** | 여유가 있다 |
| 링크 89곳 · 코드 경로 83곳 | 깨지면 발표 자료가 막힌다 | 고칠 시간이 있다 |
| 얻는 것 | **없다** — 발표에 wiki 구조는 안 나온다 | 다음 사이클부터 쓴다 |

**발표는 제품을 보여주는 자리이지 문서 구조를 보여주는 자리가 아니다.**

## 그때까지 하는 것

`[실측]` **대조는 계속한다.** 전환을 앞당기지는 않지만 **원본을 고치는 값이 있다.**

지금까지 **9번 대조에 9건**이 나왔고 그중엔 이런 게 있었다.

> 법정 지연이자를 **연 40%(상한)를 실제 요율처럼** 적고 있었다. 실제는 **연 15%**.

**그대로 답하면 고객에게 2.7배를 약속하는 셈이다.** 발표 전에 잡는 게 맞다.

| 하는 것 | 안 하는 것 |
|---|---|
| 남은 대조 33건 | **저장소로 옮기기** |
| 검사기 유지 | `CLAUDE.md` 진입점 추가 |
| **경로 재작성 스크립트 준비** | **그 스크립트 실행** |
| 낡음 검사 | 분할 결과 적용 |

**세 번째가 중요하다.** 도구는 미리 만들어 두고 **실행만 미룬다.** 발표 후에 만들기 시작하면 또 미뤄진다.
