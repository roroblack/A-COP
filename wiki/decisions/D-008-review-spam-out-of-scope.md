# D-008 가짜 리뷰 분류는 범위 밖

`[실측]` `datasets/voc/sources_catalog/_review_spam_detection_codex_논의_2026-08-20.md`에서 이관.

## 맥락

VOC 데이터에 리뷰가 있다. **가짜 리뷰를 걸러내는 기능을 넣을 수 있는가.**

## 결정

> **가짜 리뷰 분류 출시는 보류한다.**
>
> **설명 가능한 이상 징후를 사람 검토용으로 제안하는 것까지만 허용한다.**

**자동 탐지·자동 조치를 하지 않는다.**

## 왜

`[실측]` **손대지 않는 조건 넷 중 하나라도 없으면 제품 기능으로 노출하지 않는다.**

| 없으면 안 되는 것 | 지금 |
|---|---|
| 맥락 | `[미확보]` |
| **담당 절차** | `[미확보]` 누가 판정하나 |
| **정책 정의** | `[미확보]` 무엇이 가짜인가 |
| **독립 라벨** | `[미확보]` |

**"무엇이 가짜인가"를 정의하지 못한 채 분류기를 내면 잘못 지운다.**

## 약한 신호는 있다

`[실측]` 10개 신호를 정리했다.

```
중복 · 폭증 · 감성 불일치 · 계정/상품 그래프 · 문체 …
```

**그런데 전부 정상 설명이 가능하다.** 신제품 출시 직후 리뷰 폭증은 정상이다.

**약한 신호를 근거로 자동 판정하면 정상 고객을 친다.**

## 허용하는 형태

`ActionProposal`로만 낸다.

```
action_type : review_integrity_concern
상태 전이   : 사람 확인 전
Evidence    : 필수 필드 있음
```

**우리 구조가 이미 이걸 지원한다.** `[정정 2026-09-10]` 지원하는 것은 **일반 제안·승인 흐름**이다. `review_integrity_concern` Action 종류는 구현돼 있지 않다(cs·sample `app/`·`acop_basement/` 에서 찾았고 안 나왔다). 제안하고 사람이 판단하는 게 기본 흐름이다. → [D-005](D-005-write-gate.md)

## 데이터가 부족하다

`[실측]` 지금 있는 것은 **리뷰 데이터셋 2개**뿐이다.

실제 평가에 더 필요한 것.

```
주문 · 계정 · 프로모션 · 휴먼 라벨
```

**리뷰 텍스트만으로는 못 판정한다.** 같은 계정이 같은 상품군에 몰아 쓰는지 보려면 주문·계정이 필요하다.

## 다시 열 조건

```
내부 파일럿 → 성공 기준 충족
```

**제품 기능이 아니라 내부 파일럿부터다.**

## 못 하게 되는 것

- 리뷰 신뢰도를 제품 기능으로 광고할 수 없다
- VOC 리뷰 데이터의 활용 범위가 좁아진다
