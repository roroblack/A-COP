# D-009 추천 기능은 vision 으로

`[실측]` `A-COP_확장추천_검토.md`·`A-COP_비전항목_검토.md`에서 이관. **원본은 그대로 있다.**

## 맥락

**"이 구성이 낫다"를 시스템이 추천할 수 있는가.**

## 결정

> **자기 관측 추천은 `VISION-13`, 교차 프로젝트 추천은 `VISION-10` 2층에 넣는다.**
>
> **둘 다 지금 하지 않는다.**

## 근거가 두 종류다

| 종류 | 무엇에서 | 지금 가능한가 |
|---|---|---|
| **자기 관측** | 단일 배포의 **운영 기록** | **가능하다** |
| **교차 프로젝트** | 여러 배포 **구성 비교** | 데이터 없음 |

## 자기 관측은 지금 구조에서 성립한다

`[실측]` 기존 이벤트를 추천 근거로 쓸 수 있다.

```
routing_failed · classification_failed · …
```

**"이 intent 가 자꾸 실패한다 → Team 이 없는 것 아닌가"**를 데이터로 말할 수 있다.

`[미확보]` **다만 집계 조회가 없다.** 이벤트는 쌓이는데 세는 코드가 없다.

## 위험과 통제

| 위험 | 통제 |
|---|---|
| 조립 실패 | **dry-run** |
| 잘못된 자동 적용 | **사람이 적용** |
| 정보 노출 | **익명 집계** |
| 무근거 추천 | **근거 Case 공개** |

**넷 다 "자동으로 하지 않는다"로 수렴한다.** → [D-005](D-005-write-gate.md)

## `VISION-13` 트리거

`[실측]` 재검토 조건.

```
30일에 50건  또는  동일 유형 10건
```

**그만큼 쌓여야 추천이 근거를 갖는다.**

## 항목 B — RAG 지원과 평가 보조

`[실측]` 세 가지를 분리했다.

| 무엇 | 성격 |
|---|---|
| 공개 데이터 전처리 | **개발 도구.** 제품 아님 |
| 고객 문서 RAG 지원 | **제품 기능** |
| 평가문항 생성 | **보조 기능** |

**첫 줄이 중요하다.** 데이터 전처리는 vision 에서 **제외**한다. 우리가 쓰는 도구지 파는 기능이 아니다.

### 위험

| 위험 | 무엇 |
|---|---|
| **자동 지식 생성 오염** | 생성한 지식이 다시 학습에 들어간다 |
| **자기채점** | 만든 쪽이 채점한다 |
| **고객 데이터 반출** | RAG 지원이 데이터를 밖으로 뺀다 |
| **holdout 오염** | 평가문항 생성이 holdout 을 본다 |

**네 번째가 특히 조용히 일어난다.** → [../evaluation/protocol.md](../evaluation/protocol.md)

## 선행 관계

```
Team 계약 → 예제 → CRUD
문서 반입 → 승인 → RAG
실 Case  → 라벨 → holdout
```

**세 줄 다 앞 단계 없이 뒤로 못 간다.**

## 확인하지 못한 것

`[미확보]`

```
실제 CRUD 구현 · 고객 문서·배포 제약
golden/holdout 소유·봉인 절차
운영 이벤트량 · 집계 조회 존재 여부 · 표시 화면
```
