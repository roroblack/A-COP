# D-016 도시와 언어는 좁히는 이유가 다르다

`[실측]` 사용자 결정 2026-09-09. v11 §0-3 이 둘을 **「팀이 1주차에 정할 것」**으로 나란히 묶어 뒀는데, **성격이 다르고 하나는 이미 답이 있었다.**

## 결정

| | 무엇 | 왜 좁히나 |
|---|---|---|
| **도시** | **서울** (사용자 결정 2026-09-10) | **검증 편의성.** 기술 제약이 아니다 |
| **언어** | ~~한국어 하나만 낸다~~ → **원본 한국어, 직접 경로는 보낼 때 고객 언어로 생성한다(결정 14 — 언어 목록 없음)** `[2026-09-10 오후]` | **책임 경계는 경로별로 갈린다.** 에이전트 경로는 에이전트 몫, 직접 경로는 우리 몫 |

## 도시 — 기술 제약이 아니라 검증 주장의 범위다

★**도시를 좁히지 않아도 시스템은 돈다.** 공개 API(관광정보·기상·경로)를 호출하면 전국 데이터가 그대로 들어온다. 코드에 도시가 박히는 자리가 없다.

**그런데 "우리가 다 검증했다"고 말하려면 좁혀야 한다.**

```
전국을 대상으로 두면   →  표본 조사가 안 끝나고, 검증 주장의 분모가 없다
한 도시로 좁히면       →  "이 도시에서 이만큼 검증했다" 를 셀 수 있다
```

★**중간발표·최종발표에서 하는 주장의 범위를 정하는 일이다.** v11 §11 이 "성능이 더 낫다는 근거는 아직 없다"고 적은 것과 같은 태도다 — **잰 범위를 넘겨 말하지 않는다.**

### 그래서 무엇이 달라지나

| | 전에 이렇게 읽고 있었다 | **실제** |
|---|---|---|
| 도시 미정이면 | **막힌다** — Activity Team 감시 소스 조사가 도시에 걸려 있다 | **안 막힌다.** 표본 조사의 대상을 좁히는 것이고, 조사 자체는 도시가 정해지면 시작한다 |
| 다도시 확장은 | v11 §9-A 가 뺀 항목 | **기능 추가가 아니라 검증 범위 확대다.** 코드가 아니라 표본이 는다 |

`[실측]` **이 오독이 문서 여러 곳에 있었다.** [../delivery/todo-user.md](../delivery/todo-user.md) 가 "액티비티 감시 소스가 도시에 걸려 있어 제일 급하다"고 적고 있었다. **급한 것은 맞지만 막혀 있는 것은 아니다.**

## 언어 — 우리는 번역하지 않는다

> ★★`[2026-09-10 오후 — 이 절의 결정이 부분적으로 뒤집혔다]` **아래는 오전 결정이다.
> 지우지 않는다.** 같은 날 오후 **접점이 둘이 되면서**(여행계획서 링크·알림이 고객에게
> **직접** 간다) **그 경로엔 옮기는 주체가 없어졌고**, 팀장 결정 11(v11 §0-4)이 그
> 구멍을 **우리가 옮기는 것**으로 메웠다.
>
> | 경로 | 누가 옮기나 |
> |---|---|
> | 개인 에이전트 API | **에이전트** — 아래 결정 그대로 |
> | ★여행계획서 링크 · 알림 | **우리** — **보낼 때 고객 언어로 생성한다**(결정 14). 언어 목록을 미리 정하지 않는다 |
>
> ★**뒤집힌 이유는 아래 논거가 틀려서가 아니라 전제가 바뀌어서다.** 아래 논거는
> "고객은 에이전트를 통해서만 들어온다"에 서 있었고, 그 전제가 오후에 깨졌다.
> 에이전트 경로에서는 아래 논거가 여전히 맞다.

★**고객은 자기 개인 에이전트를 통해 들어온다**(v11 §1). **그 에이전트가 고객 언어로 번역한다.**

★`[2026-09-10 오후]` **접점이 둘로 늘었다** — 개인 에이전트 API 말고 **여행계획서 링크**가 생겼다(§9-C). **그 화면도 한국어 하나다.** 고객이 직접 보는 화면이 생겼지만 **번역은 여전히 우리 일이 아니다** — 브라우저나 에이전트가 옮긴다. `[미확보]` 링크 화면의 언어를 어떻게 할지 계획서가 따로 적지 않는다.

```
A-COP  ──한국어──▶  고객의 개인 에이전트  ──고객 언어──▶  고객
```

### ★ [2026-09-10 정정] 영어가 아니라 한국어다

**2026-09-09 에 이 문서는 "영어 하나"로 적었다. 틀렸다.**

`[실측]` v11 §1·§0-4 결정 2번 — **「우리가 내는 언어는 한국어 하나」.** v10 §5-A 가 "영어 통지 문구 + 운영자용 한국어"였던 것을 v11 이 **한국어 한 벌**로 바꿨다.

| | v10 | **v11** |
|---|---|---|
| 고객 통지 | 영어 | **한국어** |
| 운영자용 | 한국어 | **한국어** (같은 한 벌) |

★**왜 한국어가 맞나.** 어차피 개인 에이전트가 옮기므로 **중간 언어를 영어로 둘 이유가 없다.** 우리 쪽 작성·검수·평가 자료가 한국어 한 벌이면 되고, 영어로 내면 **우리가 영어 문장 품질까지 책임지면서 그게 고객에게 가지도 않는다.**

| | 누가 |
|---|---|
| 판정·근거·확인 시각을 **한국어로** 낸다 | **우리** |
| 그걸 고객 언어로 옮긴다 | **고객 에이전트** |
| 운영자용도 같은 한국어 | 우리 (v11 §5-A). **한 벌이면 된다** |

★**이건 MVP 범위 절삭이 아니라 책임 경계다.** 「이번엔 뺀다: 중국어·일본어」로 적으면 **나중에 넓힐 것처럼** 읽히는데 **넓힐 일이 아니다** — 다국어는 우리 층의 일이 아니다.

★**그리고 우리는 번역 품질을 보증하지 못한다**(v11 §1). 고객이 받는 문장은 상대 에이전트가 옮긴 것이다. **발표에서 "다국어 지원"이라고 말하면 안 된다.**

### 이 결정이 뒤집는 것

`[실측 2026-09-09]` **번역 모델 조사의 위치가 바뀐다.**

| | 어제 적은 것 | **정정** |
|---|---|---|
| `research/mt-benchmark.md`·`mt-methodology.md` | "갑자기 중요해졌다 — v10 이 통지를 영어로 정했고 영어 통지 품질이 제품의 일부다" | **제품 경로에서 빠진다.** 우리 출력이 **한국어 하나**라 번역이 우리 층에서 일어나지 않는다 |

★**그렇다고 조사를 지우지 않는다.** 다국어가 우리 일이 아니라는 판단의 근거로 남고, 도메인이나 접점 방식이 바뀌면 다시 쓴다.

`[미확보]` **한국어 통지 문구 자체의 품질은 여전히 우리 몫이다.** 번역이 아니라 **작성**이다 — Composer 소재를 여행 어휘로 교체한다(v11 §5-A). 그 품질을 무엇으로 재는지는 안 정했다.

### 남는 위험

`[실측]` v11 §10 이 세운 리스크는 유효하다 — 방한 상위 국가가 중국·일본·대만인데 영어만 지원하면 그 고객이 빠진다.

★**그 위험의 성질이 달라졌다.** 우리가 번역을 안 하는 게 아니라 **고객 에이전트가 그 언어를 하는지에 달렸다.** 중국어권 고객의 에이전트가 한국어를 받아 중국어로 옮기면 문제가 없고, 그런 에이전트가 없으면 우리가 못 채운다.

★**한국어 출발이 영어 출발보다 이 위험을 키울 수 있다.** 한국어→중국어 번역을 하는 에이전트가 영어→중국어보다 적을 수 있다. `[미확보]` **확인하지 않았다** — 아래 검증 항목에 붙는다.

`[미확보]` **개인 에이전트가 실제로 번역을 해 주는지 확인하지 않았다.** 시연에서 붙일 에이전트 1종(v11 §9-A)으로 **직접 확인해야 한다.** 이게 이 결정의 유일한 검증 항목이다.

## 왜 둘을 갈라 적나

★**같은 `[미확보]` 목록에 묶여 있으면 같은 종류로 읽힌다.** 실제로는 하나는 **발표에서 무엇까지 주장하나**이고 하나는 **어느 층이 무엇을 책임지나**다.

| | 안 정하면 | 정하면 |
|---|---|---|
| 도시 | **주장의 분모가 없다.** 시스템은 돈다 | 검증 표본을 셀 수 있다 |
| 언어 | **우리가 다국어를 해야 하는 것처럼 읽힌다** | 그 일이 우리 층에서 사라진다 |

## 상태

`[실측]` **사용자 결정으로 둘 다 답이 나왔다** (2026-09-09).

`[실측]` **도시는 서울이다** — 사용자 결정 2026-09-10.

★**그래서 이제 이것들이 시작될 수 있다.** 도시가 정해지기를 기다리던 것들이다.

| 무엇 | 어디 |
|---|---|
| **액티비티 운영 변경 정보 출처 표본 조사** | v11 §0-3 2주차. 「오늘 그 업체가 쉰다」를 아는 경로 — Activity Team 의 가장 큰 `[미확보]` |
| 취소·환급 규정 표본 수집 | 서울권 업체 기준. **골프장 우천 위약금 규정이 가장 문서화가 잘 돼 있다** |
| 막차 데이터 확인 | Mobility Team 이 도시가 정해져야 확인 가능하다고 적어 뒀다 |
| 여행 골든셋 시나리오 | 서울 실장소로 만든다 |

`[미확보]` **서울로 좁힌 것을 발표에서 어떻게 말하는지 정하지 않았다.** "서울에서 검증했다"이지 "서울만 된다"가 아니다 — 위 「도시」 절의 취지가 발표 문구에 반영돼야 한다.

`[실측 2026-09-10]` **계획서가 받았다** — v11 §0-4 결정 1(서울)·2(한국어 하나)와 §9-A 에 들어갔다. `[정정]` 이 줄은 「계획서가 둘을 미정으로 둔다」고 적고 있었다.
