# D-016 도시와 언어는 좁히는 이유가 다르다

`[실측]` 사용자 결정 2026-09-09. v10 §0-3 이 둘을 **「팀이 1주차에 정할 것」**으로 나란히 묶어 뒀는데, **성격이 다르고 하나는 이미 답이 있었다.**

## 결정

| | 무엇 | 왜 좁히나 |
|---|---|---|
| **도시** | 하나로 좁힌다 (서울 권장) | **검증 편의성.** 기술 제약이 아니다 |
| **언어** | **영어 하나만 낸다** | **책임 경계.** 고객 언어로의 번역은 고객 에이전트 몫이다 |

## 도시 — 기술 제약이 아니라 검증 주장의 범위다

★**도시를 좁히지 않아도 시스템은 돈다.** 공개 API(관광정보·기상·경로)를 호출하면 전국 데이터가 그대로 들어온다. 코드에 도시가 박히는 자리가 없다.

**그런데 "우리가 다 검증했다"고 말하려면 좁혀야 한다.**

```
전국을 대상으로 두면   →  표본 조사가 안 끝나고, 검증 주장의 분모가 없다
한 도시로 좁히면       →  "이 도시에서 이만큼 검증했다" 를 셀 수 있다
```

★**중간발표·최종발표에서 하는 주장의 범위를 정하는 일이다.** v10 §11 이 "성능이 더 낫다는 근거는 아직 없다"고 적은 것과 같은 태도다 — **잰 범위를 넘겨 말하지 않는다.**

### 그래서 무엇이 달라지나

| | 전에 이렇게 읽고 있었다 | **실제** |
|---|---|---|
| 도시 미정이면 | **막힌다** — Activity Team 감시 소스 조사가 도시에 걸려 있다 | **안 막힌다.** 표본 조사의 대상을 좁히는 것이고, 조사 자체는 도시가 정해지면 시작한다 |
| 다도시 확장은 | v10 §9-A 가 뺀 항목 | **기능 추가가 아니라 검증 범위 확대다.** 코드가 아니라 표본이 는다 |

`[실측]` **이 오독이 문서 여러 곳에 있었다.** [../delivery/todo-user.md](../delivery/todo-user.md) 가 "액티비티 감시 소스가 도시에 걸려 있어 제일 급하다"고 적고 있었다. **급한 것은 맞지만 막혀 있는 것은 아니다.**

## 언어 — 우리는 번역하지 않는다

★**고객은 자기 개인 에이전트를 통해 들어온다**(v10 §1 — 우리는 API 로만 만난다). **그 에이전트가 고객 언어로 번역한다.**

```
A-COP  ──영어──▶  고객의 개인 에이전트  ──고객 언어──▶  고객
```

| | 누가 |
|---|---|
| 판정·근거·확인 시각을 **영어로** 낸다 | **우리** |
| 그걸 고객 언어로 옮긴다 | **고객 에이전트** |
| 운영자용 한국어 | 우리 (v10 §5-A) |

★**이건 MVP 범위 절삭이 아니라 책임 경계다.** v10 §9-A 는 "언어: 영어 1개 + 운영자용 한국어 / 이번엔 뺀다: 중국어·일본어"로 적어 **나중에 넓힐 것처럼** 읽히게 뒀다. **넓힐 일이 아니다** — 다국어는 우리 층의 일이 아니다.

### 이 결정이 뒤집는 것

`[실측 2026-09-09]` **번역 모델 조사의 위치가 바뀐다.**

| | 어제 적은 것 | **정정** |
|---|---|---|
| `research/mt-benchmark.md`·`mt-methodology.md` | "갑자기 중요해졌다 — v10 이 통지를 영어로 정했고 영어 통지 품질이 제품의 일부다" | **제품 경로에서 빠진다.** 우리 출력이 영어 하나면 번역 품질 비교는 우리 지표가 아니다 |

★**그렇다고 조사를 지우지 않는다.** 다국어가 우리 일이 아니라는 판단의 근거로 남고, 도메인이나 접점 방식이 바뀌면 다시 쓴다.

`[미확보]` **영어 통지 문구 자체의 품질은 여전히 우리 몫이다.** 번역이 아니라 **작성**이다 — Composer 소재가 영어로 교체된다(v10 §5-A). 그 품질을 무엇으로 재는지는 안 정했다.

### 남는 위험

`[실측]` v10 §10 이 세운 리스크는 유효하다 — 방한 상위 국가가 중국·일본·대만인데 영어만 지원하면 그 고객이 빠진다.

★**그 위험의 성질이 달라졌다.** 우리가 번역을 안 하는 게 아니라 **고객 에이전트가 그 언어를 하는지에 달렸다.** 중국어권 고객의 에이전트가 영어를 받아 중국어로 옮기면 문제가 없고, 그런 에이전트가 없으면 우리가 못 채운다.

`[미확보]` **개인 에이전트가 실제로 번역을 해 주는지 확인하지 않았다.** 시연에서 붙일 에이전트 1종(v10 §9-A)으로 **직접 확인해야 한다.** 이게 이 결정의 유일한 검증 항목이다.

## 왜 둘을 갈라 적나

★**같은 `[미확보]` 목록에 묶여 있으면 같은 종류로 읽힌다.** 실제로는 하나는 **발표에서 무엇까지 주장하나**이고 하나는 **어느 층이 무엇을 책임지나**다.

| | 안 정하면 | 정하면 |
|---|---|---|
| 도시 | **주장의 분모가 없다.** 시스템은 돈다 | 검증 표본을 셀 수 있다 |
| 언어 | **우리가 다국어를 해야 하는 것처럼 읽힌다** | 그 일이 우리 층에서 사라진다 |

## 상태

`[실측]` **사용자 결정으로 둘 다 답이 나왔다** (2026-09-09).

`[미확보]` **도시를 어디로 할지는 아직 안 골랐다** — 서울 권장이 그대로 유효하다. 이 결정은 **왜 좁히는지**를 정한 것이고 **어디인지**는 남아 있다.

`[미확보]` **v10 §0-3·§9-A 에 이 근거를 넣는 일은 계획서 담당 몫이다.** 지금 계획서는 둘을 나란히 미정으로 두고 이유를 적지 않는다.
