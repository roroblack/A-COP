# 두 스트림이 같은 파일을 쓰지 않는다

`[실측]` `final_project_cs/wiki/records/handoff/05_분업_규칙.md` 에서 이관. **`final_project_sample/wiki/records/handoff/05_분업_규칙.md` 에도 같은 파일이 있다** — [work-loop.md](work-loop.md) 의 `RULE.md` 중복과 같은 상태다.

## 무엇을 막나

> 두 작업 스트림이 같은 파일을 쓰면 **마지막에 끝난 쪽이 조용히 이긴다.**
>
> **테스트도 통과하고 diff 도 깨끗한데 다른 스트림의 기능만 사라진다.**

**그래서 인원이 아니라 디렉터리로 경계를 긋는다.**

> **자기 소유 밖의 파일을 만들거나 고치지 않는다.** 필요하면 소유자에게 요청한다.

→ [../delivery/roles.md](../delivery/roles.md) 의 소유 디렉터리 표

## 넘기기 전에 순서대로

| # | |
|---|---|
| 1 | **계약을 먼저 확정한다.** 인터페이스가 **wiki 본문**에 없으면 돌리지 않는다. `[정정 2026-09-10]` `docs/handoff/` 로 적혀 있었다 — `docs/` 는 2026-09-08 `wiki/records/` 로 통합됐고, 계약의 정본은 **wiki 본문**이다([work-loop.md](work-loop.md) 09-08 결정). 옛 handoff 기록은 `wiki/records/handoff/` 에 있다 |
| 2 | **프롬프트는 계약을 인용한다.** 내용을 복사하지 않는다 — **복사하면 두 벌이 어긋난다** |
| 3 | **한 번에 한 스트림.** 같은 디렉터리를 두 세션이 잡지 않게 |

**2번이 이 wiki 를 만들면서도 계속 걸린 문제다.** 사본을 만들면 어느 쪽이 정본인지 흐려진다.

## ★ 받은 뒤 반드시 검사하는 네 가지

> **산출물을 그대로 커밋하지 않는다.**

**넷 다 실제로 나왔던 실패다.**

| # | 검사 | 실제 사례 |
|---|---|---|
| 1 | **계약 위반** | 필드 누락 · 타입 불일치 · `extra='forbid'` 우회 |
| 2 | **범위 임의 삭감** | **MCP·pgvector 를 통째로 삭감했다** |
| 3 | **잘못된 근거** | 12,000 토큰 예산을 **"context window 초과"로 설명** — 실제 근거는 비용·lost-in-the-middle·재현성 |
| 4 | 수치 불일치 · 문법 오류 | 문서 간 숫자 대조 · Mermaid/JSON 파싱 |

**3번이 가장 잡기 어렵다.** 결과가 맞으면 이유가 틀려도 안 드러난다.

> **검수 결과를 리포트에 남긴다. 조용히 고치면 다음에 또 나온다.**

### 이 wiki 작업에서 실제로 걸린 것

`[실측]` 2026-09-03. **3번에 해당하는 것을 두 번 잡았다.**

| 무엇 | |
|---|---|
| codex 가 "테스트 10개를 실행했다"고 적었다 | **로그에 실행 흔적이 없었다.** 직접 돌려 실제 결과로 바꿨다 |
| codex 가 "Controller 가 outbox 를 안 만든다"고 판정했다 | **`controller.py:168` 에서 넘긴다** |

**둘 다 결론은 그럴듯했고 근거가 틀렸다.**

## ★ [2026-09-09] 여러 세션이 git 인덱스 하나를 공유한다

`[실측]` 이 워크스페이스에서 세션 셋 이상이 같은 저장소·같은 브랜치에서 동시에 일한다. **스테이징 영역(git index)은 저장소당 하나다.** 그래서 이런 일이 난다.

```
내 세션:    git add <내 파일들>
남의 세션:  git add <남의 파일들>      ← 같은 인덱스에 얹힌다
내 세션:    git commit -m "..."        ← 인덱스 **전체**를 커밋한다
```

`git commit` 은 내가 `add` 한 것이 아니라 **그 순간 인덱스에 있는 전부**를 커밋한다. 남의 작업이 내 커밋 메시지 아래로 들어간다.

★**실제로 났다.** 2026-09-09, 문서 세션이 wiki 두 파일을 커밋했는데 도장 세션이 그 사이 스테이징한 `acop_dojo/acop_dojo/cli.py`·`refs.py` 둘이 같은 커밋(`a5ee023`)에 실려 푸시됐다. 내용은 안 깨졌지만(문법·import 확인) 커밋 메시지가 그 변경을 설명하지 않는다.

### 막는 방법 — 경로를 커밋에 직접 준다

```bash
git commit -F msg.txt -- <내 파일들>        # ★인덱스가 아니라 이 경로만 커밋한다
```

| 하지 말 것 | 대신 |
|---|---|
| `git add <paths>` 뒤에 `git commit` | `git commit -- <paths>` — `add` 없이도 된다 |
| `git add -A` · `git add .` | 경로를 always 명시한다 |
| `git commit -a` | 남의 수정 파일까지 담는다 |

**커밋 직전에 `git diff --cached --name-only` 로 확인하는 것으로는 부족하다** — 확인한 뒤 커밋하기 전 사이에 남이 `add` 할 수 있다. 경로를 커밋 명령에 주는 것만이 확실하다.

### 이미 섞여서 푸시됐으면

**되돌리지 않는다.** 그 파일을 커밋에서 빼려면 디스크 내용을 옛 상태로 돌려야 하고, 그 세션이 아직 편집 중이면 작업이 사라진다 → [git checkout 금지](../../wiki/governance/work-loop.md).

대신 이렇게 한다.

1. 섞여 들어간 파일이 **깨진 상태가 아닌지** 확인한다(문법·import·테스트)
2. 사용자와 그 세션에 **무슨 커밋에 무엇이 들어갔는지** 알린다
3. 커밋 메시지는 고치지 않는다 — 공유 브랜치의 푸시된 이력을 다시 쓰면 다른 세션의 pull 이 깨진다

## ★ [2026-09-10] 디렉터리 경로도 안 된다 — 두 번째 오염

`[실측]` 커밋 `ec57360` 이 **다른 세션이 막 만든 `wiki/business/pricing-travel.md`(여행 가격 결정)** 를 쓸어 담았다. 그 커밋은 `git add -A -- wiki` 로 **디렉터리를 통째로** 줬다.

★**「경로를 직접 준다」를 디렉터리 단위로 지키면 막지 못한다.** 디렉터리 안에 다른 세션의 **미추적 새 파일**이 있으면 `-A` 가 같이 올린다. 첫 오염(`a5ee023`)은 스테이징된 파일이었고 이번은 미추적 파일이다 — **길이 둘이다.**

| 규칙 | |
|---|---|
| **파일 단위로 준다** | `git add -- a.md b.md` 처럼 **내가 고친 파일만** 적는다. 디렉터리를 주지 않는다 |
| 커밋 전에 목록을 본다 | `git diff --cached --name-only` 로 **내가 안 쓴 파일이 섞였는지** 확인한다 |

`[실측]` **되돌리지 않았다.** 되돌리면 그 세션의 파일이 이력에서 사라진다. 파일 내용은 온전하고 `pricing.md` 가 이미 그것을 가리킨다 — **작성자 표시만 틀렸다.**
