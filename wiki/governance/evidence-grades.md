# 근거 등급

문서에 적힌 숫자가 **잰 값인지 짐작인지** 구분한다. 이 프로젝트가 이미 쓰던 관행이고, 여기서 규칙으로 굳힌다.

## 네 등급

| 등급 | 뜻 | source 필요 |
|---|---|---|
| `[실측]` | 이 저장소에서 직접 측정·계산했다 | **필수** |
| `[외부]` | 외부 자료를 인용했다 | **필수** |
| `[추정]` | 근거 있는 가정이다 | 계산 근거가 있으면 |
| `[미확보]` | 아직 모른다 | 불필요. 대신 무엇이 필요한지 적는다 |

## 왜 필요한가

사업성 문서를 예로 든다.

```markdown
A-COP 건당 LLM 비용은 3.03원이다.
사람이 문의 1건 처리하는 비용은 4,100원이다.
검토·승인에 건당 2.36분이 든다.
```

셋 다 숫자고 셋 다 그럴듯하다. 하지만 성격이 완전히 다르다.

```markdown
[실측] A-COP 건당 LLM 비용은 3.03원이다.[^S1]
[외부] 사람이 문의 1건 처리하는 비용은 4,100원이다.[^S2]
[추정] 검토·승인에 건당 2.36분이 든다. 검토 2분·승인 3분 가정.

[^S1]: eval/reports/2026-08-28_reeval_Proposed_v3.jsonl 216건 평균
[^S2]: 콜센터 평균 연봉 2,876만원 + 4대보험 10.67% + 퇴직금 8.33%
```

**세 번째가 흔들리면 결론이 통째로 흔들린다.** 등급이 없으면 그걸 아무도 모른다.

## 쓰는 법

### 문장 단위

주장 앞에 붙인다.

```markdown
[실측] 저장소 전체 md 문서는 1,285개다.
[미확보] gPUteer 문서별 최근 열람 빈도는 확보하지 못했다. 접근 로그가 필요하다.
```

### source 연결

`[실측]`과 `[외부]`는 근거를 연결한다. 짧으면 각주, 여러 곳에서 재사용하면 front matter의 `sources`에 등록하고 ID로 참조한다.

```markdown
---
sources:
  - id: S1
    title: 2026-08-28 평가 실행 로그 (새 도메인)
    resource: ../../program/final_project_cs/eval/reports/2026-08-28_reeval_Proposed_v3.jsonl
---

[실측:S1] 건당 입력 8,968 토큰, 출력 1,366 토큰이다.
[실측:S1] p95 지연은 32.2초다.
```

### 표

표도 주장이다. 셀마다 붙이면 지저분하니 두 방법 중 고른다.

**열 전체가 같은 등급이면 머리글에 쓴다.**

```markdown
| 구성 | 건당 원가 `[실측]` | 손익분기 `[추정]` |
|---|---|---|
| API | 3.03원 | — |
| 온프레미스 | 10.9원 | 월 37,600건 |
```

**섞여 있으면 셀에 붙인다.**

```markdown
| 항목 | 값 |
|---|---|
| 급여 | 28,760,000원 `[외부]` |
| 좌석 | 3,560,000원 `[추정]` |
```

## 등급별 규칙

### `[실측]`
- 무엇을 어떻게 쟀는지 재현 가능해야 한다
- 가능하면 실행 명령을 적는다

```markdown
[실측] 건당 평균 비용 $0.002165.

​```bash
python -c "import json,statistics as st; rows=[json.loads(l) for l in open('eval/reports/2026-08-28_reeval_Proposed_v3.jsonl',encoding='utf-8') if l.strip()]; print(st.mean(r['cost_usd'] for r in rows))"
​```
```

### `[외부]`
- 링크와 확인 날짜를 함께 적는다
- **1차 출처를 확인 못 했으면 그렇게 적는다**

```markdown
[외부] 한국 컨택센터 산업 9조 8,811억원, 종사자 19만 4,203명.
언론 보도 인용이며 1차 출처 미확인. 협회 원자료로 교차 확인 필요.
```

### `[추정]`
- **가정을 바로 옆에 적는다.** 숫자만 적지 않는다
- 민감도를 아는 경우 함께 적으면 좋다

```markdown
[추정] 연 처리 건수 10,500건. CPH 7 × 실가동 6시간 × 250일.

| CPH | 건당 비용 |
|---|---|
| 5 | 6,784원 |
| 7 | 4,846원 |
| 10 | 3,392원 |
```

### `[미확보]`
- **빈칸으로 두지 않는다**
- 무엇이 있어야 채워지는지, 얼마나 걸리는지 적는다

```markdown
[미확보] Qwen2.5-3B의 실제 추론 처리량. eval/finetune/serve.py 부하 측정 필요. 반나절.
```

## 등급이 바뀌면

`[추정]`이 `[실측]`이 되면 **문서의 결론이 바뀔 수 있다.** 그때는 `log.md`에 적는다.

```markdown
## 2026-09-10
### 변경 — business/unit-economics.md
검토·승인 소요시간을 실측으로 교체(2.36분 → 3.1분).
절감률 72% → 64%로 하향.
```

## 어디에 붙이고 어디에 안 붙이나

**붙인다** — 숫자, 외부 사실, 성능·비용 주장, 시장 규모, 일정 산정

**안 붙인다** — 설계 의도, 규칙 서술, 코드 위치, 정의

```markdown
⭕ Team은 side effect를 실행하지 않는다.        ← 규칙. 등급 불필요
⭕ [실측] 골든셋 72건 중 39%가 승인·입력 대기다.  ← 측정값. 등급 필요
```

모든 문장에 붙이려 하면 지친다. **사실 주장에만 붙인다.**

## ★ [2026-09-04] 표집 방법을 안 보고 "실제 분포"라 단정한 사례

`[실측]` **하루 만에 내 손으로 쓰고 내 손으로 뒤집었다.**

### 무슨 일이 있었나

`aihub_30716_callcenter_qa` 의 `mapped_intent` 를 세었더니 `order 600 · shipping 300 · return 300 · exchange 300` 이 나왔다.

**이걸 "실제 문의는 order 가 40% 다"로 [golden-set.md](../evaluation/golden-set.md) 에 적었다.**

**틀렸다.** `source_category` 를 보니 **다섯 카테고리가 각 300건씩 층화표집**된 것이었다. `주문`과 `결제` 두 카테고리가 **둘 다 `order` 로 매핑**돼서 600이 됐을 뿐, **`order` 문의가 실제로 2배 많은 게 아니었다.**

### 왜 못 잡았나

**집계 결과(`mapped_intent` 합)만 보고 판단했다.** 표집 방법(`source_category` 별 건수, `REPORT.md` 의 "300건씩 무작위 샘플링")을 안 봤다.

> **집계된 숫자는 표집 설계를 감춘다.** 층화표집이면 그룹 크기가 자연 빈도가 아니라 **표집자가 정한 값**이다.

### 규칙

> **"실제 데이터의 분포"라고 쓰기 전에 그 데이터가 어떻게 뽑혔는지 확인한다.**

**확인할 것 하나.**

```
REPORT.md 의 "추출 방법" 절을 먼저 읽는다.
"N건씩", "sample_per_group", "seed=" 가 보이면 → 층화·정량 표집이다.
→ 그룹 간 비율을 자연 빈도로 쓰면 안 된다.
```

`[실측]` **`stats.json` 에 `sample_per_group` 필드가 있으면 그게 신호다.** `aihub_102` 도 같은 필드로 같은 함정이 확인됐다.

### 이게 [drift-case-voc](drift-case-voc.md)·[known-weaknesses](known-weaknesses.md) 와 같은 자리에 있다

**"세어 보면 맞다"는 이 wiki 전체의 방법론이었다.** 그런데 **무엇을 세는지가 틀리면 셈 자체가 틀린다.** 세는 행위가 정확성을 보장하지 않는다 — **무엇을 세는지 먼저 확인해야 한다.**
