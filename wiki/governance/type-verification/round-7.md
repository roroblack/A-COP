# 7차 — research 26건 전건 판정

`[실측]` 2026-09-01

## 왜 표본이 아니라 전건인가

[6차](round-6.md)에서 `research` 표본 **2건이 2건 다 틀렸다.**

**표본으로 더 볼 이유가 없다.** 0/2 는 "일괄 이관 불가"를 이미 말한다. 26건을 다 봤다.

전문은 `program/scripts/_verify_research.tsv`.

## 결과 — 휴리스틱이 사실상 작동하지 않았다

|---|---|---|

| **`유지` 판정 유효** | — | **50.0%** (13/26) |

**26건 중 24건에서 type 이 틀렸다.**

## ★ 실제 type 분포

| 추정 | 실제 |
|---|---|
| `research` 26 | `report` 12 · `reference` 5 · `decision` 2 · **`research` 2** · `policy` 2 · 기타 3 |

**`research` 는 2건뿐이었다.**

```
program/research/ 아래 = research   ← 24/26 에서 틀렸다
```

**이 폴더는 주제로 묶인 곳이 아니다.** "여기서 조사하며 쓴 문서를 둔다"는 **작성 경로**다. 그 안에는 점검 보고서·법령 원문·결정·작업 지시가 섞여 있다.

### 고친 것

```python
# ("program/research/", "research", "hub/research")   ← 삭제
  ("program/research/", "?",        "hub/research")   ← type 을 찍지 않는다
```

`research/_prompts/` 도 `SKIP_DIRS` 에 넣었다. **`final_project_cs/wiki/records/handoff/_prompts/` 114건과 같은 작업 지시 티켓이다.**

**6차 표본에서 나는 이 문서를 "이관 policy"로 판정했다. 그건 틀렸다.** 이관하면 루트 규칙 파일의 링크가 깨진다.

**이관 판정 전에 "누가 이 경로를 가리키는가"를 먼저 세야 한다.** 새 규칙이다.

### 6번은 우리 자신에 대한 판정이었다

`_문서관리_전략.md`(8-18)의 결론이 **지금 하는 일과 정면으로 모순됐다.**

> **전면적인 OpenWiki식 파일 분할보다** index 를 얇은 입구로 강화한다.

같은 문서의 **병합 규칙 4번**이 이 경우를 다룬다.

> **모순은 사람 확인 항목으로 남긴다.** 최신 파일이라는 이유만으로 덮어쓰지 않는다.

**그래서 지우지 않고 남겼다.** 그리고 **8-18 의 경고는 틀리지 않았다** — "파일을 늘리는 것만으로 정합성 비용이 사라지지 않는다"는 이 검증 7회와 누락 7건이 증명한다.

**차이는 세는 장치를 같이 만들었다는 것뿐이다.**
