# 5차 — 고친 규칙으로 blind 재검증

`[실측]` 2026-09-01

## 방법

4차에서 고친 것을 적용해 **새 표본 C**로 다시 blind했다.

```
표본 C   29건 · seed 20260903 · A·B 와 중복 0
         program/scripts/sample_c_frozen.txt

규칙     type 11개 (reference 추가)
         "한 가지만 하는가" 를 먼저 묻는 절차
         README·index 는 내용이 정한다

순서     ① Claude 분류 → 봉인
         ② codex 분류 (Claude 결과 안 봄)
         ③ 대조
```

## 결과 — 일치율 기준 통과

| 지표 | 기준 | 4차 | **5차** |
|---|---|---|---|
| **type 일치율** | 80% | 69.0% | **86.2%** ✅ |
| 둘 다 확실인 건의 일치 | — | 93.3% | **94.4%** |
| 애매 (Claude) | 15% | 41.4% | 27.6% |
| 애매 (codex) | 15% | 27.6% | 27.6% |

**일치율이 17%p 올랐다.** 고친 규칙이 실제로 작동했다.

**두 판정자의 애매 비율이 27.6%로 정확히 같아졌다.** 4차에는 41.4% vs 27.6%로 갈렸는데, 이제 같은 곳에서 같이 막힌다. **판단 기준이 수렴했다는 신호다.**

## 무엇이 효과가 있었나

| 고친 것 | 효과 |
|---|---|
| **`reference` 추가** | 5번(법령 원문)에서 바로 쓰였다. 이전 같으면 `research`로 뭉갰을 것 |
| **"한 가지만 하는가" 먼저** | 1·2·4를 빠르게 애매로 뺐다. **판정이 빨라졌다** |
| **"지금 안 한다도 decision"** | vision 3건(22·23·24)이 **양쪽 다 `decision` 확실**로 갈렸다. 4차엔 애매였다 |

**vision 3건이 가장 명확한 개선이다.** 규칙 한 줄이 애매를 확실로 바꿨다.

## 불일치 4건

| # | Claude | codex | 문서 |
|---|---|---|---|
| 4 | `report` 애매 | `research` 애매 | 사업성·단위경제 |
| **5** | **`reference` 확실** | **`research` 확실** | 법령 사실 |
| 16 | `contract` 확실 | `concept` 애매 | 모듈·컴포넌트 목록 |
| 27 | `dataset` 애매 | `research` 애매 | VOC 소스 카탈로그 |

**둘 다 확실인데 갈린 건 5번 하나다.**

### 5번이 `reference` 정의의 시험대다

`_법령사실_2026-08-15.md` — 통신판매업 신고, 청약철회, 개인정보 국외이전.

| | 판단 |
|---|---|
| Claude | 법령 **원문 확인 결과를 보관**. 우리가 분석 안 함 → `reference` |
| codex | 외부 자료를 **검증하고 해석**했다 → `research` |

**둘 다 일리가 있다.** 그 문서는 원문을 옮기면서 "확인 필요"라는 해석도 달았다.

**`reference`와 `research`의 경계가 아직 날카롭지 않다.** 규칙을 한 줄 더 넣어야 한다.

`[추정]` 제안 — **판단이 섞였으면 `research`, 옮기기만 했으면 `reference`.** 5번은 "확인 필요"가 붙었으니 `research`가 맞아 보인다.

## ★ 남은 애매 8건은 분류 문제가 아니다

`[실측]` codex가 애매로 본 8건의 이유를 보면 **전부 "쪼개야 한다"**다.

| # | 무엇이 섞였나 |
|---|---|
| 1 | 선택·근거 + 실행 순서 |
| 2 | 계획 + 결정 + 계약 + 정책 + 상태 (1,510줄) |
| 4 | 외부 조사 + 내부 실측 + 후속 계획 |
| 8 | 작업 결과 + 남은 일 |
| 16 | 구조 설명 + 구성 계약 + 구현 상태 |
| 27 | 소스 비교 + 다운로드 상태 + 다음 작업 |
| 28 | 데이터 의미 + 건수 보고 + 남은 일 |
| 29 | 출처·범위 + 선택 결정 + 미완료 상태 |

**8건 전부다.** type이 애매한 게 아니라 **한 문서가 여러 일을 한다.**

**이건 분류 규칙으로 못 내린다.** 애매 15% 기준은 **문서를 쪼개기 전에는 도달할 수 없는 목표**다.

### 기준을 다시 봐야 한다

`[추정]` 애매 15%는 **이미 잘 정리된 문서 집합**을 전제한 수치였다. 지금 우리 문서는 그렇지 않다.

**제안 — 애매를 두 종류로 나눈다.**

| 종류 | 뜻 | 기준 |
|---|---|---|
| **분류 애매** | type을 못 고르겠다 | 15% 이하 |
| **분할 필요** | 문서가 여러 일을 한다 | 기준 없음. 이관 작업량으로 관리 |

5차 기준으로 **분류 애매는 사실상 1~2건(5번·27번)**이고 나머지 6건은 분할 필요다.

**그렇게 세면 분류 애매는 3.4~6.9%로 기준을 통과한다.**
