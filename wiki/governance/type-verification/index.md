# type 분류 검증

## 결론

**이관을 시작해도 되는 상태에 가까워졌다.** 5차에서 일치율 86.2%로 기준을 넘겼다.

| 지표 | 기준 | 4차 | **5차** |
|---|---|---|---|
| 일치율 | 80% 이상 | 69.0% | **86.2%** ✅ |
| 애매 (현행 정의) | 15% 이하 | 27.6~41.4% | 27.6% |
| **애매 (분류만)** | 15% 이하 | — | **3.4~6.9%** ✅ |

**두 판정자가 둘 다 `확실`이라고 한 건은 94.4% 일치**한다. 분류 체계는 작동한다.

**남은 애매 27.6%는 분류 문제가 아니다.** 5차에서 애매 8건의 이유가 **전부 "쪼개야 한다"**였다. 한 문서가 여러 일을 한다.

**문서를 쪼개기 전에는 못 내리는 수치이고, 그건 이관 작업 자체다.**

## 6회에서 배운 것

| 회차 | 무엇을 알았나 |
|---|---|
| [1차](round-1.md) | 애매 25%. `evidence`·`runbook`이 빠져 있었다 |
| [2차](round-2.md) | 4.5%가 나왔지만 **혼자 판정이라 믿을 수 없었다** |
| [3차](round-3.md) | codex 28.9%. **2차의 4.5%가 확증 편향이었다.** 6배 차이 |

| [5차](round-5.md) | 고친 규칙으로 재검증. **86.2% 통과.** 남은 애매는 분류가 아니라 분할 문제 |
| [6차](round-6.md) | **휴리스틱 자동 판정**을 검증. type 일치 60%. 제외 대상 2건을 놓쳤다 |
| [7차](round-7.md) | `research` 26건 **전건**. type 일치 **7.7%**. 폴더는 type 을 정하지 않는다 |

| [9차](round-9.md) | `dataset` 28건 **전건**. 42.9%. **분할 10건.** report-split 을 기계 신호로 |

## 네 가지 교훈

### 하나 — 혼자 검증하면 안 된다

2차에서 스스로 경고를 적었고 **그게 맞았다.**

> 규칙을 만든 사람이 적용하면 맞을 수밖에 없다.

독립 판정자를 안 붙였으면 4.5%를 믿고 이관을 시작했을 것이다.

### 둘 — 표본은 얼려야 한다

`[실측]` seed 고정만으로 부족했다. 수집 함수에 정렬을 넣자 **같은 seed인데 다른 표본**이 나왔다.

**뽑은 목록 자체를 파일로 얼린다.** `program/scripts/sample_frozen.txt`

### 셋 — 애매를 두 종류로 나눠야 한다

`[실측]` 5차에서 애매 8건이 전부 "쪼개야 한다"였다.

| 종류 | 기준 | 5차 |
|---|---|---|
| **분류 애매** — type을 못 고르겠다 | 15% 이하 | **3.4~6.9%** ✅ |
| **분할 필요** — 문서가 여러 일을 한다 | 기준 없음 | 20.7% |

**둘을 섞어 세면 규칙이 나쁜 건지 문서가 나쁜 건지 모른다.**

### 넷 — 분류로 안 풀리는 게 있다

`decision` + `plan` 혼재가 **세 번 다 나왔다.** "답하는 질문으로 가른다"는 규칙을 두 번 썼는데 두 번 다 안 먹혔다.

**순서를 바꿨다.** type을 고르기 전에 **"이 문서가 한 가지만 하는가"를 먼저 묻는다.** → [../front-matter.md](../front-matter.md)

## type이 3개 늘었다

전부 **두 판정자가 같은 자리에서 막혀** 드러난 빈 자리다.

| type | 어디서 | 왜 |
|---|---|---|
| `evidence` | 1차 | 재현 명령이 있는 완료 증명은 `report`와 다르다 |
| `runbook` | 1차 | 사고 때 읽는 절차는 `guide`와 다르다 |
| `reference` | 4차 | 외부 원문·기준값을 그대로 보관할 자리가 없었다 |
