## 옮길 것의 기준

다음 중 하나 이상을 만족하고 지금 유효한 문서만 옮긴다.

- 현재 제품·아키텍처·계약·평가·일정 결정의 **이유**를 보존한다
- 코드만 읽어서는 알 수 없는 **책임·경계·불변식·관계**를 설명한다
- 최종발표(2026-10-26) 또는 이후 운영에 필요하다
- 다른 저장소가 의존하는 계약이나 증거다

**제외는 삭제가 아니다.** 이관 집합에 넣지 않는다는 뜻이고 원본은 그대로 둔다.

## 옮기지 말아야 할 것

| 대상 | 처리 |
|---|---|
| `python dojo.py report` 생성물, 데이터셋 REPORT | 생성 명령과 입력만 이관하고 재생성 |
| 코드를 문장으로 다시 쓴 문서 | 책임·경계·불변식·이유가 없으면 제외 |
| 완료된 개인 TODO·임시 메모 | 제외 |
| 구버전 계획과 중복 브리핑 | 최신 정본의 `sources`로 필요할 때만 |
| 대형 로그·바이너리 | wiki에는 설명과 원본 위치만 |

## ★ 확정 전에 할 것 — 표본 검증

**구조를 실물에 대보지 않고 확정하면 안 된다.** type 목록과 영역 구분이 실제 문서를 만나면 안 맞는 게 반드시 나온다. 그때 고치면 이미 옮긴 것을 다시 건드려야 한다.

절차는 이렇다.

1. 여섯 저장소에서 크기·최근성·파일명·폴더를 층화해 **36~48개**를 뽑는다
2. README·REPORT·CLAUDE·index·티켓형 핸드오프를 각각 최소 3개 포함한다
3. **두 사람이 독립적으로** `type`·영역·유지여부를 판정한다
4. 판정 일치율과 애매 비율을 기록한다
5. **일치율 80% 미만이거나 애매 비율 15% 초과면 정의를 수정한다**
6. 1,466줄 계획서를 실제로 매핑해 누락과 중복을 확인한다

두 사람이 독립 판정한 뒤 일치율을 재는 이유는, 분류 체계가 **실제로 판별 가능한지** 보기 위해서다. 혼자 훑으면 자기가 만든 기준에 맞춰 읽게 된다.

## 지금 확정 가능한 것과 아닌 것

**확정 가능**

- 중앙과 로컬의 배치 원칙
- 저장소별 wiki 시작점
- `type` 단독 필수, `index.md`/`log.md` 예약
- 정본 우선순위
- 생성물 소유 규칙
- 불변식 ID와 테스트 연결 방식
- 상대경로 링크 (gPUteer만 절대 URL)

**써 보면서 정할 것**

- `type` 8개의 최종 경계
- 폴더 세분화 기준
- 문서 만료(`stale_after`) 도입 여부
- 실제 이관량과 문서당 처리시간

## 일괄 이관의 위험

| 위험 | 먼저 확인할 것 |
|---|---|
| 잘못된 type·영역을 수백 번 반복 | 표본 36~48개 시험 분류 |
| 중복 정본 생성 | 사실·계약별 소유 저장소 |
| 생성물을 손으로 옮겨 다음 생성 때 소실 | 생성 명령·입력·소유 프로세스 |
| 낡은 문서가 stable처럼 보임 | 이관 문서는 기본 `draft` |
| 6명 동시 작업 충돌 | 원본별 단일 판정 담당자 |
| 예상보다 큰 작업량 | 고가치 20개의 실제 처리시간 |

일괄 작업 전에 이런 표가 필요하다.

```text
원본 경로 | 추정 type | 목표 영역 | 정본 여부 | 자동생성 | 최신성 | 담당자 | 판정
                                                                    (유지/추출/재생성/제외)
```

### 표본 검증 결과 반영

[type-verification/index.md](type-verification/index.md) 참조.

| 무엇 | 결과 |
|---|---|
| `type` | 8개 → **10개** (`evidence`·`runbook` 추가) |
| 판정 규칙 | **4개 추가** (`dataset`/`report` 포함) |
| 애매 비율 (나, 2차) | 4.5% |
| **애매 비율 (codex, 독립)** | **28.9%** |
| 일치율 | **측정 못 함** |

### ★ 혼자 검증하면 안 된다는 증거

2차에서 스스로 경고를 적었고 **그게 맞았다.**

> 혼자 했다. 그리고 규칙을 내가 방금 썼다. 규칙을 만든 사람이 적용하면 맞을 수밖에 없다.

**독립 판정자를 안 붙였으면 4.5%를 믿고 이관을 시작했을 것이다.** 6배 차이였다.

**이관처럼 되돌리기 비싼 작업 앞에서는 반드시 독립 판정자를 붙인다.**

### 표본은 얼려야 한다

`[실측]` seed 고정만으로는 부족했다.

수집 함수에 정렬을 넣자 **같은 seed인데 다른 표본**이 나왔다. 모집단 순서가 바뀌면 `random.sample` 결과도 바뀐다.

**뽑은 목록 자체를 파일로 얼린다.**

```
program/scripts/sample_frozen.txt
```

### 이관 시 쪼갤 문서 — 추정 상향

`[실측]` codex가 잡은 애매 13건 중 **10건이 "결정 + 계획 혼재"**다.

| 패턴 | 표본 13건 중 |
|---|---|
| decision + plan 혼재 | 10 |
| dataset + report 혼재 | 3 |

`[추정]` 표본 비율(13/45 = 29%)로 보면 이관 대상 250~380건 중 **72~110건이 분할 대상**이다.

**2차의 "10~17건" 추정은 크게 과소평가였다.** 분할이 이관 작업량의 상당 부분을 차지한다.

### 데이터셋 REPORT는 둘로 쪼갠다

`[실측]` codex가 새로 잡은 패턴.

```
데이터가 무엇인가·출처·범위·제약   → dataset   안 변한다
지금 전처리가 어디까지인가        → report    계속 변한다
```

`datasets/README.md`의 "VOC 전처리 현황" 절도 같다.
