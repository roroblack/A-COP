# 형태 C — 배송중 (실측 추가)

배송 전(A)과 배송 완료(B) 사이에 **배송중** 상태가 있다. 세 형태로 확정.

## 세 형태 비교

| | A 상품준비중 | C 배송중 | B 배송완료 |
|---|---|---|---|
| 송장번호 | 빈칸 | **있음** | 있음 |
| 이력 표 | 없음 | **있음(2행)** | 있음(3행) |
| 도착 안내 | 내일(토) 새벽 7시 전 도착 보장 | 오늘 도착 보장 | 어제(목) 도착 완료 |
| 설명문 | 준비시작되었습니다 | 배송중입니다 | 배송완료 되었습니다 |
| 마지막 이벤트 | — | 배송출발 | 배송완료 |
| 상품수령방법 행 | 없음 | 없음 | **있음**(문앞 전달) |

## 판정 기준 정정

**"송장번호 유무"로 발송 여부를 가르는 것은 맞다.** A만 빈칸이고 C·B는 있다.

다만 **완료 여부는 별개 축**이다. C는 발송됐지만 완료가 아니다.
- `ShipmentStarted`: 송장번호가 있으면 true (C, B)
- `DeliveryCompleted`: 이력에 `배송완료` 이벤트가 있으면 true (B만)

C 상태의 주문은 나중에 다시 수집하면 이력이 늘어난다. 재수집 시 **같은 송장번호의
이력을 갱신**할 수 있어야 한다.

## 상대 시각 주의

C에서 `오늘 09:11`, B에서 `어제 23:07`이 나온다. 두 표기 모두 처리해야 하며,
**수집 시점 기준**으로 절대 시각을 계산한다. 원문은 반드시 함께 보존한다.
같은 주문을 다른 날 재수집하면 `오늘`이 `어제`로 바뀌므로, 원문만 믿으면 안 되고
절대 시각으로 변환해 저장해야 중복·갱신 판정이 가능하다.

## 배송요청사항 값이 다르다

A/B는 `새벽: 문 앞 (자유 출입가능)`, C는 `문 앞`이다. 주문마다 다르므로 고정값으로
가정하지 마라. 개인 식별성은 없으니 수집해도 된다.
