# 번역 모델 비교

`[실측:S1]` 2026-08-20 실행.

## 무엇을 했나

다국어 응대를 검토하려고 번역 모델들을 비교했다. x600 (RTX 4070 SUPER 12GB)에서 Ollama + GGUF Q4_K_M 양자화로 실행.

## 결과 — 장비 제약이 결론을 바꿨다

`[실측:S1]` **x600에서 "포기"로 결론 낸 모델들이 다른 환경에서는 돌았다.**

| 환경 | 사양 | 결과 |
|---|---|---|
| x600 | Windows, RTX 4070 SUPER **12GB** | 큰 모델 OOM |
| RunPod | Linux, RTX A4500 **20GB**, RAM 251GB | **통과** |

원문 결론이 이렇다.

> x600에서 "포기"로 결론 냈던 원인은 x600이라는 특정 환경(Windows·좁은 VRAM·비공식 경로) 때문이었다.

## 이 조사가 남긴 것

**번역 성능보다 장비 제약이 더 중요한 발견이었다.**

| 발견 | 어디로 이어졌나 |
|---|---|
| 12GB에서 큰 모델이 안 돈다 | [../business/infrastructure-cost.md](../business/infrastructure-cost.md) §3 |
| Windows가 문제를 악화시킨다 | 자체호스팅은 Linux 전제 |
| 임대 GPU로 우회 가능 | [D-004](../decisions/D-004-self-hosting-rationale.md) |

**MADLAD-400-10B**의 경우 FP16 가중치만 20~21GB라 12GB에 애초에 안 들어간다. 8-bit + CPU 오프로드로 겨우 돌렸고, 그것도 **다른 GPU 작업을 전부 멈춘 상태**에서만 가능했다.

## ★ 외부 비교표 하나가 조작이었다

`[실측]` `_번역모델_조사.md`. **이 조사의 가장 중요한 결과다.**

> **조건이 다른 비교표는 순위화할 수 없고, 외부 TOP 15 표 하나가 조작됐다.**

### 어떻게 확인했나

```

② 두 독립 추출자로 수치를 뽑는다

```

**"두 독립 추출자"가 이 프로젝트의 반복되는 방법이다.** [type 분류 검증](../governance/type-verification/index.md)에서 codex 를 붙인 것과 같다.

### 비교가 성립하는 조건

**아무 표나 나란히 놓으면 안 된다.**

| 확인할 것 |
|---|
| 동일 **언어 부분집합** |
| 동일 **지표** (XCOMET-XXL / COMETKiwi 등) |
| 동일 **셀 의미** |
| 동일 **평가 방향** |
| **미공개 값을 추정하지 않는다** |

`[실측]` FLORES·Hy-MT2·Tower+·Rosetta 결과는 **조건이 달라 직접 비교하면 안 된다.**

### 자기 보고와 공식 평가가 다르다

`[실측]` **Tencent 자기 보고와 WMT25 공식 ESA 사람 평가 결과가 달랐다.**

**모델 제작자의 자기 보고를 근거로 쓰지 않는다.**

## 번역 성능 결론

### ★ [2026-09-10] 다국어는 우리 일이 아니게 됐다 — `[미확보]` 가 닫혔다

`[결정 2026-09-10 — 두 번 바뀌었다]` v11 §0-4 결정 2 는 "한국어 하나, 번역은 에이전트"였고 **결정 11 이 직접 경로(링크·알림)를 우리가 옮기는 것으로 바꿨다 — 기본 한국어·영어.** ★**그래서 이 조사가 제품 경로로 돌아왔다.** 번역 모델을 고를 때 **한→영 품질이 첫 대상**이다.

★**그래서 이 조사는 제품 경로에서 빠진다.** 우리 층에서 번역이 일어나지 않으므로 **번역 모델 비교는 우리 지표가 아니다.**

★**다만 지우지 않는다.** 「다국어를 우리가 지지 않는다」는 판단의 근거로 남고, 접점 방식이 바뀌면 다시 쓴다. 그리고 **12GB VRAM 천장**이라는 측정 사실은 자체호스팅 논거에 그대로 쓰인다.

`[미확보]` **에이전트 경로는 여전히 우리가 보증하지 못한다** — 그 문장은 상대 에이전트가 옮긴다. **직접 경로는 우리가 보증해야 한다** — 한→영 번역 품질을 무엇으로 재는지 아직 안 정했다. ★시각·날짜·금액·고유명사·예약번호는 **번역하지 않고 원값을 싣는다**(v11 §10).

성능 비교 결과는 [원본 REPORT](../../datasets/mt/olist_reviews_mt_bench/REPORT.md)에 있다.

### ★ 어느 숫자를 인용하나 — 08-24 GPU 서버 값만

`[실측]` `program/산출물양식/README.md`(2026-08-28)가 제출 문서용 규칙으로 못 박았다.

> 번역 성능은 GPU 서버 재검증(2026-08-24) 이후 값이 정본이고, **그 이전 GGUF 결과는 양자화 문제로 신뢰할 수 없다.**

위 "x600 = Ollama + GGUF Q4_K_M"으로 나온 수치가 그 "이전 결과"다. **OOM으로 포기한 것만 문제가 아니라, 돌아간 모델의 수치도 양자화 때문에 못 쓴다.** 제출 문서에 번역 성능을 적을 땐 RunPod(A4500 20GB) 재검증 값에 파일명과 날짜를 붙인다.

`[실측:S1]` 원본 REPORT가 "신뢰할 수 없던 결과 3건"을 08-24에 **같은 모델의 비양자화 HuggingFace 체크포인트**로 돌려 원인을 확정했다 — 프롬프트는 같았고 **문제는 100% GGUF 변환 쪽**이었다.

| 모델 | GGUF Q4_K_M | 공식 체크포인트 |
|---|---:|---:|
| Seed-X-Instruct-7B | 1.29 | **57.51** — 원 리더보드 1~2위권이 맞았다 |
| Seed-X-PPO-7B | 2.37 | 47.03 |
| HY-MT1.5-1.8B | 0.00 | 22.30 (1.8B라 원래 약함, 정상 작동은 확인) |

**같은 모델이 40배 넘게 갈렸다.** 양자화된 결과로 "이 모델은 못 쓴다"고 판정하면 안 된다는 뜻이다.

**범위에 들어오면 그때 다시 본다.**
