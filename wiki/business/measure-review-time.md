# 검토·승인 시간을 재는 법

`[실측]` 2026-09-03 도구 설치 완료. **아직 안 쟀다.**

## 왜 재나

**사업 논거 전체가 이 숫자에 달려 있다.**

```
A-COP 병행: 0.56×2분 + 0.21×3분 + 0.18×1분 + 0.05×8.57분 = 2.36분/건
사람만:     8.57분/건
            → 72% 절감 · 연 3억 7,384만원
```

**비율 넷은 골든셋 실측이고 시간 넷이 추정이다.** 아무도 안 쟀다.

`[실측]` **검토가 2분이 아니라 4분이면 절감이 72% → 50% 로 떨어진다.**

**그리고 가장 흔한 게 가장 안 쟀다** — 56% 짜리 "초안 검토"가 전체의 절반이 넘는다.

## 어떻게 재나

```bash
cd final_project_cs
python -m eval.timing.measure_review_time --n 20 --action respond
python -m eval.timing.measure_review_time --n 20 --action wait_for_approval
```

**한 건씩 뜨고, 판단을 고르면 그 사이 시간을 잰다.**

```
[고객 문의]      실제 골든셋 원문
[모델이 만든 답변 초안]   실제 Proposed 실행 결과
[근거 8건]       doc_15#c5, doc_07#c3, …

  1) 그대로 보낸다   2) 고쳐서 보낸다
  3) 못 쓴다        s) 판단 보류
```

`[실측]` **지어낸 초안이 아니다.** `eval/reports/2026-08-28_reeval_Proposed_v3.jsonl` 의 실제 모델 출력이다.

| 구간 | 확보한 건수 |
|---|---|
| `respond` | **38** |
| `wait_for_approval` | **20** |

## 재는 규칙 넷

| # | |
|---|---|
| 1 | **읽고 판단하는 시간만 잰다.** 고칠 문장을 실제로 쓰지 않는다 |
| 2 | **모르겠으면 `s`(보류).** 억지로 고르면 숫자가 망가진다 |
| 3 | **`--who` 를 남긴다.** 사람마다 다르므로 누가 쟀는지가 데이터다 |
| 4 | 중간에 끊어도 된다 (`Ctrl+C`). 거기까지 기록된다 |

`[실측]` **1번이 중요하다.** 타이핑 시간은 사람마다·건마다 편차가 커서 **다른 실험이 필요하다.** 섞으면 둘 다 못 쓴다.

**순서는 고정돼 있다** (`SEED = 20260903`). **누가 재도 같은 건을 같은 순서로 본다.**
