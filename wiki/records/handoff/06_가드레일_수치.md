## 4. VOC 급증 정의 (v5 §14-3) — 문구 그대로

```
급증 =  오늘_count >= max(5, 1.5 * 최근7일_평균)
   AND  오늘_count - 최근7일_평균 >= 3
```

배치 시각: **매일 00:10 UTC**. 집계 대상: 전일 + 직전 7일의 intent·issue count, negative ratio, unresolved ratio.

❌ **금지**: z-score, embedding clustering, topic modeling (v5 §3 Out)

## 5. Scope (v5 §12)

```
case:read  case:write  subscription:read  technical:read  action:approve  mcp:read
```

| 경로 | 요구 scope |
|---|---|
| `POST /v1/cases` | `case:write` |
| `GET /v1/cases`, `GET /v1/cases/{id}` | `case:read` |
| `POST /v1/cases/{id}/messages` | `case:write` |
| `POST /v1/cases/{id}/actions/{aid}/approve` | `action:approve` |
| MCP 3 tool 전부 | `mcp:read` |

★**MCP 에는 `mcp:read` 외 어떤 scope 도 부여하지 않는다.** 쓰기는 REST + Human Approval 경로만.

## 7. Optimistic concurrency (v5 §6-1)

- 충돌 시 최신 Case 를 읽어 **최대 2회 재계산**
- 같은 Case 에 active run **1개만**
- `UPDATE ... WHERE tenant_id AND case_id AND version = :expected_version` → affected 0 이면 `StateConflict`
