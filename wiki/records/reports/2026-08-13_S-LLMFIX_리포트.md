# S-LLM 어댑터 수정 리포트

## 원인

`app/infrastructure/llm`에는 Team이 사용할 실제 OpenAI 어댑터가 없었습니다. `BillingSubscriptionTeam`과 `TechnicalEntitlementTeam`은 생성자에서 받은 `llm`을 보관만 하고 호출하지 않았고, 실호출 경로를 fake 주입 테스트로만 검증할 수 있는 상태였습니다.

이번 코드 경로에서는 `os.getenv`로 키를 읽는 구현은 확인되지 않았습니다. 대신 `.env`를 해석하는 `app.core.settings.get_settings()`를 새 어댑터의 호출 시점에 사용하도록 명시했습니다.

## 변경 파일

- `app/infrastructure/llm/openai.py`
  - `OpenAITeamLLM` 추가
  - `get_settings()`로 API 키·모델·temperature·seed를 읽음
  - `OpenAI` 클라이언트를 import 시점이 아닌 `complete()` 호출 안에서 생성
  - sync OpenAI 호출은 `asyncio.to_thread()`로 실행
  - 예외를 잡아 성공으로 바꾸지 않음
- `app/infrastructure/llm/__init__.py`
  - 어댑터 export 추가
- `app/modules/customer_ops/billing.py`
- `app/modules/customer_ops/technical.py`
  - 기존 `llm=None` 경로를 유지
  - LLM이 주입된 경우에만 Team 실행 중 `complete()` 호출
  - 주입된 fake와 기존 무주입 규칙 테스트를 제거하지 않음
- `pytest.ini`
  - `live` 마커 등록
  - 기본 실행에서 `-m "not live"` 적용
- `tests/live/test_llm_live.py`
  - 실제 LLM을 한 번 호출하는 수동 smoke test 추가

## baseline과의 정합성

baseline의 `_call_openai()`와 같이 API 키는 설정 객체에서 읽고, 클라이언트 생성 시 `api_key`와 timeout을 전달합니다. Team 어댑터도 기본 OpenAI base URL/proxy 동작을 그대로 사용하며 별도 URL을 하드코딩하지 않았습니다. 가장 중요한 차이는 기존 Team 경로에 호출 가능한 애플리케이션 어댑터 자체가 없었다는 점입니다.

## 실행 방법

기본 테스트:

```powershell
python -m pytest tests -q
```

실제 호출 smoke test(수동):

```powershell
python -m pytest tests/live -m live -q
```

요청대로 live 테스트는 실행하지 않았습니다.
