# S-WIRE 분류기 연결 리포트

## 1. 변경 목적

`create_app()`의 기본 API 분류기를 S-VOC의 `feedback.classify()`에 연결했다. 외부 주입(`create_app(classifier=fake)`)은 유지했고, 기본 경로는 `get_settings()`로 설정을 검증하며 API 키가 비어 있으면 `RuntimeError`를 발생시킨다. S-VOC의 `Classification` 객체는 API 라우터가 기대하는 `intent`, `issue_code`, `sentiment` dict로 composition root에서 변환한다.

## 2. 변경 파일

- `app/presentation/api/app.py`: 기본 분류기 연결, 설정/API 키 검증, 결과 변환
- `app/presentation/api/cases.py`: `build_router()` 호출마다 독립 라우터 생성
- `tests/integration/api/test_api_runtime.py`: 성공/실패 fake 기반 API 통합 테스트 추가 및 정상 상태 단언 갱신

## 3. 실제 출력 원문

Smoke 실행 결과:

```text
status= 201
case_id= b4db911c-c668-43f8-bcef-b9710b9af2cf
customer_cases= ('routing', 'billing', 'payment_failed', 'negative')
events= ['created', 'classified']
tenants= 1
```

DB 검증 명령 출력:

```text
tenants=1
```

API 통합 테스트:

```text
20 passed, 1 warning
```

전체 테스트:

```text
106 passed, 3 failed, 2 warnings
```

실패한 3건은 기존 RAG 통합 테스트이며, `search_policy()`가 실제 OpenAI embeddings endpoint를 호출하다가 실행 환경의 네트워크 권한 오류(`[WinError 10013]`)로 실패했다. 이번 S-WIRE 변경 파일/테스트와 무관하며, 테스트에서 실제 LLM 호출을 추가하지 않았다.

## 4. 추가 테스트 목록

- `test_create_classifies_case_and_records_classified_event`: 세 라벨 저장, `created → classified` 이벤트, 최종 `routing` 상태 확인
- `test_create_escalates_when_injected_classifier_fails`: 예외 fake 주입 시 세 라벨 미저장, `classification_failed`, `escalated` 확인
