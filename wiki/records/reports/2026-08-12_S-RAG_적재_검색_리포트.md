# 2026-08-12 S-RAG 적재·검색 리포트

## 1. 목표

`knowledge/manifest.json`의 25개 정책 문서를 `##` 단위 300청크로 pgvector에 적재하고, tenant/scope가 격리된 cosine top-k retriever를 제공한다.

## 2. 변경 파일

- `knowledge/ingest.py`: frontmatter 파싱, 300청크 검증, 설정 기반 embedding, 멱등 적재
- `app/infrastructure/rag/retriever.py`: `PolicyChunk` 반환 retriever
- `tests/integration/rag/test_rag_integration.py`: 건수·차원·적합성·격리 테스트

코퍼스 원문과 소유 범위 밖 파일은 수정하지 않았다.

## 3. 검증 결과

### 3.1 dry-run 실제 출력

```text
PS> python -m knowledge.ingest --dry-run
dry-run: documents=25 chunks=300
```

### 3.2 실제 적재 시도 실제 출력

```text
PS> python -m knowledge.ingest
ingest: documents=25 chunks=300
embedding: pending_chunks=300 model=text-embedding-3-small
...
openai.APIConnectionError: Connection error.
```

실패 원인은 실행 환경의 외부 네트워크 차단(`WinError 10013`)이다. API 키가 있어도 연결되지 않았으며, 랜덤/0 벡터 폴백은 사용하지 않았다. 트랜잭션은 커밋 전 실패했다.

### 3.3 §4 SQL 실제 출력

```text
PS> select 'documents='||count(*) from knowledge_documents
documents=0
PS> select 'chunks='||count(*) from knowledge_chunks
chunks=0
PS> select 'tenants='||count(*) from tenants
tenants=1
```

### 3.4 전체 테스트 실제 출력

```text
PS> python -m pytest tests -q
74 passed, 4 skipped, 1 warning in 6.50s
```

RAG 통합 테스트는 corpus 미적재 상태에서 자동 skip하도록 했으므로, 네트워크가 허용된 환경에서 적재 후 재실행해야 검색 적합성 결과가 생성된다.

## 4. 검색 적합성

이번 실행에서는 임베딩 API 연결이 차단되어 top-8 문서 ID/점수를 생성하지 못했다. 따라서 다음 두 시나리오의 성공 여부를 추정해 기록하지 않는다.

- `해지했는데 결제가 됐어요` → 기대 `doc_06`
- `Pro로 바꿨는데 기능이 안 보여요` → 기대 entitlement 문서

## 5. 임베딩 호출·비용

300개 청크를 64개씩 배치하도록 구현했다. 이번 실행은 첫 API 요청에서 연결 실패했으므로 성공 호출 0회, 청구 비용 0원이며, 실제 OpenAI 청구액은 확인할 수 없다. 재실행 시 이미 적재된 청크는 임베딩하지 않는다.

## 6. 후속 조치

외부 네트워크가 허용된 환경에서 아래 명령을 실행한다.

```powershell
python -m knowledge.ingest
python -m knowledge.ingest
python -m pytest tests -q
```

두 번째 ingest 후에도 `documents=25`, `chunks=300`이어야 한다.
