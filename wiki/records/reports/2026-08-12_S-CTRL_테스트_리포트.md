## 시나리오 1 상태 전이

REST approve까지 실제로 관측된 순서는 다음과 같다.

```python
[
    ("classifying", 1),
    ("routing", 2),
    ("running", 3),
    ("waiting_approval", 4),
    ("resuming", 5),
]
```

테스트는 이어서 요구된 `("running", 6), ("resolved", 7)`까지 단언하도록 작성했다. 현재 제품 코드는 `resuming` 상태에서 fake Team의 completed 결과를 곧바로 `completed` 이벤트로 적용해 `InvalidTransition`을 발생시킨다. `resuming`에서는 `resumed` 이벤트가 먼저 필요하다. 제품 코드 수정은 하지 않았다.

## 시나리오 2 상태 전이

```python
[("classifying", 1), ("routing", 2), ("running", 3), ("resolved", 4)]
```

`subscriptions.plan='Pro'`, `entitlements.plan='Free'` fixture에서 `entitlements(plan, source, updated_at)`가 실행 전후 동일했다. 테스트 통과.

## 실패 원인

1. 새 Controller 테스트 1건: `resuming --completed`가 허용되지 않는다. 승인 endpoint는 version 5의 `resuming`까지만 만들고, Controller는 `resumed`를 생성하지 않은 채 completed를 적용한다.
2. 기존 RAG 테스트 3건: `search_policy()`가 query embedding을 위해 `text-embedding-3-small` OpenAI endpoint를 호출한다. 네트워크 차단으로 `api.openai.com` 연결 오류가 발생했다. 이번 Controller 테스트 자체는 fake policy/context를 주입해 외부 호출을 피했다.

실패를 숨기거나 제품 코드를 변경하지 않았다.

## 테스트할 수 없었던 항목

요구된 8종은 모두 테스트 코드로 작성하고 실행했다. 다만 시나리오 1의 최종 `running → resolved`는 위 제품 결함 때문에 관측할 수 없었다. REST approve 직후 `resuming`까지와 그 전 단계는 관측했다.
