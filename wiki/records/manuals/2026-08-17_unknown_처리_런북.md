# unknown Outbox 처리 런북

`unknown`은 publisher가 timeout 또는 연결 오류를 반환해 실제 전달 여부를 알 수 없는 상태다. 자동 재시도하지 않으며, `/ops/outbox`는 확인 결과를 기록하는 화면이지 하류 시스템의 사실을 대신 확인하는 화면이 아니다.

## 처리 절차

1. `/ops/outbox`에서 `topic`, `payload_json` 요약, 오류, 시각과 시도 횟수를 확인한다.
2. 해당 topic과 payload가 가리키는 하류 시스템에서 직접 전달 여부를 조회한다. 실제 배포에서는 결제 게이트웨이 대시보드, 이메일 발송 로그, 메시지 브로커 소비 로그 등 해당 시스템의 공식 조회 경로를 사용한다. 이 저장소에는 실제 결제 provider 어댑터가 없으므로 화면만 보고 결론내리지 않는다.
3. 확인한 조회 시각, 시스템, 검색 키와 결과를 note에 적는다. note가 없으면 처리되지 않는다.
4. 확인 결과에 맞는 선택지를 누른다.

## 선택지의 의미

- **배달 확인됨** (`confirmed_delivered`): outbox를 `resolved`로 바꾸고 기록만 남긴다. 재발행하지 않는다.
- **배달 안 됨(재시도)** (`requeue`): 사람이 재발행해도 안전하다고 판단한 경우에만 `pending`으로 돌리고 즉시 다시 집을 수 있게 한다. worker가 한 번 다시 발행한다. attempts는 유지한다.
- **배달 안 됨(포기)** (`confirmed_not_delivered`): outbox를 `resolved`로 바꾸고 기록만 남긴다. 재발행하지 않는다.

잘 모르겠으면 아무 것도 누르지 말고 에스컬레이션하라. 불확실한 상태를 추정으로 처리하거나 일단 재시도하지 않는다.
