# 일수를 어떻게 산정하나

`[실측]` 원본은 `final_project_cs/wiki/records/vision/ESTIMATION_BASELINE.md`. **[vision-backlog](../product/vision-backlog.md)의 일수가 여기서 나온다.**

## 왜 인·일을 쓰지 않나

**AI 협업에서는 비용의 성격 자체가 다르다.**

```
전통적 산정   35~115 인·일
재산정         2~10 일
```

**같은 일을 다르게 세는 게 아니라 다른 것을 센다.**

## 실측 — 4개 저장소

`[실측]` **활동일은 커밋이 있는 고유 날짜다.** 캘린더 기간이 아니다.

| 프로젝트 | 총 줄 | 커밋 | 활동일 | **활동일당** | 커밋당 |
|---|---:|---:|---:|---:|---:|
| **A-COP** | 18,390 | 18 | **1일** (실 2시간 21분) | **18,390** | 1,022 |
| MyKeyDict | 76,059 | 52 | 8 | 9,507 | 1,463 |
| yok3x | 102,130 | 206 | 29 | 3,521 | 496 |
| jira_for_me | 24,019 | 105 | 14 | **1,715** | 229 |

`[실측]` 측정 조건 — 소스·문서 확장자만, `node_modules`·`.venv`·`dist`·`build` 제외. **전부 1인 작업이다.**

**`Hackerthon` 은 뺐다** — 3커밋 6분에 18,501줄이라 기존 코드의 초기 임포트로 봤다.

## ★ 10배 차이는 설계 판단이 끝났느냐다

**같은 1인 + AI 인데 활동일당 1,715 ~ 18,390 줄로 갈린다.**

| 상황 | 활동일당 | 어디 |
|---|---:|---|
| **설계 확정 후 구현만** | **18,000줄 이상** | A-COP — v5 계획서가 완성돼 있었고 **handoff 계약 6종을 먼저 깔고** 시작했다 |
| 새로 쓰는 작업이 지배적 | 약 9,500 | MyKeyDict |
| 설계하면서 구현 | 약 3,500 | yok3x |
| **시행착오 반복** | 약 1,700 | jira_for_me |

### 커밋당 줄 수가 더 정확한 신호다

`jira_for_me` 는 커밋 105개에 24,019줄 — **커밋당 229줄**이다.

> **코드량이 적어서 느린 게 아니라 고쳐 쓴 횟수가 많아서 느렸다.**

## AI 가 줄여주는 것과 못 줄이는 것

| 구분 | 단축 |
|---|---|
| **생성** — 어댑터·스키마·마이그레이션·테스트·문서 | **큼** |
| **검증·통합** — 결과가 맞는지 사람이 판정 | **작음** |
| **대기** — 외부 조직 연동·프로바이더 쿼터·인프라 | **없음** |

**그래서 견적을 셋으로 나눠 적는다.**

### 검증이 병목이라는 직접 증거

`[실측]` RAG 코퍼스가 **5회차에 통과했다.**

```
v1  보일러플레이트       거부
v2  중앙 유사도 미달      거부
v3  무작위 토큰 주입      거부
v4  청크 평균 56자        거부
v5                      통과
```

→ [../../final_project_cs/wiki/context/corpus-authoring.md](../../final_project_cs/wiki/context/corpus-authoring.md)

**생성은 다섯 번 다 빨랐고 검증이 네 번 막았다.**

`[실측]` 원본이 든 증거는 셋이다. 나머지 둘 — **RAG 검색이 `::vector` 캐스트 누락으로 100% 실패하고 있었는데 한동안 발견되지 않았다**([rag-retrieval.md](../../final_project_cs/wiki/context/rag-retrieval.md) 실패 사례 셋), **Controller의 `resuming→completed` 결함이 뒤늦게 드러났다**([case-lifecycle.md](../../final_project_cs/wiki/runtime/case-lifecycle.md)). 셋 다 "만드는 건 빨랐고 걸러내는 데 시간이 들었다".

### 2시간 21분에 무엇이 만들어졌나

`[실측]` 2026-08-12 15:14~17:35, 커밋 18개. 저장소 골격 + handoff 계약 6종 → Core 계약·전이표·리듀서(테스트 53건) → DB 18테이블·마이그레이션·seed → RAG 코퍼스 25문서 → Context Broker → REST 5 + MCP 3(테스트 74건) → Agent Team 2종 + VOC 배치 → 운영 UI 4화면 → 평가 하네스 → Controller·WAIT/RESUME·Outbox(테스트 107건).

**18,390줄의 구성** — Python 5,918줄/90파일 · 테스트 1,652줄/28파일 · **문서 8,718줄/132파일.** 절반이 문서다. 이 기준선을 코드 생산성으로만 읽으면 안 된다.

## 6명이라고 6배가 아니다

> **생성량이 늘어난 만큼 검수 부하도 늘어난다.**

`[실측]` **비전 항목 대부분은 한 사람이 끝까지 보는 수직 기능이다.** Graph Store 도입을 3명이 나눠서 하지 않는다.

→ [../governance/parallel-work.md](../governance/parallel-work.md)

| 무엇 | |
