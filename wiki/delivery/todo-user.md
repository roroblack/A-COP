## 2. 푸시 — 로컬 커밋 19건

`[실측 2026-09-09]` `role-core1` 이 `origin/role-core1` 보다 **19 커밋** 앞서 있다.

- [ ] 실행 전 — 다른 세션의 미커밋 파일은 스테이징하지 않는다

```bash
git push origin role-core1
```

거부되면(non-fast-forward) 억지로 밀지 않는다.

```powershell
git pull --rebase origin role-core1; if ($?) { python program/scripts/check_wiki.py }; if ($?) { git push origin role-core1 }
```

## 9. ★ 이전 판이 끝난 일을 시키고 있었다

`[실측 2026-09-09]` 이전 시트의 §2 는 **패치 6장을 적용하라**고 했다. 여섯 장 전부 `git apply --check` 를 통과했다는 표시가 붙어 있었다.

**지금 여섯 장 전부 적용에 실패한다.** 그런데 이유가 깨진 게 아니었다.

| 패치 | 지금 |
|---|---|
| 01 `research/index.md` 현재 기준 사실 | **이미 있다** |
| 02 쿠팡 확장 5.4.1 주의 | **이미 있다** |
| 03 참고판 README 제목 | **이미 있다** |
| 04 `data_go_kr` REPORT 취소선 | **이미 있다** |
| 05 DoD evidence 낡음 주석 9개 | **이미 있다** — 다른 문구로. 게다가 대상 경로 `final_project_cs/docs/` 자체가 2026-09-08 `wiki/records/` 통합으로 사라졌다 |
| 06 `.gitignore` sample wiki 예외 | **이미 있다** |

★**여섯 장 전부 이미 반영됐고 시트만 안 고쳐졌다.** 사용자가 시키는 대로 했으면 여섯 번 실패했을 것이다.

★**교훈 — 준비해 둔 작업물에는 유효기간이 있다.** `git apply --check` 통과는 **만든 시점의 사실**이지 실행 시점의 사실이 아니다. **시트를 낼 때가 아니라 사람이 실행하기 직전에 다시 재야 한다.**

`[실측]` 옛 패치는 `program/patches/2026-09-06/` 에 그대로 둔다 — **폐기가 아니라 반영 완료**이므로 지우지 않고 기록으로 남긴다.
