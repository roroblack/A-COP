# 최종발표 2026-10-26

`[실측]` 2026-09-09 기준 **D-47**. 근거는 v11 §8·§9·§12.

## 목표

> **믿을 수 있다**

중간발표가 "동작한다"였다면 여기는 **수치와 증거**다.

## ★ 그 수치의 근거가 지금 0건이다

`[실측 2026-09-09]` `eval/datasets/golden.jsonl` 72건이 전부 쇼핑몰이고 **여행 시나리오는 0건**이다(첫 행이 `g-order-01`).

★**이것이 최종발표의 가장 큰 위험이다.** "믿을 수 있다"는 주장은 측정으로만 서는데, 측정할 데이터가 아직 없다. v11 §10 도 같은 걸 리스크로 세웠다 — **하네스는 승계하고 시나리오만 교체**한다.

| | 승계 | 교체 |
|---|---|---|
| 평가 하네스 (A/B/Proposed·judge·bootstrap·McNemar) | **그대로 쓴다** | — |
| 골든셋·holdout 시나리오 | — | **전량 새로 만든다** |
| judge 루브릭 | 틀은 승계 | **구멍 먼저 수리** (v11 §10) |

`[미확보]` **여행 골든셋을 몇 건 만들지 안 정했다.** 쇼핑몰은 golden 60 + holdout 20 이었다.

## 보여줄 것

| 항목 | 무엇으로 | 지금 |
|---|---|---|
| **선제 감지 루프** | 변화 감지 → 재계획 → 재검증 → 통지 → 거부 시 되돌림 | **이게 제품의 정체성이다** (v11 §3 목표 3) |
| 통지 전 재검증 통과율 | 100% 여야 한다 | 측정 전 |
| 확인 시각 표시율 | 100% 여야 한다 (목표 2) | 측정 전 |
| 적절한 기권율 / 과잉 기권율 | **둘을 반드시 같이 본다** (v11 §8) | 여행 데이터 `[미확보]` |
| 인계 건의 근거 첨부율 | 목표 5 | 측정 전 |
| 업체 건 인계 | 변경 링크에 담긴 대안·차액 (목표 6) | 구현 전 |
| Team 교체 가능성 | Core 격리 위반 0 | **유지 중.** 단 아래 ★ |
| **DoD 26항목** | v11 §12 — 자동 20 · 아키텍처 테스트 4 · 측정 2 | v9 의 29항목은 쇼핑몰 기준이라 안 쓴다 |

★**기권 두 지표는 반드시 같이 본다.** 하나만 보면 "전부 사람에게 넘김"이 만점이 되거나 "전부 자동 처리"가 만점이 된다(v11 §8).

★**"Core 격리 위반 0"을 그대로 말하면 과장이 된다.** `[실측 2026-09-09]` 도메인을 갈면서 `app/core/` 파일 둘을 고쳐야 했다 — 구현 참조 허용 목록과 외부 소스 자격증명 칸. **Team 로직은 한 줄도 안 들어갔지만 "Core 를 하나도 안 고쳤다"는 아니다.** → [../../architecture/pack-model.md](../../architecture/pack-model.md)

## 핵심 주장

> 우리는 **고객이 문제를 알기 전에 알아채고 조정한 뒤 통지한다.**

★**일반적인 CS 와 방향이 반대다**(v11 §3). 고객은 마음에 안 들 때만 말하고, 그때 되돌린다.

★**여기에 붙는 안전 주장이 하나 더 있다** — 그렇게 먼저 고치는 것은 **우리 DB 의 일정 버전까지**다. **업체 예약과 결제는 승인 없이 건드리지 않는다**(v11 §4-C·§11).

## 시연과 실제 동작을 갈라 말한다

★**최종발표에서 가장 사고 나기 쉬운 자리다.** v11 §10 리스크 — "시뮬레이터를 실적으로 오해".

| 무엇 | 어떻게 말하나 |
|---|---|
| 우리 일정 조정 · 변경 링크 생성 | **실제 동작** |
| 협약사 자동 예약 변경 | **시연이다.** Mock 공급자 한정, `tier == 'simulated'` 게이트 |
| 예약·현장 데이터 | **합성이며 그렇게 표시한다** (v11 §11) |
| 성능 비교 | **하지 않는다.** 비교 시험을 수행하지 않았다 (v11 §11) |

★**남은 것은 액티비티 운영 변경 정보 출처 하나다.** 뒤의 둘(49,000원 수용·인바운드 손익)은 **미결정을 미결정으로 발표한다** — 억지로 채우면 질문 한 번에 무너진다.

★**서울로 좁힌 것을 어떻게 말하는지가 발표 문구의 문제다.** **"서울에서 검증했다"이지 "서울만 된다"가 아니다** — 코드에 도시가 박히는 자리가 없다(D-016).

`[미확보]` **v10 이 말하지 않는 것 하나.** `A2A`·`MCP`·`Docker`·`AWS` 문자열이 v10 본문에 0회다. 부트캠프 요구사항 대응표도 없다. **빠진 것인지 뺀 것인지 안 정해졌고, 심사에서 물어볼 수 있는 자리다.**
