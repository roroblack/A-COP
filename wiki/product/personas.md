# 페르소나

`[실측 2026-09-09]` 근거는 v11 §1·§3.

## ★ 판올림으로 구매 결정자가 바뀌었다

**이게 이 문서에서 가장 크게 바뀐 것이다.** 쇼핑몰 판에서는 상담원 12명을 거느린 운영 책임자가 돈을 냈다. 여행에서는 그 자리가 없다.

| | v9 (쇼핑몰) | **v10 (여행)** |
|---|---|---|
| 사는 사람 | **기업 CS 조직 책임자** (B2B) | **여행팀 본인** (v11 §1 — 팀당 여행 이용권 7일·4인·2도시 59,000원) |
| 우리를 쓰는 사람 | 상담원 | **고객의 개인 에이전트.** 우리는 API 로만 만난다 |
| 사람이 하는 일 | 초안 검토·승인 | 자동 처리 한계에서 넘어온 건 처리 (v11 §3 목표 5) |

★**"상담원 조직의 생산성"이라는 이야기가 통째로 빠졌다.** [../business/unit-economics.md](../business/unit-economics.md) 의 모델 조직(상담원 12명·연 126,000건)은 쇼핑몰 판의 것이고, 여행 원가 모델은 아직 없다 `[미확보]`.

## 이현우 — 인바운드 여행자 ★ 이 사람이 돈을 낸다

| | |
|---|---|
| 누구 | **처음 한국에 자유여행 오는 외국인 개인·친구 그룹** (v11 §1 1순위) |
| 상황 | 가고 싶은 곳과 예약 몇 개는 있는데 전체가 성립하는지 모른다 |
| 하려는 것 | 도착해서 헤매지 않는다 |
| 막히는 것 | 한국어 중심 플랫폼에서 정보를 못 얻는다. **변경이 생기면 현지 연락처로 혼자 풀어야 한다** (v11 §2) |
| 두려운 것 | 여행 중에 무너지는 것. 그때는 고칠 시간이 없다 |
| 성공 기준 | **문제가 생긴 걸 내가 알기 전에 이미 조정돼 있다** |

**대표 문장.** "비가 오면 그 날 예약이 어떻게 되는 건지 아무도 안 알려줘요."

★**이 사람은 우리 화면을 안 본다.** 우리는 자체 앱도 음성도 만들지 않는다(v11 §1). 이 사람은 **자기 개인 에이전트를 통해서만** 우리를 만난다.

`[미확보]` **이름을 한국어로 붙여 뒀다.** 1순위 고객이 외국인인데 페르소나 이름이 한국어인 것은 앞뒤가 안 맞는다. 국적을 정할 때 같이 고친다.

★**언어는 이 사람의 문제가 아니게 됐다.** `[실측 2026-09-10]` 우리는 **한국어 하나**만 내고 **고객 언어 번역은 개인 에이전트가 한다**(v11 §1 · D-016). 이 사람이 무슨 말을 쓰는지는 우리 층에서 안 보인다 — **에이전트가 그 언어를 하는지에 달렸고, 그건 아직 확인 안 했다.**

## 개인 에이전트 — 우리와 실제로 말하는 상대

| | |
|---|---|
| 무엇 | 고객의 개인 AI (OpenClaw·Hermes 등, v11 §0-1). **사람이 아니다** |
| 하는 것 | 일정을 만들어 우리에게 넘기고, 우리 통지를 받아 고객에게 전한다 |
| 우리에게 요구하는 것 | **기계가 읽을 수 있는 판정.** 근거·확인 시각·무엇을 왜 바꿨는지 |
| **번역** | **이쪽이 한다.** 우리는 **한국어 하나**만 낸다 → [../decisions/D-016-scope-narrowing-reasons.md](../decisions/D-016-scope-narrowing-reasons.md) |
| 우리가 하면 안 되는 것 | 근거 없이 단정하기. 이 상대는 우리 말을 **그대로 고객에게 옮긴다** |

★**계획을 만드는 것은 우리 일이 아니다**(v11 §4-A). 이 에이전트가 만든 일정을 받아 **성립하는지 판정하고 여행 종료까지 지켜본다.**

★**이건 사람 페르소나가 아니라 계약 상대다.** 그래도 여기 두는 이유는 **우리 출력의 형식을 이쪽이 정하기 때문**이다 — 통지 문구가 영어인 것도(v11 §5-A) 이 경로 때문이다.

## 운영자 — 넘어온 건을 받는 사람

| | |
|---|---|
| 상황 | 자동 처리가 한계를 만나 넘긴 건을 받는다 (v11 §3 목표 5) |
| 하려는 것 | 왜 넘어왔는지 바로 알고 판단한다 |
| 막히는 것 | 근거 없이 "확인 필요"만 오면 처음부터 다시 봐야 한다 |
| 두려운 것 | **되돌림이 실패한 업체 예약**(v11 §10). 돈이 걸렸는데 상태를 모른다 |
| 성공 기준 | 넘어온 건에 근거가 붙어 있어 재조사 없이 결정한다 |

**대표 문장.** "이게 왜 나한테 왔는지, 뭘 확인했고 뭘 못 확인했는지부터 보여주세요."

★**언어가 안 갈린다.** `[결정 2026-09-10]` 고객 통지와 운영자용이 **같은 한국어 한 벌**이다(v11 §5-A). v10 까지는 고객 통지를 영어로 두려 했다.

## 페르소나 ↔ 평가 연결

**이게 이 문서의 본래 핵심이다** — 페르소나마다 어떤 지표가 그 사람의 개선을 증명하는지 정해 둔다.

★**지금 그 연결이 끊겨 있다.** `[실측 2026-09-09]` 골든셋 72건이 전부 쇼핑몰이고 **여행 시나리오는 0건**이다(`eval/datasets/golden.jsonl` 첫 행이 `g-order-01`).

| 페르소나 | 페인 | 증명 지표 | 골든셋 |
|---|---|---|---|
| 이현우 | 변화를 내가 알기 전에 조정돼야 한다 | 감지→통지 시간, **통지 전 재검증 통과율**(v11 §3 목표 3) | `[미확보]` 0건 |
| 개인 에이전트 | 근거 없는 문장을 그대로 옮기게 된다 | `groundedness`, **확인 시각 표시율**(목표 2) | `[미확보]` 0건 |
| 운영자 | 근거 없이 넘어오면 재조사한다 | **인계 건의 근거 첨부율**(목표 5), 적절한/과잉 기권율 | `[미확보]` 0건 |

지표 정의는 [../evaluation/metrics.md](../evaluation/metrics.md), 데이터셋 상태는 [../evaluation/golden-set.md](../evaluation/golden-set.md).

★**연결이 끊긴 페르소나는 지운다는 규칙을 지금 적용하면 셋 다 지워야 한다.** 그러지 않는 이유는 **골든셋이 아직 안 만들어진 것이지 페르소나가 근거를 잃은 게 아니기 때문**이다. 여행 골든셋이 나오면 위 표의 오른쪽 칸을 실측으로 채운다 — 그전까지 이 표를 "증명됐다"로 읽지 않는다.
